# 纲目与正文校准规范

## 目录结构

- `00-full-book-outline.md`：允许剧透的全书总纲，建立六部结构、全书因果链、人物弧线和高潮回收图。
- `volumes/`：六部篇章分纲，说明每一部的进入状态、阶段目标、主要篇章、代价和离开状态。
- `arcs/`：指定高潮、大战和高潮之间过渡材料的分纲。
- `detail/`：按节编写的正文校准细纲，直接约束保留、压缩、润色和信息释放。
- `notes/`：人物、伏笔、资源、时间和事实争议台账。
- `index/`：原文候选章节索引与源文件审计。索引候选不是未经人工确认的最终篇章边界。

## 证据引用格式

纲目中的每一条事实都应尽量附带可追溯定位，推荐使用以下格式：

`[源文：第 X 节《标题》，索引行 source_line=NNN]`

跨章节归纳使用：

`[综合：第 X—Y 节；后文回收：第 Z 节]`

内部纲目允许使用完整原文的后见信息，但必须注明“后文回收”或“编辑后见”。如果只依据当前批次，明确写“当前批次证据”，不得把推测写成原文事实。

## 总纲字段

总纲至少回答：

- 六部之间如何承接；
- 方源的阶段目标、能力边界、资源边界和身份变化；
- 主要人物、势力和主题线如何变化；
- 主要高潮的前置条件、关键决断、不可逆代价和后果；
- 早期伏笔在哪里被后文回收；
- 哪些内容是编辑后见，哪些内容必须保持读者当时的未知状态。

总纲可以揭示终局，但不能成为正文的替代品。它服务于结构校准，不直接规定压缩比例。

## 分纲字段

篇章分纲使用“状态变化”而非事件清单组织内容。每个篇章至少说明：

- 开端状态和方源目标；
- 其他人物或势力的目标；
- 关键资源、时间和力量限制；
- 冲突如何升级；
- 中段转折和高潮决断；
- 决断造成的代价、关系变化和世界状态变化；
- 伏笔与信息释放的层次；
- 与前后篇章的承接；
- 正文哪些内容必须保留、哪些重复内容可压缩。

分纲不得只写“获得传承”“实力提升”“大战获胜”等结果句，必须保留实现结果的行动链和代价链。

## 细纲字段

细纲以节为单位校准正文。每节至少记录：

- 场景、时间与进入状态；
- 本节叙事功能和事件因果链；
- 方源目标、阻力、选择和代价；
- 人物心理、关系变化及现场感来源；
- 读者此时知道的内容、人物知道的内容和编辑后见；
- 伏笔、资源和时间状态；
- 必须保留、可以压缩、只能润色不可削弱的材料；
- 不得提前揭示的后文信息；
- 逻辑、称谓、设定和章节承接检查；
- 本节结束状态与下一节牵引。

## 信息释放规则

1. 总纲可以使用全书最终设定和已回收伏笔，正文不得因此提前泄露。
2. 正文遵守原书的信息释放顺序。早期叙述中的误认、传闻、家族史和人物自我判断，除非属于明确错误或编辑噪声，不得用后见真相直接替换。
3. 后文已经证明早期说法不完整时，正文保留悬念，细纲注明“后文回收”或“有意未知”。
4. 未能由全书多处证据确认的数字、时间、称谓和因果进入 `notes/fact-disputes.csv`，先使用中性表达，不擅自统一。
5. 伏笔的功能不只在于答案，还包括等待、误导、心理预期和答案揭示后的反差；压缩时不得只保留答案。

## 正文修改分级

- **保留**：剧情、心理转折、行动过程、关键对话、场景信息、伏笔、高潮前积累和高潮后果不得删除。
- **压缩**：只合并重复环境、同义解释、重复回顾和不增加信息的过渡句；不得把过程压成结果摘要。
- **润色**：修复转码残缺、语法、指代、语序、节奏和不必要的重复，保持原意、视角和情绪强度。
- **校正**：仅在全书证据足够时修复明确的时间线、称谓、数字或设定冲突；证据不足则进入争议台账。
- **不得改写**：不得新增原文没有的剧情、动机、能力、人物关系或世界真相；不得用作者解释取代人物行动和心理。

## 批次提交与校验

每一阶段独立提交并推送 `origin/main`。提交前至少运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate_editorial_assets.ps1 -Phase baseline
```

生成总纲后使用 `-Phase outline`，生成细纲后使用 `-Phase detail`，全部资产和正文回校结束后使用 `-Phase final`。校验失败时修复文件或脚本，不通过放宽规则掩盖问题。

完整原文只作为仓外证据源使用；原文路径、字符统计和索引差异记录在 `index/source-audit.*`，完整文本不得复制或加入 Git。
