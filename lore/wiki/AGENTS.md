# Wiki 编辑约定

本目录是《蛊真人》的 AI 可读蒸馏层。编辑前先读 `index.md` 和相关分类的 `index.md`。

## 页面格式

每个知识页面只使用四个 frontmatter 字段：

```yaml
---
type: character
name: 方源
aliases: [古月方源]
sources: ["notes:game/分支：六卷精编版/读书笔记/A2a-00001-15500-补读.md", "canon-index:CAN-SMALL-LIGHT-001"]
---
```

`type` 使用 `character`、`gu`、`event`、`world` 或 `theme`。文件名使用稳定的 ASCII slug，`name` 保存中文显示名。

## 正文约定

每页尽量使用以下区块：

```markdown
## 原著明确内容

## 分析与解读

## 待核对
```

主题页在上述区块之外，优先补充以下导航结构：

```markdown
## 核心定义

## 相关人物

## 相关事件

## 主题冲突
```

主题页的“游戏设计边界”只说明未来可能关联的方向，不直接写玩法规则、数值或资产方案。

原著明确内容只写有来源的事实；分析与解读可以归纳多个事实，但必须让读者看出它是分析；待核对记录缺口、冲突或尚未回读的说法。

页面之间优先使用相对 Markdown 链接；例如从 Wiki 根目录查看时可写 `[春秋蝉](gu/spring-autumn-cicada.md)`，从 `characters/` 页面则使用对应的 `../gu/` 路径。新增链接前先确认目标文件存在。

## 来源与边界

- 来源命名空间固定为四类：`source:`（原文，指向本地 `source/`）、`notes:`（读书笔记）、`memory:`（记忆库）、`canon-index:`（指向 `game/docs/lore/canon-index.md` 的事实条目 ID）。
- 原文、`canon-index.md` 和读书笔记是不同层级，不要把读书笔记的判断自动升级成原文事实。
- 《人祖传》是世界内典籍；它的寓言内容与正文中被验证的世界规则要分开写。
- `lore/research/` 下的重写总纲、人物弧光和角色台账属于创作资料，除非明确标注，不得写成原著事实。
- 不复制大段原文；使用简短转述、章节号、行号或已有笔记区间定位。
- 游戏数值、卡牌效果和《问真》改编放在游戏项目资料中，不写入本 Wiki 的原著事实区。

## 批次与评审

- 以一个可聚焦的主题簇、叙事冲突或世界规则链作为最小交付和评审单元，不按单个页面逐步请求确认。
- 一个批次至少同时完成核心页面、分类索引、反向链接、来源边界和统一验收；相关页面不再留下可以在同一批次内完成的“待建立”入口。
- 只有在范围明显膨胀、来源互相冲突、需要用户选择，或需要新的外部权限时才中途停下。普通的页面拆分、互链和格式修正应在同一批次内完成。
- 评审时优先检查批次的整体模型、事实边界和遗漏关系，而不是重复审阅单个 Markdown 文件的低收益细节。

## 更新方式

先用 `rg` 回查并定义本批次边界，再批量修改相关页面、索引和反向链接；完成后统一运行 `git diff --check`、来源路径检查、断链检查和 `git status --short -- lore/wiki`。Git 负责历史，不另建版本数据库。
