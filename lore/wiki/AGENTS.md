# Wiki 编辑约定（v2，2026-09-25 起）

本目录是《蛊真人》的 AI 可读蒸馏层，按 LLM Wiki 方法论运作：源文档只读，本目录是持续重构的编译层，读时综合。**ingest 是对既有页面的 refactor，不是追加摘要**；新资料进入时重写受影响的实体页、事件页并显式标记冲突。编辑前先读 `index.md` 和相关分类的 `index.md`。

Wiki 的目标是压缩 AI 理解原文的上下文成本：AI 平时优先读 Wiki，遇到缺口、冲突或高风险细节再回查原文；Wiki 的价值是减少 AI 重读原文并加速《问真》的剧情、系统、美术和关卡生产，不为知识治理本身继续增加规则。

## 分层模型

| 层 | 内容 | 落点 |
|---|---|---|
| L0 原文 | `蛊真人-clean.txt`、读书笔记、记忆库 | 本地只读，行号/卷节定位 |
| L1 证据 | 单条事实的原文锚点（路径+行号/节号） | 页内锚点与 canon-index 证据列 |
| L2 事件 | 叙事顺序 + 因果 + 参与者 | `events/` |
| L3 实体与状态 | 实体 + 状态时间线 + 关系演变 | `characters/`、`gu/`、`world/` |
| L4 规则命题 | 可追溯 claim（含禁止误读） | [canon-index](../../game/docs/lore/canon-index.md) + 页内规则节 |
| L5 综合页 | 人与 AI 读的 wiki 页面 | 本目录全部页面 |
| L6 推导 | 《问真》数值与改编裁定 | 不进本目录，放游戏项目资料 |

规则：L0–L5 与 L6 严格分离。原著事实、角色观点、传闻、游戏数值不得混写。

## 页面格式

frontmatter 七字段 + 迁移标记：

```yaml
---
type: gu
name: 月光蛊
aliases: [月光蛊, 月光刃]
description: 一转镇族蛊虫，发射月刃的基础战斗蛊
date: 2026-09-25
tags: [gu, combat, ancient-moon]
sources:
  - "source:蛊真人-clean.txt"
  - "canon-index:CAN-SMALL-LIGHT-001"
schema: 2
---
```

- `type`：`character`、`gu`、`event`、`world`、`theme`、`rules`。文件名用稳定 ASCII slug，`name` 保存中文显示名。
- `description`：一句具体说明（供搜索与关系图提示）；`date`：YYYY-MM-DD，实质修订时更新；`tags`：≥2。
- `sources`：页面级来源清单。`schema: 2` 标记已迁移页面，未标记页按 v1 规则继续有效。
- `source:` 命名空间沿用既有形式 `source:source/蛊真人-clean.txt`（check.ps1 已知路径）；本地 `source/` 目录缺失、原文实际在仓库根属已登记债务，不在页面层另造第三种写法。

## 正文区块

基础四区块沿袭 v1，边界不变：`原著明确内容` 只放已完成逐段原文核验的事实；`资料整理` 承载 `notes:`/`memory:` 转述（保留笔记锚点，不得当原著事实）；`分析与解读` 放跨事实归纳（必须看得出是分析）；`待核对` 放缺口与冲突。

按页面类型增加结构区块：

- 实体页（character/gu）：`## 状态时间线`——表格：时期 / 转数或形态 / 持有蛊 / 归属 / 关系变化，每行带原文锚点。实体是状态机，不是百科简介。
- 事件页（event）：`## 事件链`——mermaid 时序图 + 表格：前因 / 参与者 / 后果 / 因果指向，事件按叙事顺序编号。
- 规则页（rules）：以 `CAN-*` 为主键组织，一页一个规则簇，每条 claim 带证据列与禁止误读。
- 主题页沿用 v1 导航区块（核心定义 / 相关人物 / 相关事件 / 主题冲突 / 游戏设计边界）。

认知标记拆两维（谁说的 × 真假状态），写在主张行内：类型 `[叙事]`（叙事者陈述）、`[对话]`（角色台词，须注说话人）、`[信念]`（角色 believed X）、`[传闻]`（道听途说）；状态 `[已核]`（逐段原文核验）、`[推断]`、`[未决]`（单源/存疑）、`[已修正]`（被后续证据推翻或修正，保留原表述并注明）。**某人认为 X 不等于世界规则 X**——如"琅琊地灵说智慧蛊是星宿本命蛊"应记为 `[对话|未决]`（说话人：琅琊地灵），不得升级为世界规则。

## 一等公民 ID（L1/L2/L3）

知识编译以 ID 为骨架，不上数据库、不建独立证据目录：

- **证据 ID `E:V{段}-{6位行号}`**：指向原文证据主行，自带的定位（如 `E:V1-003380` = 段一第 3380 行，段表见 [`source/section-index.md`](source/section-index.md)）；跨行区间在正文写行号区间，E-ID 取主张主行。
- **状态 ID `ST-{实体}-{序号}`**：状态时间线行的主键，如 `ST-MOONLIGHT-02`。
- **事件 ID `EVT-{簇代码}-{序号}`**：如 `EVT-QMS-001`（QMS=青茅山簇）。事件在承载其最完整描述的页面定义一次；其他页面（人物/蛊虫/事件页）只引用同一 ID，不各自复述——防知识漂移。
- **链路约定**：Evidence → supports → Event/State → supports → Claim（`CAN-*`）。页面主张尽量落在这条链上；"谁支持某 claim"应能沿 ID 追到 E-ID 与原文行号。

## 可视化与引用

- 可视化按需提供（SHOULD，非 MUST）：页面存在 ≥3 个状态变化、≥3 个事件节点、复杂组合关系或明确时间序列时，应提供结构化可视化——状态时间线与对比用表格，流程与因果用 mermaid（节点标签含标点须加引号）；单事实简单页不强配图。
- 每个事实主张带锚点：原文用 `蛊真人-clean.txt:行号`（精确主锚点）；人文定位辅以 [`source/section-index.md`](source/section-index.md) 的全局节序（节#N）或段内节号+节题（节号按六段重置、非全局唯一）；笔记用 `notes:` 锚点；已固化命题用 `canon-index:CAN-*`。一个主张一个引用，不合并无关主张。
- 页面之间相对 Markdown 链接；新增链接前先确认目标文件存在。

## 来源与边界

- 来源命名空间固定四类：`source:`（原文，`source:source/蛊真人-clean.txt`）、`notes:`（读书笔记）、`memory:`（记忆库）、`canon-index:`（`game/docs/lore/canon-index.md` 的 `CAN-*` 条目）。
- 原文、`canon-index.md` 和读书笔记是不同层级，不把笔记判断自动升级成原文事实；《人祖传》寓言内容与正文验证的世界规则分开写；`lore/research/` 创作资料不得写成原著事实。
- 不复制大段原文；用简短转述 + 章节/行号定位。
- canon-index 是 L4 命题登记表：页面主张与 CAN-\* 条目互相链接；多证据命题进 canon-index 时保留全部引用；命题被推翻时改 canon-index 状态并同步受影响页面（refactor，不是留旧句）。

## 批次与评审

以一个可聚焦的主题簇、叙事冲突或世界规则链为最小交付和评审单元。批次内必须同时完成新增页、分类索引、反向链接、来源边界和验收，不留可在本批完成的"待建立"入口。批次内部按五步走：

1. **抽取**：只抽实体 / 事件 / 命题 / 状态变化 / 关系，禁止整段总结。
2. **归一**：名称与 ID 对齐既有页面和 CAN-\* 条目（方源=古月方源=方正哥哥 是同一实体）。
3. **时序与因果**：事件排序、前因后果接线，补 `事件链`。
4. **巩固**：多证据命题进 canon-index（引用全保留），冲突显式降级 `[后判]`。
5. **页面重构**：改既有页 + 反向链接 + 索引 + Key Findings，不追加孤立新页。

只有在范围明显膨胀、来源互相冲突、需要用户选择，或需要新的外部权限时才中途停下。两条并行工作线的簇车道划分与工作树协作规则见 [COORDINATION.md](COORDINATION.md)。

## 迁移

绞合式迁移：新页与被触碰页按 v2 执行；存量 v1 页在其批次到来前保持有效，不为迁移而迁移。**Schema v2.1 已冻结（2026-09-25 用户裁定）：除非基准暴露缺陷，不增加字段、不重构目录、不上数据库、不引入 GraphRAG。**迁移节奏以证据链簇为单位打穿（一簇内 L0→L5 全链贯通、ID 化、能沿 Wiki → Claim → Event/State → Evidence → Raw 一路追溯），不整库铺开；每打穿一簇，跑对应 `tools/benchmark-*.md` 固定题集做知识完整性回归（Wiki-Only 作答，目标 ≥45/50），并记录蒸馏率基线（簇页面 token 量 vs 覆盖同范围原文的 token 量）。`index.md` 是 hub，维护 Key Findings（跨页最重要结论，带源）与导航；范围、结论或结构变化时更新，不手工记活动日志（历史由 log.md 承担）。

## 更新方式

先用 `rg` 回查并定义本批次边界，再批量修改相关页面、索引和反向链接；完成后统一运行 `pwsh -NoProfile -File lore\wiki\tools\check.ps1`、`git diff --check`、来源路径检查和 `git status --short -- lore/wiki`。Git 负责历史，不另建版本数据库。
