## 1. 评审范围（冻结内容清单）

1. **六层模型**：L0 原文（只读）→ L1 证据（E-ID）→ L2 事件（EVT-ID）→ L3 实体状态（ST-ID）→ L4 命题（canon-index CAN-\* 复用）→ L5 综合页；L6 推导（游戏数值）严格出库。
2. **页面格式**：frontmatter 七字段（type/name/aliases/description/date/tags/sources）+ `schema: 2` 迁移标记；区块纪律（原著明确内容/资料整理/分析与解读/待核对）。
3. **ID 体系**：`E:V{段}-{6位行号}`（自带定位）、`ST-{实体}-{序}`、`EVT-{簇}-{序}`；链路约定 Evidence → Event/State → Claim。
4. **认知标记**：类型`[叙事|对话|信念|传闻]` × 状态`[已核|推断|未决|已修正]`。
5. **规则页类型**：`type: rules`，主键暂用簇内前缀（TRIB/DM/REF/KM/PR/VEN/DRM），CAN-\* 并档受 `game/` 冻结限制。
6. **可视化规则**：条件 SHOULD（≥3 状态变化/事件节点/复杂组合/明确时序）。
7. **门禁与基准协议**：check.ps1 check1–8；每簇 `benchmark-*.md` 50 题 Wiki-Only 盲测（≥45/50）；蒸馏率基线记录。
8. **迁移策略**：绞合式（触碰页按 v2 执行）；**冻结条款**：除非基准暴露缺陷，不加字段、不重构目录、不上数据库、不引入 GraphRAG。

## 3. 分维度评审

### 3.1 设计完备性
- 六层模型覆盖了已出现的全部知识形态（剧情/叙事/规则/粗蒸馏/哲学/规则页），四类簇 + 哲学页均无格式缺口。
- `type: rules` 的落地（rules/ 目录 + check7 映射）属冻结规范的实现，不构成 schema 变更。
- **缺口**：无"映射/跨引用"专用页类型——现以投影表（如 qing-mao-mountain 事件链投影）解决，未暴露为问题。

### 3.2 有效性证据
- 三类簇盲测全部达标，且质量信号递进：答题者从"答对"进化到"自发沿 ID 追溯"与"主动引用待核对边界拒绝硬答"。
- 认知标记在盲测中被用作**拒绝过度断言**的依据（Q25/47），证明两维标记不只是装饰。

### 3.3 可运维性
- 三线（精蒸馏/粗蒸馏/剧情顺序）同一 checkout 并行，依靠 COORDINATION 车道 + 分区块规则实现零同页冲突（一次竞写事故当日闭环）。
- 门禁为纯 PowerShell 无外部依赖；基准为人工盲测协议，成本约 5–7 万 token/次。

### 3.4 与上游约束的一致性
- 根 AGENTS 数据边界：原文不入库 ✓（全库无原文整段）；游戏数值不入哲学/规则页 ✓（L6 隔离多次盲测验证）。
- CHANGE_CONTROL：本 schema 是知识治理工具，不改《问真》产品逻辑/数据/契约，**不触发重大变更程序**；但 canon-index 并档涉及 `game/` 冻结，维持待裁量。

## 5. 已知局限与不适用声明

- 本 schema 约束 `lore/wiki` 蒸馏层，**不约束** `game/` 数据层、`docs/` 产品协议层与 B 线粗蒸馏粒度。
- 哲学页"小说倾向"判断、规则页"禁止误读"列均为分析/治理层产物，schema 不为其提供真值保证。
- 断点后内容、L6 游戏数值、《人祖传》单行本独立核验——均在 schema 边界之外。

## 6. 评审结论与建议

**结论：建议通过——Schema v2.1 转正为 `lore/wiki` 长期格式。**

理由：四类知识形态、五个基准、三线并行运维均无格式级缺陷暴露；全部 P2 问题有登记、有缓解路径、不阻塞长期使用。

**转正条件（进入 v2.2 迭代队列，不阻塞转正）**：
1. 基准题目池轮换与独立出题机制化（P2-1）；
2. 规则口径调和专项批（P2-2，优先 TRIB-002 与 PR-002/003）；
3. check9：E-ID 段号自动校验（P2-3）。

**冻结条款维持**：转正后同样适用——除非基准暴露缺陷，不加字段、不重构目录、不上数据库、不引入 GraphRAG；任何 schema 变更走本文件同款 L1 评审。
