# AGENTS.md

## 项目定位

本仓库包含《蛊真人》相关资料整理，以及以其世界规则为素材的单机肉鸽游戏原型。当前游戏目标以 [南疆冒烟版设计](docs/superpowers/specs/2026-08-21-nanjiang-roguelite-smoke-design.md) 为准；在实现前先阅读 [实施计划](docs/superpowers/plans/2026-08-21-nanjiang-roguelite-smoke-implementation.md) 与 [项目决策浓缩对话](docs/项目决策浓缩对话.md)。

## 工作边界

- 不改写、删除或移动 `分支：六卷精编版/`、`豆包/`、`旧稿归档_不采用/`、`肉鸽设计-原始数据/` 中的资料，除非任务明确要求整理这些资料。
- 游戏首版只做南疆凡人 45--90 分钟冒烟切片；不要擅自加入其他地域、多身份、开放世界、局外成长或可玩的蛊仙阶段。
- 游戏不是纯战斗。资源、情报、人情、交易、撤离、伪装、设局和战斗都必须是可用路径。
- 不把 LLM 当规则引擎。随机种子、数值、战斗、物品、地图、NPC 隐藏状态、存档和结局必须本地且可复现；LLM 仅能在受控 JSON Schema 下生成有限交涉文本，并必须有离线模板降级。
- 所有关键状态变化必须写入不可变结构化事件日志；结局修行札记只能从事件日志和玩家已知事实归因。

## 实现约定

- 预期技术栈：Godot 4.6.2、GDScript、JSON 数据表和 GUT 测试。源代码标识符、JSON 键、测试名称和提交信息使用 ASCII；玩家可见中文文本可使用 UTF-8。
- 蛊虫、传承杀招、节点、NPC、战斗行为和结局条件保持数据驱动。原著事实、游戏平衡数值与 LLM 文案分开存放。
- 场景只负责展示状态和提交命令；领域规则必须是可测试的纯 GDScript 逻辑，不能由 UI 直接修改状态。
- 后续引入 GDQuest Open RPG 时，保留 MIT 许可证、上游 URL 和固定提交号；未经审计不要直接耦合或修改 `vendor/godot-open-rpg/`。
- 不提交本地工作树、下载缓存、构建产物、密钥或未完成的第三方克隆。

## 工作流程

1. 开始前阅读相关设计与当前 `git status`，保留用户已有的未提交改动。
2. 按实施计划的单个 Task 工作：先写可失败的测试或验收命令，再实现最小改动。
3. 每个 Task 完成时记录实现范围、验证命令和结果，并用独立清单审查变更、边界和回归风险。
4. 提交保持小而聚焦。不要用重置、强制检出或递归删除清理不理解的文件。
5. 推送前确认工作树、测试结果和远端分支；不要声称未实际验证的功能已经完成。
