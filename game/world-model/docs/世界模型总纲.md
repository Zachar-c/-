## 一、世界层级

### 1.1 修行阶位

【原著事实】蛊师修行有**一至九转**，每一转又分**初阶、中阶、高阶、巅峰**四个小境界
（`CAN-CULTIVATION-001`）。**六转后已脱离凡体，为蛊仙层次**；九转蛊仙被称为尊者，分仙尊、魔尊
（`CAN-CULTIVATION-003`）。

【原著事实】一至五转的真元有明确品阶用词：**一转青铜、二转赤铁、三转白银、四转黄金、五转紫晶**
（`CAN-CULTIVATION-002`）。原文特别提示五转应写作「紫晶真元」而非「紫金真元」。

【原著事实】资质以**元海占空窍的比例**表达：丁等二三成、丙等四五成、乙等六七成、甲等八九成；
甲等最高可达九成九，甲等之上有十种**十绝体**，元海圆满十成，但伴随空窍崩毁与早夭风险
（`CAN-APTITUDE-001`、`CAN-APTITUDE-002`）。开窍测试以步数分级：十步以下无资质，十至二十步丁等，
二十至三十步丙等，三十至四十步乙等，四十至五十步甲等（`CAN-APTITUDE-003`）。

【兼容性游戏化】首发把这段设定收束成 5 转可控阶梯 + 独立资质轴（`ADP-CULTIVATION-001`）：
丙等角色可冲二转，但**必须先在本局提升资质，才可尝试三转**——原著只说丙等「通常停在二转、
少部分侥幸三转初阶」，游戏为可读性采用硬门槛。开局固定为**丙等一转散修，元海容量 0.44**
（`GAME-PLAYER-001`、`GAME-CULTIVATOR-003`）。

【原创内容】`realms.json` 中六至九转的 **`essence_tier` 字段留空**：原著没有给出六转以上真元品阶
的用词，本模型不臆造。蛊仙阶段的核心资源是仙元，`economy.json` 只把 `immortal_stone`（仙元石）
登记为 `in_launch_scope: false` 的占位资源，不进凡人跑局（`CAN-IMMORTAL-BOUNDARY-001`）。

### 1.3 世界模型的三条硬边界

1. **规则本地、确定、数据驱动**：所有随机都经 `engine/rng.py` 的种子化 Lehmer LCG；
   同种子 + 同数据指纹 ⇒ 逐字节可复现的台账。没有 `random`、没有时间戳进入台账正文。
2. **数值单点可调**：引擎不硬编码任何调参值，一律经 `WorldModel.b(...)` 读 `balance.json`。
3. **来源可追溯**：每个实体带 `source_class` / `source_ids` / `canon_review_status` / `adaptation_note` /
   `tunable`，字段名与 `docs/lore/content-source-schema.md` 一致。

## 二、境界体系

### 2.1 真元容量与恢复

【原著事实】资质越高，真元可储量与自然恢复越高（`CAN-APTITUDE-001`）。
【兼容性游戏化】模型把它落成两条独立系数：

| 参数 | 位置 | 含义 |
| --- | --- | --- |
| `growth.essence_base` = 10 | `balance.json` | 真元基数 |
| `growth.aptitude_factor` = 丁1 / 丙2 / 乙3 / 甲4 | `balance.json` | 资质轴（整数口径，来自原型 `data/aptitude.json`） |
| `growth.aptitude_capacity_ratio` = 丁0.23 / 丙0.44 / 乙0.67 / 甲0.89 / 十绝体1.0 | `balance.json` | 元海占比（**原著口径**，用于世界观文案与校验参照） |
| `growth.cultivation_factor` = 1/3/9/27/81（1–5 转），6–9 转为 243…6561（扩展） | `balance.json` | 转数轴 |
| `growth.regen_pct_out_of_run` = 甲40 / 乙30 / 丙20 / 丁10 | `balance.json` | 局外自然恢复率 |
| `growth.regen_pct_battle` = 甲35 / 乙30 / 丙25 / 丁18 | `balance.json` | 战斗内每回合恢复率 |

- **局外真元上限** = `essence_base × aptitude_factor × cultivation_factor`
  ⇒ 丙等一转 = 10×2×1 = **20**；乙等三转 = 10×3×9 = **270**。
- **战斗真元上限** = `stage_base_battle[转] × aptitude_factor`
  （`stage_base` = 10/30/60/100/150）⇒ 丙等一转战斗 = 20，甲等五转 = 600。
- **每回合恢复** = `ceil(真元上限 × regen_pct_battle[资质] / 100)`。
- **元石换真元** = 每颗 `floor(stone_to_essence_per_stone × (0.5 + 恢复率% / 100))`，
  不超上限、不浪费（向下取整）。

> 两套 `regen_pct` 并存（局外 40/30/20/10、战斗 35/30/25/18）来自原型 `data/aptitude.json`
> 与 `data/v1_battle.json` 的双表，本模型原样保留并在 `balance.json` 中分别命名，不合并——
> 合并会改变既有实现语义。这是**已登记的既有口径差异**，见 `RISK_REGISTER.md` RISK-08。

### 2.2 转数只抬真元

【兼容性游戏化】**转数只抬高真元上限与战斗真元上限，不直接加气血、不加攻击**
（原型 2026-08-29 裁定，`PROJECT_WORLD_MODEL_AUDIT.md` §10）。
肉身三锚（气血/力量/承载）在 `balance.json` 的 `human_base_*` 里是不随转数变化的常量。

【原著事实】真元质量决定能否驱动高阶蛊：**低转真元驱不动高阶蛊**。
【兼容性游戏化】模型的**真元质量门禁**：

```
催化合法 ⇔ gu.low_rank_exception == true  或  cultivator_rank >= gu_rank
越级实际消耗 = native_cost × rank_step_ratio^(gu_rank-1) / rank_step_ratio^(cultivator_rank-1)
             ≡ native_cost × 2^(gu_rank - cultivator_rank)
```

高阶蛊师驱动低阶蛊时有折价。`engine/rules.py:can_activate` / `actual_activation_cost` 是唯一实现；
`strict=True` 时越级催蛊抛 `GuBacklash` 且**零副作用**（供 UI 预检），`strict=False` 为「强催」路径，
先扣 `2 × 超转数` 的自伤再结算。

### 2.3 突破与门槛

| 动作 | 成本 | 门槛 | 参数位置 |
| --- | --- | --- | --- |
| 1→2 转 | 5 元石 | 无 | `balance.run.cultivate_stone_cost` |
| 2→3 转 | 12 元石 | **资质 ≥ 乙等** | `balance.growth.aptitude_hard_gate` |
| 3→4 转 | 20 元石 | 资质 ≥ 乙等 | 同上 |
| 4→5 转 | 30 元石 | 资质 ≥ 乙等 | 同上 |
| 洗髓换骨（提升资质一档） | 10 寿元 + 8 元石，每局 1 次 | — | `balance.growth.aptitude_reroll` |

【原著事实】洗髓换骨以寿元为引重塑根骨（`data/aptitude.json` 的 `paths[0]`，原始依据见
`肉鸽设计-原始数据/`）。**消耗寿元属不可逆代价，执行前必须预检并明确提示**。

【原著事实】升仙涉及**天地人三气**，天地二气需与人气平衡；过程包括碎窍、纳气与后续步骤，
**碎窍不可回头**，三气失衡或贪吸天地二气会失败（`CAN-ASCENSION-001`、`CAN-ASCENSION-002`）。
【兼容性游戏化】`regions.json` 的 `ascension_window` 把这段设定登记为终局窗口，选项
`attempt_ascension` / `prepare` / `retreat`，跳过后果 `survived_failure`；**首发不把蛊仙阶段做成可继续游玩的内容**
（`ADP-ASCENSION-001`）。

## 三、道途 / 流派

### 3.1 20 条道途

【原著事实】流派是原著的核心结构：血（掌气血生灭，以血养蛊）、气（气之有无形转化）、
力（肉身蛮力与兽力叠加）、魂（魂魄壮养收摄）、炼（炼蛊合炼与蛊阵营造）、光/月华、智（念头思算）、
梦、运（气运消长）、剑（剑道道痕有侵蚀性、攻伐第一）、木、火、水、风、金（金道道痕伤口难治）、
土、奴（驭兽驱物）、天（天地规则与灾劫天意）、人、骨。`paths.json` 的 `dao_tags` 与
`schools.json` 一一对应，共 **20 条**。

【原著事实】**道标签是开放集合**（`AGENTS.md` 核心业务红线）；血、气、力、魂、炼仅是首批重点，
不是封闭流派枚举。因此 `paths.json` 每条都带 `is_open_set: true`。

### 3.2 兼修与互斥

【兼容性游戏化】`ADP-GU-SYNERGY-001`（依据 `CAN-GU-SYNERGY-001`、`CAN-GU-SYNERGY-002`）：
用标签、冷却、真元与触发条件表达蛊虫互补。模型中的兼修参数：

| 参数 | 值 | 位置 |
| --- | --- | --- |
| `combat_gate.cross_school_penalty_per_extra` | 1 | `balance.json` |
| `combat_gate.cross_school_exclusion_penalty` | 1 | `balance.json` |
| `combat_gate.school_exclusions` | `[["sword","water"]]` | `balance.json` |
| 单派蛊池规模 | 每派 40 只（`human` 42 只） | `paths.json` |
| 蛊材流派共振 | `loot.school_material_resonance` | `loot.json` |

**剑道与水道的互斥**来自原型 `data/balance.json` 的既有裁定，本模型原样保留并作为
`conflict_paths` 暴露。

### 3.3 起始蛊

【原著事实】小光蛊可辅助月光蛊，两者并用时月刃体积与攻击力扩大；小光蛊也是可参与合炼的凡蛊
（`CAN-SMALL-LIGHT-001`、`CAN-SMALL-LIGHT-002`）。
【兼容性游戏化】小光蛊保留为**固定开局的辅助型凡蛊**（`ADP-SMALL-LIGHT-001`）。
起点构筑固定为：**丙等一转散修 + 小光蛊 ×1 + 光道**，`balance.run.starter` 是唯一真源。

## 四、蛊虫

### 4.1 蛊虫的四个核心属性

【原创内容】`GAME-GU-DATA-001`：蛊虫的四个核心属性是**转数（rank）、稀有度（rarity）、
流派（school）、用途（role）**。`gu.json` 的 802 条全部带这四个字段，另有 `value`、`tags`、
`activation_cost`、`feeding`、`effect`、`effect_source`。

### 4.2 效果来源的诚实标注

**这是本模型最重要的一条数据诚信约定**：802 只蛊里只有 **57 只**有独立效果
（原型手写的 `v1_effect`），**3 只**只有组合效果（`combat_effects`），**742 只**是按角色兜底
（`effect_source: "role_default"`，由 `v1_battle.default_effect_by_role` 映射得到）。

模型**如实标注**，不假装它们有独立效果：

| `effect_source` | 条数 | 含义 |
| --- | --- | --- |
| `explicit` | 57 | 有独立 `v1_effect` |
| `combat_effects` | 3 | 只有组合效果（`kind: composite` + `parts[]`） |
| `role_default` | 742 | **按 role 兜底，不代表该蛊在原著里的独立能力** |

角色兜底映射（`balance.json` 的原始依据是 `data/v1_battle.json`）：

| role | 兜底效果 | role | 兜底效果 |
| --- | --- | --- | --- |
| `attack` | `strike` 伤害 2 | `recon` | `status: marked` |
| `defense` | `shield` 3 | `logistics` | `heal` 1 |
| `healing` | `heal` 2 | `movement` | `shift` 1 |

### 4.3 蛊虫的经济学

| 参数 | 值 | 位置 |
| --- | --- | --- |
| 定义字面价值 | 0–30 元石 | `gu.value` |
| 中央计价表 | 1–5 转 = 3/5/8/12/20 元石 | `balance.economy.gu_value_by_rank` |
| 卖出/回购基准 | `max(定义价值, 中央表[实例转数])` | `engine/rules.gu_value` |
| 公开市场回购比 | 0.5 | `balance.economy.public_buyback_ratio` |
| 低流动性资产折价 | 0.3 | `balance.economy.low_liquidity_ratio` |
| 需求价档 | 0.8 / 1.0 / 1.2 | `balance.economy.demand_price_tiers` |
| 阶段末养护总账 | 每只蛊 `feeding.stone_per_stage`（0–2）元石 | `gu.feeding` |
| 欠账后果 | 两次欠账 ⇒ 实例转数 −1（降阶），并扣气血 | `engine/rules.settle_feeding` |

【原著事实】养蛊、用蛊、炼蛊构成持续压力；一般蛊师通常养四五只同转蛊（`CAN-GU-CARE-001`）。
【兼容性游戏化】`ADP-GU-LOADOUT-001`：**不设世界观意义上的持蛊数量上限**，以真元、元石、
每阶段自动汇总的养护总账、用途与同阶匹配形成自然负担。界面可按用途整理，但整理栏位**不是**蛊槽。

### 4.4 炼蛊

| 炼法 | `kind` | 条数 | 含义 |
| --- | --- | --- | --- |
| 同名升阶 | `advance` | 377 | 同一定义 +1 转（消耗兽骨 + 6/10 元石） |
| 定式合炼 | `fixed` | 14 | 按原著配方的固定输入输出 |
| 定向晋升 | `promotion` | 76 | Q8-G 垂直切片，严格 +1 转、换蛊名、不跳级 |
| 自由混合 | `free_mix` | 1 | 无秘方自由混合，三种结果 |

【原著事实】合炼即「将不同的多种蛊虫合并成一只更高级数的蛊虫」；合炼失败可以毁掉输入蛊
（`GAME-GU-REFINEMENT-004`）。月芒蛊 = 月光蛊 ×1 + 小光蛊 ×2，失败代价示例为小光蛊消亡
（`蛊真人-clean.txt:17024–17155`）。

【兼容性游戏化】`free_mix` 结果表（`balance.economy.free_mix_recipe`）：

| 结果 | 权重 | 效果 |
| --- | --- | --- |
| `destroyed` | 5 | 输入蛊全毁 + 染上「蛊蚀」 |
| `mutation_venom` | 4 | 变异为血别蛊 |
| `explosion` | 2 | 气血 −2 / 魂 −1 / 寿元 −1 |

成功率基础 60%、每失败 +10%（上限 +30%）、盲合 −20% 并得蛊蚀（`data/synthesis.json`）。

**升炼图的图论事实**（校验器实测）：节点 88 个、有向边 97 条、**环 0 个**、
最长升炼链深度 **5 步**、同名升阶配方 377 条、纯材料炼制 1 条（`stone_shell_bone_forge`）。

## 五、时间线与地理势力

### 5.1 地理

【原著事实】南疆地势广阔而险恶，人族以**山寨**聚居（`CAN-NANJIANG-001`）。
**十万大山、山寨与商队**构成南疆贸易环境；商队跨越山险运送货物，驻扎后会形成临时商铺与摊市；
山寨与商队相互依赖（`CAN-NANJIANG-003`、`CAN-NANJIANG-004`）。
**低阶蛊师通常没有独自远游资格，三转才具备远游能力**（`CAN-NANJIANG-002`）。
青茅山上有三家山寨，狼潮时每寨分担一条（`CAN-BEAST-TIDE-002`）。

【兼容性游戏化】`ADP-RUN-001`：把广阔南疆压缩为**三阶段 / 5 层的山域路线图**。
模型把它切成 5 层，每层有原著地名线索的层名：

| 层 | 层名 | 元石预算 | 商店加价 | 敌人转数区间 |
| --- | --- | --- | --- | --- |
| 1 | 青茅山外圍 | 12 | 0% | 0–1 |
| 2 | 落瘴岭 | 16 | 10% | 0–2 |
| 3 | 血蟒涧 | 22 | 20% | 1–3 |
| 4 | 万蛊窟 | 28 | 35% | 2–4 |
| 5 | 瘴脉深處 | 35 | 50% | 3–5 |

`travel_gate.min_rank_for_free_travel = 3` 把「三转才可远游」写进数据。

### 5.2 时间压力：兽潮与寿元

【原著事实】南疆人类「每隔一段时间，都有**兽潮**，或者是极恶天气，来冲击山寨。蛊师成为守护
山寨的中坚力量」（`CAN-BEAST-TIDE-001`）；狼潮「每三年基本上都会有一次」；雷冠头狼是狼群首领，
「狼潮冲击山寨时，最棘手的存在」（`CAN-BEAST-TIDE-002`）。
`beast_swarm` 的群体威慑是行为层现象，不表示单只电狼数值高（`CAN-BEAST-SWARM-001`）。

【兼容性游戏化】`factions.json` 把兽潮登记为 `entity_kind: faction` 的**压力源**（不可谈判、
`hostile_chance_pct: 100`、`retreat_allowed: false`），以便统一关系/路线影响面。

### 5.3 势力与关系

【原著事实】家族中「家老、话事人，执掌着各方面的权柄」；族长在祭祀时着素白祭袍率众跪拜
（`CAN-FACTION-001`）。学堂家老主持开窍大典（`CAN-FACTION-002`）。「蛊师成为守护山寨的中坚力量……
家族需要战斗蛊师，从不嫌多」（`CAN-FACTION-003`）。凡人并非没有修行资质，而是「家族体制一直将蛊师的
修行方法，严密地掌控在手中」，体制外者机缘巧合成了魔道蛊师（`CAN-CULTIVATOR-001`）。
奴道蛊师以驱役奴仆作战（`CAN-CULTIVATOR-002`）。

【兼容性游戏化】`ADP-FACTION-001`：首发设计**四个原创南疆势力**，每局激活 2–3 个，以关系影响
商队、情报、路线、撤离与终局外扰。其中两个基于原著事实（山寨秩序方、商队），两个为原创
（拾骨帮、瘴蛊教）。**不可越界项**：不冒用原著家族的具体人物、历史或既有结局；玩家不能让所有势力永久满意。

关系模型（`factions.json` 的 `relation_levels`，逐项可调）：

| 档位 | 分值 | 价格 | 转敌意概率 | 先手概率 |
| --- | --- | --- | --- | --- |
| 敌对 `hostile` | ≤ −2 | +60% | 30% | 20% |
| 冷淡 `cold` | −1 | +10% | 15% | 10% |
| 中立 `neutral` | 0 | 0% | 0% | 0% |
| 友善 `warm` | 1–2 | −10% | 0% | 0% |
| 尊崇 `honored` | ≥ 3 | −20% | 0% | 0% |

另有**全局恶名轴**（`notoriety_axis`）：杀中立者 +2、背信 +1；每点恶名 +10% 价格（封顶 60%）、
+15% 敌意、−10% 先手；洗白需 10 寿元并减 2 点。

### 5.4 敌人与战力阶梯

【原著事实】**战力阶梯口径**：凡人 < 普通野兽 < 一转蛊修 < 二转 < … < 五转；蛊修最低一转
（`CAN-RANK-LADDER-001`）。兽王按统御规模分**百兽王 / 千兽王 / 万兽王**三级，原文自陈这是
「粗略地划分」（`CAN-BEAST-TIER-001`）。兽王寄生一两隻蛊虫共生，受击时蛊虫会出力
（`CAN-BEAST-TIER-002`）。生物层级由低到高为野兽 → 异兽 → 荒兽 → 上古荒兽 → 太古荒兽，
**荒兽已可媲美蛊仙战力**（`CAN-BEAST-TIER-003`）——因此荒兽及以上**不入凡人跑局的常规敌人池**。

【兼容性游戏化】`regions.json` 的 `enemy_roster` 有 **32 条**敌人：tier = 杂兵 13 / 精英 12 / 层主 7；
theme = 野兽 12 / 势力 6 / 异变 5 / 蛊修 5 / 中立 4；grade = 蛊修 13 / 野兽 13 / 异变 4 / 凡人 2。
每只敌人的 HP、意图与反制数值都按层下压，**不代表原著战力**。

模型新增的显性威胁键：地图节点快照带只读的 `threat` 字段（`""` 或 `"elite"`），
判据真源是 `MapGenerator.node_threat` 读 catalog 的 `tier`。

## 六、数据流与依赖方向

```
world-model/data/*.json   （只读世界模型）
        ↑ 构建
world-model/tools/build_world_model.py  ← 只读 ../../data/*.json
        ↓ 加载 + 校验
engine/model.py  WorldModel
        ↓
engine/rules.py  纯规则函数（全部读 balance）
        ↓
engine/run.py    Run（一局的状态机）
        ↓
runner/cli.py    交互 / --auto / --replay / --status
        +
tools/validate_world_model.py · tools/simulate_balance.py · tests/run_tests.py
```

依赖方向只有一条：**运行器 → 运行 → 规则 → 模型 → 数据**。`engine/` 不反向依赖 `runner/` 或 `tools/`，
任何模块都不得绕过 `WorldModel` 直读 `data/*.json`（唯一例外是 `tools/build_world_model.py` 的写入方向）。

## 七、CLI 与源语料的关系

只读上游 `../data/*.json` 与 `../docs/lore/*.md` 的关系是**单向派生**：

- `../data/*.json` 是原型（Godot）的表，`world-model/data/*.json` 是它的**结构化重述**；
  重述时补齐了来源追溯字段、交叉引用索引与统一命名，但**不改动上游任何文件**。
- `docs/lore/canon-index.md` / `adaptation-register.md` / `game-rule-register.md` 提供
  `CAN-` / `ADP-` / `GAME-` 编号，`world-model` 只引用它们，不复制原文段落。
- 单条引用摘录不超过 80 字（本文件最长的一处是 `CAN-BEAST-TIER-001` 的短引）。
