# 杀戮尖塔实机游玩体会 × 《蛊路求生》项目对照

> 日期：2026-09-15　方式：自动化（computer-use）真实游玩 StS V2.3.4（Steam 版，AppID 646570，中文 UI，1920×1080）
> 对局：标准模式·铁甲战士（种子 `L2PX89D0TFK9`）·第一场战斗（双史莱姆）·败北于第 1 层
> 目的：用户要求的"实际打开游戏游玩，记录每个步骤和阶段的体会，与我的项目对照"——把成功 roguelike 的体验设计"操作学习"到《蛊路求生》（gu-zhenren-editor, Godot）。

---

## 〇、总体结论（先说最要紧的）

**杀戮尖塔（StS）的体验公式 = "开局给你一次全局成长锚点 + 每一场战斗后必给一次成长供给（卡牌/遗物/金币）+ 全图路线选择权交给你 + 死亡后 10 秒内重开"。**

对照《蛊路求生》，前两项（开局馈赠、战后供给）正是项目当前最薄弱的地方——上一验收局的 Gate B/C 失败（5 局中 4 局第 4 个炼蛊台不可达）本质就是"成长供给的确定性不足"：StS 把成长机会做成了"必然发生、只在你之间选择"，而《蛊路求生》目前是"机会存在但不保证你走到"。

## 一、游玩全程逐阶段记录（实测事实）

### 阶段 0：主菜单 / 档位管理
**实测**：主菜单一屏：开始游戏 / 百科大全 / 统计内容 / 设定 / 补丁内容清单 / 退出，右下角固定显示版本号与日期（`V2.3.4 (12-18-2022)`）。有"继续/放弃当前游戏"的档位入口，放弃时弹确认框提示"放弃游戏会视为一次失败"。

**体会**：
- 所有系统入口一屏放齐（含"补丁清单"这种社区友好的东西），不藏菜单。
- 放弃游戏有成本提示（"视为一次失败"），但**没有任何惩罚**——失败是 StS 玩法的一部分，不是挫折。

**对照《蛊路求生》**：项目有 Boss 门禁/升仙概念，但缺少"失败=重开节奏的一部分"的轻量化表达。可借鉴：结算文案要短、重开入口要快。

### 阶段 1：模式选择
**实测**：标准 / 每日挑战 / 自定义（自定义锁定）。无难度选项（难度由路线/遗物/精英承担，而非菜单）。

**体会**：难度不给玩家调，而是**内置在内容里**（精英更强、路线更难、奖励更肥），玩家调的是"路线选择"不是"难度滑块"。

**对照**：项目当前有 5 层结构+关底 Boss，可考虑把"难度感受"放进路线与精英设计，而不是让玩家在开局选难度。

### 阶段 2：角色选择
**实测**：4 个角色一屏展示；选中后进入确认页：生命 80/80、金币 99、初始遗物"燃烧之血"（战后回 6 血）、**解锁进度 36/750**。

**体会**：
- 角色=流派差异化（攻击/能力/卡组机制完全不同），确认页一屏给全关键信息。
- 解锁进度（36/750）常驻显示 = 长线成长目标可视化。

**对照**：项目已有流派差异化（剑/符/蛊等）；可借鉴"角色确认页一屏信息"的密度，以及把长线解锁进度做成可见目标。

### 阶段 3：开局馈赠（涅奥的礼物）—— 本次最重要的对标点
**实测**：开局第一件事，4 选 1：把初始牌替换成随机卡 / **+8 最大生命** / 获得一张稀有牌 / 获得一个 Boss 遗物。我选了 +8 最大生命（80→88）。

**体会**：这是 StS 的"开局成长锚点"——**每一局开始，必定给你一次全局性成长选择**。它同时做了三件事：
1. 让每局开局手感不同（可重开滚开局）；
2. 给你一个"这局想怎么玩"的第一个决策；
3. 即使整局胡牌不顺，开局也有过一次成长供给兜底。

**对照《蛊路求生》（核心缺口①）**：项目缺少对应的"开局馈赠"系统。目前玩家的成长供给主要依赖"炼蛊台"（每层 1 个，且上一验收 5/5 局不可达）。**建议：开局给一次"馈赠三选一"**（如：初始毒虫强化 / 初始印记 / 初始药引），把"成长供给的第一次"变成必然事件。

### 阶段 4：地图 / 路线选择
**实测**：全图一屏可见，底部有图例（敌人 / 精英 / 休息 / 财宝 / 商人 / ?）。节点呈分支网络，当前层只点亮本层节点，选一个进入。节点进入后会出现 [离开] 可反悔。

**体会**：
- **全图可见+图例** = 玩家永远知道"这一层有什么、可选什么"，信息 100% 透明；
- 分支路线 = 每一次选择都是"资源 vs 风险"的决策（休息 vs 精英 vs 商店）；
- 允许反悔（[离开]）= 零挫败的探索。

**对照**：项目已有分层地图与节点类型；可借鉴"图例常驻 + 节点类型全可见"的信息密度。当前项目地图的"成长机会不可达"问题（Gate C），本质是**路线供给的确定性**——StS 保证每层至少有一个休息点和一个精英附近的平衡，而项目需要校验"每层炼蛊台/黑市是否必然可达"。

### 阶段 5：第一场战斗（双史莱姆）—— 意图系统与交互手感
**实测**：
- 敌人头顶**常驻意图数字**（小史莱姆 5、大史莱姆 7/10），悬停敌人显示"这名敌人将要攻击造成 X 点伤害 / 施加负面效果"；
- 我方能量 3/3，手牌 5 张（防御×3/打击/痛击），出牌消耗能量，结束回合（按钮或 E 键）后敌方行动，然后重抽 5 张；
- 小史莱姆被多次打残后**分裂/再生**（14→5→2→重新出现 14/14），并给我的手牌**塞入"黏液"状态卡**（不可打的污染卡）；
- 回合内不能结束回合当卡牌被拿起时（新手提示框说明了完整回合流程）；
- 大史莱姆意图在 7 与 10 之间变化（受状态影响）。

**体会**：
- **意图系统** = 把"敌人的不可见随机"变成"可见的待解算术"，玩家的每一回合都在解一道确定题（挡多少、打谁）；
- 状态污染（黏液） = 简单却有效的卡组破坏压力，逼迫你消耗行动清手牌；
- 回合节奏极快（每回合 5 张、3 能量），核心决策="如何分配能量/目标"。

**对照**：项目**已有意图系统**（这是上一轮已确认的优势）。可借鉴：
- 敌方意图不仅要显示数值，还要显示"类型"（攻击/施毒/蓄力）——本项目已有；
- **状态污染类机制**（类似黏液）项目可考虑作为精英/Boss 的差异化武器；
- 卡牌交互：StS 采用"拿起→目标释放"拖拽式（且对鼠标时序极敏感）。项目若做卡牌战斗，建议**点击式**（点卡→点目标）为主、拖拽为辅，宽容度更高（详见下文"交互卡点"）。

### 阶段 6：败北 / 结算 / 重开
**实测**：0/88 死亡 → 结算页："**败北——看来需要一张新地图了。**" + 统计面板（攀爬楼层 1 / 杀敌 0 / 精英击杀 0 / Boss 0 / 分数 5）+ 解锁进度（41/750，剩余解锁 4）+ [主菜单] 一键返回。

**体会**：
- **死亡结算极简**：一句文案 + 4 个统计 + 1 个按钮，**没有复盘墙**（StS 的复盘在"百科/统计"里，不打断重开节奏）；
- 分数 = 楼层×5（攀 1 层=5 分），简单可预期；
- 解锁进度贯穿死亡（死一局也在推进长线目标）。

**对照（核心缺口④）**：项目缺"死亡复盘"。但对照 StS 的启示是：**复盘不要做成结算墙**——项目可以在结算页给"本局关键数据"（走了几个节点、炼蛊几次、死因），然后一键重开。另外"分数=楼层×倍数"这种简单公式值得借鉴。

## 二、实机中的交互卡点（诚实记录）

本次自动化游玩中，StS 的出牌交互（拿起卡→拖到目标→释放）对鼠标事件时序极敏感：点击式（点卡→点目标）与拖拽式在自动化下多次不稳定，最终依靠"结束回合"按钮完整推进了回合循环并打完整局（体验了战斗→死亡→结算全流程）。

**这本身是一条值得记录的对标信息**：
- StS 的"拿起→释放"拖拽手感是它的操作特征，但也是**高精度输入依赖**；
- 对《蛊路求生》的建议：卡牌/指令交互采用**点击式为主**（点卡选中浮起→点目标确认，两点即完成），避免高时序敏感的拖拽判定；若做拖拽，需做"拖拽起点/终点宽容判定"。

### 本次实测新增的对照点（此前分析未覆盖）
1. **开局馈赠（涅奥礼物）**——每局必然的第一次成长选择。项目缺失，建议 P1 补入。
2. **死亡结算极简+分数公式（楼层×5）**——项目结算页可参考：一句话文案+4 项统计+一键重开。
3. **解锁进度常驻（36/750→41/750）**——长线目标可视化，死亡也在推进。项目可考虑"蛊鉴解锁进度"常驻显示。
4. **手牌污染（黏液卡）**——状态类压力机制，可作为精英/Boss 差异化设计参考。
5. **新手引导的"轻量提示框"**——悬停/按钮说明就地出现，不打断操作。项目的新手引导可参考这种"即时提示"而非全屏教程。

## 四、对《蛊路求生》的三条可执行建议（本次游玩直接得出）

1. **【P0】开局馈赠系统**：开局给一次"三选一"全局成长（毒虫强化/印记/药引），保证每局第一次成长供给必然发生。成本低、对"成长供给确定性"的改善最大。
2. **【P0】每层成长供给可达性校验**：把"第 N 个炼蛊台是否必然可达"做成验收断言（对应 Gate C 的根因），而不是依赖地图随机。
3. **【P1】结算页轻量化**："一句话败北文案 + 本局 4 项统计 + 一键重开"，把死亡复盘做成"快速重开"而非"复盘墙"。
