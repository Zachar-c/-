## 0. 结论速览

1. **剑道当前没有"流派玩法"，只有"流派标签"**：40 只剑道蛊全部是程序化派生（`source: school_derived`），
   只带 `role` + `rank`，实际战斗行为由 `data/v1_battle.json` 的 `default_effect_by_role` 兜底决定 ⇒
   40 只蛊 = 6 种通用效果 × 转数，**与任何其它流派的蛊在战斗里完全同质**。
2. 差异化机制**不需要新系统**：引擎已有 `support_school / support_bonus → turn_supports[school]`（回合内同流派加伤）
   的唯一使用者是光道 `small_light_gu`；剑道把这套"流派协同"用作**剑意**即可立刻成立。
3. 最省力的落地顺序：**先 data（显式 `v1_effect` + `kill_moves` 填充）→ 再 `school_rules` 仿写（血道 `blood_stacks` 已有先例）
   → 最后才考虑引擎扩展**（临时剑、穿透、回合末结算）。
4. 设计定位一句话：**攻伐第一的快攻爆发道 —— 高频多段累积剑意，单点穿刺收割；代价是脆、念头饥渴、且剑意本身侵蚀自身。**
   与 `schools.json` 现有文案（「掌剑意锋锐与剑气纵横；剑道道痕有侵蚀性、攻伐第一」）一致。

## 1. 现状事实基线

### 1.1 剑道已有什么

| 项 | 事实 | 出处 |
|---|---|---|
| 流派定义 | `name: 剑道`，`summary: 掌剑意锋锐与剑气纵横；剑道道痕有侵蚀性、攻伐第一。` | `data/schools.json["sword"]` |
| 开局 starter | 4 只：`sword_atk_1_05_gu`（攻）/ `sword_heal_1_09_gu`（疗）/ `sword_def_1_07_gu`（防）/ `sword_mov_1_08_gu`（移） | 同上 |
| 蛊池 | 40 只全量（`data/school_pools.json["sword"]`） | `data/school_pools.json` |
| 蛊结构 | `{id, rank, role, school, rarity, value, tags, source, combat}`；**无 `v1_effect`** | `data/gu.json` |
| role 分布 | attack 多（含 rank4/5 各若干）、defense/movement/healing/recon/logistics 各若干；rank 1–5 = 11/9/8/5/7 | 实测统计 |
| combat 字段 | 6 个共享 pattern（`sword_attack_pattern` 等，**一个 role 一个**） | 同上 |
| 显式效果蛊 | 全库仅 8 只声明 `v1_effect`，**剑道 0 只** | 实测统计 |

### 1.2 战斗引擎的能力边界（决定"能做什么"）

**已有 kind 全集**（`v1_battle_resolver.gd` `SUPPORTED`）：
`strike` / `shield` / `buff` / `heal` / `heal_and_strike` / `status` / `shift`

**随转数线性成长的量纲**：`RANK_SCALED_KINDS = ["strike", "shield", "heal"]`
（`shift` 与 `status` 是位置/层数，**不随转数放大**）

**兜底表**（`data/v1_battle.json.default_effect_by_role`）：

| role | 效果 | 基础值 | 转数成长 |
|---|---|---|---|
| attack | strike | 2 | +1/转 |
| defense | shield | 3 | +1/转 |
| healing | heal | 2 | +1/转 |
| movement | shift | 1 | 无 |
| recon | status(marked) | 1 | 无 |
| logistics | status(bound) | 1 | 无 |

**蛊槽（实例）可用字段**：`true_qi_cost` / `thought_cost` / `life_cost` / `is_permanent` /
`trigger_qi_cost` / `trigger_block` / `maintain_qi_cost` / `duration_turn` / `durability_mode`

**关键钩子（现成但几乎未用）**：

- `support_school` + `support_bonus` → 写入 `battle.turn_supports[school]`，
  本回合内**同流派后续蛊伤害 +N**，`end_turn` 清零。
  **唯一使用者：光道 `small_light_gu`**（`{"kind":"strike","amount":1,"support_school":"light","support_bonus":2}`）
- `kill_moves`：结构存在；~~当前为空数组~~ **⚠️ 已过期——2026-09-11 杀招 P1 已交付 5 条，含剑道 `km_sword_double_edge`（双锋引）**
- `school_rules.gd` 现有 4 函数：`blood_stacks` / `add_blood_stacks`（血道**跨回合层数**先例）、
  `material_fuel`、`is_soul`

**当前不支持的（要新增就属引擎扩展）**：穿透护盾、生成临时蛊/派生攻击、回合末自结算、多段攻击（同一次催动打 N 下）。

### 1.3 必须遵守的边界（红线）

- **道标签不产生全局克制倍率**（规格 §2.3）：剑道不能做"对 X 道 +50%"，差异化只能落在
  **己方资源循环 + 结算方式 + 代价结构**上。
- 卡牌只是**蛊虫实例的操作界面**：无抽牌/手牌/洗牌；不许引入"剑意抽牌"式设计。
- 蛊按实例结算、无通用持有上限、无蛊槽/槽满替换。
- **重要代价必须真实结算**，不得结算后无来源补齐；**禁止静默致死**。
- 数值一律落 JSON 并通过 Schema 校验；不得散落硬编码。
- 禁止新增局外数值成长（图鉴是唯一例外）。

## 2. 市场调研：优秀 roguelike 的"锋锐系"设计经验

### 2.1 杀戮尖塔（Slay the Spire）

| 设计 | 机制要点 | 对剑道的启发 |
|---|---|---|
| **Watcher 姿态**（Calm ⇄ Wrath） | 双态互切：Calm 蓄势回气、Wrath 双倍伤害但双倍受伤。核心不是数值而是**节奏决策**：什么时候进、什么时候出 | 「拔剑 / 收剑」姿态：收剑回合蓄剑意但不输出，拔剑回合把剑意全兑现——**把"爆发"做成一个可选的时点决策，而不是无脑叠层** |
| **Silent 的 Shiv（飞刀）** | 由其它牌**生成**低费 0 费临时攻击牌，回合末消失 | 「剑气」：剑蛊催动时生成**临时剑**（当回合可用、回合末消散），把"多段"做出来 |
| **Ironclad 的 Strength** | 线性爬升的全局加伤，与多段攻击天然相乘 | 「剑意」：层数 × 段数 = 乘算，让"多段 vs 重击"两条路都有解 |
| **Ironclad 的 Self-Damage**（Blood for Blood 等） | 用自身生命换强度，代价真实 | 「侵蚀」：剑意的代价必须真的扣，构造"越锋利越伤己"的张力 |

### 2.2 其它参考

- **Hades · 武器 Aspect（形态）**：同一把剑的不同形态彻底改变手感（慢重/快轻/远程剑气）。
  → 剑道蛊的**个体差异**应落在"式"上（同一 role、不同 pattern），而非单纯堆数值。
- **Monster Train · Multistrike / 分层战斗**：把"多段"与"次数"做成可叠加的正交维度。
  → 剑道的段数应可被蛊方/杀招改造，而不是写死在蛊上。
- **月圆之夜**：单机轻量化范式——资源循环短、每回合决策点少但清晰。
  → 剑道的回合节奏应是「1 个主决策 + 1 个顺带决策」，不要引入三套并行资源。
- **Dead Cells / 动作肉鸽的连击窗口**：连续命中有额外收益。
  → 剑道的"连续出剑"应有轻量奖励（第 N 击加成），但必须能被非剑道玩家理解。

### 2.3 提炼：可借鉴要点与反面教训

**值得借鉴（6 条）**

1. **姿态/节奏优于纯数值**：爆发道好玩的不是数字大，而是"何时放手"。
2. **临时资源（Shiv）是低成本的"多段"实现**：不需要新引擎能力也能做出密度。
3. **加伤与段数相乘**：两条 build 路线的公共乘数，让构筑有张力。
4. **代价必须由玩家承担**：自伤/耗资源是"强度"的价格标签。
5. **同一武器的不同形态**：个体差异比数值差异更能撑起 40 只蛊。
6. **回合内清零 vs 跨回合保留**：前者易读（适合核心爆发），后者厚重（适合养殖类流派）——剑道应以前者为主。

**必须避免（2 条）**

1. **纯大数字流**：没有时点决策的爆发道 = 无脑按最优解。
2. **唯一解**：如果"叠满剑意再一击"横扫所有情况，另外两条 build 就是装饰。

## 3. 剑道核心定位

**一句话**：以**剑意为势**、以**剑气为刃**的快攻爆发道——用高频出剑累积剑意，在选定时刻把剑意一次性兑现为穿刺伤害；
强度越高，反噬（侵蚀）越重。

**幻想**：孤高剑修，出手快、脆、狠；靠"势"而非"耐力"取胜。

**核心张力（三条，构成所有决策）**

| 张力 | 表现 |
|---|---|
| **蓄 vs 放** | 蓄剑意时不输出（机会成本），释放时收益集中（决策点） |
| **快 vs 重** | 多段吃剑意加成但单次弱；重击单次强但难叠势 |
| **锋 vs 己** | 攻击越激进，侵蚀代价越高（真实扣血/扣念头） |

**与现有文案的对应**：「剑意锋锐」= 剑意层数机制；「剑气纵横」= 剑气/多段；「侵蚀性」= 侵蚀代价；「攻伐第一」= 上限最高的爆发。

## 4. 玩法循环

### 4.1 战斗内循环（三阶段节奏）

```
【起势】使用「养剑/蓄势」类剑蛊  →  剑意 +N，本回合输出低
   ↓
【出剑】使用剑道攻击蛊            →  伤害 = 基础 + 剑意层数 × 系数；召唤剑气补段数
   ↓
【收势】回合结束                   →  剑意按规则衰减；侵蚀结算（真实扣血/扣念头）
```

**决策点**：本回合是"继续蓄"还是"现在放"？——这正是 Watcher 姿态式的节奏决策。

### 4.2 局内循环

```
择道(剑道) → 开局 4 只 starter
   → 战利品/商店：优先剑道池(40 只) 与剑道蛊材
   → 喂养(settle_feeding) / 转阶(同蛊升阶，rank 提升 → strike 数值 +1/转)
   → 炼蛊合成(recipe)：把低转剑蛊合成高转剑蛊（升级到「暴雨」或「重剑」路线）
   → 杀招装配(kill_moves)：用剑蛊组装杀招配方（**剑道已有 1 条**「双锋引」；暴雨/剑阵两条待补，见任务书 T9）
   → 层 Boss → 升仙窗口
```

**与其它流派共享的循环不变**，剑道的差异只在"优先取什么、优先升级什么"。

## 5. 关键机制（4 个）

### 机制 A — 剑意 Intent（核心，**零引擎改动可落地**）

| 项 | 设计 |
|---|---|
| 定义 | 跨回合保留的层数资源，代表"势"；每层使剑道攻击蛊伤害 +1 |
| 获取 | ① 使用带 `support_school: "sword"` 的蛊（现成钩子，如光道先例）；② 「养剑」类剑蛊显式给 +2 |
| 衰减 | 回合末**清空回合内支援**（`turn_supports` 现成行为）；跨回合部分按 50% 向下取整保留（需 `school_rules` 新函数，仿 `blood_stacks`） |
| 上限 | 5 层（防爆值失控；与 stage_base/真元量级匹配） |
| 落地 | P0：仅用 `support_school/bonus`（回合内）→ 立即可玩；P1：`school_rules.sword_intent/add_sword_intent` 做跨回合层数 |

> **为什么先做回合内**：`turn_supports` 已端到端可用且有测试，能在一批 data 改动内让"剑意"真实存在于战斗里；
> 跨回合层数是"厚度"，需要新函数与回合末结算点，放到第二阶段。

### 机制 B — 剑气 Blade Qi（多段，**P0 可用近似 / P2 完整**）

| 项 | 设计 |
|---|---|
| 定义 | 剑蛊催动时额外产生"临时剑"：本回合可额外使用的低强度攻击，回合末消散 |
| 价值 | 让"多段"成立，使剑意（+1/层）与段数相乘 ⇒ 暴雨流成立 |
| P0 近似 | 用 `heal_and_strike` / 多只低转剑蛊占位表达"多段"；或用 `trigger_qi_cost` + `trigger_block` 做"触发式补刀" |
| P2 完整 | 需新 effect（生成临时蛊）或 `kill_moves` 层面的"多段"字段 ⇒ 属引擎扩展，需单独规格与测试 |

### 机制 C — 侵蚀 Erosion（代价，**P0 用现成字段表达**）

| 项 | 设计 |
|---|---|
| 定义 | 剑道的高强度由自身承担：每次催动高阶剑蛊扣气血/寿元；或回合结束时按剑意层数扣气血 |
| P0 表达 | 蛊定义里用 `life_cost`（现成，蛊槽已读）+ `thought_cost` 抬高念头成本 ⇒ **代价真实结算且可见**（符合红线） |
| P2 完整 | 回合末按层数结算侵蚀伤害 ⇒ 需引擎回合末钩子，**必须带死亡预检与提示**（红线要求），不能静默致死 |
| 设计意图 | 让"叠满再放"不是无脑最优：层数越高，收势的代价越大 |

### 机制 D — 破锋 Pierce（对防御的破局，**P2**）

| 项 | 设计 |
|---|---|
| 定义 | 剑道攻击可无视一部分敌方护盾（"锋锐"的具象化） |
| 合规性 | 这是**结算方式**而非"对某流派的全局克制倍率" ⇒ 符合规格 §2.3 |
| 现状 | `strike` 无 `pierce` 字段；需引擎加字段与结算分支（P2） |
| P0 替代 | 用 `status`（如 `armor_break`）给敌人挂减防标记，其层数由现有 status 通道承载（若引擎已有减防语义则零改动，否则同属 P2） |

## 6. 成长与构筑路径（3 条 build）

| 路线 | 核心 | 关键机制 | 强势期 | 弱点 | 对应蛊倾向 |
|---|---|---|---|---|---|
| **暴雨剑**（多段连击） | 多只低转剑蛊 + 剑气 | 剑意 × 段数乘算（机制 A×B） | 前期成型快、对低血群敌强 | 单次伤害低，遇高护盾乏力 | 低 rank attack 蛊多只、`support_bonus` 高 |
| **重剑无锋**（蓄势一击） | 1–2 只高转剑蛊 + 收势兑现 | 剑意上限 + 单次巨额 strike（机制 A×C） | 中期爆发、秒杀单目标 | 蓄势回合空转；侵蚀代价高 | rank4–5 attack 蛊（现有 rank4/5 共 12 只） |
| **剑阵养剑**（持续输出） | `is_permanent` / `maintain_qi_cost` / `duration_turn` | 持续型剑阵自动输出 + 剑意稳定供给（机制 A） | 长线消耗战、Boss 战 | 启动慢、真元占用高 | defense/movement 剑蛊转辅助位 |

**设计校验**：三条路线分别对应"段数""单发""持续"，共用**剑意**这一个乘数；只要剑意上限与侵蚀代价标定得当，
三者在不同敌人构成下互有优势，避免唯一解。

## 7. 资源体系（剑道视角）

| 资源 | 现有定位 | 剑道如何使用 | 风险 |
|---|---|---|---|
| **真元**（`true_qi_cost`，上限 `stage_base × aptitude_mult`） | 回合内主要燃料 | 剑道蛊成本偏高（快攻=高消耗），制约"每回合无限出剑" | 成本过高会变成"看戏" |
| **念头**（`thought_cost`，统一约束战斗操作与炼蛊投入） | 全局限流器 | 剑道的"多段"必须吃念头，否则段数无上限 | **段数与念头必须挂钩**，否则暴雨流失控 |
| **气血/寿元**（`life_cost`） | 真实代价通道 | 侵蚀代价的 P0 载体 | 必须预检 + 提示，禁静默致死 |
| **剑意**（本文新增概念） | 剑道独占层数 | 唯一乘数来源 | 上限 5，且收势要有代价 |
| **蛊槽实例字段** | `trigger_*` / `maintain_*` / `duration_turn` | 剑阵/触发式剑技 | 不要变成第二套系统 |

## 8. 与其它流派的差异化矩阵

| 维度 | 剑道 sword | 血道 blood | 力道 force | 魂道 soul | 光道 light |
|---|---|---|---|---|---|
| 强度来源 | 剑意层数（回合内协同 + 跨回合势） | 血层 `blood_stacks`（跨回合累积） | 高基础值 / 护盾互换 | 魂魄资源（可支付/可失控） | `support_bonus` 支援他人（现成） |
| 节奏 | 快（起势→出剑→收势） | 慢（吸血回复循环） | 中（防反/硬吃） | 控场/资源调度 | 辅助/续航 |
| 代价 | **侵蚀**（自伤/念头饥渴） | 自伤换资源（吸血系） | 机动性差 | 魂魄失控风险 | 输出上限低 |
| 峰值 | **最高（爆发）** | 中高（持久） | 中（稳定） | 中（条件性） | 低 |
| 短板 | 脆、怕护盾、怕多目标 | 爆发不足 | 被风筝 | 启动依赖魂魄 | 依赖队友/协同 |
| 与光道的差异 | 剑道用 `support_school` **吃自己的协同**；光道是**供给协同** | — | — | — | — |

> 注意：光道已占用 `support_school: "light"` 的"供给"语义；剑道把同一机制用于**自洽乘数**，
> 两者机制同源、体验相反（一个给队友、一个只给自己），是**低成本的差异化**。

## 10. 风险与边界

| 风险 | 说明 | 应对 |
|---|---|---|
| **同质化根因未解** | 40 只蛊共用 6 个 role 效果是**全流派的结构性问题**，不是剑道独有 | P1-3 是根治项；否则任何流派设计都停在文案层 |
| **数值失控** | 剑意（+1/层）× 段数 × 转数成长 = 三重乘算 | 剑意上限 5；段数必须吃念头；转数成长已有 `RANK_SCALED_KINDS` 约束 |
| **静默致死** | 侵蚀若走回合末扣血，可能无提示致死 | 红线：必须预检 + 明确提示；P0 阶段只用可见成本（`life_cost`/`thought_cost`） |
| **与光道机制撞车** | 两者都用 `support_school` | 语义相反（自用 vs 供给），且快照/日志可区分；若后续要做"团队"，需再评估 |
| **规格合规** | 不得出现"对 X 道加成"的全局克制 | 所有机制均落在己方资源与结算方式，无跨流派倍率 |
| **杀招系统为空** | `kill_moves` 是空数组，等于该玩法支柱目前没有内容 | P1-2 是"核心玩法支柱"（AGENTS 裁定）的直接缺口，优先级应高于剑道专属内容 |
