# P0-1 问眞主题迁移收尾设计

> 日期：2026-08-28
> 状态：已获用户批准，待进入实施计划

## 1. 目标

完成正式 UI 的问眞浅色主题迁移，清除旧暗色主题残骸并统一色轨。正式 UI 的视觉语义唯一来源为 `scripts/presentation/gu_style.gd` 的 `GuStyle`。

本批只处理展示层主题，不修改领域规则、数据表、RunData、存档结构或第三方目录。

## 2. 删除范围

- 删除 `scripts/presentation/components/ui_theme.gd`。
- 删除 `assets/theme/gu_theme.tres`。
- 删除正式 UI 对该 `.tres` 的 `@theme` 声明、preload 和 `theme = THEME` 赋值。
- 删除 `GuStyle` 中的旧暗色兼容别名，包括 `BG_*`、`BONE*` 以及仅为旧主题保留的颜色命名；调用方先完成语义迁移。

不删除图片资源、`.import` 文件、RUI 上游代码或非主题用途的资源文件。

## 3. 主题边界

### 3.1 基础色轨

- 纸面：`PAPER_BG`、`PAPER_RAISED`、`PAPER_DEEP`
- 墨色：`INK_PRIMARY`、`INK_SOFT`、`INK_MUTED`
- 结构线：`RULE`、`HAIRLINE_COLOR`
- 间距、圆角和字体：使用 `GuStyle` 已有 token。

原生 `Control` 不再依赖全局 Theme 继承。需要字号、字体、文字颜色、按钮状态或面板样式的视图，必须显式设置，或调用 `GuStyle` 提供的无状态样式工厂。

### 3.2 语义强调色

以下颜色保留，但必须通过 `GuStyle` 语义 token 使用：

- 朱砂：危险、诅咒、死亡线和不可逆操作
- 契约蓝：契约与规则修改
- 异变黄/红：DDA 与险象、衰运
- 玉色：护盾、正向状态与可恢复资源
- 稀有度色：只用于稀有度识别，不作为普通界面主色

调试面板可保留红色“调试”识别，但面板底色、文字和结构线必须属于浅色主题，不得恢复深色卡片。

### 3.3 允许的直接颜色

直接 `Color(...)` 只允许用于透明填充、白色高光、蛊虫专属识别色，且应集中定义并有明确语义。普通背景、普通文字、普通边框和按钮状态不得散落硬编码颜色。

## 4. 迁移方式

- 将 `UiTheme` 的面板、按钮、标签调用点迁移为显式本地构造或 `GuStyle` 无状态工厂。
- 将正式 UI `.guitkx` 和展示层 `.gd` 中的旧暗色值替换为 `GuStyle` token。
- 将地图、大厅等局部色常量改为 `GuStyle` 语义 token，保留必要的布局专用透明色。
- 修正视觉测试中关于旧暗色主题的命名、期望值和断言，使测试验证浅色主题契约而非兼容旧值。
- 不通过放宽测试、增加无语义别名或继续保留隐藏全局主题来解决迁移问题。

## 5. 验收标准

### 静态验收

- 正式 UI 不再引用 `UiTheme`。
- 正式 UI 不再引用 `gu_theme.tres`。
- `GuStyle` 不再导出已删除的旧暗色兼容别名。
- 旧深色背景与旧浅色文字组合清零。
- 未授权的普通 UI 直接颜色值清零；允许例外必须在守卫白名单中有明确说明。

### 行为与视觉验收

- 问眞视觉 token 测试通过。
- 共享组件、卡牌、tooltip、危险确认、死亡线、调试面板测试通过。
- RUI 编译/构建检查通过。
- 正式 UI 集成烟测通过。
- 既有桌面视口截图无深色卡片墙、文字裁切、主体截断、图层遮挡或空白主题资产。

## 6. 风险与处理

- 移除全局 Theme 可能暴露原先由 Theme 继承提供的默认字体、字号或按钮状态，因此每个受影响视图必须在测试中检查关键控件的可见性与交互状态。
- `UiTheme` 的删除可能触及旧视图和旧测试；应迁移真实消费者，不删除仍承担验收职责的测试。
- 旧工作树中的资源导入改动和临时文件属于用户现有改动，本批不得清理或重置。
