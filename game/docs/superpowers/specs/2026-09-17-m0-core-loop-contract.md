# M0 阶段契约：有限资源下的蛊师战斗闭环

## 目的

本阶段假设项目从零开始，只回答一个问题：

> 玩家在有限真元、有限蛊虫和部分已知敌情下，持续作出取舍，是否已经足够好玩？

M0 不验证世界观规模、美术完成度、完整养成或内容数量。阶段价值来自这条闭环：

```text
观察敌意 → 分配真元 → 使用蛊虫 → 承担结果 → 获得奖励 → 改变 Build → 再战
```

核心参考方向是：敌意可读、资源有限、蛊虫组合有取舍、局内风险可判断、局外奖励改变下一场策略。

## 五项核心契约

### 1. 玩家每回合必须有真实判断

玩家在战斗回合内必须能够：

1. 观察敌人下一步行动；
2. 使用蛊虫处理威胁；
3. 调整真元、生命和防御等有限资源；
4. 结束回合并承担敌人行动结果。

蛊虫是主要能力系统，不以传统普攻作为核心玩法。最小可验证例子：攻击蛊消耗真元造成伤害，防御蛊消耗真元提供护甲，代价型蛊以生命换取本回合收益。

### 2. 敌人行动必须可理解、可预测、可针对

敌人主要行动应在玩家行动前公开，至少包含行动类型和影响量，例如“下一回合撕咬 8”。普通敌人可以有可识别的行为序列；Boss 可以在达到阈值后改变规则，但不能靠无预警随机秒杀决定胜负。

失败原因应主要来自错误判断、Build 缺陷或资源管理失误，而不是玩家无法理解的随机秒杀。

### 3. 胜负和奖励必须推动下一次选择

- 单场胜利：敌人 HP ≤ 0。
- 单场胜利后：必须出现能改变本局状态的奖励选择，优先验证新蛊、强化、资源或恢复生命。
- 单局胜利：普通战斗 → 普通战斗 → 精英/事件 → Boss，击败 Boss 即通关。
- 失败：玩家 HP ≤ 0，立即结束本局并可重新开始。
- M0 不依靠永久属性成长解决难度；第二次游玩应因理解系统而变好，而不是因局外攻击力增加。

### 4. 随机性只负责制造问题

M0 只保留三类随机：

- 敌人组合随机；
- 战后奖励随机，例如三选一蛊虫；
- 战斗之间的路线/事件随机，例如战斗、商人、炼蛊、休息。

战斗内部的重要信息应尽量确定。随机决定“这一局拿到什么”，玩家决定“如何把它变成能赢的 Build”。

### 5. 循环必须短且可重复

- 单场战斗目标：30 秒至 2 分钟；
- 完整 M0 一局目标：5 至 10 分钟；
- 最小循环：进入战斗 → 看敌意 → 用蛊并消耗真元 → 敌人行动 → 回收部分真元 → 击败敌人 → 三选一奖励 → 进入下一战。

## 内容上限

M0 锁死为：

- 1 个玩家角色；
- 6 种蛊虫；
- 3 种普通敌人；
- 1 个 Boss；
- 1 种核心资源“真元”与 HP；
- 3 选 1 战后奖励；
- 4 场战斗。

以下内容不属于 M0 放行条件：装备系统、复杂地图、境界系统、完整炼蛊、蛊虫喂养、NPC 好感、剧情树、局外科技树、存档成长、大量属性和完整世界观。

## M0 唯一放行条件

只有同时满足以下事实，M0 才算通过并允许进入下一个阶段：

1. 玩家无需正式美术和剧情，仅通过观察敌意、管理真元和组合蛊虫，连续完成四场战斗；
2. 不同随机奖励确实让两局出现不同的战斗策略，而非只改变数值文本；
3. 普通战斗默认通过真实战斗结算进入奖励和下一节点，投降只作为显式异常/终局路径；
4. 失败后能够立即重新开始，且玩家有再次尝试的理由；
5. 失败主要可归因于可解释的决策、Build 或资源管理问题。

## 实测证据与放行结论

### 自动化验收证据

- `tests/integration/test_m0_core_loop.gd`：6/6 测试、83 个断言通过，包含 M0 存档恢复回归。
- 四场路线实测为：`ridge_hound` → `iron_hide_boar` → `ridge_elite_scout` → `miasma_vein_lord`；前三场各进入三选一奖励，选择后蛊囊 Build 改变，Boss 胜利写入 `m0_boss_defeated` 并进入 Ending。
- 两个不同 seed 产生不同的奖励签名；奖励由 seed + 战斗序号确定性生成，不因快照刷新重抽。
- Reward 未选择前，`leave_encounter` 被拒绝；重复提交同一奖励被拒绝；死亡后重新开始时状态为 `active`、M0 战斗计数为 0、路线回到 `trailhead`。
- 真实挂载 `reward_screen.tscn` 后，场景树渲染出 3 个可点击按钮；点击后 Continue 解锁且三个选项锁定。
- 大厅真实场景新增 `M0 · 四战试炼` 入口；点击后进入 Map 且 `m0_mode=true`，普通 `new_run` 入口仍存在。
- M0 状态写入既有 `node_flags.m0_mode`，经 v4 序列化后重载仍恢复 M0 模式和四节点路线。
- `tests/integration/test_wenzhen_ui_flow.gd` 的普通路线继续先完成真实战斗胜利；投降仅在显式地图终局覆盖中使用，默认战斗路径无 `battle_retreat`。
- 全量集成回归：11 个脚本、39 个测试、1566 个断言通过；单元回归：215 个脚本、1556 个测试、52302 个断言通过；`git diff --check` 通过。

### 仍需人工观察、但不阻塞工程收口的事项

- 自动化只能证明两个 seed 的奖励问题和 Build 状态不同，不能替代真实玩家是否会因此采取不同策略的行为观察。
- “失败后玩家愿意立刻重试”以及单场 30 秒至 2 分钟、单局 5 至 10 分钟，尚未通过真人试玩计时/访谈证明。
- 当前证据是 headless 场景树与命令点击验收，尚未完成带真实窗口输入、分辨率和帧率的人工试玩；这属于体验验收，不应伪称为已完成。
- 完整运行流仍保留原有自动战利品语义；M0 是隔离垂直切片，不把完整大系统数量当作 M0 证据。

因此本阶段可以收口为：**M0 工程闭环通过，允许进入下一阶段的内容设计；“是否足够好玩”仍需真人试玩作为体验结论，不得用自动化通过替代。** 下一阶段仍应围绕蛊虫、战斗、奖励和 Build 迭代，不扩张世界观、美术或永久成长来掩盖体验问题。
