# 蛊真人肉鸽垂直切片设计

> 日期：2026-09-03。状态：已获用户确认，作为第一轮可试玩交付边界。

## 目标

在现有 Godot 4.7.2 半成品上交付一个可立即试玩的 10--20 分钟垂直切片。玩家必须能够从大厅开始一局，选择流派，经过地图节点、遭遇、至少一场战斗、战后奖励、休整或商店、炼蛊或强化、关底战斗，并主动确认结局后返回大厅。

## 范围

- 复用现有 `RunController`、`Resolver`、地图生成、战斗和屏幕路由；运行路径不设教学种子或固定种子（见「种子策略」）。
- 保留现有领域/表现层边界：UI 只渲染快照并提交命令，领域层负责状态转换、成本、随机和事件日志。
- 大厅提供流派选择；试玩路线至少覆盖遭遇、战斗、奖励、休整或商店、炼蛊或强化、关底和统一结算。
- 战斗继续使用蛊虫实例、真元、念头、生命/护盾和敌人意图等现有规则；关键风险和成本在执行前可见。
- 关底胜利后进入升仙窗口，由玩家二次确认结局；所有结局统一进入 `Ending`，展示统计并清理局内资源后回到大厅。
- 本轮不新增跨局战力、抽牌/手牌/弃牌堆规则、平行经验等级或独立的第二套控制器。

## 种子策略（2026-09-03 裁定）

- **玩家局没有教学种子、没有固定种子**：大厅新一世与结局结算后再入，都由 `roll_seed()` 掷出随机种子；`RunState.seed` 只记录该局掷出的种子，地图按该种子确定性生成。
- **种子 101 不再映射手写教学路线**：`RunController.start_new_run` 一律以生成式地图开局（`MapGenerator.build(seed, false)`）。`seed == 101` 与任何其他种子一样走普通生成；手写 `data/first_run.json` 教学路线仅作为显式 `MapGenerator.build(seed, true)` 的测试夹具保留，永不进入玩家路径。
- **结局即此世终点**：死亡/弃世/升仙等任一结局结算时删除进行中 Run 存档（AGENTS 既有约束），返回大厅后 `has_save=false`，入口恢复为「开始此世」，下一世必然以新的随机种子展开——多次「续入此世/开始此世」进入不会回到同一张旧图。
- 确定性仅指「相同种子 + 相同命令序列 ⇒ 相同状态/事件日志」，这是自动化测试的可复现性依据，不是给玩家设置固定开局的理由。

## UI 裁定补充

- **旅行可达性优先**：地图显示、选中、检视和提交命令必须共享同一份领域可达节点集合。所有可达节点必须在当前视口内可见并可点击；不可达或前瞻节点不得暴露“前往”命令。验收同时检查节点几何可见性和真实按钮点击，不只检查领域拒绝结果。
- **取消三死线常驻 UI**：移除 `GuDeathLineWarning` 及顶栏中的“三死线”区域，不再显示重复的死亡线数值。气血、魂魄、寿元只在既有状态栏资源 chip/状态条中展示；伤害抖动、回血流光、危险红色反馈属于状态栏已有表现。死亡条件固定为气血、魂魄、寿元任意一项 `<= 0`，由领域层判定；精确死因只在结算/死亡说明中展示。
- **战斗卡牌详情改为悬浮提示**：战斗手牌区域只保留可操作卡牌本体和必要的短摘要，不设置独立的卡牌详情面板。鼠标悬浮卡牌时显示共享 tooltip，包含名称、品质、效果、联动、代价、不可用原因和咒/风险提示；tooltip 不得拦截卡牌本体点击。
- **行囊/收获视图**：材料不得作为顶部状态栏的单一“材料数值”展示。新增局内可访问的行囊视图或侧栏，统一展示 `RunState` 当前物品：材料及数量、蛊虫实例、战斗/节点收获、已知情报。该视图只读，所有变更仍通过领域命令产生并从快照刷新。
- **真实鼠标操作验收**：卡牌和地图节点必须通过 Godot 控件的真实鼠标事件完成一次点击验证；测试覆盖子控件 `mouse_filter`、禁用卡牌仍可悬浮查看原因、单目标卡牌选敌、危险卡牌确认和点击后命令只提交一次。

## 不在本轮范围

- 完整 3--5 小时、200--300 节点的最终内容平衡。
- 新的流派、资源类型、存档格式或第三方依赖。
- 重写现有 UI 工具链、RUI 组件体系或 vendor 目录。

## 验收路径

从大厅随机开始一局（无旧档时点「开始此世」选流派开局；有进行中 Run 时先按「种子策略」确认该档已在结算后清除），按地图可见候选节点推进。验收记录应能确认：

1. 大厅可以选择流派并成功创建 `RunState`。
2. 地图显示可达节点，旅行命令进入遭遇或战斗屏。
3. 遭遇命令能够启动战斗；战斗回合可使用蛊虫或基础动作，敌人意图、生命和护盾可见。
4. 战斗胜利后不丢失生命、材料、元石或事件日志，并进入奖励/战后结算。
5. 至少一条休整、商店、炼蛊或强化路径可以完成并回到地图。
6. 关底节点可达；胜利后升仙窗口只提供可见且需确认的结局选择。
7. 结局页面展示结构化结果，局内资源清理，返回大厅后不能继续使用上一局构筑。
8. 同一局内相同命令序列产生一致状态、结果和事件日志；不同局（不同随机种子）的地图/事件/掉落不同，多次从大厅进入不会回到同一张固定图。
9. 地图上每个可达节点都在视口内且真实点击能提交一次旅行命令；前瞻节点不暴露旅行按钮。
10. 顶栏不存在“三死线”独立区域；资源归零仍按领域规则进入精确死因结算。
11. 战斗卡牌详情仅在 hover tooltip 中出现，真实鼠标点击能够完成出牌/选敌/确认链路。
12. 行囊视图能同时看到材料、蛊虫、收获和已知情报，且内容来自只读快照。

## 实现边界

- `RunController` 负责屏幕路由、命令提交和快照装载，不直接实现游戏规则。
- `Resolver`、`EncounterSessionResolver`、`BattleCommandFacade` 及现有领域规则继续作为唯一状态转换入口。
- 玩家局地图若遇既有内容或路由断点，优先修复数据与路由；不得为绕过断点而给玩家局回退固定种子或教学路线。
- 所有手工测试使用 `tools/play.ps1`；自动验证使用 `tools/test.ps1`、`tools/check.ps1` 及现有冒烟脚本。

## 风险与降级

- 若单条随机路线受既有内容门禁阻塞，可修复数据或路由断点，必要时以显式种子（仅限自动测试）复现定位，但玩家局始终保持随机种子开局，不伪造战斗胜利、奖励或结局状态。
- 若云端对话不可用，继续使用现有本地模板降级。
- 任何未能验证的图形渲染或交互状态必须在交付说明中明确列出。
