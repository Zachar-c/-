# Battle 视觉实施规格

> 审阅：✅ 2026-09-06 用户审订通过（定稿）

## 目的

把 `docs/superpowers/specs/2026-09-04-wenzhen-visual-direction-design.md` 中提炼出的风格规则，落实成 Battle 视觉基准屏的可执行规格。此规格只服务 Battle 及其共享公共组件，不扩展到 Map、Hall、Ending，也不改动战斗业务数值逻辑。

## 适用范围

### 本次落实

1. Battle 主屏视觉布局。
2. Battle 共享公共组件的职责边界。
3. Battle 最小资产清单。
4. Battle 动效边界。
5. Battle 验收标准与验收路径。

### 明确延后

1. Map、Hall、Ending 的视觉改造。
2. 战斗业务数值、规则、回合流程、卡牌结算逻辑。
3. 全局主题重构、Shader 框架、粒子系统、完整插画库。
4. 其他屏幕的统一推广。

## 风格映射原则

本屏只采用三组风格语义，并把它们落实到可见结果上：

1. **浅纸墨规则界面**：负责清晰、秩序、层级、信息承载。
2. **暗色南疆志怪叙事插画**：负责世界感、湿冷、生物性、压迫感。
3. **稀有概念色**：只用于危险、契约、异变、重大事件，不做日常装饰。

落实到 Battle 时，所有视觉元素都要回答一个问题：它是在讲规则、讲世界，还是讲事件。回答不清楚的元素直接删除。

## Battle 视觉结论

Battle 不是通用卡牌战斗面板，也不是暗黑 HUD。它应当像一页被持续翻阅的旧命簿，正面记录一场志怪战斗：

- 规则层清楚，纸面克制。
- 世界层有湿冷、压迫、异物感。
- 事件层只在必要时用概念色和短促动效标记。

Battle 必须在同一屏内同时成立以下四件事：

1. 玩家能快速读到当前战况。
2. 敌我识别清晰。
3. 蛊牌与 tooltip 可读。
4. 危险、禁用、确认与结算状态不靠猜。

## 目标布局

### 总体结构

Battle 采用三段式布局，但不做现代应用式卡片堆叠：

1. **上段：战局摘要区**
   - 只放高频规则信息。
   - 保持横向克制，避免横幅化装饰。
   - 作用是交代当前回合、资源、关键状态。

2. **中段：主战场区**
   - 以人物、敌人、场地关系为视觉中心。
   - 负责叙事压力和对抗关系。
   - 插画或轮廓可以更暗，但信息不能更乱。

3. **下段：手牌与操作区**
   - 手牌、可执行操作、提示、确认入口集中在这里。
   - 这个区域必须清楚但不能喧宾夺主。
   - tooltip 的视觉浮层属于这里的延伸，不属于常驻版面。

### 版式规则

- 主战场区永远优先于装饰背景。
- 任何大图都不能挤压卡牌、按钮、意图、状态文本。
- 行为反馈必须落在固定区域，不能让布局跟着状态跳动。
- 关键交互必须有稳定锚点，hover 后不重排主版面。

### 视觉优先级

1. 人物、敌人、蛊牌的识别。
2. 危险、意图、禁用、确认状态。
3. 资源、回合、辅助提示。
4. 纯装饰细节。

如果某个元素无法在这个顺序中找到位置，就不应出现在 Battle 里。

## 组件职责

### TopBar / 战局摘要条

职责：

- 承载当前战斗必须读到的高频状态。
- 使用纸墨式排版，而不是浮夸横条。
- 通过字重、留白、线条建立层级。

不负责：

- 叙事铺陈。
- 装饰性 logo。
- 与回合无关的长期信息。

### 敌人展示区

职责：

- 提供敌人识别、意图、HP、护盾、状态的清晰阅读。
- 让敌人首先像“有行为逻辑的对象”，不是单纯数值条。
- 保留敌人个体差异，但不把每个敌人都做成独立主题页。

风格要求：

- 外观偏湿冷、压迫、自然志，而不是高饱和怪物卡面。
- 危险感来自结构、姿态、状态痕迹，不来自爆闪。

### 玩家展示区

职责：

- 只承载必须即时理解的资源与生存信息。
- 危险状态必须可以用颜色、文案和结构共同表达。
- 关键变化优先体现在文本、位置、留白和状态痕迹上。

风格要求：

- 像命簿中的当下记录，不像角色面板广告。
- 朱砂只用于危险、不可逆和裁定。

### 手牌组件

职责：

- 卡牌名、可执行性、代价、块原因和 hover 触发。
- 让玩家在小尺寸下也能辨认卡牌轮廓和正式图标。
- 不把所有规则文本都直接铺在牌面上。

风格要求：

- 牌面像被记录的蛊虫标本，不像通用技能卡。
- 牌面正文保持克制，细节交给 tooltip。
- 禁用与风险必须可读，不可只靠灰掉。

### Tooltip 容器

职责：

- 承接不适合常驻版面的详细信息。
- 把质量、效果、代价、联动、不可用原因放进统一结构。
- 在 hover 时出现，离开后收束。

风格要求：

- 纸面化、清晰、短促。
- 作为信息补充，不作为第二套主视觉。
- 不抢占战场布局。

### 反馈区

职责：

- 承接短促确认、错误、落定、事件反馈。
- 只显示功能信息，不做日志墙。

风格要求：

- 像命簿批注，而不是聊天记录。
- 只在有意义时出现，结束后回到安静。

### 确认对话框

职责：

- 处理不可逆动作确认。
- 只表达“是否继续”，不做戏剧化包装。

风格要求：

- 朱砂级别的危险确认可以更明确，但不能更花。
- 必须保持规整、冷静、可扫描。

## 最小资产集

### 必需资产

1. Battle 已有共享 UI 组件。
2. 纸墨语义所需的基础视觉 token。
3. 敌我、危险、确认、禁用的状态图标或标记。
4. Battle 所需的最小背景或材质表现，优先沿用现有纸面语义。

### Battle 验证用最小新增项

1. 用于敌人 / 人物基线的轮廓或占位视觉。
2. 用于卡牌识别的最小图鉴表达。
3. 用于 tooltip 的统一容器样式。
4. 用于危险和确认的少量概念色表达。

### 明确不引入

1. 全量人物、敌人、蛊牌、地点插画库。
2. 新 Shader 框架。
3. 粒子雨、持续辉光、装饰性漂浮效果。
4. 第二套主题系统。
5. 未定义的概念色扩展。

## 动效边界

### 允许

1. 墨迹显现，用于状态揭示。
2. 翻页或层级切换，用于面板变化。
3. 盖印式确认反馈，用于不可逆动作。
4. 小幅有机微动，用于蛊虫或状态元素的生命感。

### 禁止

1. 持续发光。
2. 粒子雨。
3. 常驻漂浮。
4. 每次点击都产生戏剧化转场。
5. 用长动画掩盖状态信息。

### 时间要求

- 常规反馈保持短。
- 重大结算可以略长，但必须快速回静。
- 动效服务于阅读，不服务于表演。

## 验收标准

### 视觉判定

1. Battle 第一眼像命簿中的志怪战况，不像通用卡牌 UI。
2. 纸面规则与暗色插画各司其职，没有互相吞没。
3. 朱砂、契约蓝、异变黄、玉色只在语义成立时出现。
4. 概念色不退化为普通装饰色。

### 信息判定

1. 正文、数值、代价、不可用原因、敌人意图、确认状态可直接读取。
2. 小尺寸卡牌仍可凭轮廓和正式图标识别。
3. 普通、悬浮、选中、禁用、危险、已确认状态不只靠颜色区分。
4. 动效结束后界面回到稳定安静状态。

### 结构判定

1. Battle 保持三段式清晰结构。
2. 共享组件职责边界清楚，不越权。
3. 没有把 Map、Hall、Ending 的需求混入本次规格。
4. 没有要求新增未定义资源才能判断通过。

## 验收路径

1. 先确认版式是否正确：顶部摘要、中部战场、底部手牌与操作是否稳定成立。
2. 再确认组件职责是否正确：TopBar、敌人区、手牌、tooltip、反馈区、确认框是否各做各的事。
3. 再确认风格是否正确：纸墨规则层、志怪叙事层、概念色层是否都能被看见且不过量。
4. 最后确认交互是否正确：hover、点击、禁用、确认、少敌、多敌、空状态是否都能工作。

### 分辨率检查

- `1920×1080`
- `1366×768`
- `1280×720`

检查项：

- 不裁切。
- 不遮挡。
- 不漂移。
- 不空白。
- 不因悬浮态导致布局跳动。

2. 把读书笔记的风格要求映射成版式、组件职责、资产最小集和验收标准。
