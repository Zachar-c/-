# 《問眞》蛊界世界模型纠偏设计

> 日期：2026-09-16  
> 状态：用户已同意进入设计阶段  
> 适用范围：`gu-zhenren-editor` 的规则、数据、内容和表现语义  
> 当前阶段：只做审计与设计，不修改生产代码和数据

## 0. 设计决定

《問眞》采用“原著优先、兼顾可玩性”的世界观标准：

1. 《蛊真人-clean.txt》中的明确规则、因果和行为逻辑优先。
2. 原著没有明确规定的部分允许游戏化，但不能与原著的资源关系、力量逻辑、社会逻辑和因果逻辑冲突。
3. 游戏可以压缩时间、空间和内容规模，但不能把压缩后的抽象伪装成原著规则。
4. 方源的既定故事不作为首版主线；《問眞》仍然是随机经历一段蛊界修行人生的肉鸽。
5. 现有设计文档、代码和数据全部视为待审计的实现材料，不自动视为世界观真相。

本次工作不是给现有卡牌系统继续添加蛊真人名词，而是重新检查：玩家看到的每个机制，是否能从蛊界世界模型中自然推导出来。

### 0.1 优先级与冻结令

本设计是当前《問眞》的最高层级设计宪章，高于此前 Q8-G、F1 Pity、流派晋升链、材料扩充、promotion economy 及其他以现有机制闭环为目标的设计和交接文档。

- Q8-G 及其交接文档降级为“现有系统状态与历史决策档案”。
- 在 Stage 0 通过前，不得继续实施 F1 Pity、promotion/material、流派晋升链或依赖这些模型的生产规则变更。
- 现有实现可以继续作为审计对象、回归基线和迁移参考，但“已有代码/测试通过”不构成保留理由。
- Stage 0 期间允许新增审计报告、证据索引、只读探针和测试夹具；不得修改生产 `scripts/`、`data/`、`scenes/` 或生产配置来绕过尚未完成的裁决。

## 1. 目标与非目标

### 1.1 目标

- 建立一套可引用、可验证、可扩展的蛊界底层世界模型。
- 明确蛊虫、蛊师、转数、空窍、真元、寿元、魂魄、肉身、道痕、蛊方、杀招、传承、势力和升仙之间的关系。
- 对当前系统逐项标注“符合、可解释游戏化、需要补充、需要删除、需要重做”。
- 优先修正会改变玩家决策逻辑的偏差，而不是优先补充百科数量。
- 保留确定性、数据驱动、领域层结算、事件日志和可测试架构等工程优势。
- 使用代表性原著场景验证改造后的规则，而不是只做文字层面的自洽。

### 1.2 非目标

- 不在本阶段实现代码、重写 JSON 或调整 UI。
- 不把《問眞》改造成方源剧情复刻。
- 不一次性还原小说全部 802 只蛊、所有人物和所有仙尊内容。
- 不为了“原著感”把所有系统做成高复杂度的模拟器。
- 不把原著中的叙事结果直接复制成玩家必经剧情。

## 2. 证据层级

### 2.1 证据优先级

| 优先级 | 来源 | 用途 |
|---|---|---|
| P0 | `gu-zu/豆包/蛊真人-clean.txt` | 原著事实、规则、场景因果和人物行为 |

| P2 | `gu-zhenren-editor/data/` | 当前内容实现事实 |
| P2 | `gu-zhenren-editor/scripts/domain/` | 当前规则实现事实 |
| P3 | 现有 specs、wiki、README | 既有设计意图，可被本设计推翻或重写 |

### 2.2 每条规则的记录格式

后续审计条目必须至少记录：

```text
rule_id
world_claim
evidence_location
confidence
current_implementation
classification: keep / supplement / delete / redesign / defer
player_facing_consequence
validation_case
```

“原著没有写过”不能自动推出“游戏可以随便设计”；需要说明它是必要的游戏压缩、内容预算还是新的世界内规则。

### 2.3 假设与事实的边界

第 4 节的偏差表是**初步假设/偏差候选表**，不是已经确认的世界事实，也不是可直接转换成代码任务的需求清单。

- 只有完成原文证据定位、反例检查和影响评估后，候选项才能进入 `World Model Baseline v1`。
- “本命蛊如何形成”“魂魄与兽性的关系”“凡人期道痕边界”“资质与恢复的具体关系”等条目默认标记为待验证 claim。
- 任何 claim 在没有达到确认门槛前，只能产生研究结论、待裁决项或实验方案，不能改变生产规则。

## 3. 蛊界底层世界模型

### 3.1 世界对象

《問眞》后续所有机制应围绕以下对象展开：

| 对象 | 世界内含义 | 游戏要求 |
|---|---|---|
| 人 | 有肉身、寿元、情绪、关系和行动能力的个体 | 不能只作为 HP 容器或 NPC 立绘 |
| 蛊虫 | 天地真精、独立生命和能力载体 | 每只蛊应有来源、用途、食性、转数、风险和处置方式 |
| 蛊师 | 通过空窍、真元和蛊虫修行的人 | 能力由拥有和催动的蛊、肉身和经验组成，不是职业卡组 |
| 空窍 | 蛊师体内的修行容器 | 资质决定容量和恢复质量；不能只显示为抽象等级 |
| 元海/真元 | 催动蛊虫的真实修行资源 | 是世界内资源，战斗显示只是局部窗口 |
| 转数 | 蛊虫与蛊师的量级和质量 | 影响催动、承载、资源和社会地位，不只是伤害倍率 |
| 寿元 | 生命存在的期限 | 是极重的不可逆代价，不是普通货币 |
| 魂魄 | 灵魂强度、承载和兽性风险 | 与念头分离，不能用行动点简单替代 |
| 道痕 | 对某一道的永久积累和影响 | 主要用于有充分世界依据的内容，不能泛化为普通经验条 |
| 蛊方 | 已知的蛊虫组合、炼制方法和知识资产 | 通过传承、交易、推演或实践获得；配方本身有价值 |
| 杀招 | 多蛊组合、顺序、操控和经验形成的高级手段 | 需要条件、知识、代价和被破解的风险 |
| 传承 | 前人留下的蛊虫、蛊方、经验、考验和资源 | 必须有来源和争夺，不是无条件奖励房 |
| 势力 | 家族、宗门、商会、魔道组织和地域秩序 | 决定交易、保护、追杀、信息和行动后果 |
| 灾劫/升仙 | 修行层级改变时的世界性考验 | 不能只做一个 Boss 房或分数结算 |

### 3.2 重要关系

底层因果应保持为：

```text
资质 → 空窍与真元质量
真元质量 + 蛊虫转数 → 能否催动及催动成本
蛊虫获取 → 炼化/认主 → 喂养/维护 → 催动/组合
蛊虫组合 + 知识/操控 → 杀招
修行、交易、战斗和传承 → 资源、关系、情报与追杀变化
修为提升 → 更高收益、更高消耗、更强灾劫与更大势力反应
```

任何无法接入这条因果链的常驻属性，都必须先证明它是必要的游戏界面抽象，否则应删除或降级为表现层文本。

## 4. 初步偏差审计

| 领域 | 当前实现倾向 | 判断 | 改造方向 |
|---|---|---|---|
| 蛊虫 | 802 只目录，大量由 `role` 兜底效果驱动 | 高风险偏差 | 把蛊虫恢复为独立实例；生产内容禁止用同质化兜底冒充完整蛊效 |
| 流派 | 20 个流派各有起始蛊，接近职业选择 | 高风险偏差 | 流派改为道标签、传承和构筑倾向；开局身份不锁定职业包 |
| 核心蛊 | 后置选择一只“核心蛊” | 概念错位 | 重新定义为本命蛊/主修枢纽；原则上由炼化顺序和身份经历产生，不是任意选出的天赋槽 |
| 转数 | 主要用于倍率、门禁和真元 | 不足 | 增加承载、催动质量、价值、肉身、势力和风险维度；避免所有高转内容只是大数字 |
| 真元 | 局外 `essence` 与战斗 `true_qi` 双轨 | 可解释但易错位 | 合并世界语义；战斗轨道只能是同一元海资源的场景化显示或预算窗口 |
| 念头 | 接近每回合行动点 | 概念压缩过度 | 作为操控复杂度和心神容量的临时抽象，不与魂魄、转数直接绑定 |
| 寿元 | 可在多处作为可支付资源 | 高风险偏差 | 保留真实代价，但删除普通货币化感觉；所有寿元支付必须是禁忌、修行或特殊方法 |
| 魂魄 | 与行动次数、魂量级和兽性并列 | 方向正确但需重做 | 建立量级、承载、安定和兽性之间的因果，不能只做额外行动点 |
| 道痕 | 过早泛化到凡人流派和各种印记 | 高风险偏差 | 凡人期只保留有原著依据的肉身/蛊效痕迹；道痕主系统延后到仙人阶段或明确例外 |
| 战斗 | 回合、护盾、卡牌区域仍是主要认知模型 | 高风险偏差 | 卡牌仅作操作界面；战斗核心改为蛊虫组合、距离、速度、准备、情报和代价 |
| 杀招 | 预设杀招与卡牌释放并存 | 方向正确但不完整 | 让杀招成为知识资产；需要配方、顺序、操控、泄密、反制和真实成本 |
| 炼蛊 | 同转合成、随机自由混合占比较高 | 高风险偏差 | 已知蛊方确定性优先；盲炼是高风险知识不足的行为，失败必须有世界内原因 |
| 养蛊 | 有喂养字段，但维护压力弱 | 不完整 | 食性、饥饿、忠诚、凶性、寄生和逃遁进入日常取舍；不能用统一 `feed_points` 取代食物关系 |
| 经济 | 元石统一购买、回收和兑换大量内容 | 偏游戏化 | 元石是一般等价物，但稀有蛊、禁忌物、人情和传承不能都折算成价格 |
| NPC | 目标、底线和需求已有框架 | 方向正确 | 从一次交涉结果升级为关系账、势力反应、保护与追杀链 |
| 地图 | 五层节点 + Boss 门禁是主要结构 | 可保留抽象 | 每层必须对应修行阶段和地理/势力压力；Boss 不是纯关底敌人，而是阶段性强者或危机 |
| 轮回/Meta | 图鉴跨局保留，轮回提供解释 | 游戏层可保留 | 明确区分玩家知识与角色记忆；不得把跨局解锁伪装成所有角色共享的世界事实 |
| 结局 | 多种评分和结局类型 | 可保留抽象 | 结局必须由此前积累的修行、关系、代价和已知事实归因，而非单纯分数 |

## 5. 保留、补充、删除、重做

### 5.1 保留

- 固定种子和确定性规则。
- 数据驱动的蛊虫、蛊方、敌人、节点和 NPC 目录。
- 领域层负责判定，表现层只读快照并提交命令。
- 不可变事件日志及基于日志的结算归因。
- 地图路线、路线取舍和随机修行人生的总体形态。
- 元石作为普通交易的一般等价物。
- 图鉴作为玩家层面的知识型跨局进度，但重新定义其叙事边界。

### 5.2 必须补充

- 蛊虫的来源、认主/炼化、食性、运作方式、生命周期和处置后果。
- 资质、空窍、真元质量、转数和催动门槛之间的真实关系。
- 蛊方的来源、知识门槛、成功条件、失败原因和产物身份。
- 杀招的步骤、操控、反制、泄密和被破解后的风险。
- 势力影响、关系账、情报事实、保护、追杀和行动后果。
- 代表性原著场景的规则验证案例。
- 对玩家已知事实与角色隐藏事实的严格区分。

### 5.3 应删除或禁用

- 把流派当作开局职业和固定牌组的语义。
- 把 `role` 兜底效果作为生产环境完整蛊效的长期替代品。
- 把寿元、魂魄和特殊蛊材当作普通商店货币的通用兑换品。
- 没有来源、没有食性、没有独立风险的装饰性蛊虫条目。
- 没有世界内解释的“核心蛊槽”“万能卡牌许可”“纯数值 Boss 门禁”。
- 用全局统一克制倍率解释所有道标签的做法。
- 不产生未来后果的单次 NPC 成功/失败结算。

### 5.4 必须重做

- “本命蛊/核心蛊”体系：从任意后置选择改为炼化与经历形成的身份关系；换本命应是极少见且有重大代价的事件。
- “流派选择”体系：从职业入口改为初始背景、已有蛊和传承倾向；玩家通过实际持有和使用形成主修路线。
- 真元双轨语义：从两个平行资源改为一个元海资源的不同显示/场景结算方式。
- 炼蛊与养蛊：从数值配对和统一喂养点改为具体蛊方、具体食性和具体代价。
- 战斗行动模型：保留回合作为界面节奏，但隐藏的核心应是蛊虫运作、距离、速度、准备、反应和资源质量。
- 地图与 Boss：从纯肉鸽节点推进改为有地域、时间、势力和修行阶段解释的路线。

## 6. 改造后的目标循环

```text
认识身份与当前处境
  → 侦察地点、势力、人物和资源
  → 选择获取蛊、交易、修炼、炼蛊、战斗或撤离
  → 炼化并维护真实蛊虫
  → 通过蛊虫组合和知识形成个人打法
  → 承担资源、关系、伤势、追杀和暴露后果
  → 在阶段性机缘中争夺更高修为或传承
  → 以当前积累决定突破、退避、死亡或留下新的修行记录
```

玩家每次做出的选择都应至少改变以下一项：

- 能否催动或维持某只蛊；
- 元石、真元、寿元、魂魄或蛊材；
- 某个具体人物或势力的态度；
- 玩家已知事实或敌人的准备状态；
- 后续路线、追杀、传承或突破条件。

## 7. 分阶段改造顺序

本设计不把全量改造视为一个开发任务，而是拆成可独立验收的阶段。Stage 0 是硬 Gate；未通过前，后续阶段只能调查和设计，不能改生产规则。

### 阶段 0：世界规则基准（硬 Gate）

建立 `World Model Baseline v1`：原著事实索引、规则 ID、证据位置、置信度、反例和冲突裁决表。首批至少冻结 20 条、目标 24 条高影响 `world_claim`，覆盖：蛊虫、炼化、本命蛊、空窍、资质、真元、转数、寿元、魂魄、肉身、道痕、流派、蛊方、炼蛊、杀招、传承、势力、交易、战斗、升仙和灾劫。

Stage 0 出口必须同时满足：

1. 每条基准 claim 都有原文位置、证据摘要、置信度和适用边界。
2. 关键冲突都有明确裁决，不能以“以后再说”作为通过条件。
3. 明确哪些是原著事实、哪些是兼容性游戏化、哪些是暂不采用的推论。
4. 形成 Q8-G/F1/promotion/material 等现有模型的保留、冻结、重做或废止初判。
5. 产出可复现的 Stage 0 报告与配置；生产规则、数据和场景未被改写。

未满足以上条件时，Stage 0 失败，阶段 1～6 不得进入实现。

### 阶段 1：蛊虫实体与构筑

先做一个纵向切片：10–20 只蛊、1 个身份背景、1 条地图路线、2–3 个敌人、1 个炼蛊场景和 1 个 NPC。重建蛊虫定义与实例边界，清理角色兜底，补充来源、食性、运作方式和生命周期。切片通过前，不扩大生产目录。

### 阶段 2：修行资源与转数

在同一纵向切片中统一元海/真元语义，重新检查资质、转数门槛、真元质量、寿元支付、魂魄承载和修为推进。所有不可逆支付先建立预检与解释；切片通过前，不扩大资源模型。

### 阶段 3：蛊虫组合、杀招与战斗

在同一纵向切片中把卡牌降为输入界面，改造战斗规则的叙事语义和数据接口。逐步加入距离、速度、战前准备、组合步骤、反应窗口、泄密和反制；通过后才扩展敌人池和杀招池。

### 阶段 4：炼蛊、养蛊与经济

在同一纵向切片中以“已知蛊方稳定、盲炼危险、养蛊持续有压力、稀缺物不能全都价格化”为原则，重建蛊材、喂养、交易和处置。通过后才决定 promotion/material 体系是否保留。

### 阶段 5：势力、NPC、地图与事件

让节点成为地点和局势，而非只是一张奖励卡。加入势力保护、行动暴露、追杀、关系账和信息失效。

### 阶段 6：轮回、图鉴与结局

明确玩家跨局知识与角色世界内记忆的边界，重做结算归因，使结局体现修行路线和代价，而非单纯分数。

每个阶段都应有单独设计稿、迁移说明、领域测试、数据校验和至少一个代表性场景验收，不跨阶段同时改动。

## 7.1 阶段级 Non-regression Gate

每个阶段除了功能验收，还必须证明没有破坏以下约束：

- 被替换的旧系统有迁移、废止或兼容说明；不能通过删除旧字段掩盖影响。
- 新世界模型规则仍由领域层统一结算，UI 不直接改状态。
- 所有随机继续使用统一种子化入口；原著还原不能引入不可复现的随机。
- 不得为了增加原著细节牺牲可测试性、事件日志完整性或存档一致性。
- 代表性原著场景没有通过前，不扩大蛊虫、敌人、流派、材料或视觉内容池。
- 旧 Run 无法可靠映射时必须拒绝继续并保留大厅知识，不猜测转换。

## 8. 兼容与迁移原则

- 规则版本必须递增；旧 Run 无法可靠映射时直接拒绝继续，不猜测转换。
- 大厅图鉴、已解锁知识和统计可以迁移，但不把旧 Build 当作新世界规则继续运行。
- 原文资料目录、`豆包/`、`分支：六卷精编版/` 和 `肉鸽设计-原始数据/` 保持只读。
- 每次阶段迁移都必须提供旧字段到新字段的明确映射或明确废止说明。
- 任何临时兼容层都不得成为新的生产世界规则。

## 9. 验收标准

### Stage 0 Gate

- `World Model Baseline v1` 至少包含 20 条已裁决高影响 claim，目标为 24 条。
- 每条 claim 都能沿着“原著事实 → 推导 → 当前实现 → 裁定 → 玩家后果”回溯。
- 第 4 节所有候选项都标注为已确认、待验证、游戏化或废止，不能把候选项伪装成事实。
- Q8-G/F1/promotion/material 的处理状态已经明确为保留、冻结、重做或废止之一。
- Stage 0 期间生产代码、生产数据和生产场景无变更。

### 世界观验收

- 每个进入生产池的蛊虫都有可追溯来源、明确主功能、运作方式、转数、成本和处置方式。
- 开局不再强制玩家选择一个与生俱来的“职业流派”。
- 本命蛊、普通蛊、借用蛊、未炼化蛊和传承蛊在规则上有明确区别。
- 转数不只改变伤害；低转蛊在低成本、特殊功能、组合或知识价值上仍有存在理由。
- 寿元和魂魄的支付、危险和死亡后果在执行前可预见。
- 已知蛊方与盲炼的成功/失败逻辑不同，并且失败有世界内原因。
- NPC 选择能留下未来关系或势力后果。

### 游戏性验收

- 玩家仍能在有限时长内完成一局，并保有路线、构筑和资源取舍。
- 五种以上构筑方向不依赖唯一指定蛊或唯一杀招。
- 不因删除通用兜底而产生空节点、死按钮或无法继续的 Run。
- 所有随机来源可复现，关键状态变化有事件日志。
- 每个阶段都有单元测试、集成测试和一个可复现的场景探针。

## 10. 当前结论

《問眞》最需要修正的不是名称、立绘或单个数值，而是“蛊界因果是否真正驱动玩法”。后续实现应优先修正以下三件事：

1. 蛊虫从同质化技能目录恢复为有身份、有成本、有生命周期的世界实体。
2. 修行资源从平行的游戏货币恢复为由空窍、真元质量、寿元和魂魄共同约束的世界关系。
3. 战斗从卡牌效果释放恢复为信息、准备、蛊虫组合、杀招知识和真实代价的交锋。

这三件事完成前，不应继续扩大蛊虫数量、流派数量或视觉内容规模。
