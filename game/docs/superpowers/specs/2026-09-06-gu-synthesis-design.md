# 蛊虫合成设计 · 古方知识模型（2026-09-06，用户逐条裁定定稿）

> 裁定记录：用户 2026-09-05/06 多轮裁定 + 本日终审（配对定形、A3 分层揭示、B1 稳定绑定、
> 合成零门槛、古方=知识、输入按主道、次道痕规则记档不改数据）。
> 设计原则：肉鸽减法——玩家在有限游玩中无负担地体验「战斗→资源→商店→合炼→更强敌人」环路。

## 0. 一句话模型

> **任何两只蛊都可以丢进炉子**（主蛊+辅蛊）；出什么由这一对决定，稳定可复现；
> **古方是知识**：持有它=提前知道产物；不持有=赌一次未知。炼出来的永远记进图鉴。

## 1. 合炼权限（零门槛）

- 同道、跨道合炼**均无需持有任何方子**即可尝试。
- 成本 = 输入蛊实例（真实消耗）+ 按转阶的元石（`stone_cost`，落 balance.json）。
- 原文语义对应："先祖们通过数不清的失败才总结出秘方"——玩家自己就是做实验的先祖。

## 2. 产物解析：配对稳定映射（B1）

- 域 = 产出道（主蛊的主道）× 产出转（主蛊转数 + 1）。例：2转血道主蛊 + 2转光道辅蛊 → 3转血道域。
- 产物 = 域内蛊群按 **(主蛊 id, 辅蛊 id) 的稳定映射**选出的一只。
- **映射与种子无关**（纯函数）：同对永远同产物、跨局跨种子恒真——图鉴知识因此永久有效，肉鸽随机性全部放在"你会捡到哪两只蛊"的输入端。
- 预检透明度：成本、成功率、失败代价永远可见；产物名按 §3 的知识状态显示。

## 3. 古方 = 产物知识（三层揭示，A3）

| 知识状态 | 预检显示 |
|----------|----------|
| 未持有古方、未炼过 | 域信息（血×光·3转）+ 成功率 + 失败代价；产物 **"？？？"** |
| 炼过该产物（自动获得古方）/ 持有该古方 | 产物名 + 效果，所见即所得 |

- **古方按产物蛊登记**（每只 rank≥2 蛊一张；映射函数可推导，无需逐条数据表；系统只记"玩家持有哪些古方"）。
- **获得途径**：①首次合成出该蛊 → 自动获得其古方（实验发现）；②直接获取（黑市购买/遗葬继承）——**免未知损失**，这是买方的价值。
- 图鉴（蛊方图鉴，唯一跨局解锁）= 古方收藏册：跨局记得的是配方知识，不是数值。

## 4. 名方（现有固定方，特例层）

- 现有 8 条原文锚点方（月芒=月光蛊+小光蛊×2、白玉=白豕+玉皮+獠牙添头……）保留为**精确输入→精确产物**的名方：持有即直知，且支持多输入（一心多用语义）与添头材料。
- 名方与自由配对并存：名方是"被原文/先祖验证过的最优认知"，自由配对是实验场。
- `optional_materials` 添头机制沿用（野猪王雪獠牙先例）。

## 5. 道痕模型（规则记档，当前数据不改）

- 每只蛊可有多条道痕：**主道痕 1 条（`school` 现字段）+ 次道痕 0--N 条**；**绝大多数蛊是单道痕**，次道痕是例外（血月蛊=主光次血）。
- 输入归属**按主道计**（血月蛊进炉算光道蛊）；次道痕 = 风味 + 将来杀招匹配的语义，不参与本次任何判定。
- 已知校正项（概念层面，暂不动数据）：血月蛊（blood_atk_3_11_gu）主道应为光。
- 实现落点：实现合成时不需要次道痕字段；杀招匹配期再引入。

## 6. 成败与代价（悬点五已裁定）

- 切片宽：2 转约 90% 成功，失败以输入蛊受伤为主（休整可愈）。
- 4/5 转收紧：成功率降至 ~50/35%，失败可蛊死；参数全部落 `balance.json`。
- 反噬诅咒沿用既有耦合（F4 冻结的既有接口）。

## 7. 同名晋升（advance 腿）保留

377 条同名晋升方是低转资源的升转通道（买两只一转同蛊→晋升→喂更高转域），与古方模型并存。
