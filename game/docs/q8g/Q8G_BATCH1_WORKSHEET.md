## A. 战斗产石

### A.1 语义（已冻结）

- **战斗是"主循环的风险生产者"** —— `风险 ↑ → 收益 ↑`，**不是固定收益**。
- **挂载层级**：`tier` 决定基础值 + `layer` 做阶段修正。
- **禁止**按 `enemy hp/damage` 实时公式推导（**避免经济与战斗平衡过度耦合**）。

### A.2 落点设计（待确认）

| 项 | 内容 |
|---|---|
| 结算位置 | `LootResolver.settle_victory` 返回结构中**新增石字段** |
| 消费位置 | `battle_command_facade.gd` victory 分支**写入 `state.stones`** |
| 数据位置 | `loot_tables.loot.{common,elite,boss}` |
| 数值 | **`provisional: true` 占位**（由后续裁定确定） |

### A.3 ⚠️ 需确认的技术问题

1. **结算位置**：是否新增 `settle_victory` 的返回键（如 `stone_reward`）？
   → 会影响 `battle_command_facade` 与快照契约。
2. **数据键位置**：新增 `stone_reward` 键名需**同步 `content_catalog` 白名单**（AGENTS.md 红线）。
3. **`layer` 修正系数**：是否复用现有 `pacing.layers[*]` 结构（该结构已有 `shop_price_pct`）？

> **建议**：新增独立小节（如 `pacing.layers[*].stone_modifier`），**不复用 `shop_price_pct` 语义**。

## B. `promotion` 骨架

### B.1 语义（已冻结）

| 项 | 冻结结论 |
|---|---|
| 定义 | **Rank N → Rank N+1 的独立语义** |
| recipe kind | **新增 `kind: "promotion"`**（**不复用 `fixed`**） |
| 规则 | **流派约束 + 蛊系/目标蛊明确映射**（混合，非纯流派、非自由配方） |
| 表现 | `Rank N 某类蛊 → 指定 Rank N+1 候选`（**不是任意 N 转蛊 → 任意 N+1 转蛊**） |
| 成本 | **蛊 + 材料 + 元石**（**不含寿元**） |
| 核心语义 | **"牺牲现有资产换更高阶资产"**，不是"花钱升级" |
| 骨架粒度 | **每流派 × 每转数跃迁 ≥1 条路径**（1→2 / 2→3 / 3→4 / 4→5） |
| **不要求** | 每个 role 都有完整链 |

### B.2 ⚠️ 红线（任务书 §六）

```
低转蛊 + 材料 + 元石 → 高转蛊
        总成本  <  直接购买同等级高转蛊的成本
```

> **硬红线，不得以"平衡"为理由删除。**

### B.3 ⚠️ sword 异常链处理（已冻结为"必须加成本"）

- 现状：`ascend_sword_rec_1_10_gu`：**1→5 / 0 石 / 0 材料** → **必须加成本**。
- 可保留"剑道更容易晋升"特色，**但不能是零成本直达**。

### B.4 现有 377 条 advance 处置（已冻结）

```
现有 377 条  → 尽可能保留为 advance（同名培炼）
真正的升转配方 → 迁移/新增为 promotion
```

### B.5 ⚠️ advance 的可测成长（已冻结）

- ❌ **不新增实例数值**（撞白名单 + 扩 scope）。
- ✅ **采用已有实例状态**：**道痕 / 已解锁步骤**。
- 条件：**执行后必须有可观察、可验证的增强**，否则仍是坏数据。

### B.6 ⚠️ 需确认的技术问题

1. **`promotion` 配方的数据结构**：
   - 是否复用 `refinement_recipes.json`（新增 kind）？
   - 还是新建独立数据文件？
2. **"蛊系"如何表达**：现有 `gu.json` 有 `school` / `role` / `rank`，
   **无"蛊系"字段** → 需新增字段还是用命名约定推导？
   → **若新增字段必同步白名单**。
3. **骨架的 20 流派 × 4 跃迁 = 80 条最低**，是否全部在 Batch 1 一次做完，
   还是先做骨架 + 少量流派验证？

## C. 三档蛊获取通路

### C.1 语义（已冻结）

| 档位 | 职责 |
|---|---|
| **普通战** | 低概率获得 **Rank 1 / 基础型蛊**（**不能变成抽卡机**） |
| **精英** | **定向候选 + 修正 70% 负期望**（候选池 → 选择/定向获得） |
| **Boss** | **配方线索 > 关键晋升材料 > 定向池/选一 > 专属蛊** |

### C.2 高转可达性（已冻结为混合）

```
promotion → 主要
Boss      → 少量关键钥匙/定向资源
```

> Boss **帮你突破**，**不替你玩晋升系统**。

### C.3 780 只非掉落蛊（已冻结）

```
主渠道：promotion
次渠道：商店
少量特殊：Boss / 精英
```

> ❌ **不通过"扩大商店槽位"解决**。
> 目标：**让 802 只蛊成为"可炼制的世界内容"，而不是"802 张商店卡"。**

### C.4 ⚠️ 需确认的技术问题

1. **Boss "配方线索"如何表达**？现有机制里有 `scavenge_recipe`（2 条）——
   是否复用/扩展？
2. **精英"定向候选"如何实现**？现有 `gu_pool` 是权重随机 → 需改为**候选池 + 玩家选择**？
   → 涉及 UI 改动（**需核对 `docs/contracts/` 三份契约文档**）。
3. **精英负期望修正的具体方向**：降低必然代价 还是 提高回报？（**数值后置**）
4. **`gu_pool` 空内容**（boss）需补全 → **数据填充 + 契约同步**。
