## 2. Q1 元石生产者（冻结）

### 2.1 生产者与转换器必须分离 【新增正式语义】

```
净新增元石（生产者）：
  - 战斗
  - 打工 / 采集 / 欺骗

资产转换（非生产者）：
  - 卖蛊
  - 卖材料
```

> **裁定**：**这一区分必须进入正式规格。**
>
> **理由（审阅者原话）**：否则将来 F8 统计会再次出现
> "卖掉 100 份垃圾材料赚了 50 石"，然后**误以为经济系统产生了 50 石**。

**冻结结论**：

| 类别 | 通道 | 语义 |
|---|---|---|
| **主生产者** | 战斗（普通/精英/Boss） | 净新增 |
| **辅助生产者** | 打工 / 采集 / 欺骗 | 净新增，**非主要货币来源** |
| **转换器** | 卖蛊 / 卖材料 | **资产形态转换，不计入收入** |
| **❌ 不接线** | `stone_budget` | **不接线**（第二个独立 faucet） |

### 2.2 遭遇收入随层缩放 【冻结原则，不冻结数值】

> **裁定**：**要缩放，但不是简单 `×层数`。**

**冻结的原则表述**：

> **遭遇行为的收益随危险度/机会成本增长，但增长幅度低于战斗收益增长。**

**双向风险（审阅者明确列出）**：

- 若层 5 打工仍 +3，而战斗已获高层收益 → **打工成为近乎无风险的固定套利**
- 若按层线性暴涨 → **不战斗 → 打工刷钱**

**冻结口径**：

> **"随层增长，但不是主要货币来源"** —— 具体数值进入之后 F8 模拟。

### 2.3 待办登记

| 项 | 状态 |

| 遭遇收益随层缩放的具体曲线 | ⏸ **数值后置** |

## 3. Q2 元石消费者（冻结）

### 3.1 优先级顺序 【冻结】

```
第一优先：炼蛊 / 晋升（promotion）
第二优先：关键成长内容
第三优先：商店
第四优先：服务 / 信息
第五优先：其他消费
```

> **核心原则（审阅者原话）**：不是"商店不能花钱"，而是
> **元石首先应该推动玩家成长，其次才是消费。**

**判定当前结构的反常之处**：

> 基础炼蛊 6/10 石几乎免费，而古方 60–200 石；
> 删卡 120、拔印 150 又非常遥远。

**目标循环（要建立）**：

```
战斗 → 元石 → 炼蛊 / promotion → 构筑成长 → 更强战斗
```

**当前循环（要消除）**：

```
战斗 → 元石 → 逛商店 → 买成品
```

### 3.2 主要 sink

> **裁定**：**混合，但"成长导向"为主** → `成长 > 商店 > 服务`
>
> **比例现在不要写死。**

### 3.3 删卡 / 拔印记

> **裁定**：**暂不改价格，先看晋升经济建立后的完整收入规模。**

→ 与工单原选项"需先看晋升经济规模再定"一致，**冻结为该结论**。

## 4. Q3 战斗经济角色（冻结）

### 4.1 定位 【冻结】

> **裁定**：**不是 A 或 C 单选，而是 C 的展开版 —— "主循环的风险生产者"。**

```
战斗是主要生产者之一，并且收益必须与实际战斗风险绑定。
```

**要避免的两种错误理解**：

- ❌ "打一次就凭空掉钱"
- ❌ "战斗一定要亏生命，所以才配给钱"

**正确关系**：

```
风险 ↑ → 收益 ↑
```

而**不是**：

```
风险 ↑ → 固定收益
```

### 4.2 产出挂载层级 【冻结】

> **裁定**：**组合 —— `tier` + `layer`，必要时再允许 `enemy modifier`。**

```
基础值：common / elite / boss 决定
阶段修正：layer 决定
```

> **理由（审阅者原话）**：**暂时不建议直接按敌人 HP 算钱**，
> 因为会把**经济模型和战斗平衡过度耦合**。

### 4.3 是否按敌人 HP/伤害实时公式 【冻结为否】

> **裁定**：**先不要按 `enemy hp / damage` 实时公式推导。**
>
> 使用 **`tier` 固定区间 + `layer` 修正** —— **更稳定，也更容易测试**。

### 4.4 ⚠️ 数值暂缓期的落地方式 【冻结，且修正了原工单选项】

> **裁定**：**不要二选一**（既不阻塞 Batch 1，也不塞 TODO 数字）。

**冻结做法**：

```
semantic implementation = now     （语义实现：现在做）
numeric tuning          = later   （数值调整：以后做）
```

具体：

> **先定义数据接口与结算位置，数值使用 provisional 配置参数，明确禁止视为最终平衡。**

**要避免的两个极端**：

- ❌ "先做战斗内部建模，整个 Batch 1 阻塞"
- ❌ "随便塞一个 TODO 数字"

> **目的**：**Batch 1 可以推进，不会被完整战斗模拟拖死。**

## 5. Q4 `advance` 语义（冻结）

>
> **冻结结论（拆分为 advance / promotion）仍然有效**，但**理由改写**：
> 不是"advance 是坏数据"，而是 **"advance 承担实例培炼，play 需要跨蛊系的定向晋升"**。

> **裁定**：**直接冻结 A —— 同名培炼 / 精炼。**

**依据**：现有数据 377/377 同名、220 条 1→1、157 条 2→2，**与该语义高度吻合**。

### 5.2 ⚠️ "培炼"不能只是改文档名称 【冻结要求】

> **必须有真实、可测的实例成长。**

**可测维度裁定**：


> **理由**：**不会把现有数据整个推倒。**

## 6. Q5 `promotion` 语义（冻结）

### 6.1 基本规则 【冻结为 D：流派 + 蛊系混合】

> **不是纯流派，也不是完全自由配方。**

**理由**：《問眞》核心是**海量蛊虫 + 组合**，因此 `promotion` 应同时具备：

```
流派约束  +  蛊系/目标蛊的明确映射
```

**最终表现**：

```
Rank N 某类蛊  →  指定 Rank N+1 候选
```

**而不是**：

> ❌ 任意一只一转剑蛊都可以变成任意一只二转剑蛊。

### 6.2 可达性骨架粒度 【冻结，比原工单三选项更精确】

> **每个流派 × 每个转数跃迁至少存在可达路径。**

最低保证：

```
每个流派必须覆盖：
  1 → 2
  2 → 3
  3 → 4
  4 → 5
```

> **但不要求每个 role 都有完整链。** —— 这是"骨架"最合理的粒度。

### 6.3 成本结构 【冻结为组合】

> **裁定**：**蛊 + 材料 + 元石**。

**明确排除**：

> ❌ **寿元暂时不要强行塞进 `promotion` 基础成本。**
>
> **理由**：寿元在第 3 批要作为"生命周期风险资源"处理；
> **若现在就把寿元变成每次晋升税，会过早锁死寿元设计。**

**核心语义要求（重要）**：

> 晋升的核心成本应体现 **"你牺牲现有资产，才能获得更高阶资产"**，
> **而不是简单"花钱升级"。**

### 6.4 低转蛊成本优势 【冻结为"必须保持"】

> **裁定**：**必须保持。这是任务书硬红线，不能拿"平衡"作为理由删掉。**

**目标关系**：

```
低转蛊 + 材料 + 元石 → 高转蛊
        总成本  <  直接购买同等级高转蛊的成本
```

> 这样低转蛊才真正有 **"进入高转构筑的成本效率价值"**。

### 6.5 recipe kind 【冻结为 A：新增独立 `kind`】

> **不要复用 `fixed`。**

**理由（审阅者原话）**：现在最大的问题就是**数据语义混在一起**。

**目标结构**：

```
advance
promotion
fixed（若仍有独立语义）
...
```

**而不是**继续依赖 `fixed + output_rank` 来"**隐式表示晋升**"。

### 6.6 sword 1→5 零成本异常 【冻结为 B：必须加成本】

> ## ⚠️ **本节前提已于 2026-09-12 更正 —— 见 §13**
>
> 实测：**`ascend_sword_rec_1_10_gu` 实为 60 石 + 1 獠牙**，**不是零成本**。
> 「sword 零元石零材料」为**记录错误**（源自 F4 未提取 `stone_cost` 字段）。
>
> **真正的不对称在相反方向**：**非 sword 的 7 条 `fixed` 完全免费**（light 3 / earth 2 / blood 1）。
>
> **冻结结论（加成本、保对称）仍有效**，但**对象需要反转**。

> **裁定**：**必须加成本。不能保留成"剑道专属设计"。**

**理由（不是"剑道不能特殊"）**：

> 而是它**直接破坏了整个"低转 → 晋升 → 高转"经济模型**，
> 且与其他流派**完全不对称**。
>
> **可以保留"剑道更容易晋升"的特色，但不能 1→5 / 0 石 / 0 材料。**
> **这已经不是特色，而是绕过整个经济系统。**

## 7. Q6 三档蛊获取（冻结）

### 7.1 三分法总表 【冻结】

| 档位 | 职责 | 细节 |
|---|---|---|
| **普通战** | 低概率获得 **Rank 1 / 基础型蛊** | **不能让普通战变成抽卡机**；核心仍是"战斗收益 + 材料 + 小概率基础蛊" |
| **精英** | **定向候选 + 同时修正 70% 负期望** | 改为"高质量候选池 → 选择/定向获得"，而非"30% 抽到 3 只固定蛊" |
| **Boss** | **配方线索/关键材料为主，少量定向成品** | 见 §7.2 优先级 |

### 7.2 Boss 价值优先级 【冻结】

```
第一优先：配方线索
第二优先：关键晋升材料
第三优先：定向池 / 选一
第四优先：Boss 专属蛊
```

> **裁定**：Boss 的价值更多是 **"给玩家通往更高阶内容的钥匙"**，
> **而不是"随机爆出答案"**。

### 7.3 精英负期望 【冻结为"调整"】

> **裁定**：**调整。不应该保留当前结构。**

**理由**：现有 70% 分支必然带代价，且负面结果**还会提高后续商店价格**。

### 7.4 高转可达性承担者 【冻结为 B：混合】

```
promotion  → 承担主要高转可达性
Boss       → 提供少量关键钥匙/定向资源
```

> **要形成**：Boss 帮你突破 —— **而不是** Boss 替你玩晋升系统。

### 7.5 780 只非掉落蛊 【冻结为主渠道 `promotion`】

> **❌ 不建议通过"扩大商店槽位"解决。**

```
主渠道：promotion
次渠道：商店
少量特殊渠道：Boss / 精英
```

**理由（审阅者原话）**：

> 如果 780 只都变成"商店随机出现"，就会继续走回当前的
> **"海量内容存在，但玩家根本无法在一局中获得"**。
>
> 反而应该：**让 802 只蛊成为"可炼制的世界内容"，而不是"802 张商店卡"。**

## 8. Q7 legacy `soul` 定位（冻结）

### 8.1 本质定位 【冻结为 A】

> **裁定**：**行动意志 / 精神状态。**

**理由（审阅者明确列举）**：

- 它实际驱动的是 `action_points.per_turn`
- 且 `soul` 通过魂丹、黑市影响行动次数
- 同时又被 `soul_drain`、`free_mix` 使用
- → **从系统语义上，它已经明显不是普通货币**

### 8.2 消费 【冻结：少量重大行为】

> **裁定**：**需要消费，但不是"每回合不断扣"。维持低频、重大决策消耗。**

```
普通行动   → 不消耗
强力 / 超规格行动 → 消耗
```

> **目的**：体现 **"多做事的能力"**，**而不是第二个 HP**。

### 8.3 获取 【冻结：稀缺、低频】

> **裁定**：**保持稀缺，但允许极少量获取。**

**明确排除**：

> ❌ **不要把它设计成 60 → 100 → 200 这种成长属性**，
> 否则它会直接变成**第二条等级成长线**。

**目标形态**：

```
初始 1
常规流程基本维持
极少数特殊机会 +1
高价值行为可能 -1
```

> 这样才有决策。

### 8.4 汇率「1 石 ≈ 3.3 寿元」 【冻结为"设计线索，不是硬锚"】

> **裁定**：**现在视为"设计线索"，不是硬锚。**

**理由**：虽然 6 石 → 1 魂、20 寿元 → 1 魂、1 寿元 → Rank 1 蛊价值 3 石
确实形成接近倒数的关系，但**只能证明这些数据之间存在潜在的一致性**，
**还不足以证明设计者明确指定 `1 石 = 3.3 寿元`**。

> ⛔ **不要把这个数字写死进经济规格。**
