## 2. 六个高优先问题：逐项裁定

### 2.1 战斗是否应产元石？ → 🟢 **批准结构，暂缓数值**

- **Go**：战斗必须成为元石生产者。
- **暂缓**：`common 2–4 / elite 6–10 / boss 15–25` 这组数字**不批准**，
  因为 F8 自承未建模战斗内部（真元、气血、蛊使用）。
- **补充要求**：定义成**战斗结果的一部分**，而不是"偷偷再接一个 `stone_budget` 式外部补贴"。

### 2.2 `stone_budget` 层预算是否接线？ → ❌ **现在不做**

> 已决定让战斗成为元石生产者；再加入"进层自动 +N 石"会产生**第二个完全独立的货币 faucet**，
> 容易形成"战斗收益 + 层预算 + 打工 + 采集 + 卖材料"的多头叠加，
> 而我们**还没定义每种来源应承担什么经济职责**。

**处置**：暂时改为**规划/模拟参数**，不是运行时发钱机制；**未来可能彻底删除**。

### 2.3 普通战 / Boss 是否掉蛊？ → 🟡 **批准建立获取路径，不批准 5%/100%**

- **事实成立**：802 只蛊只有 22 只进掉落表，普通战与 Boss 均 0%，Boss pool 为空 → **蛊获取渠道严重不足**。
- **但**：`Boss 100% 随机掉蛊` **不是自然推导的答案**。
  项目另一根支柱是**海量蛊虫合成配方**；若 Boss 像开宝箱一样稳定喷高价值蛊，
  玩家会倾向"打 Boss → 直接拿成品"，而非"打 Boss → 获得资源/情报/材料/关键配方 → 自己炼"，
  **削弱世界模型**。

**要求的三分法**：

| 来源 | 职责 |
|---|---|
| **普通战** | 低概率基础蛊 / 低转蛊 |
| **精英** | 高质量**定向**蛊或特殊候选 |
| **Boss** | **强确定性的"高价值获取机会"** —— 固定池 / 定向池 / 选一 / 首领特产 / **配方线索** / 高转关键材料 |

> **Boss 的定位**：**高确定性、高价值、低随机陷阱** —— **而不是"100% 随机掉一只"**。

### 2.4 377 条 `advance` 是否应真正升转？ → ❌ **不能直接改**

> ## ⚠️ **本节依据事实已于 2026-09-12 实测更正 —— 见 `Q8G_BATCH0_RULING.md` §13.1**
>
> **实测（真实 `Resolver` 调用）：`advance` 确实会升转**——产出实例
> `rank = min(输入实例 rank + 1, 5)`（`refine_command_rules.gd:229-232`）。
>
> **377 条不是坏数据、不需清洗。** 本节"220 条 1→1、157 条 2→2"
> 对应的是 **`stone_cost` 分档（6 石 220 条 / 10 石 157 条）**，不是转数区间；
> 所谓"输入输出转数相同"是**用定义转数对比实例转数**造成的**比较对象错配**。
>
> **✅ 裁定结论（拆分 `advance` / `promotion`）完全不变，且因此更稳固**；
> ⚠️ 但**理由改写**：不是"advance 语义混乱所以拆分"，而是
> **"`advance` 已正确承担同名培炼；play 缺少的是跨蛊系定向晋升，故新增 `promotion`"**。

> ❌ **不能把 377 条直接改成升转。**

审阅者认定这更可能是**概念命名/数据模型错误**：

- 377/377 输入输出同名；
- 220 条 1→1、157 条 2→2；
- → `advance` **并不代表"升转"**，它实际是 **"同名蛊 + 材料 + 元石 → 同名蛊"**。

**正确的问题不是**"把 377 条全部修成升级配方吗？"
**而是**："`advance` 到底应该代表什么？" —— **必须先裁定世界语义**。

**审阅者倾向的拆法**：

```text
同名精炼 / 培养     ≠     跨转晋升
```

- **`advance`**：保留为"同名蛊培炼/提升/修炼"机制。
- **新增明确的 `promotion`**：专门表示 **Rank N → Rank N+1**。

> 目的：**数据语义不再混淆**。

### 2.5 `free_pair` 是否接线？ → ❌ **现在不做**

> 高转晋升链本身还没建立；此时接 `free_pair` 相当于给玩家一个
> **"绕过晋升系统，直接花钱买结果"的逃生门**。
> 且 `free_pair` 与 `advance_bonus_by_rank` 一样是孤儿定义（只被校验）。

**顺序**：**先建立正常晋升经济 → 再决定有没有必要提供付钱跳过机制**。
**未来定位**：**昂贵的捷径 / 特殊市场 / 后期保底** —— 不是基础成长路径。

### 2.6 是否补全转 3/4/5 晋升配方？ → ✅ **做，但不是"424 只全补一遍"**

**做**（"高阶内容可达"确实未成立），但**方向不是**"424 只蛊 × 每只一条配方"（会爆炸）。

**要求的结构**：

```text
流派 / 蛊系
    ↓
明确的升转规则
    ↓
精选关键晋升节点
    ↓
覆盖 Rank 1→2→3→4→5
```

> 即：**建立"可达性骨架"，而不是给每一只蛊机械补方。**

## 3. 对原"三批候选顺序"的否决

**原方案**（F8 §6）：

```
第一批：战斗石 + 掉蛊
第二批：商店价格 + 通胀
第三批：寿元/魂 + 清理材料
```

**❌ 审阅者不接受**，理由：

> **第二批实际上建立在"价值模型已经正确"的假设上。**
> 但 `gu_value` 只读 Rank 一轴，802 只蛊压成 3/5/8/12/20 五档，11 条轴只有 1 条被消费。
> 此时把商店直接改成 `gu_value × K` **不是"修复价格"，只是把一个错误的价值模型推广到全商店**。

**→ 改为四阶段（见 §4）。**

## 4. 批准的真正执行顺序（四阶段）

### 第 0 批：先修"经济语义"（**不做数值**）

> 这一批**甚至不应该叫 balance tuning**。

**必须先裁定这 8 件事**：

```
1. 元石有哪些生产者？
2. 元石有哪些主要消费者？
3. 战斗在经济里承担什么角色？
4. advance 到底是什么？
5. promotion 到底是什么？
6. 普通/精英/Boss 的蛊获取分别负责什么？
7. soul 到底是不是"经济资源"？
8. SoulRules 是未来系统还是废案？
```

> **这一批完成后，才能开始改数据。**
> **详细裁定工单见 `docs/q8g/Q8G_BATCH0_SEMANTICS_WORKSHEET.md`。**

### 第 1 批：闭合主循环

**做**：
- **A. 战斗产生元石**
- **B. 建立 Rank 1→2→3→4→5 的晋升骨架**
- **C. 给普通/精英/Boss 建立合理的蛊获取通路**

**不做**：
- `stone_budget`
- `free_pair`
- 全量商店改价
- `SoulRules` 接线

**收口**：重新跑 F8，**只问三个问题**：

> 1. **打架是不是已经成为合理路径？**
> 2. **玩家是不是能够通过玩法获得高转蛊？**
> 3. **高转内容是不是不再强迫玩家只靠商店？**

### 第 2 批：价值模型（**不是"调商店数字"**）

**① `gu_value`**

> 目前最大的问题不是"3/5/8/12/20 不好看"，
> 而是 **"蛊的价值"根本没有表达"这只蛊是什么"**。

**不批准**一次性上"11 轴定价系统"。**最少先确定**这 5 项哪些进入 v1：

```
rank
+ 获取稀缺性
+ 实战贡献
+ 成本
+ 可替代性
```

→ 修完 `gu_value` **之后**，它才能作为商店基准。

**② 商店**

> **暂不批准** `shop_price = gu_value × 3`。
> K 值可继续作为**候选实验参数**，但**不能提前视为正确答案**。
> 当前买价/价值比跨度 22 倍**证明商店有问题**，但**不证明 K = 3 是正确解决方案**。

### 第 3 批：资源压力

**寿元** → **应增加真实消费**。

> 但**不是为了机械满足**"每个资源都必须有支出去处"。
> 寿元在世界模型中应是**生命周期风险资源**，不是普通货币。

**要建立**：`强力行为 / 特殊炼蛊 / 高风险行动 ↔ 寿元机会成本`。

**魂** → **❌ 不要现在接 `SoulRules`。**

> 若现在直接接线，很可能不是"完善经济系统"，而是
> **"把一个尚未裁定的第二套世界模型突然塞进 Q8-F"** —— **典型的 scope creep**。

**暂定裁定**：`SoulRules` **No-Go，暂不接线，后续单独立项审计**。

**同时要严肃考虑**：

> legacy `soul` 到底应该叫"魂"，还是"**行动意志 / 念头 / 精神状态**"？
> 因为它本质上是 `action_points.per_turn`，**而不是经济货币**。

### 第 4 批：清理数据垃圾（**最后**）

- `moon_blue_petal`
- `inheritance_token`
- 同蛊多价格
- pity 死代码
- `advance_bonus_by_rank`
- `durability_mode`

> **例证**：`moon_blue_petal` 零配方，却贡献了 B 型 **69% 的收入** →
> 这会让经济模拟被**"垃圾出售"主导**。
>
> 但**不与主循环修复混在一起**。

## 6. 审阅者补充的关键维度：经济闭环 ≠ 所有资源都成货币循环

> ## ⚠️ **引用本节时注意：`Q8G_BATCH0_RULING.md` §6.6 的"sword 零成本"前提已于 2026-09-12 更正（见该文件 §13.3）**
>
> 实测：**剑道 6 条晋升链各有完整成本**（12/12/24/24/40/60 石 + 材料）。
> **真正零成本的是 5 条 light 系（月/光）`fixed` 配方**，其中 2 条 **0 成本直达三转**。
> 冻结结论"`fixed` 必须加成本"有效，但**对象从 sword 反转为 light**。

> 这是审阅者认为 **F8 遗漏的最重要一点**。

F8 把"元石 / 寿元 / 魂"统一放进"三种资源没有闭环"里。**作为诊断没问题，但作为最终设计原则不够精确。**

**正确的三分法**：

```text
经济资源      → 元石 / 材料
成长资源      → 蛊 / 配方 / 高转内容
生存/节奏资源  → 气血 / 真元 / 寿元 / 魂
```

> 它们**不一定都需要** `来源 ↔ 消费 ↔ 再生产` 完全对称。
>
> **真正必须闭环的是**：**玩家核心决策是否形成稳定的机会成本。**

**例**：寿元不是"必须花掉的钱"，而应该是：

> **"我要不要为了这个强力收益，缩短自己的修炼生命？"**

—— 这种才符合《蛊真人》的世界模型。

## 7. 下一阶段目标链条（Q8-G 的验收靶）

**目标（要建立）**：

```text
战斗
 ↓
获得真实收益
 ↓
有意义的资源取舍
 ↓
炼蛊 / 晋升
 ↓
获得更高阶内容
 ↓
继续承担更高风险
```

**当前实测（F8 已证明的坏结构）**：

```text
战斗
 ↓
掉一堆材料
 ↓
卖垃圾
 ↓
买商店里的蛊
 ↓
高转内容继续买不到
```
