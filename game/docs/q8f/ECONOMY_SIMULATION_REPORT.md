## 2. 五条核心发现

### 2.1 发现一：**"打得多"必导致破产** `[FACT]`

| 原型 | 战斗数 | 净变化 | 关系 |
|---|---|---|---|
| D 贫困 | 15 | **+43.6** | 不打 → 唯一盈利 |
| A 新手 | 20 | +5.7 | |
| E 高层 | 14 | −11.9 | |
| B 正常 | 35 | −7.4 | |
| C 富裕 | 50 | **−17.3** | 打最多 → 亏最多 |

> **`[FACT]` 唯一的盈利原型是 D（不逛店）**。
> 而**战斗越多，收支越失衡** —— 因为战斗**不产元石**（F1 §0.B / F6 §0.1），
> 只产材料；而材料的**变卖价值 < 商店购买成本**。

### 2.2 发现二：**材料只能卖出极低价** `[FACT]`

7 种材料的**卖出总收入**（全种子聚合，A 原型）：

| 材料 | 掉落总量（A） | `value` | 流动性 | 单价 | **卖出总额** |
|---|---|---|---|---|---|
| beast_bone | 112 | 1 | 0.7 | 0.5 | **0（不卖，留作炼蛊）** |
| beast_blood | 122 | 2 | 0.8 | 1.0 | **0（不卖）** |
| moon_blue_petal | 89 | 1 | 0.5 | 0.5 | 44 |
| venom_sac | 28 | 3 | 0.3 | 0.9 | 25 |
| moon_dew | 24 | 4 | 0.4 | 1.2 | **0（不卖，留着）** |

> **`[FACT]` 关键**：`public_resale = value × 0.5`（`low_liquidity` 更低）→
> **卖出价是 `value` 的一半**。而 `value` 本身极低（兽骨 = **1**）。
> → **卖全部月蓝花瓣只回 44 石**，相当于**每场战斗约 2.2 石**。

### 2.3 发现三：**寿元从 60 → 120，纯增长** `[FACT]`

所有原型（除 E 高层因起始层不同只到 80）**终局寿元 = 120**：

```
60（初始） + 10（stage_one_ledger） + 10×5（boss_defeated × 5 层） = 120
```

> **`[FACT]` 与 F7 预测完全一致**：寿元**净增长 60**，
> 而唯一的寿元支出（黑市 −20、洗恶名 −10、`lifespan_deal` −1）**全部可选**。
> → **寿元在模拟中从未接近危险**，**从未触发任何决策**。

### 2.4 发现四：**魂恒为 1，零变化** `[FACT]`

所有原型、所有种子：**`end_soul = 1.0`**（= 初始值）。

- 魂的收入源：`soul_pill`（6 石，需在货架）+ 黑市（每局一次）
- 魂的支出源：黑市、`soul_drain`、`free_mix` 爆炸
- `[INFERRED]` 模拟中未购买 `soul_pill`（理性代理优先买蛊）→ **魂完全不变**
- **`[FACT]` 行动点由魂驱动**（`action_points.per_turn`）→
  **玩家的每回合行动次数整局不变** → **魂系统对玩法零影响**

### 2.5 发现五：**真元恒为 20，零变化** `[FACT]`

- 所有原型 `end_essence = 20.0`（= 初始 `essence_capacity`）。
- 战斗中真元应被消耗（`essence_cost`）+ 自然回复（`natural_recovery`）→
  模拟中**未建模战斗内部**，但从数据看 `essence_cost` 只覆盖 16/802（F3 §A3）
  → **745 只批量蛊零真元成本** → 真元同样**不构成压力**。

## 6. 数值修改候选（**提案，不落地**）

> 任务书 §十三：F1–F7 只审计；F8 可提候选；**只有外部架构审阅者裁定后才可改**
> `balance.json` / `loot_tables.json` / `shops.json` / `refinement_recipes.json`。

按**依赖顺序**（后者依赖前者）排列：

### 候选 1（最高优先）：战斗元石奖励
**问题**：战斗 0 元石 → "打怪赚钱"不存在 → D 原型最优。
**候选**：`loot_tables.loot.{common,elite,boss}` 增加 `stone_drop`：
- common: 2–4 石
- elite: 6–10 石
- boss: 15–25 石

> **理由**：让"战斗"成为**正收益路径**。数值锚点：`stone_per_t1_material = 10`
> → 普通战 ≈ 0.3 份 T1 材料 = 3 石，与材料掉落的期望价值**对齐**。
> **风险**：会同时放大 C 富裕（打最多）→ 需与候选 3 配套。

### 候选 2：普通战掉蛊率 > 0
**问题**：802 只蛊只有 22 只进掉落表；普通战 0%、Boss 0%。
**候选**：`common.gu_chance_pct = 5`；`boss.gu_chance_pct = 100` 并补 `gu_pool`。
**风险**：蛊供给大增 → 需与 F3 的蛊价值修正配套。

### 候选 3：商店价格锚定 `gu_value`
**问题**：F5 §2.1 离散度 22 倍（`heaven_dew` 26.67 vs `stone_shell` 1.2）。
**候选**：`purchase` offer 价格改为 `gu_value × K`（K ≈ 2.0–3.0）+ 层通胀。
**理由**：`stone_shell`(1.2) / `moon_glow`(1.33) / `moonlight`(1.5) /
sword 系列(3.5–3.75) 已自然收敛在 **1.2–3.75** → **取 K = 3.0 最贴近已有手工值**。
**风险**：会**大幅降低** `heaven_dew`(80→9)、`jade_skin`(30→24)、
`white_boar`(35→30) → 需确认这是意图。

### 候选 4：层通胀改为"只影响高档"
**问题**：F5 §2.2 整体 +50% 使高层更穷，而收入恒定。
**候选**：`shop_price_pct` 只作用于 `tier >= 4` 的货。
**风险**：改变层间节奏，需 F8 复跑。

### 候选 5：寿元支出通道
**问题**：F7 / F8 §2.3 → 寿元净增长 60，无决策压力。
**候选**：① 让 `life_cost` 覆盖更多蛊（当前 1/802）；
② 让强效 fixed 配方消耗寿元；
③ 接线 `SoulRules` 五量（爆魂/兽性）使高魂有代价。
**风险**：涉及新数据键 → **必须同步 `content_catalog` 白名单**（AGENTS.md 红线）。

### 候选 6：清理无用途材料
**问题**：`moon_blue_petal`（零配方）占 common 池 1/3；
`inheritance_token`（60 石纯亏）在售。
**候选**：① 给 `moon_blue_petal` 接入一条配方；② 移除 `inheritance_token` offer
或实现"遗葬之地感应"。
**风险**：低（但移除 offer 需同步 `shops.json` 与相关测试）。

## 7. 模拟的局限（诚实声明）

1. **未建模战斗内部**：真元消耗 / 气血消耗 / 蛊使用**未推演** →
   §2.5 的"真元恒定"是**因为未建模**，不是"确实恒定"。
2. **未建模配方**：`advance` / `fixed` 的**实际炼蛊消耗**未推演 →
   兽骨囤积量**不会真的累积到 301**（会被消耗）。
3. **未建模精英成本**：`settle_victory` 的 elite 分支会加诅咒/恶名，
   但恶名对价格的影响（+10%/点）**未回灌到购买决策**。
4. **购买代理是理性的**：真实玩家会买"看起来酷"但低效的蛊 →
   C 富裕的实际支出会**更高**，赤字**更大**。
5. **未建模商店货架洗牌**：模拟允许购买任意 offer，
   真实游戏每店只有 4–6 件（F5 §2.3）→ **实际可得性更低**。

> **这些局限全部使模拟结果偏乐观**。真实情况**只会更糟**。
