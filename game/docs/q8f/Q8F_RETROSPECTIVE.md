## 3. 三条最根本的结构缺陷

### 3.1 缺陷一：元石循环缺失 `[FACT]`

```
              ┌──── 战斗（0 元石）────┐
              │                        │
   材料掉落 ──┤                        ├── 商店买入
   （唯一产出）└── 打工/采集（+2/+3）──┘
                        │
              ❌ 层预算 stone_budget 无注入
              ❌ 遗物 grant_stone_on_battle_end 无调用者
              ❌ stone_to_essence 无命令
```

**后果**：玩家收入 **69% 来自卖垃圾材料**（F8 §4）。
**唯一盈利策略是"不玩"**（F8 §2.1 D 原型）。

### 3.2 缺陷二：蛊的价值只有转数一轴 `[FACT]`

| 事实 | 值 |
|---|---|
| 被 `gu_value` 消费的价值轴 | **1 / 11**（仅 rank） |
| 802 只蛊压缩成的价格档 | **5 档**（3/5/8/12/20） |
| 有显式 `v1_effect` 的蛊 | 57 / 802（**7.1%**） |
| 有 `life_cost` 的蛊 | **1 / 802（0.1%）** |
| 有 `essence_cost` 的蛊 | 16 / 802（2.0%） |

**后果**：**"这只蛊是什么"与"它值多少"完全无关**（F3 §5）。

### 3.3 缺陷三：晋升链在第二跳断裂 `[FACT]`

> ## ⚠️ **本节图解已于 2026-09-12 更正（`advance` 行有误）—— 见 `Q8G_BATCH0_RULING.md` §13.1**
>
> 原文"同名蛊（**转数不变**）"**错误**：`advance` 产出的同名蛊**实例转数 +1**。
> 正确图解首行应为：
>
> ```
> 低转蛊（377 只）── advance ──> 同名蛊（实例转数 +1，封顶 5）   ← 377 条，吃大量兽骨
> ```
>
> **"第二跳断裂"的判定仍成立**，但断裂点不在 advance，而在
> **`fixed` 只覆盖 4/20 流派 + 无跨蛊系定向晋升**。

```
低转蛊（377 只）── advance ──> 同名蛊（实例转数 +1，封顶 5）   ← 377 条，吃 537 兽骨
                    │
低转蛊（含 16 流派）── fixed ──> 高转蛊            ← 仅 13 条，仅 4 流派
                    │
元石 ── free_pair ──> 高转蛊                        ← [GAP] 未接线
                    │
高转蛊（424 只）──── 无配方 ────────────────────────> 只能靠商店
```

**后果**：**16 个流派的低转蛊没有升转通道**；
**sword 独占 6 条**（可从转 1 直达转 5）（F4 §2.1）。

> **增收**：`fixed` 链中 **5 条 light 系配方 0 石 0 材料**（F4 未提取 `stone_cost`/`materials`）——
> **不只是"覆盖不足"，还有"覆盖到的地方不要钱"**（详见 §13.3）。

## 8. 阶段自我评价

### 8.1 做对的

- ✅ **没有调价**：严格遵守任务书 §0（"不得做成重新调一遍商店价格"）。
- ✅ **用真实代码模拟**：F8 调用 `LootResolver` / `GuBalance` / `RunState.new_run`，
  不是自造假规则 → 结论可复现、可被质疑。
- ✅ **证据分级**：`[FACT]` / `[INFERRED]` / `[GAP]` 逐条标注，
  推断与实测严格分离。
- ✅ **发现并纠正自己的预判**：F4 §5 推测兽骨是卡点 →
  F8 §3 实测**兽骨过剩** → 已在 F8 §8 明确回写推翻。

### 8.2 做得不够的

- ⚠️ **未建模战斗内部**：真元/气血/蛊使用未推演（F8 §7 已声明）。
- ⚠️ **未建模配方消耗**：兽骨囤积量在真实游戏中会被炼蛊吃掉。
- ⚠️ **未建模货架洗牌**：模拟允许买任意 offer，真实只有 4–6 件在架。
- ⚠️ **未建模恶名回灌**：精英的恶名 +2 未影响后续购买价。
- ⚠️ **`essence_capacity` / `stone_to_essence` 语义未深挖**：
  F1 §46 已标 `[GAP]`，但未深入分析其设计意图。

> 这些局限**全部使结论偏乐观**（真实经济只会更差）。

1. **优先提交本阶段 8 份文档**（不改任何生产数值，零风险）。
