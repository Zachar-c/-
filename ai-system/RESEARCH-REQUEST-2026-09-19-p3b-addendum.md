## 4. 阻塞项 ③：转数曲线会打断「世界模型引擎」——**这条阻塞整条 B1**

**发现**：除了 Godot 运行时，仓库里还有**第二个结算 effect 的引擎**：
`game/world-model/engine/rules.py`（被 `engine/run.py`、`tests/run_tests.py` 使用）。
它的 `resolve_effect(wm, effect, gu_rank, state)` 直接读 `effect.get("amount", 0)`，
**并且把传进来的 `gu_rank` 参数完全不用**（只用于签名，函数体内零引用）。

而 `effect` 的来源是**派生镜像** `world-model/data/gu.json`，由
`build_world_model.py:315` 这么写进去的：

```python
effect = dict(role_default.get(g["role"], {"kind": "none"}))   # 直接把兜底表整份拷进去
```

也就是说：**741 只走兜底的蛊，其镜像记录里内嵌的是兜底表的那个标量 `amount`**。

**后果**：一旦按你裁的 B3 把兜底表从标量改成 `amount_by_rank`（按转数索引的数组），
镜像里就会变成 `{"kind":"strike","amount_by_rank":[4,6,8,11,16]}`，
而 `resolve_effect` 读 `effect.get("amount", 0)` → **取不到 → 0**
→ 世界模型引擎里 741 只蛊的效果**静默归零**。这不是漂移，是断裂。

**同时暴露一个更早的问题**：这个引擎与 Godot 运行时**对同一份数据本来就有两套语义**——
Godot 的 `default_v1_effect` 做 `base + (rank-1)` 线性缩放，
而 `resolve_effect` 完全按转数取平值（`gu_rank` 收了不用）。即
**「一份 Effect 语义」在引擎侧本来就没成立**（RUL-2026-09-19-010 W3 的主题）。

**L2 已确认：本批不存在零漂移的拆法。** 新曲线的**一转基准值本身就变了**
（attack 2→4、defense 3→4、healing 2→3、logistics 1→2），
所以镜像里 741 条记录的数值**必然**要动，引擎的模拟输出**必然**要变。
按 V6，这里直接说明必须等裁决，不假装能拆出一个安全批。

**三条可选路径（请指定一条）：**

| | 做法 | 引擎行为 | 代价 |
|---|---|---|---|
| **P1** | 镜像写**该蛊自身转数已解析的标量** `amount`（= 曲线[该蛊 rank]）；`resolve_effect` 不动 | 从「平值」变成「按转数沿曲线」，与运行时一致 | 镜像 `effect` 形状不变；引擎数值变；`simulate_balance.py` 等产物要重跑核对 |
| **P2** | 镜像写 `amount_by_rank`；`resolve_effect` 用**它已经收到但没用的** `gu_rank` 去索引 | 同上 | 最忠实于数据、彻底消除两套语义；但 `resolve_effect` 要改，且是**引擎语义变更**，波及更广 |
| **P3** | 镜像只写**一转基准值**（曲线[0]），运行时用完整曲线 | 引擎继续按平值（与今天同类，只是基准值变了） | 零结构风险；但**镜像与运行时长期不一致**，等于把 W3 的「两套语义」固化下来 |

**L2 倾向 P1**（最小改动 + 消除断裂 + 不引入新形状），但**这是架构取舍，且会改变模拟产物，
不由 L2 或 Worker 自定**。

**请裁**：P1 / P2 / P3 选哪条；若选 P1 或 P2，是否要求本批同时跑一次
`simulate_balance.py` 之类产物并核对差异。
