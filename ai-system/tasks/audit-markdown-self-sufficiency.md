# 只读审计：Wiki Markdown 自足性

## 目标

回答以下四个问题，不修改任何文件：

1. 一个新人或新 Agent 只看 Markdown，能否理解当前 Wiki 的知识？
2. 不使用数据库、不运行脚本，能否完成阅读和导航？
3. 看到重要结论，能否区分原著明确内容、资料整理、分析与解读、待核对？
4. 删除 `lore/wiki/tools/check.ps1` 后，知识本身是否仍完整？

## 严格限制

- 只读；禁止 Edit、Write、Move、Delete、Format。
- 禁止提交、推送、切换分支或修改任何文件。
- 不读取或打印 Secret。
- 不把“验收脚本通过”当成知识完整性的证据。

## 检查范围

阅读：

- `AGENTS.md`
- `PROJECT_MAP.md`
- `lore/wiki/README.md`
- `lore/wiki/AGENTS.md`
- `lore/wiki/index.md` 及五个分类 `index.md`
- 所有 `lore/wiki/**/*.md` 页面
- `lore/wiki/tools/check.ps1` 只作为“可删除工具”观察，不依赖其运行结果

## 需要回答的维度

- 新人首次阅读路径是否明确，是否存在只能靠脚本/数据库才能解释的知识。
- 关键页面之间的 Markdown 链接是否足够，是否有孤立页面、死链、只有文件名没有入口的页面。
- 重要结论是否有稳定的区块边界：`原著明确内容`、`资料整理`、`分析与解读`、`待核对`；指出任何混淆例子。
- 来源字段和正文锚点是否让人能知道“证据在哪里”；区分逻辑 source 命名空间与实际 local-only 文件债务。
- 删除 `check.ps1` 后仍保留的知识能力，以及会损失的机械验收能力。
- 给出最多 5 个高价值改进建议，按阻塞性排序；不要为了形式完整建议建立数据库或新基础设施。

## 输出

按以下格式给出审计报告：

- 总体判定：PASS / PASS WITH FOLLOW-UP / BLOCKED
- 问题 1：结论、证据、例外
- 问题 2：结论、证据、例外
- 问题 3：结论、证据、例外
- 问题 4：结论、证据、例外
- 当前最大风险
- 最多 5 条改进建议
- 只读验证命令及结果（如执行）

必须明确区分“知识本身”和“自动化门禁”。不要修改文件。
