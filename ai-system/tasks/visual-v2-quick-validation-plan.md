## 一、当前更正

前一版试点把“视觉原则验证”错误地做成了逐只蛊虫正式资产生成。

L0 已更正：

- 当前阶段不是资产生产阶段，也不是单纯工程复用阶段；
- 本阶段唯一目标是验证调研后的新视觉方向是否成立；
- 不是让 L0 生成“原著图”，也不是现在生产正式立绘；
- 通过调研形成的视觉风格变更，不能被旧水墨 / 纸面 / 朱砂素材验证；
- 旧素材只能在结构验证中当占位，不得作为新风格的锚点或验收样本；
- 风格验证必须等 L1 视觉定位 / L0 选择后另走最小切片，不能混在本轮复用盘点里；
- 当前阶段不批量产出需要生图的美术资产；
- 优先使用现有资产、开源资源和工程内已有组件；
- 能用复用解决，就不自研代码；
- 先用低成本视觉迭代验证方向，再决定是否值得投入正式资产。

## 二、验证目标

本轮拆成两轨。

执行顺序：

```text
先冻结视觉母方向
→ 再做月光蛊 POC
→ 最后做结构验证适配
```

### A 轨：结构验证，可复用旧素材

优先级：非主线。只能做低成本验证，不得扩展 UI 开发。

只回答：

1. 现有界面与主题系统能否承载 `Canonical Form / Theme Skin` 的层级区别；
2. 组合成长、规则效果和代价是否能用现有信息组件表达清楚；
3. 哪些缺口是组件缺口，哪些只是旧视觉素材不匹配；
4. 哪些资产可直接作为占位，哪些必须在新风格中重做。

本轮回答：

> 系统结构能不能装得下新视觉。

不回答：

> 旧素材是否符合新视觉风格。

### B 轨：视觉验证，不得复用旧风格资产

只回答：

1. 调研后的新视觉方向是否能在单个最小切片中成立；
2. 新方向的材质、光感、角色化边界、规则表达是否能同时成立；
3. 哪些旧界面只是结构可保留，哪些视觉语言必须完全替换。

B 轨允许使用 GPT Image 制作少量概念验证图，但只限 `Visual Proof of Concept`，不得进入正式资产生产。

B 轨前置：

```text
已冻结的新视觉定位（L1 决策 / L0 选择）
→ L2 填写单个 POC Task Packet + Prompt Draft
→ L1 审查 Prompt
→ GPT Image 生成单样本
→ L0 / L1 判定
→ 样本通过后，才允许下一个单样本
```

B 轨禁止：

```text
拿旧 gu_*.png、旧 paper / ink / cinnabar token 当新风格样本
批量生成
建立资产库
修改游戏资源
```

B 轨强制规则：

```text
1. 所有 AI 生图 Prompt 必须经 L1 审查；
2. 生图工具只允许 GPT Image；
3. 必须引用同一份视觉规范，不能每张图一套风格；
4. 单个样本通过后才能扩展；
5. POC 图不是正式资产，不进入资产库；
6. POC 不得修改 game/ 下的脚本、场景、数据或资源。
```

本轮不回答：

- 哪只蛊最适合商业化；
- 最终主题皮肤数量；
- 最终角色化比例；
- 大批量资产预算。

## 三、复用优先顺序

### A 轨：结构验证

按以下顺序选择资源：

```text
1. 工程内已有资产与主题
2. 工程内已接入的开源图标、字体、组件
3. 可合法引入的开源资源
4. 现有工具即可完成的低成本改造
5. 单个占位资产（仅当 1–4 都不可行，且明确标记为非风格样本）
```

禁止：

- 为验证先自研视觉框架；
- 为验证先新增美术生产管线；
- 批量生成逐只蛊虫资产；
- 把单个正式图当成默认交付；
- 用“将来会需要”作为当前扩范围的理由。

### B 轨：视觉验证

不得用旧风格资产作为证据。

新风格验证必须：

```text
由 L1 视觉定位 / L0 选择提供方向
→ 只做一个最小切片
→ 与旧素材明确隔离
→ 不让旧水墨 / 纸面 / 朱砂体系污染判断
```

## 四、快速验证内容

### 验证 A：资产复用清单

只做只读盘点：

- 现有蛊图标、流派图标、UI 资产；
- 现有主题 tokens、材质、字体和组件；
- 已有开源资源与许可证；
- 哪些资产可直接复用，哪些只能作为占位。

产物：

```text
一份 Reuse Inventory 表
```

### 验证 B：单屏双层的结构表达

只选一个已验证存在的界面，不新做整套 UI。

验证内容：

- 同一蛊的 `Canonical Form` 与 `Theme Skin` 是否能在界面上被明确区分；
- 玩家是否能看懂主题皮肤不是世界事实；
- 现有信息组件能否表达能力语义、来源和层级。

若现有界面无法承载，先改文案、标签或已有组件组合，不先开发新系统。

本验证不判断：

- 旧素材是否好看；
- 旧素材是否符合新视觉；
- 旧配色是否应保留。

### 验证 C：组合与代价的可读性

用现有数据和已有组件验证：

- 蛊 → 炼蛊 → 杀招 → 阵 / 屋的关系是否能被看懂；
- 代价和限制是否能与视觉反馈同时出现；
- 是否必须做新特效，还是现有图标与状态标签已经足够。

### 验证 D：新视觉 POC（月光蛊）

状态：

```text
DRAFT / BLOCKED_ON_L0_VISUAL_BIBLE_DECISION
BLOCKED ON: L0 批准视觉圣经 v1.0 + 视觉规范冻结 + L1 Prompt 审查
```

只做：

- 一个对象：月光蛊；
- 先做 1 张本体层 POC；
- 本体层样本通过后，才允许做 1 张主题层 POC；
- 每次只判断一个明确命题。

不做：

- 逐只蛊虫；
- 整套 UI；
- 配色大全；
- 角色化比例。
- 正式资产生产；
- 资产库；
- 游戏资源替换。

任务单：


## 五、交付物

本轮只交付：

1. 现有资产复用清单；
2. 一个单样本 POC 任务单（执行前须有新视觉定位与 L1 审查）；
3. 缺口分类：`可直接复用 / 开源可补 / 需要新资产`；
4. 是否进入正式美术生产的结论。

不交付：

- POC 图本身若未通过，不得进入资产库；
- 批量主题皮肤；
- 逐只蛊虫立绘；
- 新视觉引擎；
- 新数值或玩法系统。

## 六、停止条件

出现以下情况时停止并上报：

- 需要新增一套视觉框架才能继续；
- 现有资源无法合法复用；
- 验证要求已经变成正式美术生产；
- 任务扩展到多屏、多蛊或全量资产；
- 必须修改数值、规则或世界模型才能完成验证。
