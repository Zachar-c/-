## 一、世界定位

> 《问真》是一个“规则生命收藏世界”：
> 本体层展示蛊作为承载天地规则的超凡生命；主题层允许玩家以高完成度人格化表达建立情感连接。

三层关系冻结为：

```text
                蛊道文明模拟世界
                  （长期扩展）
                         ↑

        超凡收藏世界 ← 玩家情感层
             ↑
             |
规则炼成世界 ← 世界真实性层
```

## 二、视觉核心原则

### 1. 本体层：规则炼成世界（Canonical）

目标：

让玩家第一眼理解：

> “这个东西为什么能产生这种力量？”

不是：

> “这个角色很帅”。

而是：

> “这个生命本身就是一条规则。”

表现重点：

- 身份识别；
- 能力来源；
- 材质与结构；
- 生命感；
- 代价感。

例如：

月光蛊：

错误：

> 月亮少女释放月刃。

正确：

> 一枚具有生命性的弯月玉晶，通过自身结构产生月道力量。

### 2. 主题层：超凡收藏世界（Skin）

目标：

解决长期玩家情感连接。

允许：

- 人格化；
- 半人化；
- 完整角色化；
- 概念化。

但必须满足：

```text
主题皮肤 ≠ 世界事实

主题皮肤 = 玩家收藏表达
```

例如：

月光蛊主题：

本体：

> 月光玉晶生命

主题：

> 月之灵体少女

玩家必须理解：

> 这是“月光蛊的幻想形态”，不是原著世界里的真实形态。

## 三、生产策略冻结

不再制作：

- A 档轻人格化；
- B 档半人格化；
- 大规模平均铺开主题。

原因：

资源应该集中到：

> 少量、高辨识度、高收藏价值、高完成度主题。

## VISUAL_BIBLE

## 1. 世界视觉核心原则

### 核心定义

《问真》的视觉必须持续表达：

> **这是一个由规则生命构成的超凡世界。力量不是外部装备，而是生命、规则与代价共同形成的结果。**

视觉判断标准不是：

> “是否华丽”。

而是：

> “玩家是否能理解这个对象为什么拥有这种力量”。

### 必须稳定

所有视觉资产必须共享以下底层规律：

#### 1. 能力来源可追溯

任何力量表现必须回答：

```text
这个效果来自什么？
↓
哪只蛊？
↓
什么组合？
↓
付出了什么代价？
```

禁止：

无来源的光效、爆炸、魔法纹路。

#### 2. 超凡但非神秘万能

《问真》的力量不是：

```text
召唤神迹
```

而是：

```text
理解规则
+
利用规则
+
承担规则代价
```

#### 3. 生命与规则统一

蛊不是：

- 道具；
- 装备；
- 技能图标。

蛊是：

```text
生命形态
+
规则载体
+
能力来源
```

### 允许变化

允许：

- 不同流派拥有不同表达；
- 不同转数拥有不同复杂度；
- 不同五域拥有不同社会视觉；
- 主题层拥有高度自由表达。

### 禁止回潮

禁止回到：

#### 普通仙侠模板

包括：

- 纯粹飞剑法宝视觉；
- 仙气飘渺万能光效；
- 金碧辉煌仙宫；
- 无代价的大招爆炸；
- 角色站桩释放技能。

原因：

这些表达强调：

> “人控制力量”。

而《问真》强调：

> “人理解并驾驭规则生命”。

#### 旧水墨方案

旧方案的问题不是水墨本身。

问题是：

它容易把《问真》降维成：

```text
东方仙侠插画
```

而不是：

```text
蛊道规则世界
```

因此旧方案不能作为默认视觉约束。

### HARD / SOFT / OPEN 映射

| 层级 | 作用 |
| --- | --- |
| HARD | 保护身份 |
| SOFT | 提供重新解释空间 |
| OPEN | 建立独特世界表达 |

规则：

```text
HARD决定“它是什么”
SOFT决定“它如何被表达”
OPEN决定“它如何区别于其他作品”
```

## 2. 本体层规范

### 定义

本体层：

> 蛊在《问真》世界中真实存在的形态。

承担：

- 世界真实性；
- 战斗识别；
- Lore 对齐；
- 规则理解。

### 识别规则

一个本体设计必须满足：

#### 第一眼识别

玩家应该能回答：

> “这是什么蛊？”

而不是：

> “这是什么漂亮东西？”

#### 第二层理解

玩家应该能理解：

- 流派倾向；
- 能力来源；
- 使用方式。

### 材质与结构规则

本体设计优先表现：

```text
结构 → 功能 → 美感
```

而不是：

```text
美感 → 加特效 → 编故事
```

例如：

防御类蛊：

应该体现：

- 防护结构；
- 稳定性；
- 承载能力。

而不是：

随机套一个护盾光圈。

### 生命感规则

蛊必须具有：

> “活着”的感觉。

但：

> 生命感 ≠ 必须像动物。

允许：

- 虫；
- 植物；
- 矿物生命；
- 器物生命；
- 概念生命。

### 代价感规则

本体视觉应暗示：

> 力量不是免费的。

可以表现：

- 消耗；
- 脆弱点；
- 限制；
- 不稳定性。

## 3. 主题层规范

### 定义

主题层：

> 玩家对蛊的收藏表达，不等于世界事实。

### 人格化边界

允许：

- 半人化；
- 完整角色化；
- 概念人格化。

但必须满足：

```text
玩家知道：
这是月光蛊主题皮肤

而不是：
月光蛊真实就是一个少女
```

### 来源识别规则

主题皮肤必须保留：

至少一个核心识别锚点：

例如：

- 形态；
- 能力象征；
- 材质；
- 色彩逻辑；
- 标志结构。

### 幻想表现标识

主题层需要明确：

它属于：

```text
收藏表达
```

而非：

```text
世界设定
```

### 禁止事项

#### 1. 人格化替代本体

错误：

月光蛊：

> 变成普通月神少女。

正确：

> 月光蛊的幻想人格化表达。

#### 2. 失去能力来源

错误：

火系蛊皮肤变成冰系少女。

#### 3. 模板化二次元角色

禁止：

所有蛊：

- 一个脸；
- 一个身体模板；
- 换颜色。

## 4. 材质语言

### 约束对象

材质负责表达：

> “这个东西为什么属于这个世界”。

### 必须稳定

材质需要具有：

#### 超凡可信度

玩家感觉：

> “它真的可以存在。”

#### 规则关联性

材质应该暗示：

能力来源。

例如：

- 月道 → 月光、晶体、冷感；
- 炼道 → 结构变化、融合感；
- 防御 → 稳定、承载感。

### 不约束

不规定：

- 单一材质；
- 单一颜色；
- 单一表现形式。

### HARD / SOFT / OPEN

HARD：

明确材质必须保留。

SOFT：

材质表现方式。

OPEN：

未知结构创新。

## 5. 光影语言

### 核心原则

光不是装饰。

光必须说明：

> 力量状态。

### 必须稳定

光影表达：

```text
来源
+
状态
+
强度
```

例如：

不是：

> “发光很帅”。

而是：

> “这个蛊正在释放某种能力”。

### 禁止

- 无意义全屏光爆；
- 颜色越亮代表越强；
- 神圣万能光。

### 转数表现

低阶：

强调：

- 材质；
- 局部力量。

高阶：

允许：

- 空间变化；
- 概念化；
- 大尺度规则表现。

## 6. 构图规则

### 核心原则

构图服务理解。

不是海报优先。

### 本体层

优先：

```text
对象识别
↓
结构观察
↓
细节欣赏
```

要求：

- 主体明确；
- 轮廓清晰；
- 不被背景抢夺。

### 主题层

允许更多：

- 情绪；
- 故事；
- 人格表达。

### 场景层

必须体现：

> 人与世界关系。

不是：

> 单纯漂亮背景。

## 7. Prompt 规范

### Prompt 结构统一

以后所有 GPT Image 任务采用：

```css
[世界定位]

+

[资产层级]

+

[对象身份]

+

[HARD约束]

+

[SOFT发挥]

+

[OPEN创新]

+

[材质]

+

[光影]

+

[构图]

+

[禁止事项]
```

### 禁止低质量 Prompt

禁止：

> “做一个帅气蛊虫”

这种无法验收的描述。

必须回答：

```text
它是谁？
为什么存在？
力量来源是什么？
不能变成什么？
```

## 8. 资产验收标准

任何资产进入候选库前必须通过：

### A. 身份验收

问题：

> 不看名字，是否能判断它是谁？

失败：

退回。

### B. 世界一致性验收

问题：

> 它是否属于《问真》的世界？

失败：

如果像：

- 普通仙侠；
- 普通二游；
- 普通魔幻。

退回。

### C. 规则一致性验收

问题：

> 外观是否支持能力理解？

失败：

视觉和机制割裂。

### D. 双层验收

本体：

必须：

```text
符合世界事实
```

主题：

必须：

```text
保留身份锚点
```

### E. 收藏价值验收

主题资产：

必须回答：

> 为什么玩家想拥有它？

## 一、裁定结论

当前计划方向正确，但阶段优先级必须调整：

> 当前视觉线唯一最高优先级是完成视觉定位决策。

当时最大风险不是工程结构无法承载双层体系，而是新视觉方向尚未冻结。
该风险现已由 L0《问真》视觉定位 v1.0 冻结件关闭。

因此：

- A 轨结构验证可以存在，但不得成为主线工作；
- 资产复用可以存在，但不得成为视觉方向未决时的替代性进度；
- 月光蛊 POC 定位正确，但必须排在视觉定位决策和视觉规范冻结之后。

## 二、强制执行顺序

```text
1. 完成《问真视觉定位决策稿 v1》Research Request
2. L1 输出视觉定位候选方案
3. L0 裁决视觉母方向
4. 冻结视觉规范
5. 启动月光蛊 Visual Proof of Concept
6. 最后进行结构验证适配
```

顺序不得倒置。

## 三、A 轨限制

A 轨只允许：

- 低成本结构验证；
- 复用现有组件与占位资源；
- 验证 UI、交互和信息架构是否能承载已冻结的视觉规则。

禁止：

- 因结构验证提前修改大量 `game/`；
- 用复用旧资产拖延新视觉验证；
- 把旧资源表现效果作为方向依据；
- 将 A 轨扩展成 UI 开发、组件重构或资产生产。

## 四、B 轨与月光蛊 POC 的前置

月光蛊任务必须保持：

```text
Visual Proof of Concept
NOT Canonical Asset Production
```

启动前必须满足：

```text
视觉定位决策完成
+ L0 冻结视觉母方向
+ 视觉规范冻结
+ L1 审查 Prompt
+ GPT Image only
+ 单样本通过后才允许下一样本
```

## 五、L2 阶段门禁

L2 收到视觉任务时，必须先执行阶段判断，而不是直接拆解执行：

```text
收到任务
→ 判断当前阶段
→ 确认上游决策是否冻结
→ 未冻结：BLOCKED / ESCALATE
→ 已冻结：再拆解、派 Worker、执行
```

若方向未冻结，L2 不得用以下工作制造“正在进行”的假象：

- 复用盘点；
- UI 组件整理；
- 旧资产清理；
- 非前置性的文档扩展；
- 单点美术试验。

这些工作只能作为明确的低优先级旁路，不能取代上游决策。

### A 轨：结构验证，可复用旧素材

优先级：非主线。只能做低成本验证，不得扩展 UI 开发。

只回答：

1. 现有界面与主题系统能否承载 `Canonical Form / Theme Skin` 的层级区别；
2. 组合成长、规则效果和代价是否能用现有信息组件表达清楚；

本轮回答：

> 系统结构能不能装得下新视觉。

不回答：

> 旧素材是否符合新视觉风格。

### B 轨：视觉验证，不得复用旧风格资产

只回答：

1. 调研后的新视觉方向是否能在单个最小切片中成立；

3. 哪些旧界面只是结构可保留，哪些视觉语言必须完全替换。

B 轨允许使用 GPT Image 制作少量概念验证图，但只限 `Visual Proof of Concept`，不得进入正式资产生产。

## 1. 项目视觉定位

### 核心目标

《问真》的视觉不是：

- 普通仙侠；
- 传统国风单一模板；
- 单纯角色收集；
- 无美学控制的黑暗猎奇。

核心方向：

> 基于《蛊真人》“万物有灵、力量有代价、生命皆可成为道路”的世界观，
> 将蛊的本质转化为具有收藏价值的幻想生命体。

视觉目标：

```diff
原著识别度
+
幻想生命感
+
角色吸引力
+
高级收藏感
```

## 2. 双层视觉原则

### 本体层 Canonical Form

目标：

> 表现这个世界真实存在的蛊。

要求：

- 保留原著核心形态；
- 保留功能识别；
- 保留材质逻辑；
- 保留世界真实性。

禁止：

- 默认人格化；
- 默认角色化；
- 为了美观修改身份。

### 主题层 Theme Skin

目标：

> 玩家收藏和表达自己的幻想版本。

允许：

- 完整人格化；
- 角色化；
- 戏剧化；
- 概念化。

必须满足：

```text
看见皮肤
↓
仍然能联想到原蛊
```

## 3. 高完成度主题皮肤核心规则

高完成度主题皮肤不是：

> 普通角色换皮。

而是：

> 将蛊本身的生命属性、能力属性、象征属性人格化。

### 角色设计必须回答：为什么这个角色是这只蛊？

示例：

月光蛊不能只是“白发月系少女”，必须体现：

- 月光；
- 玉质；
- 清冷；
- 灵性；
- 月牙核心结构。

酒虫不能只是“酒系少女”，必须体现：

- 贪食；
- 灵酒；
- 醇香；
- 小巧灵动。

血道蛊不能只是“红衣少女”，必须体现：

- 血液；
- 生命交换；
- 危险诱惑；
- 代价。

## 4. 统一视觉语言

### 材质

优先：

- 玉；
- 晶体；
- 虫甲；
- 半透明组织；
- 灵光；
- 特殊纹理。

避免：

- 普通布料堆砌；
- 无身份依据的古代服饰；
- 无意义珠宝。

### 光感

统一：

- 高级幻想光；
- 有生命感的发光核心；
- 局部高光；
- 空气感。

避免：

- 普通仙侠滤镜；
- 满屏特效；
- 廉价发光。

### 角色气质

整体偏向：

```diff
神秘
+
美丽
+
非人
+
危险
```

而不是：

```diff
普通角色
+
换装
+
通用古装
```

### 普通仙侠模板

- 无身份依据的白衣；
- 云雾山水；
- 琉璃宫殿；
- 飘带飞舞；

禁止：

- 只有角色吸引力，没有力量来源。

### 黑暗猎奇模板

禁止：

- 纯血腥；
- 纯怪物；
- 无美学控制。

## L0 已生效的视觉宪法

以下七条是 L0 对 v3 结果的采用结论，作为视觉定位候选的共同上游约束。

1. **蛊不是“特殊虫子”，而是规则能力的身份载体。**
   设计问题不是“它像不像虫”，而是“玩家能否看一眼就理解它承载什么规则”。

2. **拟人、角色化只能进入表现层，不能改写已明确的本体。**
   可使用化形、投影、催动形态、使用状态等；不得把原文明确写出的本体替换成人形。69 只本体样本中，人形拟人型为 0，但 35% 的本体没有直接描写，且 OPEN 区仍存在。

3. **效果必须属于规则变化的结果，而不是无来源的通用技能爆点。**
   力量视觉主体是具体形态或半实体；八至九转开始明显松动，允许纯光、无形和概念化表现。关键不是禁止效果，而是效果必须能追溯到蛊、杀招、阵、屋或其代价。

4. **组合成长是《问真》的高价值核心。**
   原文关系链是：

   ```text
   蛊 → 炼蛊 → 杀招 → 蛊阵 / 蛊屋 → 战斗结果
   ```

   其中蛊屋被原文定义为“数种、十数种蛊虫相互集合的固化定型的杀招”。该链条天然支持单卡、卡组、构筑、组合技和永久成长，不是普通技能树。

5. **五域差异先从社会运行方式推导，不从地貌标签反推。**
   当前已确认的差异包括：中洲门派与师徒体系；南疆家族、山寨、商贸中心与品级腰带；北原部族、王庭、黄金血脉与皮袍制度。建筑、服饰、NPC 与界面应从制度、权力、交易和生活方式推导，不能先贴地域颜色。

6. **HARD 保留，SOFT 重演，OPEN 原创。**
   282 条记录的约束分布为：

   | 等级 | 数量 | 比例 | 使用含义 |
   | --- | ---: | ---: | --- |
   | HARD | 96 | 34% | 不得随意改动身份级形态、配方关系和明确规则 |
   | SOFT | 117 | 41% | 可保留功能与识别点，重新设计表达 |
   | OPEN | 69 | 24% | 原著没有视觉约束，可进行原创建设 |

7. **蛊虫视觉采用本体层与主题层双层表现体系。**
   - 本体层 = 蛊在游戏世界中真实存在的形态，承担世界观、战斗识别、Lore 对齐与规则理解；
   - 主题层 = 玩家可解锁、收藏、切换的视觉表达，包括人格化、半人化、角色化与概念化；
   - 本体层不得替换蛊名、能力、流派、功能来源或已明确且承担身份识别的形态；
   - 主题层不得修改本体身份、能力规则或世界设定，也不得让玩家误以为主题外观是世界事实；
   - 主题层的人格化不能破坏能力语义，也不能退化为统一模板；
   - v2.0 取消 A/B/C 人格化生产档，统一为少量高完成度主题皮肤；
   - 主题皮肤按高辨识度、高使用率、高收藏价值、高情感潜力筛选，不对全部蛊平均制作；
   - 详细原则见 `docs/superpowers/specs/2026-09-20-wenzhen-gu-dual-layer-visual-design.md`。

## 必须先分开的两类 HARD

v3 的 HARD / SOFT / OPEN 回答的是“原著对外观有多少约束”，不是“游戏规则可以随意改”。

因此本件采用两层约束：

| 层 | 例子 | 是否可由视觉设计改动 |
| --- | --- | --- |
| **世界规则 HARD** | 炼蛊配方关系、蛊屋结构、五域组织制度、代价机制 | 否；属于系统与叙事契约 |
| **视觉 HARD** | 已明确且承担身份识别的形状、材质、颜色、标志件 | 否；改动会改变对象身份 |

需要注意：v3-D1 的五域组织在**视觉约束**上为 `HARD 0 / SOFT 8 / OPEN 17`。这不是说组织制度可以改，而是说原著对组织“具体看起来怎样”大量留白。候选方向必须同时做到：

- 不改世界规则 HARD；
- 不碰视觉 HARD；
- 优先在 SOFT 重演、在 OPEN 原创。
