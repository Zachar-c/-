## 2. 本轮最重要的发现：它证明的不是「Web 更快」，而是「Godot 有没接线的数据」

Web 原型这一轮的产出，实质上是一份 **Godot 侧「数据写了但规则没接线」的缺陷清单**。
以下三条是 L2 **逐条复算过**的（不是照抄交接文档）：

**① `counter_status="sparked"` 无任何规则实现**
- 数据：`data/enemies.json` 里雷冠头狼（thunder_crown)有反击「雷甲反噬」声明 `counter_status: "sparked"`。
- 实测分布（L2 复算，全 32 敌）：`guarded` **24** / `bound` **11** / `sparked` **1**。
  （交接文档写 guarded 16，是错的；以 24 为准。）
- `sparked` 在 `game/scripts/` 与 `game/docs/` 下 **零命中**。
- 运行时读取点 `scripts/domain/action_preview_service.gd:330-348` 的 `_live_counter_labels`
  只枚举 `bound` / `guarded` 两种状态。
- **后果**：这条反击在 Godot 侧**永远算生效**，且**没有任何机制能解除它** —— 玩家永远被它吞掉攻击。

**② 多阶段 AI：数据与 schema 校验都写完了，运行时不存在**
- 32 个敌人里 **5 个**带 `phases`：`miasma_vein_lord`、`thunder_crown_sovereign`、
  `blood_vein_bishop`、`clan_patriarch`、`blue_fur_jiangshi`。
- `scripts/domain/enemy_catalog.gd` 为它写了**严格校验**：`until_hp_ratio` 必须落在 `(0,1]`、
  必须严格递减、`intents` 非空、`cooldown` 合法。
- 但 `until_hp_ratio` 在 `game/scripts/` 下**只出现在该校验文件里** ——
  **没有任何运行时按血量比切换阶段**。
- **后果**：这 5 个 Boss 在 Godot 侧打起来与单意图杂兵**完全一样**。
- **结论（我认为这是最重要的单点）**：「AI 看起来很呆」的根因**不是缺 AI 逻辑调研，
  而是这套逻辑一直没接线**。数据、校验、意图表、冷却语义（`miasma_vein_lord._phases_note`）
  早就设计完了。

**③ 焚元意图 `essence_burn` 被静默丢弃**
- `essence_burn` 在 `game/scripts/` 下 **零命中**。
- `battle_command_facade.gd:171-179` 复制意图字段时带了
  `label`/`speed`/`seal_turns`/`soul_drain`/`life_cost`/`counter_tag`，**没有 `essence_burn`**。

**这三点合起来说明**：本仓目前最大的质量缺口不在引擎能力，而在**数据 ↔ 规则的接线**。
而 Web 原型（1,041 行、0 测试、直接读同一批数据表）**只花一轮就把它挖出来了** ——
这恰好印证了它作为「功能验收台」的定位价值，而不是作为「更快引擎」的价值。

## 3. 请你判三件事

### Q1. 「弃 Godot 全转 Web」的**判定标准**该怎么设？

要让这个结论**可裁决**，决定性实验必须是什么？
具体地：Web 原型必须在**同等复杂度**下复现哪些东西才算通过？
哪些 Godot 侧的复杂度属于「**必须复现，否则结论无效**」，哪些可以明确豁免？

> L2 的观察，供你参考而非采信：
> 真正的成本源可能**不是引擎**，而是**接线与门禁** ——
> Godot 侧那 232 个测试脚本、13 份契约、确定性种子 / 事件日志 / 存档迁移，
> Web 原型里**一行都没有**（10 文件 1,041 行，0 测试 0 契约）。
> 如果「效率」的代价是**永久放弃这些保障**，那问题就不是「Web 能不能做」，
> 而是「**这个项目要不要这些保障**」。这个取舍只有你和 L0 能定。

### Q2. 「Web 做原型/验收台 + Godot 做正式交付」的**双线分工是否稳定**？

还是必然漂移？本轮证据倾向后者：
Web 原型是**手抄** Godot 的判定逻辑到 `js/rules.js`（照抄 `_live_counter_labels` 的
`trigger=direct_strike` / `window=before_damage` / `bound`·`guarded` 抑制规则），
**不是共享**。这意味着**同一条规则改一次要改两处**，而两处没有任何机制保证一致。

若走长期分工，请给出防漂移口径。例如（仅举例，不预设结论）：
Web 只允许「读数据 + 呈现 + 派发」，**所有判定必须从单一来源导出**，
不允许在 `js/` 里出现第二份规则实现。

### Q3. Web 线与 **P3（Effect 管线）** 的耦合怎么处理？

P3 一旦按你的预算公式重标定蛊效果，Web 战斗面板的数值会**同时**变
（它直接读 `data/*.json`）。若 Web 要当验收台，P3 的裁定是否应做成
「**一份口径、两处消费**」（Godot 与 Web 都从同一份生成物取数）？
还是接受两边各自实现、各自对齐？
