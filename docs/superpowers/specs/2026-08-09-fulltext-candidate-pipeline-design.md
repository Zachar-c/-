# 全书候选扫描 + 会话驱动分层自动化管线（设计）

> 日期：2026-08-09
> 状态：待用户审阅
> 关联：AGENTS.md §2/§8/§11/§12、README 提效工具节

## 1. 背景与目标

现状痛点：每批 30 节由 LLM 会话全读原文/细纲/台账/上批正文后逐节编辑，90 节约耗 6000 万 token（约 67 万 token/章，而一章正文仅 4-7 千 token），全书 1400 余万字符需两周一上。九成 token 花在上下文重读，而非决策。

目标：建立「代码全书扫描 → 候选清单 → LLM 会话逐条决策 → 直接编辑正文 → 全量人工待检」的分层流水线，把每章 LLM 接触量降到只读候选与局部上下文，目标全书机械与语义层在试点验证通过后数日内跑完；文学层仍保留批式审阅。

质量承诺：自动化的前提是不破坏 AGENTS.md §4/§5 的内容边界与判据。任何规则只产生候选，不产生删除；B/C 级删除权留给会话与人工。质量究竟下降多少，以试点 vol3-151-180 的全量待检统计为准，而不是靠猜测。

## 2. 术语

- 基线文件：`volumes/<卷>/<卷>-sec<范围>.edited.txt`，未精编时与源文同内容（候选扫描器以源文行号挂载，双标识）。
- 候选：扫描器产出的一个"此处值得处理"的记录。类型分 A/B/C 三级（见 §4.2）。
- 待检审计表：验收期把候选+编辑结果交给用户逐条 tick 的表格。
- 主操作词：扫描器只读、不写正文；唯一写正文的自动化是 A 级词表自动应用器（见 §6）。

## 3. 架构总览

```
               ┌───────────────────────────────────────┐
净版源文        │ scripts/scan_candidates.py            │
蛊真人-clean.txt│  规则引擎(正则+词表+启发式，无模型)    │
基线与已精编    │  输入: 卷/批次/源文/台账词表/细纲      │
正文            │  输出: candidates TSV + MD(带局部上下文)│
台账词表        └──────────────────┬────────────────────┘
                                 │ (只读，不改正文)
                                 ▼
            working/candidates-<卷>-<范围>.tsv/.md
                                 │
                ┌────────────────┴───────────────────┐
                ▼                                      ▼
    A级自动应用器(幂等，写正文+留痕)          LLM 会话(人工驱动)
    scan_candidates.py -Apply 模式      ★只读候选+命中段落+节细纲
                                      ★逐条决策：改/删/留
                                      ★直接编辑 .edited.txt（现有流程）
                                 ！ 共用同一份候选，顺序：先 A 级应用，
                                 ！   再 B/C 级会话按新行号继续处理
                                 ▼
          回归：validate_editorial_assets.py + git diff --check
          批报：gen_report.py（注入候选统计与 verdict 汇总）
                                 ▼
           审计表 audit_candidates.py → 全量人工待检 tick → 误差统计
                            → 决定铺开/降级/回退
```

## 4. 组件一：scripts/scan_candidates.py（新）

### 4.1 输入输出
- 输入参数：`-Volume <卷id> -Batch <范围>`（与 editorial-volumes.json 一致）、`-Source <净版或源文>`、`-LedgerDir notes/`（自动挂载本卷台账）、可选 `-OutDir`。
- 输出：
  - `working/candidates-<卷>-<范围>.tsv`：候选记录（编码 UTF-8、**不**带 BOM，见 GA 约定）。
  - `working/candidates-<卷>-<范围>.md`：会话友好版，候选按节分组，每条带局部上下文（命中段前后 2 句）与节内细读要点链接。
- 幂等：同一输入多次运行结果逐字节一致（输出到 `-OutDir` 覆盖即可；结果以当前源文/台账为锚，不依赖运行顺序）。

### 4.2 分层与严重度

| 层 | 规则 | 处理方式 |
|---|---|---|
| A（机械·已验证） | 已裁决词表（淬不及防→猝不及防、青矛山→青茅山、黒豕→黑豕、爱生离→爱别离等）、错字累计表、乱码字符、遮蔽 `[***]`/`**`、网页残留（站点标/未完待续/`</dd>`）、拼音/英文残留、重复标点 | 自动应用（见 §6）；清单中标记为 `已自动` |
| B（语义·候选） | 相邻重复句/段（80% 相似）、人名/地名一致性（基于已批建立的实体表，只列差异不判对错）、数字/修为/元石矛盾（基于台账关键词索引） | 只出候选，LLM 核后改/留 |
| C（文学·提示） | 作者越位句式（第一人称"我/作者/本书"直论）、网络腔词表、疑似无功能环境复写（启发式：段落内高比例景语/形容词且无事件推进） | 只提示，改删由 LLM 逐条判断，禁止规则直接删 |

### 4.3 候选字段

`seq | type | severity | section | line_source | line_edit | sample | rule | verdict`

- `line_source`：源文行号（蛊真人-clean.txt 行号，零漂移锚点）。
- `line_edit`：编辑文件行号（若源=基线则与 line_source 相同；应用器执行后 B/C 需要据此定位，会话编辑后由 LLM 复核并重校验）。
- `verdict`：初始为空，会话逐一填入 `改/删/留/跳过` + 理由简码。TSV 循环读写，重跑不丢 verdict（若行号变化则用 `seq` 关联，逐行更新）。

## 5. 组件二：候选清单集成到现有工具

- `gen_brief.py` 增加 `-Candidates` 开关：简报新增“本批候选”一节（类型分布 + 总数 + 第一条条预览）。未给开关时保持现状。
- `gen_report.py` 增加候选摘要节：自动统计本批候选总数、verdict 分布（N 改/N 删/N 留/N 跳过）、A 类留痕数；并输出`待检清单`入口路径。
- 两处均不改写现有输出章节，只追加章节与开关。

## 6. 组件三：A 级自动应用器（脚本内 `-Apply` 模式）

- 只处理 `severity=A` 且规则为「词表替换」的候选；其余 A 类（乱码/遮蔽/残留）仍留会话处理（需判断），不进自动。
- 应用方式：**对 .edited.txt 做精确字符串替换**（词表条目 `old→new`），不按行号改行。
- 留痕：每次替换写 `working/apply-a-<卷>-<范围>.log`：`seq | 源行 | old | new | 位置(节/段落行) `，同时在候选 TSV 的 verdict 列记 `已自动应用`。
- 幂等：对已应用的词表项不动手重改；重复运行不重复计数。
- 安全网：替换前跑一次全文件扫描，若 `old` 出现在**引号内或语境异变**（通过后缀黑名单如"书名、专名"），不自动改、降级为 B 级候选，交由人工。

## 7. 会话工作流（改造 AGENTS.md §8 步骤 4 之后插入 4.5）

1. 按现有协议恢复上下文（gen_brief -Candidates）。
2. 若候选含 A 级词表：先运行 `-Apply` 自动应用并核对留痕。
3. B/C 级逐条处理：LLM 只读该条上下文（候选文件已带局部上下文与细纲节要）→ 直接编辑正文。
4. 每个章节处理完毕即 update TSV verdict（`改/删/留/跳过`）。
5. 整批完成后例行回归（validate、标题数、sc原文对照）、台账落账（批内状态只记本次落账），按现有批次提交口径 commit。

所有候选不要求"节与节之间上下文全量重读"，但 **B 级人名/矛盾候选必须参照实体台账相关行**，不能凭空判。

## 8. 验收与铺开决策（audit_candidates.py，新）

- 脚本把本批候选+verdict 转成审计表：`seq | type | 原片段摘要 | 改后摘要 | verdict | 人工结论(对/错/存疑) `，输出 `working/audit-<卷>-<范围>.tsv`，支持用户直接编辑填写。
- 统计：误改数（人工判"错"）、漏改数（候选漏上网）、漏检数（审计时人工发现的未入候选问题）、按层分布；汇总为《质量下降报告》。
- 铺开决策规则（建议）：
  - A 层误伤 0 → 全卷自动应用 A 级词表。
  - B 层漏检+改错合计 ≤ 人工可接受阈值（目测建议 ≤10%）→ 全卷 B 层会话铺开，batch 容量可扩大（如 60 节）。
  - C 层误删哲思/伏笔=0 且改错 ≤ 15% → 全卷 C 层铺开；否则 C 层保持"仅标记、人工决定"。
- 任一不达标：试点批次回退或降级到上层（如只自动 A 级 + 传统人工批）。

## 9. 试点：vol3-151-180（30 节）

前置事实（已验证）：该批 .edited.txt 为基线未精编文本（2828 行），细纲在 `outlines/detail/vol3-sec151-180.md`。

执行顺序：
1. 生成候选清单（A/B/C 全开）→ 产出统计（类型分布、总条数）写入简报。
2. 跑 `-Apply` 应用 A 级词表，校验留痕与幂等。
3. B/C 层会话逐条处理并直接编辑正文。
4. validate + 标题核对 + git diff --check。
5. gen_report 交付（含候选统计）；用户全量待检 audit 表。
6. 按统计结果执行铺开/降级/回退决策；试点结果结论记入 vol3 决策注册表。

## 10. 风险与边界（不做的事）

- 扫描器不主动删除任何内容；C 层只提示不判定。
- 不改变 AGENTS.md §4 的任何内容边界；B 层对人物/伏笔的修改仅允许「修复矛盾」方向，禁止改变信息释放顺序。
- 全量自动应用只限词表项；乱码/遮蔽/残留类保持人工。
- 对比现有流程，试点期间不要求缩短"批审"闸门：多快取决于统计结论与用户决策。
- 不引入第三方大模型服务；管线只支持"会话人工驱动"路径（用户已确认）。
- 管线脚本不写云台账；台账落账仍走现有规程（编辑会话提建议→总编会话落账）。
