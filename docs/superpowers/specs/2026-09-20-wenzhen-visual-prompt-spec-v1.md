> 允许的是单个 `Visual Proof of Concept`：一次一个对象、一次一个样本、通过后才允许下一步。
> POC 不是正式资产，不得修改 `game/` 资源。

> 术语归一：`C 档` 不重新成为独立生产等级。旧任务包中的“C 档”一律映射为
> `Theme Skin Asset`，并遵守 L0《蛊虫双层表现体系 v2.0》。

## 1. 项目视觉定位

### 核心目标

《问真》的视觉不是：

- 普通仙侠；
- 传统国风单一模板；
- 单纯角色收集；
- 无美学控制的黑暗猎奇。

核心方向：

> 基于《蛊真人》“万物有灵、力量有代价、生命皆可成为道路”的世界观，
> 将蛊的本质转化为具有收藏价值的幻想生命体。

视觉目标：

```diff
原著识别度
+
幻想生命感
+
角色吸引力
+
高级收藏感
```

## 2. 双层视觉原则

### 本体层 Canonical Form

目标：

> 表现这个世界真实存在的蛊。

要求：

- 保留原著核心形态；
- 保留功能识别；
- 保留材质逻辑；
- 保留世界真实性。

禁止：

- 默认人格化；
- 默认角色化；
- 为了美观修改身份。

### 主题层 Theme Skin

目标：

> 玩家收藏和表达自己的幻想版本。

允许：

- 完整人格化；
- 角色化；
- 戏剧化；
- 概念化。

必须满足：

```text
看见皮肤
↓
仍然能联想到原蛊
```

## 3. 高完成度主题皮肤核心规则

高完成度主题皮肤不是：

> 普通角色换皮。

而是：

> 将蛊本身的生命属性、能力属性、象征属性人格化。

### 角色设计必须回答：为什么这个角色是这只蛊？

示例：

月光蛊不能只是“白发月系少女”，必须体现：

- 月光；
- 玉质；
- 清冷；
- 灵性；
- 月牙核心结构。

酒虫不能只是“酒系少女”，必须体现：

- 贪食；
- 灵酒；
- 醇香；
- 小巧灵动。

血道蛊不能只是“红衣少女”，必须体现：

- 血液；
- 生命交换；
- 危险诱惑；
- 代价。

## 4. 统一视觉语言

### 材质

优先：

- 玉；
- 晶体；
- 虫甲；
- 半透明组织；
- 灵光；
- 特殊纹理。

避免：

- 普通布料堆砌；
- 无身份依据的古代服饰；
- 无意义珠宝。

### 光感

统一：

- 高级幻想光；
- 有生命感的发光核心；
- 局部高光；
- 空气感。

避免：

- 普通仙侠滤镜；
- 满屏特效；
- 廉价发光。

### 角色气质

整体偏向：

```diff
神秘
+
美丽
+
非人
+
危险
```

而不是：

```diff
普通角色
+
换装
+
通用古装
```

## 5. 禁止模板

### 普通仙侠模板

例如：

- 无身份依据的白衣；
- 云雾山水；
- 琉璃宫殿；
- 飘带飞舞；
- 金碧辉煌。

原因：

无法体现《蛊真人》的独特性。

### 普通二游模板

禁止：

- 单纯卖脸；
- 与蛊无关的人设；
- 只有角色吸引力，没有力量来源。

### 黑暗猎奇模板

禁止：

- 纯血腥；
- 纯怪物；
- 无美学控制。

## 6. Prompt 固定结构

所有正式 Prompt 必须包含：

```css

[对象]

[原蛊核心]

[人格化方向]

[角色设计]

[材质]

[光影]

[构图]

[质量要求]

[负面约束]
```

## 7. 生图约束

### 7.1 Visual Proof of Concept

允许使用 GPT Image 制作少量概念验证图，但必须满足：

```text
1. 已冻结的新视觉定位已写入 Prompt；
2. L1 已审查并确认最终 Prompt；
3. Provider = GPT Image only；
4. 每次只生成 1 个样本；
5. 样本通过后才允许下一个样本；
6. POC 图不进入资产库；
7. POC 任务不修改 game/ 下任何资源或代码。
```

### 7.2 正式资产

正式资产：

```text
Image Provider:
GPT Image only
```

禁止：

- 第三方模型作为正式候选；
- 混合模型比较后直接采用；
- 非 GPT Image 图进入最终资产池。

其他模型仅可用于参考、对比、思路探索和非正式研究。

## 8. L2 职责

### 1. 任务收束

把 L0 的审美偏好整理成：

- 生图目标；
- 任务边界；
- 本体 / 主题层定位；
- HARD / SOFT / OPEN 约束；
- 当前批次要解决的问题。

### 2. 提示词起草

L2 必须先产出 `Prompt Draft`，再提交给 L1。

### 3. 风格统一管理

维护统一视觉规范，确保资产不是一只蛊一个项目。

### 4. 质量预审

只有经过一次筛选的任务包才提交给 L1。

## 9. 协作流程

```text
L0
↓
确定方向与产品价值

L1
↓
审查视觉逻辑 + 修改 Prompt + GPT Image 生成

L2
↓
拆解任务 + 管理规范 + 保证一致性

Worker
↓
资料采集、原著核验、任务准备
```

正式流程：

1. L2 提交 Visual Task Packet；
2. L2 同时提交 Prompt Draft v1；
3. L1 审查、收紧、重写或驳回；
4. L1 用 GPT Image 正式生成；
5. L1 回传图像、审查意见和可固化规范。

## 10. 提示词硬要求

合格提示词至少覆盖：

1. 对象是谁；
2. 本体层还是主题层；
3. 必须保留哪些原始识别特征；
4. 主情绪 / 主气质；
5. 角色化程度；
6. 服饰 / 材质 / 饰品的逻辑；
7. 构图与展示重点；
8. 明确不要什么。

## 11. L1 审查标准

### 1. 对象识别是否清晰

看完 Prompt，是否知道具体是哪只蛊。

### 2. 主题层边界是否清晰

是否明确这是主题层，不是本体层替代。

### 3. 风格是否统一

是否能识别为《问真》同一项目下的系列资产。

### 4. 审美是否高级

是否只是普通角色收集，是否只是堆珠宝、堆白发、堆月亮。

### 5. 商业吸引力是否成立

是否有收藏价值、传播性和解锁吸引力。

### 6. 是否过度跑偏

是否已经与原对象无关，或成为另一个世界观的角色。

## 12. 统一风格维护项

### 系列共同点

- 同一项目世界气质；
- 接近的精度等级；
- 接近的材质处理逻辑；
- 接近的光照语言；
- 接近的饰品密度控制；
- 接近的角色完成度；
- 接近的幻想表达方式。

### 个体变化点

- 核心主题色；
- 危险 / 圣洁 / 妖异等气质倾向；
- 标志结构；
- 人格气息；
- 功能象征元素。

### 禁止失控

禁止出现：

- 不同渲染语言互相冲突；
- 气质在极端之间无理由跳变；
- 世界观来源互相冲突；
- 细节密度失控；
- 完全不像同一项目。

## 13. L2 维护要求

Prompt Spec 持续维护以下模块：

1. 固定项目前缀；
2. 固定负面约束；
3. 对象专属模块；
4. 批次风格漂移记录；
5. 已被 L1 固化或否决的规则。
