# 问真 Web 原型 · 节点后整备流程收敛设计

日期：2026-09-20

状态：L0 已要求直接实施，本文件记录本轮已确认规则与实现默认值。

## 目标

把 Web lab 从“固定线性首局路线 + 节点类型专属页面”收敛为：

```text
开局难度选择
  -> 固定分支节点图
  -> 战斗 / 精英 / 层主
  -> 自动战斗奖励 + 可选蛊虫三选一
  -> 统一整备页
  -> 选择下一个节点
  -> 重复五段
  -> 第五层主胜利后终局
```

## 已确认规则

### 地图与难度

- 难度只改变每个层主前必须经过的准备节点数：
  - 简单：每段 15
  - 普通：每段 10
  - 困难：每段 5
- 整局固定 5 段、5 个层主，第五段层主是终局 BOSS。
- 进入一局即固定生成整张可预见节点图。
- 当前节点只展示 2 至 3 条直接后继边，路径允许分叉和汇聚。
- 每段最后一个准备节点的后继固定为该段层主。
- 节点类型第一阶段只使用战斗、精英战斗、层主。

### 战斗与失败

- 延续当前战斗规则：所有已炼化战斗蛊可用，无固定蛊槽。
- 同名蛊按实例结算；同回合同一实例只能用一次。
- 杀招仍为 3 个槽，整备页可随时调整。
- 主玩家行动后主动结束回合，再进入敌方回合；无念头时直接推进下一回合。
- 任意战斗失败立即结束本局，进入失败结算，不允许重试。
- 战斗胜利后：
  - 真元恢复至上限。
  - 气血恢复最大气血的 30%。
  - 不设独立休整节点，也不在整备页提供调息。

### 奖励

- 除蛊虫三选一外，元石与材料按节点奖励表直接到账。
- 蛊虫按概率掉落；触发时提供 3 个候选，玩家选择 1 个。
- 小说式“为获取目标蛊而刻意留手/保留局面”不单独建模；统一抽象成战后蛊虫三选一。
- 节点类型影响奖励表；难度不影响奖励和战斗数值。

### 整备页

每个节点结算后进入同一个完整整备页，包括：

- 炼蛊、野生蛊炼化。
- 突破。
- 坊市交易。
- 杀招布局。
- 蛊仓查看与卖出。
- 进入下一个节点。

整备操作不设次数上限，只检查元石、材料、真元、状态与配方门禁。

### 坊市

- 每个节点后的整备页生成一批新货架。
- 货架在本页买完即售罄；进入下一节点后刷新。
- 除蛊方服务外，不继承 Godot 的服务型系统。

### 蛊仓与卖蛊

- 蛊按实例结算。
- 卖蛊返还 `value × 50%` 向下取整的元石。
- 不追查购入历史。
- 卖蛊导致杀招配方失效时，先警告并自动卸下对应杀招。

### 修炼与突破

- 不设独立等级轴。
- 修炼范围为 1 至 5 转。
- 转数与层主无关；满足条件即可在任意整备页突破。
- 每转固定 4 个小境界：初阶 -> 中阶 -> 高阶 -> 巅峰。
- 小突破消耗元石，或消耗 1 只当前转数同阶舍利蛊。
- 舍利蛊不能越阶替代。
- 从巅峰冲击下一转是大突破，要求资质和元石同时达标。
- 初版大突破资质门槛：
  - 一转 -> 二转：丙等
  - 二转 -> 三转：乙等
  - 三转 -> 四转：乙等
  - 四转 -> 五转：甲等

### 资质与舍利蛊

- 资质蛊和舍利蛊都是普通蛊实体，进入蛊仓。
- 两者不参与战斗，不能通过炼蛊获取。
- 舍利蛊可作为小突破材料消耗。
- 资质蛊在整备页随时可用；使用后立即提升一档资质，并同步更新真元容量与恢复。
- 资质蛊不强制绑定大突破，也可以卖出。
- 所有战斗节点概率掉落二者；精英和层主概率提高。
- 坊市可概率上架二者。

## 实现默认值

以下细节用于本轮可直接执行的 Web lab 实现：

- 节点模板名与敌人仍来自 Godot 数据；图结构由 Web lab 的确定性 `run_flow` 规则生成。
- 每段每个准备深度生成 3 个可预知候选节点；同层候选均可达，汇入下一层。
- 每段最后准备层全部汇入该段唯一层主。
- 地图页显示当前段固定图与高亮路径，不显示跨段更深预览。
- 蛊虫三选一从该战斗 tier 对应奖池按种子抽取 3 个不同候选。
- **~~不伪造一转舍利蛊~~ 已更正（2026-09-20）**：原写「不伪造一转舍利蛊」，前提是数据里找不到一转舍利蛊。该前提**已被原著证伪**——`蛊真人-clean.txt:86506` 一句话列全系列：「从一转到五转，分别有青铜、赤铁、白银、黄金、紫晶舍利蛊」（另见 `:18066`「一转的是青铜舍利蛊……二转的是赤铁舍利蛊……三转的就是这白银舍利蛊了」与 `:18068`「到了四转，还有黄金舍利蛊」）。现按原著建五转映射：一转青铜 / 二转赤铁 / 三转白银 / 四转黄金 / 五转紫晶，**按名字定转数、不读 gu 的 rank 字段**。
  为什么不能读 rank：金色进阶链是 1→5 的严格阶梯，其第 2 级正是 `gold_atk_2_12_gu`（青铜舍利蛊），`game/tests/unit/test_promotion_1b1a.gd` 断言每级 rank 恰好 +1；改它的 rank 会打断那条链。**Godot 数据一字未动**，此项已登记为数据命名缺陷。
  同时舍利货架的 `tier` 改为取原著转数（青铜 = tier 1），否则一转区域买不到它，一转小突破永远没有舍利可用。
- 无舍利蛊时，小突破仍可消耗元石。
- 突破元石成本沿用现有 `DATA.cultivationCosts` 的大突破成本；小突破使用 Web lab 配置表。
- 资质蛊使用 lab-only 普通蛊实体，因为 Godot 现有数据没有对应实体。

## 验收

- 规则测试覆盖：图深度、2 至 3 后继、层主汇聚、突破阶位门禁、同阶舍利消费、卖蛊价格。
- 数据生成必须仍产出 `gu / recipes / killMoves / enemies / nodes / route / shopOffers`。
- 浏览器验证：
  - 开局可选难度。
  - 选择节点后进入战斗。
  - 胜利后自动回真元、回 30% 气血。
  - 蛊虫掉落显示三选一。
  - 节点后进入统一整备页。
  - 整备页可炼蛊、突破、交易、调杀招、卖蛊、进入下一节点。
  - 失败直接终局。
  - 控制台 0 error。

## 边界

- 仅修改 `game/wenzhen-web-lab/` 与本设计文档。
- 不提交、不推送、不回退现有脏工作树。
- 不继承恶名、动态难度和除蛊方外的服务型系统。
