# 南疆凡人 V2：连续节点与交锋循环重构设计

## 状态与目的

状态：待用户审阅。

本规格替换当前首个 V2 纵向切片中“单次按钮成功后自动完成节点并返回地图”的交互模型。目标不是扩充地图或事件数量，而是交付一个可连续操作、可胜可死、可复盘的核心循环：玩家进入节点后能持续观察、试探、交涉或交锋；每个行动都留在现场展示结果；只有玩家或规则明确结束事件时才返回路线。

首个可手工验收闭环为：

```text
可见路线
  -> 中立散修遭遇
  -> 观察、欺瞒、试探、离开或开战
  -> 敌方意图与条件化反制的连续战斗
  -> 胜利后现场处理结果，或死亡复盘
  -> 玩家明确离开节点
  -> 路线
```

该闭环稳定后，再接入商队、炼蛊与连招快捷方式。不得以增加按钮、路线或文本替代该闭环的实际可玩性。

## 保持的约束

- 首版只支持 Windows 键鼠和中文玩家界面。
- 保持窗口标题 `Nanjiang Smoke (DEBUG)` 与 `renderer/rendering_method="gl_compatibility"`。
- 规则、战斗、敌人状态、随机、事件日志与死因复盘均为本地可复现逻辑。
- 场景只展示状态并提交命令；不得直接改变 `RunState` 或战斗状态。
- 所有关键状态变化继续经 `RunState.append_event()` 写入不可变事件日志。
- 不改写、删除或移动受保护原始资料目录；原著资料只用于整理可复用规则，不复制原著剧情人物或主线。
- 不设蛊虫持有数量上限与战前固定可用蛊槽。所有已养且已炼化的蛊虫，只要满足真元、目标、冷却、状态与局势条件，均可催发。

## 重构原则

### 节点不再是一次性按钮

地图只负责给出可到达节点。进入节点后，由节点会话维护其当前阶段、可用行动、已见结果与完成条件。普通行动成功不等于节点完成。

以下情况才可结束一个节点：

1. 玩家主动选择带着当前后果离开。
2. 节点目标已达成，玩家确认领取结果并结算。
3. 战斗胜利后的现场处理完成。
4. 玩家死亡。
5. 明确声明为不可逆的事件完成。

交易、炼蛊、欺瞒、试探、一次修行和一次普通交涉都必须留在节点中，给玩家展示变化、继续操作或主动离开的机会。

### 每个操作都有可见后果

领域规则返回结构化结果条目而不是仅返回 `ok`。每条结果至少包含：

- 行动是否生效及失败原因。
- 资源、真元、伤势、蛊虫、关系、敌意、事实或状态的实际变化。
- 新出现、失效或被锁定的后续行动。
- 对本节点、后续路线或战斗局势的已知影响。

界面在当前节点显示结果记录和当前状态，直到下一次玩家输入。控制器不得在普通成功结果后自动切换地图。

## 模块边界

### EncounterSessionResolver

节点会话的唯一领域入口。它保存当前节点的会话阶段、已执行行动、局势标记、可用行动、是否可离开及节点结算资格。

- 输入：`RunState`、当前节点、会话状态、命令与内容数据。
- 输出：更新后的 `RunState`、会话状态、结构化结果。
- 依赖：交涉、商队、炼蛊或战斗模块的结构化结算结果。
- 不负责：蛊虫伤害、敌人 AI、UI 渲染。

`RunController` 只根据会话状态决定呈现遭遇、战斗、死亡复盘或地图，不能自行推断节点是否应完成。

### ResultFeed

表示一次领域操作之后玩家应当看见的结果。它由纯数据组成，不是 UI 节点。

每条条目包含变化项目、原因、可见事实、关联行动及面向玩家的中文文本键。展示层将条目累积为当前节点的结果记录，并提示当前仍可进行什么。

### BattleState 和 BattleResolver

`BattleState` 是独立于节点会话的战斗快照，至少含：

- 玩家生命、真元、伤势、持续状态与已养已炼化蛊虫。
- 敌方生命、真元、已暴露状态、已知蛊虫线索、当前意图、可用后手与行为层级。
- 当前轮次、玩家是否已收势、可触发反制窗口、战斗日志与最终状态。

`BattleResolver` 只处理战斗命令和战斗结算，输出新的战斗快照、`RunState` 与结构化结果。它不直接完成地图节点；战斗结束后由节点会话接收胜利、败北或撤离结果。

### EnemyDefinition 和 EnemyResolver

敌人使用数据定义，而不是仅以生命和控制值定义。每个敌人声明：

- 层级：普通、精英或首领。
- 生命、真元、伤害、行动与撤离的基础规则。
- 可观察征兆、已知信息与尚未确认的推断范围。
- 意图队列或意图选择规则。
- 后手、触发条件、反制窗口与破解条件。
- 性格、战利品与死亡敌语条件。

敌人信息采用“可观察、不可穷尽”原则：玩家先从行为、真元波动、伤势、环境痕迹和已催发蛊虫推断；可通过试探、侦查、逼其消耗、诱导出手或遭遇后逐步确认。后手不能随机阴人，必须存在可回看、可学习的征兆和触发逻辑。

敌人分层如下：

| 层级 | 内容 | 风险 |
| --- | --- | --- |
| 普通敌人 | 一个主套路和至多一张弱后手，线索清楚 | 数值克制但可杀死玩家 |
| 精英/势力蛊师 | 两套可协同手段和一张需试探确认的后手 | 高收益对应构筑与情报考验 |
| 守关首领 | 多阶段、底牌与准备空间 | 高压终局，进入前须由局势明确其危险 |

首个中立散修属于普通层：表面可见石粉、稳定站姿等护身征兆，可能持有一张护身或反制蛊；玩家可谈判、欺瞒、试探、撤离或战斗。其后手能被小光蛊等信息手段确认，也可被控制或消耗策略破解。

### GuEffectResolver

蛊虫效果从数据表读取，并统一结算为可测试的效果：伤害、护身、控制、移动、治疗、揭露、打断和状态变化。它验证真元、目标、冷却、持续状态与局势条件，并返回结构化效果，不把某一种敌人的特殊逻辑硬编码在蛊虫分支中。

### ComboTracker

自由杀招保持为玩家自发探索的连续催蛊顺序，不成为预设正确技能，也不需要名称、备注、目标配置或独立管理界面。

- 战斗中，每次连续催发的蛊虫自动记录为当前轮连招。
- 若实际出现了状态互动，日志以“揭露 -> 束缚 -> 攻杀”这类顺序标注该段连招。
- 战斗后玩家可选择保留为常用顺序或不保留。
- 最多保存三条常用顺序；它们只是一键按原顺序尝试催发的快捷方式，没有额外伤害或隐藏增益。
- 真元不足、蛊虫失去、状态不符、目标不合法或敌方反制导致中断时，立即停止并显示原因。
- 获得、失去或炼制蛊虫改变构筑后，相关常用顺序标记为条件变化，不要求玩家手动维护。

### RefinementSessionResolver

炼蛊是节点内连续会话：浏览可用配方，选择或确认输入，查看成本、成功条件、风险与失败毁蛊后果，执行炼制，查看结果后继续调整或主动离开。

炼蛊成功或失败都不自动结束节点。失败按配方声明毁掉输入蛊虫，并写入事件日志和结果记录。

## 战斗节奏

首轮采用可控的回合制状态对局：

```text
敌方显露当前意图与表象征兆
  -> 玩家连续催发蛊虫，或主动收势
  -> 每个关键效果依条件打开即时反制窗口
  -> 敌方完成未被破解的本轮意图
  -> 结算持续状态、真元、伤势、冷却和新增情报
  -> 下一轮
```

玩家一轮可连续催发多只蛊虫，限制来自真元、目标、状态、冷却与敌方反制，而不是每回合一个抽象行动点。顺序因此是战术核心：先揭露、再控制、后攻杀，与直接连续攻击应产生不同结果。

首轮只实现四类条件化即时反制：

| 反制 | 时机 | 可识别线索 | 常见破解 |
| --- | --- | --- | --- |
| 护身 | 攻击命中前 | 体表异状、环境痕迹、站姿或真元波动 | 揭露、控制、耗真元、换目标 |
| 反击 | 玩家攻击或暴露破绽后 | 预备动作、武器/蛊虫征兆、敌方意图 | 防御、移动、打断、诱导先手 |
| 逃遁 | 敌方不利或撤离条件满足时 | 地形、退路、移动征兆 | 封路、束缚、追踪、抢先施压 |
| 打断 | 玩家蓄力、移动或特定效果生效前 | 敌方蓄势、声光或位置变化 | 先控制、护身、改变顺序 |

首轮只制作中立散修和山道野兽两类普通敌人；两者均可能杀死玩家，但数值、意图与后手线索应清楚，不能以不可推断的隐藏机制制造挫败。

## 死亡与临死前敌语

本轮采用单一死亡机制：玩家生命归零即死亡，本局结束；敌方生命归零即死亡，进入当前节点的战后处理。撤离必须由玩家主动选择并满足条件，失败时敌方继续施压；不做濒死、多段保命、尸体回收或额外死亡惩罚系统。

死亡页应当从战斗日志生成：

- 最后一击及其实际来源。
- 已发生且可见的关键状态、后手或玩家失误。
- 一句由最后一击敌人说出的条件化“临死前敌语”。

敌语是带一点刻薄的江湖嘲弄，而不是系统旁白。它必须仅使用敌人实际看见、实际推断或亲手利用的事实；不得泄露后台数值、未暴露底牌或敌人不可能知道的信息。它应当在一句话中留下可学的机制线索、南疆修行风险和敌人的个人态度。

首轮为中立散修和山道野兽分别提供 6--8 条条件化敌语，按最后一击、已暴露后手、玩家真元耗尽、忽视明显征兆或错误顺序等战斗事实筛选。

## 实施顺序

### 第一段：节点会话与结果反馈

1. 移除控制器和普通领域命令中的隐式节点完成。
2. 引入节点会话状态与结构化结果记录。
3. 将中立散修的欺瞒、试探、开战和主动离开接入会话。

验收：玩家欺瞒中立散修后仍停在现场，能看见元石、警惕和新线索变化，并继续试探、开战或离开；任何一次普通行动不会自动跳到地图。

### 第二段：战斗与敌人状态机

1. 替换只含 `enemy_hp` 的战斗快照为敌我状态、意图、反制窗口和日志。
2. 将蛊虫效果结算从现有战斗分支拆入 `GuEffectResolver`。
3. 实现中立散修和山道野兽的普通敌人行为、胜利、撤离、死亡及敌语。
4. 将战斗结果交还节点会话，而不是由控制器直接完成节点。

验收：固定种子下，玩家能通过不同催蛊顺序分别触发敌人护身、被反制、击杀敌人、撤离或死亡；战斗界面能看见敌我生命/真元、敌方意图、已知线索、行动结果与死亡复盘。

### 第三段：炼蛊与连招快捷方式

1. 将炼蛊改为节点内多步会话，并实现成功、失败毁蛊、继续与离开。
2. 记录连续催蛊，支持最多三条常用顺序。
3. 商队获得、出售、交换与炼蛊结果均通过结果记录留在现场展示。

验收：玩家可在商队调整构筑、进入炼蛊场景、执行成功或失败炼制、继续比较或离开；随后能在战斗中使用一条已保存的常用顺序，并能清楚看见其中断或被反制的原因。

## 测试与手工验收

每段均先建立可失败的领域测试，再接入界面；不得仅通过 UI 点击证明功能存在。

自动测试至少覆盖：

- 节点普通动作不会写入完成标记，也不会改变地图可达性。
- 只有明确离开、确认结算、战后处理完成、死亡或不可逆事件能完成节点。
- 敌方意图、反制窗口、后手触发和状态变化在相同输入下可复现。
- 每种首轮反制都有触发测试、可观察线索测试与至少一种破解测试。
- 玩家与敌人均可合法死亡；死亡记录包含最后一击和只基于已知事实的敌语。
- 蛊虫顺序影响实际结果，但常用顺序不获得额外数值。
- 炼蛊失败按数据表毁掉输入蛊，并留在炼蛊会话中。
- 每次关键变化均保留不可变事件日志。

手工验收固定种子 `101`，按顺序确认：

1. 进入中立散修后执行欺瞒，观察结果，继续试探或开战而非跳图。
2. 以小光蛊或其他合法手段确认散修的护身征兆。
3. 直接强攻触发护身或反制；改用揭露、控制、攻杀顺序可改变结果。
4. 在不利局面主动撤离，或让玩家死亡，确认不会出现无反馈卡死。
5. 阅读死因页，确认最后一击与敌语均可由当前战斗事实解释。
6. 胜利后仍在现场处理结果，玩家主动离开才回到地图。

## 非目标

- 本轮不扩充三阶段地图、势力池、守关首领、升仙考验或美术替换。
- 本轮不制作卡组、抽牌、固定战前蛊槽、预设正确杀招或泛化标签自动技能。
- 本轮不做复杂死亡惩罚、濒死救援、尸体系统、局外数值成长或 LLM 规则裁定。
- 本轮不把原著原文直接作为运行时规则、敌人台词或剧情复刻；原著提炼仅形成受审查的原创机制与证据链。
