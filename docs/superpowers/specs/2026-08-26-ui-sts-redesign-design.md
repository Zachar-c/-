## 1. 设计简报

**目标**：以 Slay the Spire 的界面信息架构为骨架，套入《蛊路求生》的南疆仙侠水墨质感，建立一套「信息清晰、质感统一、肉鸽可读」的视觉系统，覆盖三主屏（大厅 / 战斗 / 地图）与全部公共控件。

**不做的边界**（守住 AGENTS.md）：
- 领域层 `scripts/domain/*`、`data/*.json`、存档格式一律不动；UI 只读 state、仅发 command。
- 不引入需商业化付费许可的美术资产；所有新增视觉尽量用程序化 / 现有贴图派生。
- 不改变 §16.5 / §16.6 已锁定的信息透明与页面流转规则，本设计是在其上做视觉表达，不是改动规则。

**设计判断（专业审稿）**：现有 UI「功能正确、视觉朴素」——三屏均为纵向 VBox 堆叠，信息无主次分区、无背景氛围、无卡牌质感、无意图可视化，地图甚至仍是滚动面板而非路网。StS 的价值不在「好看」，而在**通过空间分区 + 视觉符号把状态与决策压到玩家一眼可读**。本设计的核心不是贴图，而是**重建信息层级与视觉语法**。

## 2. 参考分析与设计语言

### 2.1 StS 三屏设计语言提炼（来自用户参考图）

| 屏幕 | 信息架构 | 视觉语法 | 对肉鸽的贡献 |
| --- | --- | --- | --- |
| 主菜单 | 全屏场景插画作底，标题居中，菜单纵向居左/中，左上角版本角标 | 低饱和暗调叙事背景，前景信息极简克制 | 一眼建立世界观与氛围，菜单零干扰 |
| 战斗 | 顶 HUD（元信息横向铺开）→ 中战斗区（左我右敌、状态在脚下/头顶）→ 底操作区（能量+抽牌堆 / 手牌 / 结束回合+弃牌堆） | 三区严格分层；敌方**意图以符文+数值**悬于头顶；手牌大图横向展开、选中放大 | 意图可视化 = 决策前置；手牌即资源，底栏即「手」
| 地图 | 中央分层节点网络（路径虚线连接）+ 右侧卷轴图例 | 羊皮纸质感；节点**图标化**（类型一眼可辨）；当前/可达/已走三态 | 路线即策略，节点类型图形化消除阅读成本 |

### 2.2 本作融合定位

**StS 的信息架构 × 南疆仙侠水墨的质感**。二者不冲突：StS 的「清晰分区 + 图形符号」是通用的肉鸽语言，水墨风负责世界观氛围与情感基调。核心原则：

1. **分区即语法**：顶=状态、中=战场、底=操作，永不混区。
2. **符号即信息**：敌方意图符文、节点类型图标、资源图标、风险徽章，全部图形化，文字只作补充。
3. **暗底亮文、克制动效**：墨青夜色为底，月光银/蛊虫青白为第二光源，暖橙烛火点缀；动效只做引导（悬停/切换），不做常驻动画。
4. **危险永远红、正向永远玉**：诅咒/反噬/死亡线/恶名高——血锈暗红；生命/炼蛊/正向反馈——玉青。颜色语义全局锁死。

**语义锁死**（跨屏统一，禁止漂移）：
- 危险三件套（诅咒蛊 / 反噬结算 / 死亡线 / 极高恶名）→ `DANGER`/`BLOOD`，强红视觉警示（§16.5）。
- 契约 → 蓝系 / 异变与 DDA → 黄红系（§16.13 已定分区）；顶栏背景区分蓝系面板与黄红系面板。
- 普通正向 / 玉系资源（生命、魂魄、玉）→ `JADE`；货币与材料（元石、寿元）→ `GOLD`/`EMBER`。

### 3.2 字体与字号层级

> 字体资产缺口：当前主题未绑定中文字体（Godot 默认字体中文为 fallback）。标题建议引入一款可商用楷体/宋体（如思源宋体 SIL OFL），正文用系统中文回退；**字体资产落地单列待办，不阻塞本次布局设计**。

| 层级 | 字号 | 颜色 | 场景 |
| --- | --- | --- | --- |
| H1 屏标题 | 40–48 | `GOLD` | 主菜单题字、结算标题 |
| H2 屏内标题 | 24–28 | `GOLD` | 地图「南疆行程」、面板大标题 |
| H3 面板标题 | 20 | `BONE` | 战斗敌我面板标题、遭遇面板 |
| 正文 | 18（主题默认） | `BONE` | 卡牌效果、事件正文 |
| 次要 | 14–16 | `BONE_DIM` | 说明、图例、footer |
| HUD 数值 | 20–22 加粗 | 随资源色 | 顶栏真元/元石/寿元/魂魄 |

### 3.3 间距 / 圆角 / 描边 / 阴影

- 间距基准 4pt 网格：4 / 8 / 12 / 16 / 24 / 32。
- 面板圆角 6px、卡牌圆角 10px（RUI 主题统一，不散落硬编码）。
- 描边：面板 1px `BG_RAISED` 亮边 + 墨色投影；选中态 `JADE_BRIGHT` 或 `GOLD` 描边加粗至 2px。
- 阴影：悬浮卡片投影 8px / 4px 偏移，避免纸片感。

### 3.4 动效预算（克制，遵循 §4 设计文档）

- 界面切换：淡入 + 轻微滑动 120–180ms。
- 卡牌悬停：上浮 6px + 描边高亮 100ms。
- Tooltip / 确认框：淡入 / 缩放出现 100ms。
- 数值变动：仅 HUD 数值轻微脉冲一次（不做循环）。
- 禁止常驻循环动画（保持肉鸽安静可读）。

> 每屏给出：布局线框、区域职责、信息层级、组件映射、与现状差异。参考分辨率为项目窗口设置（1920×1080 基准，UI 全 scale 适配）。

### 4.1 主菜单（大厅 HallView）

```

│                                                             │
│                     蛊 路 求 生                              │
│             夜入密林，蛊路求生 · 南疆篇                       │
│                                                             │
│              ┌──────────────────────┐                       │
│              │  继续上次冒险   ▲光标  │                       │
│              │  开始新冒险（流派/契约）│                       │
│              │  图鉴               │                       │
│              │  设置               │                       │
│              │  退出               │                       │
│              └──────────────────────┘                       │
│   版本角标 v0.4                                          ─ □ ×│

```

- **布局**：全屏叙事背景 + 中央竖向菜单卡；标题区与菜单区拉开呼吸。
- **信息层级**：背景（氛围）→ 题字（身份）→ 菜单（操作）。菜单项悬停金色描边 + 左侧「▶」形光标指示（现有 `selection_arrow` 贴图复用）。
- **四分支**：继续 Run（优先，有存档时置顶高亮）/ 开始新冒险（流派+契约占位）/ 图鉴 / 设置；保留已接的 `continue_requested` 等信号（§6.2）。
- **组件映射**：`GuButton`（主菜单大按钮变体）、`GuPanel`（菜单卡）、`GuTopBar`（不占本屏，背景直出）。
- **与现状差异**：现状为纯色 VBox 堆叠；新增全屏氛围底 + 菜单卡片化 + 版本角标。

```
└────────────────────────────────────────────────────────────┘
```

- **三区语法**：顶 HUD（元信息 + 契约/异变常驻）→ 中战场（左我右敌、状态脚下/头顶）→ 底操作（能量 + 手牌 + 回合控制 + 牌堆计数）。
- **敌方意图**（§16.5 硬约束）：意图符文（攻击 ⚔ / 防御 🛡 / 蓄力 ☾）+ 数值 + 效果文字；攻击意图 `DANGER`、防御 `GOLD`。敌方头顶意图、脚下血条与 Buff。
- **我方**：生命与护盾分条展示（§16.5）；真元/魂魄/寿元用 `GuStatBar`；蛊躁动/诅咒 status 用红色 chip 沉底。
- **手牌**：横向卡片带（≤6 张，无翻页需求沿用 §3 裁决）；`GuCard` 尺寸约 200×280，左上品质角标、上蛊名、中效果、右上真元代价、危险蛊强红卡面描边。
- **组件映射**：`GuTopBar`（HUD）、`GuCard`+`GuTooltipView`（手牌）、`GuStatBar`（双方状态）、`GuDeathLineWarning`（三死线预警，§16.17）、`GuButton`（操作区）。
- **与现状差异**：现状为顶栏+敌我两面板+滚动手牌+按钮行的 VBox 堆叠；重做为严格三区 + 敌意图可视化 + 卡带式手牌 + 立绘氛围层。

## 6. 实施路线（落地到 RUI）

按「设计确认 → 高保真方向稿 → 令牌落地 → 组件改造 → 逐屏重构 → 验证」推进，每步一个 Task、先写可失败验收：

1. **T0 令牌落地**：扩展 `GuStyle` 至全 token（§3.1），`gu_theme.tres` 补圆角/描边/阴影；验收：RUI 样例屏以新 token 编译通过、GUT 全绿。
2. **T1 公共组件视觉**：按 §5 改造 `GuCard`/`GuButton`/`GuTopBar`/`GuStatBar`/`GuTooltipView`/`GuConfirmDialog`；验收：无头冒烟断言各控件渲染、交互回调不触发（沿用 §8 冒烟方式）。
3. **T2 大厅**：全屏氛围底 + 菜单卡 + 版本角标；验收：四分支按钮可点、信号接到 `RunController`。
4. **T3 战斗**：三区重排 + 意图符文 + 卡带手牌 + 状态分条；验收：无头冒烟、意图含数值+效果文字断言。
5. **T4 地图**：路网视觉（节点图标 + 金丝连线 + 云雾未探明）+ 图例卷轴 + 底部按钮组；验收：八类节点三态渲染、travel 命令正确。
6. **T5 打磨**：跨屏过渡、tooltip 一致性、危险蛊强红视觉、空池回退小字提示（§16.5/§16.6）。
7. **验证**：领域 GUT（423 unit + 8 integration）全绿；Godot 4.7.2 实跑走通 大厅→地图→遭遇→战斗→结算→大厅。

**字体资产待办**：标题中文字体（思源宋体/楷体，SIL/OFL 可商用）落地为独立 Task，不阻塞布局。

## 7. 验收标准

- 三屏达到「分区即语法」：状态/战场/操作严格分层，玩家一眼定位。
- 敌方意图、节点类型、资源、品质、危险全部图形符号化 + 数值化，文字仅补充（§16.5）。
- 全部颜色语义锁死（危险红 / 正向玉 / 资源金 / 契约蓝 / 异变黄红），跨屏无漂移。
- 动效克制（120–180ms 引导性动效，无常驻循环）。
- 领域层零改动：GUT 423 unit + 8 integration 全绿；UI 只读 state、仅发 command。
- 导出前 `.guitkx` 编译 `.gd` 链路正常（§8 导出前置）。
