## 1. 设计简报

**目标**：以 Slay the Spire 的界面信息架构为骨架，套入《蛊路求生》的南疆仙侠水墨质感，建立「信息清晰、质感统一、肉鸽可读、流转无歧义」的完整视觉系统，覆盖上表 22 个界面、全部公共控件，以及每个界面的状态与流转。

**不做的边界**：
- 领域层 `scripts/domain/*`、`data/*.json`、存档格式一律不动；UI 只读 state、仅发 command；`RunController` 仍是状态所有者，本设计只定义 UI 可见状态与转移表达。
- 不引入需商业化付费许可的美术资产；新增视觉尽量程序化 / 现有贴图派生。
- 不改变 §16.5 / §16.6 已锁定规则。

**核心设计判断**：肉鸽 UI 的崩溃多半不是"不好看"，而是**玩家不知道自己在哪、能做什么、怎么回去**。因此本规格把**状态与流转**提升为一等公民：每个界面必须能回答"我从哪来 / 我现在能做什么 / 我要怎么调整 / 我如何退出和返回"。视觉风格服务于这套流转的可读性。

## 2. 参考分析与设计语言

### 2.1 StS 三屏设计语言提炼（来自用户参考图）

| 屏幕 | 信息架构 | 视觉语法 | 对肉鸽的贡献 |
| --- | --- | --- | --- |
| 主菜单 | 全屏场景插画底，标题居中，菜单纵向，左上版本角标 | 低饱和暗调叙事背景，前景信息极简 | 氛围即世界观，菜单零干扰 |
| 战斗 | 顶 HUD → 中战场（左我右敌）→ 底操作（能量+手牌+结束） | 三区严格分层；意图符文+数值悬头顶；手牌横向展开 | 意图可视化=决策前置 |
| 地图 | 中央分层节点网络 + 右侧图例 | 羊皮纸质感；节点图标化；三态区分 | 路线即策略 |

### 2.2 本作融合定位与全局视觉语法

**StS 信息架构 × 南疆仙侠水墨质感**。四条全局语法（所有界面强制遵守）：

1. **分区即语法**：状态（顶）→ 内容（中）→ 操作（底），永不混区。
2. **符号即信息**：意图符文、节点图标、资源图标、风险徽章、结局徽章全部图形化，文字只作补充。
3. **暗底亮文、克制动效**：墨青夜色底，月光银/蛊虫青白第二光源，暖橙烛火点缀；动效只做引导。
4. **颜色语义全局锁死**（见 §3.1）：危险永远红、正向永远玉、资源永远金、契约蓝、异变黄红、死亡线血锈。

- 间距 4pt 网格：4 / 8 / 12 / 16 / 24 / 32。

- 描边：面板 1px `BG_RAISED` 亮边 + 墨色投影；选中态 `JADE_BRIGHT`/`GOLD` 描边 2px。

### 3.4 动效预算（克制）

- 界面切换：淡入 + 轻滑 120–180ms；死亡返回大厅加载尽量短（§16.5）。
- 卡牌悬停：上浮 6px + 描边高亮 100ms；Tooltip / 确认框淡入 / 缩放 100ms。
- HUD 数值变动：轻微脉冲一次；禁止常驻循环动画。
- 可选跳过：杀招动画 / 死亡演出一键跳过（R5.22、§16.5）。

## 4. 状态与流转设计（本次重点）

> 原则：**每一屏必须能回答四问**——①进入（Entry）：我从哪来、什么条件可进；②调整（Adjust）：屏内能操作/切换/预览什么；③退出（Exit）：什么动作会离开本屏、带什么副作用；④返回（Back）：离开后回到哪、能否原路返回。**全部流转遵守三条铁则**：无读档回溯、所有结局统一走结算、退出即保存。

### 4.1 全局应用状态机

```
[启动页 APP_STARTUP]
    │  点击/按键
    ▼
[大厅 APP_HALL] ◄──────────────────────┐
    │                                   │
    ├─ 分支A 继续上次冒险（有 Run 存档）   │ 返回大厅
    ├─ 分支B 开始新冒险                  │
    │    └→ [流派选择]→[契约]→ 新 Run    │
    ├─ 分支C 图鉴（子视图）               │
    ├─ 分支D 设置（子视图）               │
    └─ 手记库 / 轮回统计（子视图）          │
    │                                   │
    ▼                                   │
[局内-地图 APP_RUN_MAP]                  │
    │  选择可达节点                       │
    ▼                                   │
[局内-节点 APP_RUN_NODE]                 │
    │  战斗/事件/商店/休整/炼蛊/宝箱/     │
    │  Boss/突破/隐藏逃离                │
    │  任意结局条件达成                   │
    ▼                                   │
[结算 APP_ENDING] ──返回大厅/查看图鉴─────┘
```

**状态枚举**：

| 状态 | 含义 | 大厅「继续」按钮 |
| --- | --- | --- |
| `APP_STARTUP` | 启动页 | — |
| `APP_HALL` | 大厅（含子视图 A3–A8） | 随存档有无显隐 |
| `APP_RUN_MAP` | 局内·地图 | 隐藏 |
| `APP_RUN_NODE` | 局内·节点（C1–C9） | 隐藏 |
| `APP_ENDING` | 结算 | 隐藏 |

**存档三态**（驱动「继续上次冒险」显隐与可用性，R1.5/R1.6）：

| 状态 | 含义 | 大厅表现 |
| --- | --- | --- |
| `SAVE_NONE` | 无进行中 Run | 「继续」置灰 |
| `SAVE_RUN_ACTIVE` | 有进行中 Run（关闭/切出自动保存） | 「继续」可用置顶高亮 |
| `SAVE_RUN_CLOSED` | Run 已结束（结算完成 / 主动放弃） | Run 存档已删 → 置灰 |

**关键转移约束**：
- 任意界面关闭游戏 = 自动保存 Run → 重进 `APP_STARTUP` → 大厅分支 A 续玩；**无读档按钮、不可回退重roll已结算奖励**（R1.5/P3 SL 禁令）。
- 主动放弃本局（仅大厅可见入口）→ 结算为失败求生，Run 存档删除（R1.6）。
- 所有结局（死亡/逃离/蛊化/险成/成功/真结局）→ **统一走 `APP_ENDING`**，禁止直接跳回大厅（§16.6）。
- 结算完成 → 删 Run 存档 → 写大厅档 → 返回 `APP_HALL`（§16.10 顺序固定）。

### 4.5 弹窗与叠层管理（模态分层）

**层序（z-order，0 最低）**：

| 层 | 内容 | 模态性 | 说明 |
| --- | --- | --- | --- |
| L0 | 主屏（B2 地图 / C1–C9 节点屏） | — | 状态/内容/操作三区 |
| L1 | 侧栏（B3 蛊囊、C4 侧边状态） | 非模态 | 可与其他层共存 |
| L2 | 浮层（C2 奖励、C7 情报、图鉴详情、节点详情） | 半模态 | 可关闭回 L0 |
| L3 | 确认弹窗（D1） | 模态 | 锁住下层，防绕过二次确认 |
| L4 | Tooltip / Toast | 不拦截 | 悬停/短暂显示 |
| 全局 | B1 顶栏 | 恒在 | 任意层可见 |

**规则**：
1. **弹窗可随时关闭回地图**：事件/奖励弹窗不阻断退出（§16.5）。
2. **危险确认未完成不关下层**：D1 未确认前，下层操作不可达，杜绝绕过二次确认（R2.2/R7.3）。
3. **叠层上限 2 层**：L0 + 至多一个 L2/L3 浮层，避免层层嵌套；侧栏（L1）与 tooltip（L4）不计。
4. **无读档按钮**：任何层不出现「读档/回溯」，只有「继续上次冒险」（§16.5/§16.6）。
5. **退出=保存**：任意层关闭游戏自动保存 Run（R1.5）。

### 4.6 中断与恢复状态

| 场景 | 行为 | 条款 |
| --- | --- | --- |
| 关闭游戏 | 任意界面自动保存 Run 存档 → 启动页 → 大厅「继续上次冒险」可用 | R1.5 |
| 重进续玩 | 恢复本局全部状态（RunData 重建），只能向前推进 | R1.5/P3 SL 禁令 |
| 主动放弃 | 大厅提供「放弃本局」→ 确认 → 结算为失败求生，Run 存档删除 | R1.6 |
| Run 结束 | 结算完成 → 删 Run 存档 → 写大厅档 → 返回大厅 | §16.10 |
| 版本不符 | hall 存档版本差距过大 → 提示重置（D4） | §16.22 |
| 中途续玩存档 | 局内任意节点均可被自动保存，无手动存档点 | R1.5 |

### 4.7 状态可视化原则

每屏让玩家随时回答「我在哪 / 能做什么 / 怎么返回」：
- **界面标题 + 当前节点名**常驻顶栏下方（如「三转 · 黑市」）。
- **按钮三态**：可用（亮）/ 禁用（灰+原因 tooltip）/ 锁定（灰+锁图标），视觉绝不歧义。
- **返回路径永远可见**：地图返回、弹窗关闭、结算返回大厅按钮恒在。
- **状态徽章常驻**：锁定/封印/危险/契约/异变/DDA，对应 §3.1 语义色。
- **动效只标识切换**：状态转移用 120–180ms 过渡，不做常驻动画。

## 11. 验收标准

- **覆盖完整**：§0 覆盖矩阵 22 个界面全部有设计、有组件映射、有现状差距；规格书每一条「需要玩家界面」的条款可追溯。
- **状态流转完备**：每个界面四问（进入/调整/退出/返回）均有定义（§4.4）；全局状态机、节点流转、弹窗叠层、中断恢复均有规则。
- **三铁则**：无读档回溯、所有结局统一走结算、退出即保存，全部界面不违反。
- **视觉语法统一**：分区语法与颜色语义跨全部界面无漂移。
- **信息透明**（§16.5）：意图含数值+效果文字；生命护盾分条；Tooltip 完整；服务显示剩余次数；事件选项后果预览+侧边状态；保底只暗示不裸露；结算六要素；全局状态常驻顶部。
- **领域层零改动**：GUT 423 unit + 8 integration 全绿；UI 只读 state、仅发 command。
- **动效克制**：120–180ms 引导性动效，无常驻循环；杀招/死亡演出可跳过。
