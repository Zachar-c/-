## 一、阶段目标切换（批准）

从「验证线性强度闭环」正式切换为：

> **验证构筑分叉与完整力量循环。**

验收单位是 **Build Mutation**，不是伤害数字、HP、Rank 或稀有度。

Build Mutation 至少发生一种：

1. 获得新战斗动词；
2. 杀招因组件替换而改变机制；
3. 资源循环发生变化；
4. 原本难处理的一类敌人获得新答案；
5. 玩家因为新构筑开始追逐不同掉落。

**不算**构筑变化：

- 伤害 4 → 6
- HP +10
- Rank +1
- 稀有度提升

## 二、vertical 最小解冻（批准）

允许以下规则动词进入 live 玩家链：

| 动词 | 语义族 | 说明 |
| --- | --- | --- |
| `inspect` | 信息 | 观察 / 揭示 |
| `suppress` | 反制 | 压制触发 |
| `armorBreak` / `pierce` | 绕防 | **实施前统一为一个语义族** |
| `ignoreEvasion` | 稳定命中 | 否定闪避 |

其余 vertical 内容继续冻结，**不得顺带扩容**。继续冻结至少包括：

- `damage_return`
- 完整距离系统
- 复杂 upgrade / obsolescence
- 自由声明式杀招自动推导

## 三、杀招权威语义（批准）

```text
组件 battleEffect 的实际合成结果
= 杀招战斗语义权威
```

约束：

1. **展示、门禁、实际结算必须一致。**
2. 组件条件**默认继承**。
3. 只有明确声明 `override`，才允许杀招突破组件限制。
4. 预制 `m.effect` 只允许作为元数据 / 兼容字段；显示必须从实际语义生成，或通过一致性校验。

血昙满血打出且组件条件被静默绕过：**判 Bug**，不得当作「组合技无视组件限制」的产品特性。

## 四、材料定位（批准）

```text
材料系统主角色 = 炼蛊配方钥匙 / 定向获得力量
```

允许少量材料未来承担：

- 突破祭品
- 临时耗材

**禁止**把所有材料统一成万能货币。

第一阶段只激活 Phase 4 真正使用到的材料；其余材料不删除，但在有 Consumer 前不进入正式掉落池。

## 五、构筑成型来源（批准）

Build identity 主要来自：

```text
蛊的获得 / 替换
+ 炼蛊分支
+ 杀招重构
```

Rank 只承担：

- 力量承载
- 使用门槛

Rank **不作为构筑身份**，也**不得退化为万能数值倍率**。

## 七、材料与目标感原则（吸收 L0 总计划）

战斗目标必须由构筑目标产生：

```text
我想炼某只蛊
→ 缺某材料
→ 知道哪类敌人产
→ 主动选择去打
```

Boss 奖励核心不是「+15 → +27 元石」，而是：

> 通常至少打开一个此前不可达的构筑未来。
