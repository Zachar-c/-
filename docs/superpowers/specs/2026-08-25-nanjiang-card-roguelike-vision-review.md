# 《蛊路求生》卡牌肉鸽新方向设计评审

> 评审日期：2026-08-25
> 评审基线：用户在会话中提供的新方向设计梳理（地图 / 战斗资源 / 炼蛊合成 / 资源循环 / NPC 交互）**作为新方向权威**；`docs/GDD.md` 视为待按新方向更新的旧文档。
> 评审方式：只读评审，不改代码。引用代码事实均来自工作树 `task1-vendor-open-rpg` 当前提交（`4c35348`）。
> 结论编号：问题 `R*`（资源）、`C*`（卡牌战斗）、`M*`（地图）、`G*`（炼蛊）、`B*`（黑市/循环）、`N*`（NPC）；待定问题 `P*`。

## 0. 评审结论速览

- **方向可行性：高。** 现有代码已实现本设计的大部分骨架：卡牌即蛊虫的战斗、真元与每回合恢复、魂魄反噬公式、三种炼蛊模式（配方/定向/盲盒）、黑市三方交易（元石购、寿元换、以物易物）、NPC 立场与交涉、不可变事件日志、跨局图鉴记录层、LLM 离线模板网关，均有雏形可复用。
- **三大高危点（必须先拍板）：**
  1. **R1 魂魄双重职责**：设计把"单回合蛊虫数量上限"和"可被反噬扣减的储量"合并为同一个"魂魄数值"，超额扣减上限本身会形成死亡螺旋（多打一张→扣上限→下回合上限更低→更容易超→再扣）。现有代码已分离为 `soul_control_limit`（上限）与 `soul`（储量），需要统一口径。
  2. **R2 三条死亡线的可预见性**：气血 0 / 寿元 0 / 魂魄 0 皆死，而黑市与 NPC 又接受"寿元、魂魄"作货币——"在商店界面因结算顺序误死"与"允许打出但打出即死"是设计必须防住的两种状态。
  3. **G2 全局图鉴与"不做局外成长"**：设计要求蛊方录入全局图鉴、后续对局可见，与 AGENTS.md / GDD 的"不做局外成长"直接冲突；`meta_progress.gd` 的跨局记录层已经写好，启用与否是策略裁决，不是工程问题。
- **设计内部矛盾 3 处**：N2 交易后开战 vs NPC 消失；局内图鉴 vs 全局图鉴表述张力（设计一"局内不开放"与设计三"全局图鉴"并存）；非战斗交互禁恢复 vs 休息点节点（边界规则 #1 与节点类型列表冲突）。
- **"待完善点"六项全部是负载性前置**（魂魄反噬公式、寿元节奏、资质公式、牌组容量、失败惩罚梯度、地图权重），不补齐无法定数值；现有代码已给出其中三项的可用雏形（反噬公式、`essence_regen_per_turn`、失败 `destroyed` 结果权重）。

## 2. 逐系统评审

### 2.1 战斗资源体系（设计二）

**现状对照**

| 资源 | 设计描述 | 代码现状（已验证） | 差距 |
| --- | --- | --- | --- |
| 气血 | 归零直接死亡 | `health`/`max_health` 初始 6；`finalize_death` 判死 | 一致 |
| 寿元 | 货币化生存资源；耗尽即死，无视气血 | `cultivator.lifespan` 初始 60；`spend_lifespan` 已有；黑市 `shop_lifespan_deal` 已实现寿元换蛊；`_finalize_if_dead` 任一资源 ≤0 判死 | 一致；寿元**获取途径**未定义（R5） |
| 魂魄 | 单回合蛊虫数上限；超额扣魂魄并附带伤害/debuff；负值即死 | `soul` 4 / `soul_max` 4 / `soul_control_limit` 2 **三者分离**；反噬公式已有（见下） | **R1 口径冲突**：设计把上限与储量合并为一个数值 |
| 真元 | 蛊虫消耗；上限=等级+资质；不足无法打出 | `essence`（局）+ `cave_aperture.essence_max` 固定 4 + `essence_regen_per_turn` 2；`insufficient_essence` 拒绝已有；首回合额外能量遗物钩子已实现 | **R3**：上限公式未定，资质目前只影响反噬系数，不影响真元上限 |
| 等级/资质 | 等级+资质决定真元上限；资质局内可提升 | `cultivation` 1；`aptitude` "bing"，按资质档位（jia…wu）缩放气血/魂魄反噬系数 | **R3**：需求改表 |

**发现的问题**

- **R1（高危）魂魄双重职责**。设计原文"上限由魂魄数值决定；超额每 1 张扣减魂魄值；魂魄变负直接死亡"意味着：上限即储量 → 超发一次永久降低未来上限 → 更容易再次超发，且"允许继续释放"却可能当场致死。建议二选一：
  - 方案 A（推荐，贴近现有代码）：保留 `soul_control_limit`（每回合数量上限，独立数值）与 `soul`（储量）分离；反噬只扣储量与气血，上限不因超发变化；储量 0 即死。
  - 方案 B：按设计原样合一，但必须加"临危护栏"：当扣减会导致死亡时禁止该次释放（先提示再允许，或强制阻断）。
- **R2（高危）商店/交易界面误死**。黑市与 NPC 接受寿元/魂魄作货币；若结算顺序是"先扣寿元再判死"，玩家可能在商店界面直接暴毙且无法反悔。必须在交易前做可预见性预检：显示交易后剩余寿元/魂魄，若将触及死亡线则红字警告并需要二次确认（对应"死亡只来自玩家已看见且选择进入的险境"原则）。
- **R3 真元上限公式与资质提升路径**（设计待完善点 #2）。建议定稿：`essence_max = base + function(level) + function(aptitude)`；资质提升途径（传承/炼蛊台/事件）与消耗（寿元/材料）一并写入数值表。现有 `APTITUDE_BACKLASH_FACTORS` 已按资质缩放反噬，可扩展同一张表增加 `essence_factor`。
- **R4 反噬公式可直接定稿**（设计待完善点 #3）。现有公式：`soul_damage = ceil((1 + 2 * rank_gap) * soul_factor(aptitude)) + max(0, 场上蛊数 - soul_control_limit)`，气血另有 `ceil((1 + rank_gap) * health_factor)`；不足 0 不触发。此公式完整覆盖"等级差反噬+数量反噬+资质缩放"，建议以现有公式为基线做平衡调参，而不是重写。注意：现有实现把魂魄用 `maxi(0, …)` 钳制为 0，即反噬不会当场致死；若采纳方案 A 应保留此护栏。
- **R5 寿元供给节奏**（设计待完善点 #4）。设计只定义了"消耗"，未定义"获取"；寿元既是生存线又是货币，若全程不回复，"黑市都用不起"；若回复过多则"刷黑市苟活"。建议数值设计任务定：起始 60（现状）、每层少量保底（事件/节点 or 炼蛊产物）、黑市总额度上限。

### 2.2 卡牌战斗层（设计二/三附注）

- **C1 一致**："卡牌即蛊虫、无普攻卡"与现有 `cards.json`/`deck_builder`/`battle_resolver` 体系一致，无需改动方向。
- **C2 牌组数量模型是炼蛊的前置依赖**（设计待完善点 #1）。卡牌同时是战斗资源与炼蛊输入，消耗卡牌永久离开牌组；必须把牌组建成"卡牌 id → 数量"（现有 `gu_instances`/`gu_card_overrides` 已接近），并明确：炼蛊投入卡牌后由哪个字段扣减、容量上限如何拦截、移除/升级游戏如何呈现。没有这一模型，炼蛊台无法安全实现。
- **C3 先手权未实现**。NPC 系统要求"主动开战玩家先手 / 敌视随机 / 极度仇恨敌方先手"，`battle_resolver` 目前无先手概念（`start()` 后总是玩家行动）。需新增先手字段 + 敌方先手回合（工作量小，但必须进测试）。
- **C4 战斗中禁炼蛊**：设计约束与现状一致（战斗命令集不含 refine），无冲突。

### 2.3 网状两端收敛地图（设计一）

**现状**：`MapGenerator.build(seed, first_run)` 按 `nodes.json` 分层（one/three/four/five）每阶段抽 ≤2 节点链式串联，`first_run.json` 固定首局；节点 `next_ids` 已具备支路，迷雾可见性（`visible_nodes`/`forward_layers`）与"跳过节点有代价"（`on_skip` 字段：`lose_route`/`gain_pursuit`/`price_rises` 等）已实现。现有 14 种节点类型：contact/caravan/refinement/cultivation/ledger/hazard/inheritance/wild_gu/market/shop/event/combat/pursuit/commission + ascension_node。

**发现的问题**

- **M1 收敛网络未实现**。现状是"分段链式"，没有"多入少出、跨支路跳转、收拢到终点"的网状生成。建议新任务：网络生成器（每层从候选池生成 2–3 条支路，跨层入口合并，终点前强制并入 1–2 个收敛点），保持 `nodes.json` 数据驱动与固定种子可复现。工作量中等，是地图方向最大的一笔。
- **M2 节点预算与锚点未定**。设计未写明每局节点数；沿用 GDD 的 10–14 个有效决策节点预算即可。更重要：**锚点规则**——每局必须保证至少 1 个黑市、1 个炼蛊台、1 个传承点（否则整局无炼蛊、无结账），建议以现有"固定锚点"机制（first_run/关键节点强制入列）扩展为"按类型保底抽取"。
- **M3 精英/BOSS/残骸搜刮/休息未落地**。`enemies.json` 有 4 类敌人原型与变体，无精英/BOSS 标记；无残骸搜刮节点（可并入战斗奖励结算而非独立节点，工作量小）；无休息节点。另外**内部矛盾**：NPC 边界规则 #1"非战斗交互不能恢复气血/真元/寿元"与节点类型"休息点"并存——需区分"节点效果恢复"（允许）与"NPC 交互行为"（禁止），否则休息点名存实亡。
- **M4 终局收敛目标**：设计的"终点 BOSS 节点"与现状 `ascension_node`（五转升仙窗口，抉择式终局）不同。建议合并：最终节点 = 强敌战（BOSS 原型）+ 升仙/撤离抉择，一次解决"收敛点要有内容"与"终局叙事"两个需求。结局判定沿用现有成功/险成/失败求生三支（设计"死亡即结束"较粗暴，与 GDD"失败也是人生"体验支柱冲突，建议保留求生结局）。
- **M5 防刷黑市**（设计待完善点 #6）：现状黑市 offer 有限 + 元石/寿元供给有限，天然有防刷器；仍需路径权重任务（黑市节点不再访问后收益递减或价格上浮，`on_skip: price_rises` 已有雏形）。

### 2.4 炼蛊合成系统（设计三）

**现状**：`refinement_recipes.json` 已有三种模式与门禁：
- `kind: fixed`（定向炼法，确定性产出）；
- `kind: combine`（组合炼法，`success_roll_max` 概率 + `failure: destroy_inputs`）；
- `kind: free_mix`（盲盒：`min_inputs` + 加权 outcomes，已含 `destroyed` weight 5）；
- `locked: true` + `requires_legacy_knowledge_id`（配方门禁，未解锁不可见/不可炼，由 `knowledge` 传入校验）；
- `_refinement_roll` 基于种子随机，可复现。
- 炼蛊入口为节点动作 `refine`（`encounter_session_resolver` → `refinement_result`），战斗内无入口。

**发现的问题**

- **G1 三种炼法与设计一一对应**，且门禁机制已实现：**强烈建议不再重写**。缺口只是数据：combine/free_mix 的负面/自爆蛊结果（现网只确认有 `destroyed`；fear 面结果需在数据表补齐并配"凶兆提示"文案——盲盒前显示模糊风险等级，满足"可预见性"原则）与失败惩罚梯度（设计待完善点 #5）。
- **G2（高危）全局图鉴 vs 局外成长**（裁决点，见 P4）。`meta_progress.gd` 已实现跨局图鉴记录（`gu_codex_ids`/`recipe_codex_ids`/`unlocked_content_ids`/`unlocked_random_outcomes`/统计），且 `record_random_outcome` 已记录盲盒结果。现状**只记录、不设跨局门槛**（配方门禁是局内 `requires_legacy_knowledge_id`）。建议 v1 维持"局内解锁"（每局从零开始，配方见没见过由局内线索/传承决定），全局图鉴仅作统计展示；若用户要"全局解锁"则需显式豁免 AGENTS.md 的局外成长条款。
- **G3 材料体系**：`materials` 字典与养护（feeding）已实现，但无容量/重量概念、无独立"炼蛊材料"分类（只有 `feed_points` 一类）。设计把材料作为炼蛊输入，需要材料类型扩展 + 数量模型与 C2 一起落地。

### 2.5 资源循环与黑市（设计四）

**现状**：`shops.json` offers + 三通道命令已实现：`shop_purchase`（元石购）、`shop_lifespan_deal`（寿元换）、`shop_barter`（以物易物）；元石 `stone` 是中性货币。

**发现的问题**

- **B1 交易媒介缺口**：设计未定义中性货币（"变卖材料换取其他资源"换什么？）。建议保留元石为中性媒介（现状），寿元/魂魄只作特殊高代价货币——与设计"部分特殊 NPC 接受寿元/魂魄"兼容，且避免把生存线当通用货币的刷取漏洞。
- **B2 同 R2**：寿元/魂魄交易必须有死亡预检（见 2.1）。
- **B3 循环闭环与现状一致**：战斗掉落 → 炼蛊/黑市 → 消耗 → 死亡/求生结局，闭环各环节现状均有对应实现；缺口集中在数值（寿元节奏、比例、掉落表）而非机制。

### 2.6 局内非战斗 NPC 交互系统（设计附录）

**现状**：`npcs.json` 已有立场/性格数据模型（`goals`/`bottom_line`/`will`/`known_facts`/`retreat`/`reinforcements`/`injury_reaction`）；`encounter_session_resolver` 已实现 probe（套情报）/trade（交易）/fight/retreat/leave 动作与立场转换（`npc_disposition`: neutral → examining → guarded；投降路径）；`resolver.gd` 有 NPC 作用域命令路由（`npc_id`）；魂魄变化已入事件日志（before/after）。地图情报揭示有 `buy_information` 动作雏形。

**发现的问题**

- **N1 三立场映射**：设计的三立场（中立/敌视/极度仇恨）需映射到现有 disposition 体系，通常做法：`neutral`（全选项）→ `hostile`（仅战斗+随机先手）→ `extreme_hostile`（强制战斗+敌方先手）。现网只到 `guarded`/投降，需补两个立场与先手权（C3）。
- **N2（矛盾，裁决点）交易后开战 vs NPC 消失**："交易完成后 NPC 可以离去，（也）可以主动选择开战"与边界规则 #4"交易结束 NPC 消失"直接冲突。若可杀商，最优策略永远是"交易完就杀"回收资源；若消失则贸易有真实成本。**建议：交易/情报完成后 NPC 必定退场**（战利品归零兜底），防杀商刷子。
- **N3 隐藏倾向翻转**：设计"交易/情报失败后立场可能滑向敌视"是好设计，但"失败"定义未给出（提议被拒？预算不足？）。落地时：翻转掷骰必须来自局种子并写入事件日志（AGENTS.md 隐藏状态本地可复现）；失败判定需数据化（如 `will` 对照）。
- **N4 魂魄作货币**：风险同 R2，且"魂魄减少→战斗数量上限不变（方案 A）"时魂魄作货币影响的是死亡线与反噬容忍度，需要数值约束（单笔交易扣魂魄上限，防一买暴毙）。
- **N5 无视离开的边界**：设计规则 #2（关键 NPC 不可无视、极度仇恨不可逃）合理；现状 `on_skip` 机制可承载（关键节点 `on_skip: blocked` 已存在，如 stage_one_ledger）。"特殊道具才能脱离战斗"的道具来源未定义（建议：黑市/NPC 交易可购的"脱身符"类一次性道具）。
- **N6 情报→战斗增伤**：设计"拿到弱点的 NPC 开战时战斗内增伤"，现网无此机制；需在战斗命令中携带"intel"标记并走事件日志记录来源（小任务）。
