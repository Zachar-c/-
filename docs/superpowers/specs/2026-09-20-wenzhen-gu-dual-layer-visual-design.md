# 《问真》视觉体系原则：蛊虫双层表现体系 v2.0

状态：

```yaml
TYPE: PRODUCT VISUAL PRINCIPLE
SOURCE: L1 Research（v1.0）；L0 产品收敛裁定（v2.0）
APPROVAL: L0（用户）
STATUS: L0 APPROVED WITH REVISION
SCOPE: 蛊虫表现、图鉴、卡牌、主题外观
NOT: 数值规则修改
```

## 一、核心原则

《问真》采用：

```text
本体层（Canon Representation）
+
主题层（Player Expression）
```

的双层视觉体系。

目标：

在保持《蛊真人》世界规则可信度的同时，为游戏提供现代化、美术化和长期内容扩展空间。

## 版本变更（v2.0）

v2.0 取消原 A/B/C 人格化生产档。

原因：

- 低价值过渡档不能提供足够收藏价值；
- 半成品档位的制作成本接近角色级内容，却缺少对应回报；
- 只有高完成度主题皮肤才具备明确的情感连接与商业价值。

因此：

```text
v1.0：本体层 + A/B/C 人格化档位
v2.0：本体层 + 高完成度主题皮肤
```

主题皮肤不再按“人格化程度”分档，而是按内容价值筛选制作对象。

## 二、本体层（Canon Representation）

### 定义

本体层代表：

> 蛊在《问真》世界中真实存在的形态。

它承担：

- 世界观表达；
- 战斗识别；
- Lore 对齐；
- 游戏规则理解。

### 约束

本体层必须遵守：

#### 1. 身份不可替换

蛊虫名称、能力、流派、功能来源必须保持一致。

例如：

```text
月光蛊
=
月道能力载体

小光蛊
=
光道能力载体

石皮蛊
=
防御能力载体
```

视觉设计可以创新，但不能让玩家无法理解其规则身份。

#### 2. 原著明确形态优先

如果原著已经明确描述：

- 外形；
- 材质；
- 特征；
- 功能表现；

则本体层优先遵循。

例如：

- 石皮蛊具有石质特征；
- 月光蛊具有玉质/月光相关特征。

#### 3. 未明确区域允许创造

对于原著没有详细描述的蛊：

允许重新设计。

设计依据：

```diff
功能
+
流派
+
能力逻辑
+
世界生态
```

而不是简单套用普通昆虫模板。

## 三、主题层（Player Expression）

### 定义

主题层是：

> 玩家可解锁、收藏、切换的幻想表现，不改变蛊的真实身份。

它不是世界真实层。

类似：

- 卡牌皮肤；
- 图鉴外观；
- 收藏主题；
- 限定表现。

### 主题皮肤标准

主题皮肤统一按“高完成度主题皮肤”制作。

允许：

- 拟人化；
- 角色化；
- 概念化；
- 风格化。

但必须满足：

```text
主题皮肤 ≠ 修改世界事实

主题皮肤 = 对蛊意志、属性、传说的视觉解释
```

### 主题层生产策略

不平均分配产能。

资源集中于同时具备以下价值的蛊：

```text
高辨识度
+
高使用率
+
高收藏价值
+
高情感潜力
```

第一批主题皮肤只考虑以下筛选类别。它们不是生产档位，而是内容筛选条件：

#### A 类：核心代表蛊

条件：

- 原著辨识度高；
- 玩家认知强；
- 能代表世界观。

例如：

```text
春秋蝉
智慧蛊
月光蛊
酒虫
定仙游
```

#### B 类：具有人格空间的蛊

条件：

- 原著体现意志；
- 有成长或故事空间；
- 适合角色化表达。

#### C 类：商业收藏蛊

条件：

- 视觉记忆点强；
- 容易形成玩家喜爱；
- 适合长期运营。

## 四、拟人化主题规则

《问真》允许：

### 蛊虫主题皮肤

作为主题层内容存在。

高完成度主题皮肤允许包括：

- 人格化；
- 半人化；
- 角色化；
- 概念化。

但必须满足：

```text
不修改本体身份
不修改能力规则
不修改世界设定
```

### 示例

正确：

```text
月光蛊

本体：
玉质蛊虫/月光形态

主题皮肤：
月华少女主题形态

说明：
月光蛊人格化表现
```

错误：

```text
创造一个月光少女角色

但玩家不知道她是一只蛊
```

## 五、主题表达不能退化为统一模板

主题层允许人物化，但禁止机械化处理，也禁止把“高完成度”理解为同一个模板。

不同蛊应拥有不同表达方向：

| 类型可能方向 | |
| --- | --- |
| 生命类蛊 | 少女、少年、兽化、人外 |
| 器物类蛊 | 器灵、机械、武器人格 |
| 植物类蛊 | 自然精灵、妖植 |
| 概念类蛊 | 抽象人格、规则化形 |

核心原则：

> 人格化服务于蛊的规则表达，而不是替代蛊的规则表达。

## 六、视觉商业化原则

主题层的意义：

不是改变《蛊真人》。

而是提供：

```text
原著世界
        ↓
游戏化表达
        ↓
玩家个性选择
```

因此：

基础玩家看到：

```text
这是蛊真人世界中的蛊。
```

收藏玩家看到：

```text
这是我选择的独特表现。
```

两者不冲突。

### 商业产能原则

不再为所有蛊制作过渡档。

802 只蛊不可能全部高质量人格化。首批内容应集中于少量高价值主题蛊，以建立收藏驱动力，并验证主题皮肤是否真正形成玩家展示、讨论与长期追求。

### 主题皮肤目标

主题层不是：

> 让蛊稍微可爱一点。

而是：

> 创造玩家愿意收藏、展示、讨论的视觉资产。

因此主题皮肤允许达到角色级设计质量。

## 七、禁止事项

### 禁止 1：将主题皮肤误认为世界事实

例如：

错误：

> 月光蛊原本就是少女。

正确：

> 月光蛊拥有少女主题外观。

### 禁止 2：为了吸引力破坏能力语义

例如：

- 防御蛊不能设计成明显攻击型形象；
- 治疗蛊不能视觉上表现为纯破坏。

### 禁止 3：所有蛊统一人格模板

避免：

```text
100只蛊
=
100个不同发型少女
```

这种低辨识度设计。

### 禁止 4：制作低价值过渡档

不再制作仅改变少量外观、但无法形成独立收藏价值的中间档主题皮肤。

主题内容要么不进入制作，要么直接追求高完成度。

## 八、最终视觉定位

《问真》的蛊虫视觉目标：

不是：

```text
完全复刻原著插图
```

也不是：

```text
脱离原著的二次元角色收集
```

而是：

```diff
原著规则作为骨架
+
游戏美术作为表达
+
主题皮肤提供自由
```

v2.0 的产品裁定是：

```text
本体：
严格原著一致。

主题：
开放高自由度角色化。

生产：
不制作低价值过渡档。

商业：
通过少量高价值主题蛊建立收藏驱动力。

目标：
同时满足原著玩家与更广泛的视觉消费用户。
```

## 九、对后续 AI / Worker 的执行要求

任何蛊虫视觉任务必须先回答：

1. 这是本体层还是主题层？
2. 如果是本体层：
   - 原著明确限制是什么？
   - 可创造空间在哪里？
3. 如果是主题层：
   - 是否保持蛊虫身份？
   - 是否保持能力语义？
4. 是否会让玩家误解规则？

未回答以上问题，不进入美术生成阶段。

### 本体任务

输入：

```text
蛊名称
+
原著视觉证据
+
HARD/SOFT/OPEN 标签
```

输出：

```text
Canonical Form
```

验收：

- 是否仍能识别原蛊；
- 是否符合原著关键特征；
- 是否保持名称、能力、流派、功能来源与真实关系。

### 主题任务

输入：

```text
蛊名称
+
本体形态
+
主题方向
```

输出：

```text
Theme Skin
```

验收必须同时满足：

1. 玩家可理解其来源；
2. 保留核心符号；
3. 不影响能力认知；
4. 具有独立收藏价值。

主题任务统一使用 `Canonical Asset / Theme Skin Asset` 二分，不提供 A/B/C 生产档选择。

## L0 裁决摘要

```text
APPROVED

蛊虫视觉采用“本体层 + 高完成度主题皮肤”双层体系。

本体层保证原著一致性。
主题层提供高自由度角色化表达。

拟人化允许存在，但属于解锁外观，不属于世界事实。

取消 A/B/C 人格化生产档。
```

## 层级与执行边界

- 本件由 L1 产出、L0 已批准，是产品视觉原则，不是游戏规则或数值方案。
- 本件低于 PRD 与 AI 开发协议，高于具体美术实现、资产任务和局部的视觉风格文档。
- v2.0 已覆盖 v1.0 的 A/B/C 人格化档位；HARD/SOFT 的解释以 `docs/superpowers/specs/2026-09-20-wenzhen-gu-hard-soft-binding-decision.md` 为准。
- 与现有游戏工程文档冲突时，不直接修改 `game/`；先登记冲突并上抛 L0。
- 任何落地任务必须明确写出来源层：本体层或主题层。
