# 蛊真人肉鸽垂直切片设计

> 日期：2026-09-03。状态：已获用户确认，作为第一轮可试玩交付边界。

## 目标

在现有 Godot 4.7.2 半成品上交付一个可立即试玩的 10--20 分钟垂直切片。玩家必须能够从大厅开始一局，选择流派，经过地图节点、遭遇、至少一场战斗、战后奖励、休整或商店、炼蛊或强化、关底战斗，并主动确认结局后返回大厅。

## 范围

- 复用固定种子 101 的演示路线及现有 `RunController`、`Resolver`、地图生成、战斗和屏幕路由。
- 保留现有领域/表现层边界：UI 只渲染快照并提交命令，领域层负责状态转换、成本、随机和事件日志。
- 大厅提供流派选择；试玩路线至少覆盖遭遇、战斗、奖励、休整或商店、炼蛊或强化、关底和统一结算。
- 战斗继续使用蛊虫实例、真元、念头、生命/护盾和敌人意图等现有规则；关键风险和成本在执行前可见。
- 关底胜利后进入升仙窗口，由玩家二次确认结局；所有结局统一进入 `Ending`，展示统计并清理局内资源后回到大厅。
- 本轮不新增跨局战力、抽牌/手牌/弃牌堆规则、平行经验等级或独立的第二套控制器。

## 不在本轮范围

- 完整 3--5 小时、200--300 节点的最终内容平衡。
- 新的流派、资源类型、存档格式或第三方依赖。
- 重写现有 UI 工具链、RUI 组件体系或 vendor 目录。

## 验收路径

使用大厅开始固定种子 101 的一局，按地图可见候选节点推进。验收记录应能确认：

1. 大厅可以选择流派并成功创建 `RunState`。
2. 地图显示可达节点，旅行命令进入遭遇或战斗屏。
3. 遭遇命令能够启动战斗；战斗回合可使用蛊虫或基础动作，敌人意图、生命和护盾可见。
4. 战斗胜利后不丢失生命、材料、元石或事件日志，并进入奖励/战后结算。
5. 至少一条休整、商店、炼蛊或强化路径可以完成并回到地图。
6. 关底节点可达；胜利后升仙窗口只提供可见且需确认的结局选择。
7. 结局页面展示结构化结果，局内资源清理，返回大厅后不能继续使用上一局构筑。
8. 相同种子和相同命令序列产生相同状态、结果和事件日志。

## 实现边界

- `RunController` 负责屏幕路由、命令提交和快照装载，不直接实现游戏规则。
- `Resolver`、`EncounterSessionResolver`、`BattleCommandFacade` 及现有领域规则继续作为唯一状态转换入口。
- 固定演示内容优先修复现有数据和路由断点；只有在无法满足验收路径时才新增最小测试覆盖或数据字段。
- 所有手工测试使用 `tools/play.ps1`；自动验证使用 `tools/test.ps1`、`tools/check.ps1` 及现有冒烟脚本。

## 风险与降级

- 若完整固定路线受既有内容门禁阻塞，可在不绕过领域命令的前提下缩短演示路线，但不得伪造战斗胜利、奖励或结局状态。
- 若云端对话不可用，继续使用现有本地模板降级。
- 任何未能验证的图形渲染或交互状态必须在交付说明中明确列出。
