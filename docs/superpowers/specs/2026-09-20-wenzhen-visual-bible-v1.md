## VISUAL_BIBLE

## 1. 世界视觉核心原则

### 核心定义

《问真》的视觉必须持续表达：

> **这是一个由规则生命构成的超凡世界。力量不是外部装备，而是生命、规则与代价共同形成的结果。**

视觉判断标准不是：

> “是否华丽”。

而是：

> “玩家是否能理解这个对象为什么拥有这种力量”。

### 必须稳定

所有视觉资产必须共享以下底层规律：

#### 1. 能力来源可追溯

任何力量表现必须回答：

```text
这个效果来自什么？
↓
哪只蛊？
↓
什么组合？
↓
付出了什么代价？
```

禁止：

无来源的光效、爆炸、魔法纹路。

#### 2. 超凡但非神秘万能

《问真》的力量不是：

```text
召唤神迹
```

而是：

```text
理解规则
+
利用规则
+
承担规则代价
```

#### 3. 生命与规则统一

蛊不是：

- 道具；
- 装备；
- 技能图标。

蛊是：

```text
生命形态
+
规则载体
+
能力来源
```

### 允许变化

允许：

- 不同流派拥有不同表达；
- 不同转数拥有不同复杂度；
- 不同五域拥有不同社会视觉；
- 主题层拥有高度自由表达。

### 禁止回潮

禁止回到：

#### 普通仙侠模板

包括：

- 纯粹飞剑法宝视觉；
- 仙气飘渺万能光效；
- 金碧辉煌仙宫；
- 无代价的大招爆炸；
- 角色站桩释放技能。

原因：

这些表达强调：

> “人控制力量”。

而《问真》强调：

> “人理解并驾驭规则生命”。

#### 旧水墨方案

旧方案的问题不是水墨本身。

问题是：

它容易把《问真》降维成：

```text
东方仙侠插画
```

而不是：

```text
蛊道规则世界
```

因此旧方案不能作为默认视觉约束。

### HARD / SOFT / OPEN 映射

| 层级 | 作用 |
| --- | --- |
| HARD | 保护身份 |
| SOFT | 提供重新解释空间 |
| OPEN | 建立独特世界表达 |

规则：

```text
HARD决定“它是什么”
SOFT决定“它如何被表达”
OPEN决定“它如何区别于其他作品”
```

## 2. 本体层规范

### 定义

本体层：

> 蛊在《问真》世界中真实存在的形态。

承担：

- 世界真实性；
- 战斗识别；
- Lore 对齐；
- 规则理解。

### 识别规则

一个本体设计必须满足：

#### 第一眼识别

玩家应该能回答：

> “这是什么蛊？”

而不是：

> “这是什么漂亮东西？”

#### 第二层理解

玩家应该能理解：

- 流派倾向；
- 能力来源；
- 使用方式。

### 材质与结构规则

本体设计优先表现：

```text
结构 → 功能 → 美感
```

而不是：

```text
美感 → 加特效 → 编故事
```

例如：

防御类蛊：

应该体现：

- 防护结构；
- 稳定性；
- 承载能力。

而不是：

随机套一个护盾光圈。

### 生命感规则

蛊必须具有：

> “活着”的感觉。

但：

> 生命感 ≠ 必须像动物。

允许：

- 虫；
- 植物；
- 矿物生命；
- 器物生命；
- 概念生命。

### 代价感规则

本体视觉应暗示：

> 力量不是免费的。

可以表现：

- 消耗；
- 脆弱点；
- 限制；
- 不稳定性。

## 3. 主题层规范

### 定义

主题层：

> 玩家对蛊的收藏表达，不等于世界事实。

### 人格化边界

允许：

- 半人化；
- 完整角色化；
- 概念人格化。

但必须满足：

```text
玩家知道：
这是月光蛊主题皮肤

而不是：
月光蛊真实就是一个少女
```

### 来源识别规则

主题皮肤必须保留：

至少一个核心识别锚点：

例如：

- 形态；
- 能力象征；
- 材质；
- 色彩逻辑；
- 标志结构。

### 幻想表现标识

主题层需要明确：

它属于：

```text
收藏表达
```

而非：

```text
世界设定
```

### 禁止事项

#### 1. 人格化替代本体

错误：

月光蛊：

> 变成普通月神少女。

正确：

> 月光蛊的幻想人格化表达。

#### 2. 失去能力来源

错误：

火系蛊皮肤变成冰系少女。

#### 3. 模板化二次元角色

禁止：

所有蛊：

- 一个脸；
- 一个身体模板；
- 换颜色。

## 4. 材质语言

### 约束对象

材质负责表达：

> “这个东西为什么属于这个世界”。

### 必须稳定

材质需要具有：

#### 超凡可信度

玩家感觉：

> “它真的可以存在。”

#### 规则关联性

材质应该暗示：

能力来源。

例如：

- 月道 → 月光、晶体、冷感；
- 炼道 → 结构变化、融合感；
- 防御 → 稳定、承载感。

### 不约束

不规定：

- 单一材质；
- 单一颜色；
- 单一表现形式。

### HARD / SOFT / OPEN

HARD：

明确材质必须保留。

SOFT：

材质表现方式。

OPEN：

未知结构创新。

## 5. 光影语言

### 核心原则

光不是装饰。

光必须说明：

> 力量状态。

### 必须稳定

光影表达：

```text
来源
+
状态
+
强度
```

例如：

不是：

> “发光很帅”。

而是：

> “这个蛊正在释放某种能力”。

### 禁止

- 无意义全屏光爆；
- 颜色越亮代表越强；
- 神圣万能光。

### 转数表现

低阶：

强调：

- 材质；
- 局部力量。

高阶：

允许：

- 空间变化；
- 概念化；
- 大尺度规则表现。

## 6. 构图规则

### 核心原则

构图服务理解。

不是海报优先。

### 本体层

优先：

```text
对象识别
↓
结构观察
↓
细节欣赏
```

要求：

- 主体明确；
- 轮廓清晰；
- 不被背景抢夺。

### 主题层

允许更多：

- 情绪；
- 故事；
- 人格表达。

### 场景层

必须体现：

> 人与世界关系。

不是：

> 单纯漂亮背景。

## 7. Prompt 规范

### Prompt 结构统一

以后所有 GPT Image 任务采用：

```css
[世界定位]

+

[资产层级]

+

[对象身份]

+

[HARD约束]

+

[SOFT发挥]

+

[OPEN创新]

+

[材质]

+

[光影]

+

[构图]

+

[禁止事项]
```

### 禁止低质量 Prompt

禁止：

> “做一个帅气蛊虫”

这种无法验收的描述。

必须回答：

```text
它是谁？
为什么存在？
力量来源是什么？
不能变成什么？
```

## 8. 资产验收标准

任何资产进入候选库前必须通过：

### A. 身份验收

问题：

> 不看名字，是否能判断它是谁？

失败：

退回。

### B. 世界一致性验收

问题：

> 它是否属于《问真》的世界？

失败：

如果像：

- 普通仙侠；
- 普通二游；
- 普通魔幻。

退回。

### C. 规则一致性验收

问题：

> 外观是否支持能力理解？

失败：

视觉和机制割裂。

### D. 双层验收

本体：

必须：

```text
符合世界事实
```

主题：

必须：

```text
保留身份锚点
```

### E. 收藏价值验收

主题资产：

必须回答：

> 为什么玩家想拥有它？
