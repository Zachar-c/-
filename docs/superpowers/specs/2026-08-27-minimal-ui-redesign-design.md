# 《問眞》极简 UI 重设计规格

- 日期：2026-08-27
- 状态：已完成视觉母版评审，待书面规格复核
- 范围：完整替换现有视觉世界；先以大厅、地图、战斗三张母版建立系统，再推导其余界面
- 技术边界：Godot 4.7.2、RUI `.guitkx`、GDScript；UI 只读快照并通过 `RunController` 提交命令
- 替代关系：本规格取代 `2026-08-26-ui-sts-redesign-design.md` 的品牌、视觉语言、布局、组件外观与动效章节；旧规格中不冲突的页面覆盖、领域规则、流转和信息透明约束继续有效

## 1. 设计命题

游戏正式名为横排繁体 **《問眞》**。

主题不是蛊虫陈列，而是一个人在代价、命运与自我之间不断确认真性情：

> 蠱為術，道為途，我自問眞。

UI 不充当世界观说明墙，也不以装饰证明“仙侠”。它应像一张被修行者使用过的宣纸：克制、准确、有呼吸，同时让每一项策略事实立即可读。

本设计的极简定义是：

> 每一项决策所需信息都有固定位置、固定符号和明确出现规则。极简不等于隐藏策略信息。

因此：

- 高频决策信息常驻，不依赖打开面板。
- 中频详情由悬停、聚焦或长按 Tooltip 提供。
- 低频资料进入独立子视图。
- 留白用于建立归属和视线，而不是牺牲内容尺寸。
- 美术必须让角色、敌人、蛊虫和地点成为第一视觉信号，UI 退居其后。

## 3. 视觉世界

### 3.1 材质与色彩

| Token | 建议值 | 唯一语义 |
| --- | --- | --- |
| `PAPER` | `#ECE9DF` | 游戏主表面、宣纸白 |
| `PAPER_DEEP` | `#DDD8CC` | 次级纸面、禁用层、轻分区 |
| `INK` | `#171814` | 主文字、主结构线 |
| `INK_SOFT` | `#686960` | 次要文字、已知但不紧急的信息 |
| `RULE` | `#AAA89F` | 发丝分隔线、轨迹与边界 |
| `CINNABAR` | `#9C332D` | 危险、不可逆、死亡线、当前焦点 |
| `CONTRACT_BLUE` | `#315F73` | 契约规则，禁止挪作普通装饰 |
| `ANOMALY_YELLOW` | `#936F1E` | DDA、异变、险象，禁止与契约混用 |
| `JADE` | `#3F7063` | 护盾、有效增益、可恢复状态 |

规则：

- 全游戏以宣纸白为主，不使用暗色地牢作为常规界面底色。
- 朱砂只表达危险、不可逆动作、死亡线和当前交互焦点；不能成为普遍强调色。
- 契约蓝与异变黄必须分区，不能只依赖文字区别。
- 不使用渐变字、彩色光晕、玻璃卡片、装饰性圆角面板或一屏同色系堆叠。
- 纸张质感只能是低对比细颗粒，不可降低文字、角色和路径可读性。

### 3.2 字体

- 游戏名、屏幕主标题、角色名：有真实字形品质的繁体宋体或楷体资产。
- 正文、数值、按钮：清晰的中文宋体或黑体资产。
- 数据与计数可使用等宽数字，但不能用等宽字体制造“技术感”。
- 字距固定为 `0`；不按视口宽度缩放字体。
- 《問眞》始终横排，字间不拥挤，上下必须保留足够延伸空间。

生产实现前必须完成字体许可证核验并将字体打包进项目，不能依赖开发机系统字体得到最终效果。

### 3.3 线、容器与层次

- 页面分区优先使用留白和 1px 发丝线。
- 不把页面章节做成浮动卡片；卡片只用于真正的蛊牌、重复商品/奖励项和受保护的确认对话。
- 不允许卡片嵌套卡片。
- 控件圆角上限 8px；本视觉世界优先直角或 2px 微圆角。
- 悬浮层只使用一次轻投影建立前后关系，不同时叠加描边与厚阴影。
- 图标使用同一套线性矢量资产；禁止用 Emoji 或随意 Unicode 字符代替正式图标。

### 3.4 影像与角色

- 大厅第一视口必须出现真实角色/地点美术与横排《問眞》，不能只有菜单文字。
- 战斗角色使用真实立绘、序列帧或动画资产；不得用 CSS 几何剪影、文字框、泛化矩形或卡牌代替人物。
- 单敌居中且放大；多敌按阵型重排，不缩成不可读的小图标。
- 图片可进行灰度、水墨化和纸面融合处理，但人物轮廓、姿态和朝向必须清楚。
- 正式资产要保留角色面对战场方向的延伸空间，标题和 UI 不得截断其视线或动作方向。

## 4. 信息分层

### 4.1 三档出现规则

**常驻高频**：当前决策每回合或每节点都要读取的事实。

- 局内资源、契约、异变、死亡线。
- 战斗真元、操作上限、牌堆计数。
- 敌人精确意图、生命、护盾、Buff/Debuff。
- 地图可达路径、已知节点类型、已知危险和已知奖励。

**触发中频**：需要理解但不必持续占据画面的详情。

- 卡牌完整效果、联动、来源和关键词解释。
- 敌人意图速度、结算顺序和反制提示。
- 状态剩余回合、叠层规则和来源。
- 契约、异变的完整规则。

桌面端使用悬停和键盘聚焦；移动适配必须提供点击/长按等价路径。

**收纳低频**：完整牌组、图鉴、手记、设置、统计和规则档案。

### 4.2 固定归属

- 跨场景事实归全局顶栏。
- 角色局部事实锚定角色脚下或近身区域。
- 敌人下一步行动锚定其头顶。
- 卡牌费用、名称、插画、效果和品质在卡面固定位置。
- 路线关系由线和节点表达，不用说明文字替代拓扑。
- 解释层不得挤压或重新排版其所属主体。

## 5. 大厅母版

大厅是“这一世的第一页”，不是菜单墙。

### 5.1 有进行中 Run

- 唯一主动作是「续入此世」。
- 只展示恢复判断必需的摘要：当前地点、阶段、生命/寿元风险、关键契约或异变、最近一次不可逆选择。
- 图鉴、手记、设置以安静的档案入口退到边缘。
- 不出现读档、回滚或重掷入口。

### 5.2 无进行中 Run

- 唯一主动作是「开启今世」。
- 跨局继承仅展示已批准内容：蛊方/图鉴、手记、契约解锁和零加成统计。
- 不展示或暗示跨局战力成长。

### 5.3 构图

- 横排《問眞》为最大一级标题。
- 标题上下留出明显空间，不截断人物头部、视线或身体动作的延伸方向。
- 角色/地点美术必须是首屏信号；操作文字不放进大卡片。
- 在常见桌面和移动比例下，首屏底部保留下一内容带的一点可见线索。

## 6. 地图母版

地图采用《杀戮尖塔》式多分支结构，但不把完整拓扑压缩进单屏。

### 6.1 视口与历史

- 一个视口约展示 2.5 个层级。
- 地图大于视口，通过滚轮、拖动和触控移动检查未来。
- 未来分支完整显示；已经经过的层级只保留实际路线，未选择历史分支隐藏。
- 当前节点保持足够大，不能为了展示更多未来而整体缩小。

### 6.2 路径与信息

- 每个节点可连接多个下一层节点，路径单向且清楚。
- 选中候选节点后，只强调其可达未来；其他未来仍可见但降权。
- 已知类型、危险和奖励必须显式呈现。
- `?` 仅代表真正未知的结果，不用于遮挡已被情报揭示的事实。
- 不可达节点不提交命令；已走路径和当前可选路径必须有不同语义。
- 节点符号固定，形成扫视记忆；文字只在 Tooltip 或节点详情层补充。

### 6.3 响应式

- 宽屏增加横向呼吸，不增加同屏层级数量。
- 窄屏保持节点物理尺寸，通过平移检查分支。
- 触控支持单指平移、双指缩放和点击节点详情；不依赖悬停。

## 7. 战斗母版

战斗参考《杀戮尖塔》的信息架构与空间纪律，不参考其暗色地牢、厚框、拟物按钮或卡通风格。

### 7.1 上视界：全局 HUD

常驻：

- 魂魄及一心多用/操作上限。
- 寿元、元石、已行节点或当前层级。
- 契约蓝区、异变黄区、诅咒/反噬/死亡线朱砂区。
- 地图、牌组、设置等低频入口使用图标按钮和 Tooltip。

战斗真元不放在全局顶栏，放到下方手牌决策区；玩家和敌人的生命、护盾、状态不放在顶栏。

### 7.2 中视界：战场

- 玩家角色在左，敌方阵型在右。
- 生命和护盾分开显示，并锚定各自角色。
- Buff/Debuff 使用图标和叠层数字；详情层显示持续时间、来源和叠加规则。
- 每名敌人独立显示意图图标、精确数值和行为类型。
- 意图 Tooltip 显示完整效果、速度、结算顺序和当前反制影响。
- 所有公开意图同时可见，不轮播、不折叠、不用总数替代逐敌信息。
- 可在不代替逐敌信息的前提下显示本回合预计生命损失汇总。

敌阵：

- 1 敌：居中放大。
- 2 敌：前后错位，意图与状态互不遮挡。
- 3 敌：浅弧或前后层次排列，三名敌人仍保持可辨认尺寸。
- 4+ 敌：紧凑两排；前后排关系明确，公开意图全部保留。
- 阵型变化只重排敌方战场，不改变 HUD、玩家和手牌区尺寸。

### 7.3 下视界：手牌决策区

- 手牌水平居中，占据下方主要决策空间。
- 真元靠近手牌左侧。
- 抽牌堆在左下，弃牌堆和消耗牌堆在右下。
- 结束回合在右下独立于手牌，不会被卡牌遮挡。
- 卡面固定布局：左上费用、顶部名称、中部插画、下部效果、品质/边框、升级标记。
- 无法支付的卡牌整体降权，同时 Tooltip 精确说明缺少的资源或守卫条件。
- Tooltip 展开不永久占据战场，也不引发布局位移。

### 7.4 卡牌交互 FSM

互斥状态：

```text
Idle -> Hover -> DragStart -> Dragging
Dragging -> PlaySuccess                 [无目标牌且释放区合法]
Dragging -> TargetSelect                [需要目标且释放区合法]
TargetSelect -> PlaySuccess             [合法目标]
Dragging/TargetSelect -> DragCancel -> Idle
```

守卫和回退：

- `canPlay == false` 时不能进入 `DragStart`。
- `ESC`、右键或拖回手牌取消，回到 `Idle`。
- 选目标时只高亮合法目标，公开敌方信息不被遮罩隐藏。
- 普通无目标卡可直接释放执行。
- 新手可启用普通目标二次确认；熟练玩家可关闭普通确认。
- 寿元、魂魄、反噬、杀招和其他不可逆成本不能被设置关闭确认。
- 命令提交前必须经过领域权威预检；UI 不自行计算致死结论。

视觉层独立于 FSM 数据：卡牌本体、Tooltip、合法目标遮罩、飘字、受击反馈和确认层分别开关，不能揉进卡牌节点内部形成状态耦合。

## 8. 由母版推导其他界面

其余界面不另造视觉世界，按以下规则继承：

- 事件：沿用大厅的叙事留白和战斗的信息归属；选项后果常驻，详情触发显示，危险选择走朱砂确认层。
- 商店/NPC：沿用战场左右关系，左为人物与立场，右为商品/交易；价格、剩余次数和通胀贴交易项。
- 休整/成长：沿用大厅单主动作纪律；互斥选项平铺，不做多层卡片。
- 炼蛊：沿用战斗下视界的操作台纪律；输入、产物、成功率、诅咒继承和全部代价同屏可见。
- 奖励：卡牌组件保持战斗中的固定信息位置；槽满必须进入显式取舍。
- 图鉴/手记：采用阅读界面，不沿用战斗 HUD；内容优先，筛选与导航安静常驻。
- 结算：沿用地图的路线表达与大厅的生命叙事；六要素、路线、契约和 DDA 复盘不做仪表盘卡片阵列。
- 设置：使用标准列表、分段控件、滑块、开关和图标按钮，不做装饰卡片。

## 9. Tooltip、确认与反馈层

### 9.1 Tooltip 固定格式

卡牌/蛊虫：

1. 名称与品质。
2. 精确效果。
3. 联动与关键词解释。
4. 精确代价。
5. 诅咒或不可逆警示。

敌人意图：行为、精确数值、速度、效果、结算顺序、当前预期结果。

状态：名称、层数、剩余回合、叠加规则、来源、移除条件。

### 9.2 受保护确认

以下动作必须显示领域预检结果并二次确认：

- 消耗寿元或魂魄。
- 增加反噬、诅咒或可能触发死亡线。
- 杀招释放。
- 炼蛊失败风险与诅咒继承。
- 槽满替换、拆解、永久丢弃。
- 非死亡结局和主动放弃。
- 清除存档或破坏性设置。

确认层描述执行前后精确值、即时后果和不可撤回性。确认层保护焦点，关闭后返回触发前状态；陈旧版本命令由现有 stale-command 机制拒绝。

### 9.3 动效

- 卡牌悬停/抬起：100–160ms。
- 拖拽归位：160–220ms，明确回到原手牌位置。
- Tooltip：快速淡入，不移动底层布局。
- 伤害、护盾和资源变化：数字与所属对象同源出现。
- 杀招和死亡演出可跳过；普通动作不以长动画拖慢长局。
- 禁止无意义常驻呼吸、循环光晕和所有元素统一入场动画。

## 10. 呈现边界与快照契约

生产 UI 继续遵守：

- `.guitkx` 是 UI 源文件；禁止手改生成的 `ui/**/*.gd`。
- 屏幕只读取快照，通过 `RunController`/既有命令构造器提交行为。
- UI 不直接修改 `RunData`、RNG、存档、敌人或结局。
- 命令携带显示时的状态版本，保留 stale-command 拒绝机制。
- 所有不可逆后果由领域服务计算；UI 只呈现预览结果。

战斗母版落地前，快照至少需要审计并按真实领域能力补足：

- 抽牌、弃牌、消耗牌堆数量。
- 魂魄操作上限与已使用次数。
- 多个存活敌人实体及各自唯一标识。
- 敌人意图图标语义、精确数值、效果文本、速度和目标范围。
- 角色 Buff/Debuff 的图标 ID、层数、持续时间、来源和 Tooltip 文本。
- 卡牌费用、品质、升级、插画 ID、目标类型和不可用原因。
- 生命与护盾独立值。
- 寿元/魂魄/反噬等动作的领域预检结果和确认级别。

如果当前领域只支持单敌，必须先扩展领域和快照模型，再接多敌 UI；禁止由 UI 伪造多个敌人或自行分摊伤害。

## 11. 响应式与可访问性

- 目标优先级：Windows 桌面 16:9，其次宽屏与窄屏桌面，最后触控适配。
- 固定格式元素使用稳定尺寸、网格轨道和 `aspect-ratio`，状态变化不得推动主布局。
- 文本必须在中文最长文案和繁体字下验证，不得遮挡前后内容。
- 颜色不是唯一编码：危险、契约、异变、Buff/Debuff 同时有图标/形状/文字。
- 所有悬停信息支持键盘聚焦；所有按钮有可读名称和清晰焦点态。
- 触控端用点击/长按代替悬停，目标尺寸不得小于可可靠点击的范围。
- 提供减少动态效果选项；快速模式缩短而不是破坏反馈顺序。

## 12. 验收与测试

### 12.1 结构验收

- 大厅有且只有一个情境主动作。
- 地图在当前视口约显示 2.5 层，未来完整、历史折叠、当前节点可读。
- 战斗 HUD、战场、手牌三层在切敌阵和卡牌状态时尺寸稳定。
- 1/2/3/4+ 敌阵均不遮挡意图、生命、护盾或状态。
- 五至七张手牌仍可读取费用、名称和核心效果。

### 12.2 行为测试

- 不可支付卡不能进入拖拽，且暴露精确不可用原因。
- 有目标/无目标卡按 FSM 进入正确状态。
- `ESC`、右键、拖回手牌均可取消。
- 危险卡必须消费领域预检并显示精确确认文案。
- stale command 在快照变化后被拒绝，UI 刷新到权威状态。
- 不可达地图节点不能提交 travel command。
- 槽满、空池和所有结局保持现有领域约束。

### 12.3 视觉验证

- 使用 Godot 实际渲染，不以 HTML 原型截图代替最终验收。
- 至少检查 1920×1080、1366×768、2560×1440 和一个窄屏比例。
- 检查文字截断、图层遮挡、Tooltip 越界、禁用态、加载态、空状态和错误态。
- 多敌、最大状态数量、长卡名、长效果、长契约名使用真实极限数据验证。
- 战斗角色资产非空、朝向正确、主体不被裁切；画布像素检查不能为纯色或透明占位。
- 执行现有 UI capture/smoke 流程、相关 GUT 测试和完整 `tools/check.ps1`。

## 13. 实施范围与顺序

本规格批准后另写实施计划，顺序固定为：

1. 视觉令牌、字体与图标基础。
2. 全局 HUD、Tooltip、确认层和卡牌公共组件。
3. 大厅母版生产化。
4. 地图母版生产化。
5. 战斗快照契约与领域缺口审计。
6. 战斗母版生产化及卡牌 FSM。
7. 由三张母版推导其余屏幕。
8. 全流程视觉、行为、发布构建回归。

每一阶段先写可失败测试或可执行验收，再修改最小生产代码。设计探索文件不进入运行时，也不作为正式资产打包。

## 14. 明确不做

- 不在本轮改变已锁定的游戏规则、经济或结局。
- 不加入读档、撤销、回滚或 Save Scumming。
- 不由 UI 充当规则引擎、预检器或多敌模拟器。
- 不用程序化框线、CSS 人形或文字块替代最终角色美术。
- 不把《杀戮尖塔》的美术、暗色地牢、卡通比例、厚重边框和拟物按钮复制进《問眞》。
- 不以“极简”为由隐藏公开敌人意图、危险成本、路径信息或当前状态。
