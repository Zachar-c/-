# 《问真》视觉阶段优先级补充裁定

```yaml
STATUS: APPROVED
DATE: 2026-09-20
AUTHORITY: L0 确认的 L1 REVIEW 调整
SCOPE: 视觉线阶段优先级、A 轨限制、L2 阶段门禁
PURPOSE: 防止用结构验证、资产复用或单点 POC 替代视觉定位决策
```

## 一、裁定结论

当前计划方向正确，但阶段优先级必须调整：

> 当前视觉线唯一最高优先级是完成视觉定位决策。

当时最大风险不是工程结构无法承载双层体系，而是新视觉方向尚未冻结。
该风险现已由 L0《问真》视觉定位 v1.0 冻结件关闭。

因此：

- A 轨结构验证可以存在，但不得成为主线工作；
- 资产复用可以存在，但不得成为视觉方向未决时的替代性进度；
- 月光蛊 POC 定位正确，但必须排在视觉定位决策和视觉规范冻结之后。

## 二、强制执行顺序

```text
1. 完成《问真视觉定位决策稿 v1》Research Request
2. L1 输出视觉定位候选方案
3. L0 裁决视觉母方向
4. 冻结视觉规范
5. 启动月光蛊 Visual Proof of Concept
6. 最后进行结构验证适配
```

顺序不得倒置。

## 三、A 轨限制

A 轨只允许：

- 低成本结构验证；
- 复用现有组件与占位资源；
- 验证 UI、交互和信息架构是否能承载已冻结的视觉规则。

禁止：

- 因结构验证提前修改大量 `game/`；
- 用复用旧资产拖延新视觉验证；
- 把旧资源表现效果作为方向依据；
- 将 A 轨扩展成 UI 开发、组件重构或资产生产。

## 四、B 轨与月光蛊 POC 的前置

月光蛊任务必须保持：

```text
Visual Proof of Concept
NOT Canonical Asset Production
```

启动前必须满足：

```text
视觉定位决策完成
+ L0 冻结视觉母方向
+ 视觉规范冻结
+ L1 审查 Prompt
+ GPT Image only
+ 单样本通过后才允许下一样本
```

## 五、L2 阶段门禁

L2 收到视觉任务时，必须先执行阶段判断，而不是直接拆解执行：

```text
收到任务
→ 判断当前阶段
→ 确认上游决策是否冻结
→ 未冻结：BLOCKED / ESCALATE
→ 已冻结：再拆解、派 Worker、执行
```

若方向未冻结，L2 不得用以下工作制造“正在进行”的假象：

- 复用盘点；
- UI 组件整理；
- 旧资产清理；
- 非前置性的文档扩展；
- 单点美术试验。

这些工作只能作为明确的低优先级旁路，不能取代上游决策。
