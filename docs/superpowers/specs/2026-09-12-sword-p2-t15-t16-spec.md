## 1. T15 刻痕通道（P2 第一优先）

### 1.1 原文依据（重查报告 §2-M3）

> 「剑痕索命这个杀招，是**永久性地耗费剑道仙蛊中的道痕，刻印在目标的身上**。剑道仙蛊飞走之后，
> **剑道道痕就会自寻目标的弱点**，加以攻击。」
> 实例：「仙蛊贯穿的伤口，**很快就自己愈合了**。但它**刻印下来的剑道道痕，却游走在雪怪体内**，
> 将雪怪体内深藏不漏的**雪核绞杀**。」

⇒ 剑道的伤害**不是"砍掉多少血"，而是"在目标体内埋下会自动找要害的道痕"**；表面伤口会愈合，**刻印不会消失**。
⇒ 成熟对照：STS 中毒——**独立伤害通道**，不吃格挡、不受力量影响（「ignores enemy Block completely」）。

### 1.2 现状缺口（实测）

| 事实 | 位置 |
|---|---|
| `status` 白名单只有 `marked` / `bound` | `content_catalog.gd:1161` |
| `marked` 由 **recon 角色兜底**产生（`default_effect_by_role.recon`），层数在 `enemies[i].statuses.marked` 累加 | `v1_battle.json`、`v1_battle_resolver._apply_enemy_status` |
| **全仓无任何读取 `marked` 参与伤害/结算的点**；仅 UI 转成「标记」文本 | F2 实测（重查报告 §0） |
| 结果 | recon 5 只（每流派）+ 剑道杀招的 `marked` 步 = **无结算效果**；20 个流派的 recon 蛊同此 |

### 1.3 设计（拟）

在**回合末**（`end_turn` 的敌方结算之后、新回合开始之前）新增一步：

```
对每个存活敌人：若 statuses.marked > 0 →
    damage = f(marked 层数)          # 独立通道：不吃护盾、不吃力量/虚弱
    扣敌方 hp；若 hp<=0 → alive=false（正常胜负判定）
    写入事件日志（新 action：mark_scratch），层数可见
```

**不影响玩家侧**：刻痕只伤敌，**不产生玩家致死路径** ⇒ 无需死亡预检
（任务书 T15 写的"死亡预检"源自已被重查推翻的「侵蚀自伤」，此处按重查口径更正）。

### 1.4 待裁定决策点

| # | 决策 | 选项 | 建议 |
|---|---|---|---|
| **D15-1** | 伤害公式 | (a) `damage = marked 层数`（线性）(b) 三角累加（STS 中毒式：10 层 = 10+9+…+1）(c) `层数 × 常数 K` | **(a)**：线性最易读、可被 `balance.json` 单点调参；三角在"层数难叠"的我们这里收益过低 |
| **D15-2** | 是否衰减 | (a) 不衰减（原文「刻印不会消失」）(b) 每回合 -1（STS 式） | **(a)**：贴原文；且层数受"每回合 2 念头"天然限流，无需衰减抑制 |
| **D15-3** | 是否吃护盾 | (a) 不吃（独立通道，剑道差异化）(b) 吃 | **(a)**：这正是"剑道不靠数值、靠结算方式"的落点，也是与其它流派的机制差异 |
| **D15-4** | **影响面** | (a) 全局：所有流派的 recon 蛊都获得伤害通道 (b) 仅剑道杀招的 `marked` 步生效 | **(a)**，但须明确这是**全局平衡变更**——它同时修掉「recon/logistics 25% 死数据」的结构性空洞（`gu-everything-mapping` M5 亦指向此）。若选 (b)，需为 `marked` 增加来源标记（新字段） |
| **D15-5** | 数值参数 | —— | 落 `data/balance.json`：`mark_scratch_per_layer`（默认 1）、`mark_scratch_cap`（默认 10，防失控） |

### 1.5 验收

1. 单测：给敌人叠 3 层 `marked` → `end_turn` 后 hp 减 3，且**护盾不减**（独立通道）。
2. 单测：`marked` 不因回合末而减少；跨回合持续。
3. 单测：`marked` 击破敌人时正常判胜（`_check_victory`）。
4. 单测：事件日志出现 `mark_scratch`（不可变、可归因）。
5. 回归：`integration` 31/31、`unit` 既有项不减、`check.ps1` 全绿。
6. **平衡复核**：20 流派 recon 蛊获得伤害后，重跑 `test_drive_to_ending` 的 25 seed 扫（断言 `reached_l5 ≥ 22` / `entered_ending ≥ 22` 不得退化）。

## 2. T16 残锋降转

### 2.1 原文依据（重查报告 §2-M7）

> 「原来，剑痕索命这个杀招，是**永久性地耗费剑道仙蛊中的道痕**」
> 「**永久性的消耗仙蛊上的道痕**……**无法回复**。这样一来，**剑道仙蛊会越来越弱**。
> 次数达到一定程度之后，就会引来**质变**，使得**六转仙蛊跌落到五转凡级**」
> 「每使用一次剑道杀招剑痕索命，就相当于**一次逆炼仙蛊**的过程」
> 市场评价：「这个弊端相当严重，使得剑痕索命这个杀招**价值不高，并不太受欢迎**」

⇒ 剑道真正的代价机制：**用强力杀招永久削弱你那只剑蛊，累积到质变就降转**。
原文亲自承认这是"强但没人愿意用"的设计——正是我们需要的**非唯一解范本**。

### 2.2 现状缺口（实测）

| 事实 | 位置 |
|---|---|
| `sword_mark_cost: true` 已在 **4 只** rank4–5 主力剑蛊上预留 | `data/gu.json`（4 处） |
| **全仓无读取点**（仅数据声明） | grep 实测 |
| 蛊实例无"道痕余量"字段 | `RunState.gu_instances[inst] = {instance_id, definition_id, state, rank}` |

### 2.3 设计（拟）

1. 蛊实例新增 `dao_marks`（道痕余量）：`gu_instances[inst]["dao_marks"] = N`。
2. 使用**带 `sword_mark_cost` 的杀招**时，其**配方中所有带该标记的剑蛊**各扣 1 点余量（= 逆炼）。
3. 余量低于阈值 → **等效转数下降**（`effective_rank = max(1, rank - downgrades)`），影响转数门禁与（若显式 amount 与转数挂钩的）结算表现。
4. **不可逆**：`dao_marks` 只能被 T15/T16 机制扣减，**无回复路径**（贴原文「无法回复」）。

### 2.4 待裁定决策点

| # | 决策 | 选项 | 建议 |
|---|---|---|---|
| **D16-1** | 余量载体与存档 | (a) `gu_instances[inst]["dao_marks"]`（新字段，**须提升 `SAVE_VERSION`** 并按缺键空迁移）(b) 复用 `node_flags` 旁路（不推荐：会把实例级状态塞进节点标记） | **(a)**，按项目既有迁移范式（缺键空迁移） |
| **D16-2** | 初值与阈值 | —— | 建议 `dao_marks_init = 5`、每扣 1 点；`downgrade_every = 5`（即 5 次逆炼降 1 转）；全部落 `balance.json` |
| **D16-3** | **不可逆代价的执行前预检**（红线强制） | (a) 出招前若会触发降转 → 弹确认（沿用 `lethal_confirm_required` 同款形状）(b) 只做提示不阻断 | **(a)**：红线要求「稀有资源永久消耗……执行前必须预检并明确提示」；降转不可逆 ⇒ 必须确认 |
| **D16-4** | 降转如何落到结算 | (a) 只影响**转数门禁**（能否催动）(b) 同时按比例下调显式 `amount` | **(a)** 先做（最小完整改动）；(b) 会与 T2–T4 的"行为保持"口径纠缠，建议另批 |
| **D16-5** | 可见性 | 蛊卡/战斗栏需显示"道痕余量 / 距降转还剩几次" | 属快照键扩容 ⇒ **须同步回写 `docs/contracts/2026-09-02-domain-ui-contract.md`** |

### 2.5 验收

1. 单测：带 `sword_mark_cost` 的杀招释放后，配方剑蛊 `dao_marks` 各 -1；无该标记的蛊不受影响。
2. 单测：扣至阈值 → 等效转数 -1，转数门禁随之变化（`insufficient_qi_quality` 路径可复现）。
3. 单测：**无回复路径**（任何现有命令都不得增加 `dao_marks`）。
4. 单测：触发降转前**必须**返回确认请求；未确认时不执行、不扣余量（红线）。
5. 单测：存档 roundtrip 保留 `dao_marks`；旧存档缺键时按初值迁移。
6. 契约：快照新键已回写 `docs/contracts/`；`check_contract_drift` 绿。
7. 回归：`unit` / `integration` / `check.ps1` 全绿。

## 4. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **T15 是全局平衡变更** | `marked` 来自所有流派的 recon 蛊，20 个流派同时获得伤害通道 | 25 seed 扫回归门；`mark_scratch_cap` 上限；数值单点可调（`balance.json`） |
| **T16 存档迁移出错** | 新字段 + `SAVE_VERSION` 提升 | 按既有"缺键空迁移"范式；roundtrip 单测 |
| **T16 违反红线** | 不可逆代价未预检 = 静默惩罚 | D16-3 强制确认；未确认不执行 |
| **降转与行为保持冲突** | 显式 `amount` 是手写值，降转不自动改 amount | D16-4 先只做门禁；amount 联动另批并同步改 T1 数值表 |
| **原文承认"不受欢迎"** | 残锋会让玩家不愿用强杀招 | 这是**有意设计**（非唯一解）；但须在 UI 明确显示余量，避免"不知情被削弱" |
