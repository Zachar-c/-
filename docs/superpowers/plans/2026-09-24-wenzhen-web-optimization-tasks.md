## 派发与裁决点

1. 一次只派发一个可验收批次。WOPT-01 结束前，后续性能、内容与数值结论都标为未验证。
2. 2026-09-24 L0 已裁定 WOPT-02：新局不选主道，血、魂、光、力可混搭；暂不批准魂魄“获得、投入、守护”扩展。当前迭代沿用已有规则和数据验证开放获取，魂道完整玩法、追杀/声望、身体过载、接近距离、净化、速度等新机制不在本批实施。用户明确允许 Codex 自行或派子代理实施，本轮由 Codex 直接执行。
3. 2026-09-24 L0 明确 WOPT-04 不需要，专项跳过；后续批次不把它当作必须先行完成的优化。
4. WOPT-03/06 若指向价格、Rank 真元曲线、胜率或其他数值调整，先提交包含应用点与正常局账本的 L1 Research Request。L2 只修可验证的接线与缺陷。
5. 战后真元是否跨战继承、路线是否硬锁未来、任何新核心机制均不在本清单实施范围；需要时按变更控制协议单独裁定。

## WOPT-02 首批实施计划（2026-09-24）

### 决定与目标

- L1 评审建议四道是可组合的决策方式；本批以现有 Web 能力验证，不把它们改成四种伤害标签。
- L0 决定：新局不选择主道；四道可通过既有奖励、商店、炼方和杀招入口混搭。单光道临时改动不再作为新局规则。
- L0 决定：暂不扩展魂魄状态的“获得、投入、守护”；本批不宣称魂道完整可玩，不加入魂道蛊或新魂魄规则。

### 实施边界

1. 新局不写入 `playableSchool: light`；已有进行中档即使含该字段也不再被它拦截，继续按现有规则结算。
2. 现有可见/可取得蛊通过奖励、商店、炼方、杀招、图鉴和使用入口保持一致；不得出现“看见但不能取得/使用”的假选择。
3. 保持种子化和确定性；恢复探索性单光开局前已经存在的多道起始库存，以免“无主道”仍呈现为光道起步。不新增蛊虫或库存数量；不改奖励概率、商店价格、战斗效果、资源结算或 `saveCompatibilityVersion`。若验收证明必须改变这些项目，先记录证据并另交 L1。
4. 不删除或覆盖工作树中的无关改动。相关文件只做实现本批所需的窄幅修改。

### 明确不做

- 不新增蛊虫、不把 `game/data/` 未投影内容整批扩入 Web、不扩展魂魄/死亡/念头规则。
- 不新增血道追杀/恶名系统、力道过载/距离系统、光道净化/行动顺序系统。
- 不为保证掉落而调概率或改价格；如正常局显示四道可达性不足，提交轨迹和资源账本供 L1 再审。

### 验收

- 代码核对：起始状态、奖励、商店、炼方、杀招、图鉴提示、蛊虫使用及进行中档续玩均不按单一道过滤；已开放数据中的其他道也不被新白名单误删。
- 测试：先跑受影响的范围/商店/掉落/存档测试，再运行 `node --test tests/*.test.mjs`；附真实输出和退出码。
- 可见操作：在 `lab.html` 普通模式用空档及固定种子走到奖励或商店，展示跨道蛊的实际获取、进入整备/战斗后的可用状态；同 seed 重复运行结果一致。
- 未验证项：不把此批当作整局可赢性、3–5 小时节奏、魂道完整玩法或三种新机制的验收证据。
