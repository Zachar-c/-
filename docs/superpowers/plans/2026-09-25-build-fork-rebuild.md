## 总目标

本阶段正式从：

> 验证线性强度能不能跑

切换为：

> **验证构筑分叉能不能活**

最终必须跑通：

```text
敌人提出不同问题
        ↓
玩家用当前蛊/杀招解决
        ↓
战斗产生有目标的掉落
        ↓
材料 / 蛊 / 元石进入经济
        ↓
出售 / 购买 / 炼蛊 / 修整
        ↓
获得或替换力量元件
        ↓
重新配置 / 推演杀招
        ↓
Build Mutation
        ↓
下一场战斗拥有不同解法
        ↓
新的敌人又暴露新的短板
```

## Phase 0 — 建立可信实验基线

不改善乐趣，只确保后面的测试是真的。

| 项目 | 处理 |
| --- | --- |
| Boss 55% 掉蛊但池为空 | **补真实池**（修为一致行为） |
| 杀招显示 ≠ 实际结算 | **必须统一**；组件 `battleEffect` 合成结果 = 权威 |
| 血昙组件条件被静默绕过 | **判 Bug**；组件条件默认继承；仅显式 override 可突破 |
| `advance_*` 输入输出同 ID、净亏 | **从 live 可见路径移除**，直到定义真实语义 |
| 古方收费但没有机械收益/目标不存在 | **未接通前不得作为正式可购成长项** |
| 复写引擎模拟结果 | **永久不得进入平衡证据** |

### 杀招权威（冻结）

```text
组件 battleEffect 合成结果 = 战斗语义真源
预制 m.effect 只允许元数据/兼容
显示必须从实际语义生成或通过一致性校验
```

### Gate 0

必须满足：

1. 同一个行动：UI 所说的 = 门禁所检查的 = resolver 实际结算的
2. 所有正式掉落：掉到以后至少有一个合法未来用途
3. 所有正式出售商品：购买后至少有机械意义

**过不了 Gate 0，不进入玩法平衡。**

## Phase 1 — 建立第一组「敌人问题 × 玩家解法」

只建立 **3 个问题轴**，不要同时扩十类敌人：

| 问题轴 | 敌人提出的问题 | 玩家可用解法 |
| --- | --- | --- |
| 信息/反制 | 不理解规则就会吃反制 | `inspect`、`suppress`，或规避触发行为 |
| 重甲/防御 | 普通 direct damage 效率低 | `armorBreak`/`pierce`、持续/绕防路线 |
| 高速/闪避 | 高伤攻击并不稳定命中 | `inspect`、`ignoreEvasion`、另一种稳定手段 |

允许解冻的动词仅限 L0 裁决中的四项。`damage_return`、完整距离、复杂 upgrade 继续冻结。

关键原则：**不能做「甲怪只能用 A、乙怪只能用 B」**。每个问题至少两种可辩护方案。

### Gate 1

三个敌人隐藏名称和图片，只看行动 trace：

- 应能明显看出玩家正在处理三种不同问题；
- 而不是三只怪都「观察 → 最大伤害 → 最大伤害」。

## Phase 2 — 把玩家蛊从「数值牌」变成「解法元件」

不增加蛊数量。只对当前 live 蛊做角色整理：

`Core / Support / Transform / Resource / Defense / Information / Finisher`

至少形成三套最小能力组合：

1. 信息 → 压制
2. 破甲 → 爆发
3. 稳定命中 → 持续输出

数值蛊继续允许存在。目标是「手里至少有几个能改变解决问题方式的元件」。

### Gate 2

相同 Rank 下 Build A/B/C 面对同一敌人至少两种有效行动结构；同一 Build 面对 Phase 1 三敌不能保持完全相同动作序列。

## Phase 3 — 接通「获得新蛊 → 构筑改变」

不要求自动替玩家装备。需要：

```text
获得蛊
↓
系统明确告诉玩家：
可替换什么 / 可炼成什么 / 可组成或改变哪些杀招
↓
玩家主动选择
保留 / 出售 / 炼蛊 / 装备 / 进入杀招
```

杀招第一阶段不做自由生成。继续使用固定杀招家族，但真正允许：

- 兼容组件替换
- 重新计算合成结果
- 形成 Variant

### Gate 3

关键新蛊进入库存后，必须至少有一个真实决策（继续旧 Build vs 用新蛊重构），且重构后下一场战斗的 action pattern / resource pattern / enemy matchup 至少一项改变。

## Phase 4 — 重建最小炼蛊网络

不要立刻补几百条生产级配方。第一版只围绕 Phase 1–3 解法建立小型但真有分支的炼蛊图。

目标结构示例：

```text
同一只基础蛊
      ↓
 ┌────┼────┐
 ↓    ↓    ↓
攻击  信息  规则
```

要求：

1. 至少一个节点拥有 2 个真实去向；
2. 两个去向不能只是 damage 5 vs damage 7；
3. 炼制一个分支必须关闭或推迟另一个未来；
4. 成品必须能进入 Phase 1 的敌人问题体系；
5. 不允许存在「永远更优」的被支配配方。

### Gate 4

同一初始资产下，炼 A 与炼 B 必须在 3 场以内形成不同装备 / 杀招 / 资源状态 / 敌人优劣势。

## Phase 5 — 让材料成为「定向追逐力量」的桥梁

材料采用：

```text
配方钥匙为主，突破祭品/临时耗材为辅
```

第一阶段只激活 Phase 4 真正使用到的材料。其他材料：

- 不删除
- 无 Consumer 前不进入正式掉落池

### Gate 5

至少两条可验证链：

```text
目标 Build → 目标配方 → 缺材料 X → 敌人 A 高概率提供
目标 Build → 材料 Y → 选择敌人 B
```

## Phase 6 — 重构掉落，让「风险 → 新未来」

掉落三种价值：

1. 经济价值：元石 / 可出售资产
2. 成长材料：炼蛊 / 维护 / 突破
3. 构筑组件：蛊 / 配方 / 杀招相关资产

普通敌 / 精英 / Boss：

| 类型 | 核心回报 |
| --- | --- |
| 普通敌 | 稳定经济 / 常用材料 |
| 精英 | 构筑材料 / 较高品质组件 |
| Boss | **新未来**（打开此前不可达构筑） |

### Gate 6

精英/Boss 结束后至少存在一个「因为刚才这个奖励，我下一段 Run 有了新的选择」，而不仅是购买力增加。

## Phase 7 — 让经济真正服务取舍

Phase 1–6 接通后再调经济。钱必须面对至少三种竞争：

1. 现在买构筑组件
2. 买炼蛊材料
3. 保留资源准备突破
4. （若有成本）恢复

不要先用绝对石价平衡。用购买力：普通战收入 = 1 个单位 I。

### Gate 7

任一主要阶段不能存在「始终应该买 / 始终应该炼 / 始终应该存钱突破」的唯一策略；禁止净资产无风险循环。

## Phase 8 — Rank 从「主成长」降回「承载轴」

最终关系冻结：

```text
Rank = 我能承载什么
Gu + Killer Move = 我实际上会什么
```

Rank 影响：最高正常催动转数、真元质量/规模、稳定杀招复杂度、炼蛊层级、维持高阶蛊能力。

Rank **不自动**：全伤害倍率提升、Build 自动升级。

### Gate 8

同 Rank 玩家必须能够有明显不同的 Build；Rank 提升后若不改蛊/杀招，不能自动变成完全不同的 Build。

## Phase 9 — 最后才引入跨战资源压力（HOLD-1）

当前战后真元直接回满。**现在不要第一个改它。**

Phase 1–8 成立后，再 A/B 验证 FULL RESET vs PARTIAL CARRY。

观察：

- 是否产生「留资源」选择
- 是否让路线历史有意义
- 是否造成不可逆死亡螺旋

**必须由 L0 最终确认。**

### Gate 9

若采用跨战资源：必须出现「我有最强解，但不一定值得现在使用」；同时不能出现「一场坏战斗 → 后续整个 Run 数学必死」。

## Phase 10 — 节点与路线最后接入「未来锁」（HOLD-2）

只有当敌人 / 掉落 / 材料 / 构筑都有差异后，路线选择才值得修。

节点应传递：未来敌人类型、资源倾向、经济机会、构筑机会、风险。

**须 L0 确认后实施。**

### Gate 10

同一 seed 强制走两条路线，3–6 场后至少两项仍明显不同（inventory / killer moves / materials / resource state / enemy matchup / future target）。

## Phase 11 — 可赢性与联合平衡

顺序：

```text
先保证至少 1 条已知基准路线数学可赢
→ 再证明多条构筑真的分叉
→ 最后才调总体胜率
```

禁止先把胜率调到 70%。联合 balance 同时观察：Combat / Drop / Economy / Refinement / Killer Move / Rank / Resource / Route。

## 最终验收矩阵

| 目标 | 最低验收 |
| --- | --- |
| 每回合决策 | 通常存在约 2–3 个真实优先级 |
| 敌人差异 | 至少 3 个不同问题轴 |
| 玩家解法 | 至少 4 个正交规则动词进入 live |
| Build Mutation | 每 3–6 场至少 1 次 |
| 炼蛊 | 至少一个真实二选一分支 |
| 材料 | 正式掉落材料 100% 有 Consumer |
| Boss | 至少打开一个新的构筑未来 |
| 新蛊 | 获得后能明确关联装备/炼蛊/杀招未来 |
| Rank | 承载力量，不成为 Build 身份 |
| 路线 | 强制分叉 3–6 战后仍有状态差异（待 HOLD-2） |
| 资源 | 强招存在机会成本（待 HOLD-1） |
| 可赢性 | 至少一条基准路线稳定可达终局 |
| 策略空间 | 强制不同路线不应迅速重新汇合 |

外部调查给出的 3–6 战一次 pattern-warp、约 3 个真优先级，作为体验目标带而非硬公式。
