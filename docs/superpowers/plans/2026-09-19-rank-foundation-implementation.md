## 0. 本次真正冻结的东西

L1 的原话：**「这次真正应该冻结的不是『一转伤害等于多少』，而是：以后所有数值系统都知道——
转数究竟意味着什么，以及哪些东西绝对不能拿同一个倍率硬乘。」**

三条不变量（此后任何数值改动都不得违反）：

1. **转数是综合层级轴（Rank Axis），不是万能倍率（Power Multiplier）**
2. **Rank Power Budget ≈ 每转 ×2、1→5 约 ×16，作用于「效果预算」，不直接乘所有伤害**
3. **不同轴不要求共用同一倍率**——真元品质曲线、能力预算曲线、经济稀缺曲线、成长门槛各自独立

---

## 1. 目标与非目标

**目标**：让六套互不知情的「转数阶梯」收敛到 L1 指定的 **3+1 个概念**：
`Rank Power Budget` ｜ `Essence Budget` ｜ `Economy / Availability` ＋ `Progression Gates`。

**非目标（明确踢出转数曲线）**：Boss 倍率、难度、奖励——它们是别的系统。
**非目标（L1 未决，L2 不得代决）**：见 §4。

### P2 · 定 Rank Power Budget（② 定 Rank Power Budget）

| 项 | 内容 |
|---|---|
| 目标 | 建立**唯一一处**的转数能力预算来源：`rank_power_budget(rank)`，1→5 约 ×2/转、总计约 ×16 |
| 产出 | 一条命名公式 + 一张 1–5 转预算表，落在上游数据（`game/data/balance.json`）并由构建器派生到世界模型；删除或标注其余 5 套「伪转数曲线」的去向 |
| 同时处理 | **D11 的 HP 基准**：把 `100` 立为 Source of Truth；玩家开局 80 若保留，必须**显式成对配置**（`standard_human_hp` / `player_start_hp`）并注明「玩家开局是标准一转肉身的 80%」，不得继续藏在构建脚本字面量里 |
| 验收 | 全仓只有一处定义该曲线；`rg` 证明其余转数倍率不再被当作通用战力倍率消费；同种子模拟结果可复现 |
| 依赖 | P1 ｜ **需 L2 在 Worker 前定稿「预算表的基数口径」**（基数锚定 human_base_health=100，属 D11 已裁范围） |

### P3 · 统一蛊的 Effect Budget 管线（③）——**工作量最大，L1 标为最高优先**

### P4 · 定 Essence Budget（④）

| 项 | 内容 |
|---|---|
| 目标 | 真元成为**独立轴**：原文 ×10 只作「1–3 转真元品质」证据，**不外推 4/5 转**、**不等于战力**；战斗真元改用归一化的「本转资源点」 |
| 产出 | 明确拆分 `essence_max_out_of_run`（局外真元海）与 `essence_max_battle`（战斗真元）各自的口径与适用范围；给出并列对账表（此前从未对账） |

### P5 · 资质 + 突破 + 跨转门槛（⑤）

| 项 | 内容 |
|---|---|
| 目标 | 资质改为 **Soft Gate**：语义取「倾向 / 概率」，**实现优先用确定性成本门槛**；跨转催动作为**独立曲线**，不与 rank_power 绑定 |
| 产出 | ① 替换现有「目标三转」硬门禁为成本门槛；② 资质 → 成长成本 / 自然上限倾向的曲线；③ 突破成本表；④ `cross_rank_penalty` 独立曲线（现有 `2^(rank gap)` 暂留，**未来可更陡**） |
| 明令禁止 | 「丙等永远不能三转」的永久硬锁；因「战力 ×2」推出「催动成本也 ×2」 |
| 验收 | 低资质开局不被锁死（可经机缘/特殊蛊/传承/资源突破）；跨转曲线与 rank_power 无耦合；相关测试全绿 |
| 依赖 | P2、P3 ｜ 突破成本的具体数额涉及 L1 未决项 O2，**触及时须上抛** |

## 4. 执行约定

- 每阶段：先出 Worker 任务包 → 实施 → L2 Review → **独立复算验收命令** → 独立提交
- 每阶段的验收必须包含：`git diff --check`、相关测试全绿、确定性（同种子同结果）、世界模型 `accept.py`
- **数值改动必须走上游 `game/data/`**；`game/world-model/data/` 是派生镜像，改它会被覆盖
- Worker 不 commit / push / merge；推送须全部验收通过并经用户确认
- 涉及「同类型倒挂」类判断时，先写扫描器再改数据，用扫描器归零作为验收证据
- 阶段之间**不得并行跨越依赖**；P3/P4 可部分并行，但合入顺序固定
