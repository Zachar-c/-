# 评审后优化方案（2026-08-25）

> 依据：`2026-08-25-nanjiang-card-roguelike-vision-review.md` 评审结论（玩家/评委双视角）与其缺口清单。
> 实施原则沿用项目约定：TDD（先失败测试）、数据驱动、事件日志、种子可复现、提交小而聚焦（ASCII 信息）、AGENTS.md 实时同步。
> 所有批次均不触碰 master 资料目录；补数值的地方一律进 `data/*.json`，不硬编码进 .gd。

## 目标

当前实现 = 机制 100%、内容 30%、随机性 0% 的工程演示版。本方案以最小改动换取最大体验提升，分五批落地：

| 批次 | 名称 | 解决的问题（评审编号） | 依赖 |
|---|---|---|---|
| B1 | 随机种子与新局入口 | P-1 每局完全相同 | 无 |
| B2 | 战利品闭环 T16 | P-2 战斗零收益（§7：战斗掉落/尸体搜刮/材料买卖/材料入炉） | 无（数值待批准） |
| B3 | 体验细节批 | P-4 速度不可见、P-5 日志截断、P-7 结局统计、敌人映射硬编码、README 陈旧 | 无 |
| B4 | NPC 深度 N1–N6 | 情报→弱点→增伤、三立场翻转、洗魂道具 | 数值待裁定 |
| B5 | 内容扩充 | P-3/P-8 血道数据、敌人/卡池薄 | **用户提供 5×3 流派卡数据** |

## B1 随机种子与新局入口

**范围**
1. `title_view.gd`：新增"种子"数字输入（LineEdit）+ "随机"按钮（生成随机种子并回填显示）；"开始游戏"携带所选种子。
2. `run_controller.gd`：`_start_run_from_title` 读取该种子；未填/随机为空时自动生成（系统时间取模，ASCII 无依赖）；`start_new_run(seed, school)` 接口不变。
3. 保留 101 为"演示/回归"路线：`MapGenerator.build(seed, seed == 101)` 不变，`first_run.json` 仅 101 使用。
4. 种子入起始事件（现有 `event_0000` 带 seed，无需改）；存档/读档延续。
5. HUD 或地图页显示本局种子号（便于复现汇报 bug）。

**验收（先写测试）**
- 同种子两次建房 → 路线全等；不同种子 → 节点序列不同（`test_random_seed_distinctness`）。
- 标题页暴露种子输入与随机按钮（结构化断言，参照 `test_v3_title_screen` 风格）。
- 101 回归：现有 first_run/vertical_slice 测试不得回退。
- 随机种子局不依赖 first_run.json（生成器纯网络路径）。

**风险**：低。种子随机只影响 `MapGenerator.build` 与全局 roll 流，所有 roll 已种子化。

## B2 战利品闭环 T16（战斗掉落 / 尸体搜刮 / 材料买卖 / 材料入炉）

**范围**
1. **战斗掉落**：新增 `data/loot_tables.json`（按敌人 tier 配表：每表 = 必掉材料 1–2 种 + 概率性蛊虫/材料；drop 判定用局种子 roll，入事件日志；`run_controller._finish_battle_in_session` 胜利后结算并把"战利品"反馈进遭遇页）。
2. **尸体搜刮**：BOSS（`miasma_vein_lord`）胜利后遭遇页出现一次性"搜刮"动作卡 → 得蛊方（解锁对应 `refinement_recipes.json` locked 配方 → 入 meta 全局图鉴 + 局内 knowledge，符合 P4 豁免口径）。
3. **材料买卖**：`shops.json` 增"变卖材料"offer（元石回收价，走现有 `price_for` 恶名加成）；黑市额外增补一枚"材料换蛊"的以物易物 offer。
4. **材料入炉**：`refinement_recipes.json` 的 fixed/combine/free_mix 增加可选 `materials` 输入字段；解析层保持向后兼容（原测试不破）；投入计件复用 `soul_capacity.craft_cap` 既有规则（材料与蛊虫合并计件）。
5. 材料种类扩展并配 `display_text.material` 中文名（如 兽血/兽骨/毒囊/月华露…）。

**数值档（待用户批准，见文末裁定清单）**
- 推荐档：常见敌人必掉 1 材料；精英 必掉 1 材料 + 30% 蛊虫；BOSS 必掉材料 2 种 + 蛊方（搜刮解锁）。
- 变卖价：材料 1–3 元石/份（按 rarity）；恶名加成沿用 10%/点、上限 60%。

**验收（先写测试）**
- `loot_tables.json` 结构校验（tier 全覆盖、id 合法、权重和）。
- 同种子同结果：胜利掉落完全可复现；掉落差异只随种子变化。
- BOSS 搜刮：一次一局、解锁配方入图鉴、重复搜刮被拒。
- 材料买卖：报价与恶名加成正确；元石不足被拒。
- 材料入炉：fixed/combine/free_mix 均接受；数量不足拒；计件上限（craft_cap）生效。
- 无掉落/无材料时不出现空收益空窗（"此战无收获"文案路径）。

**风险**：中。炼蛊输入签名扩展触碰 `test_v3_refinement_and_knowledge` 等既有测试——以向后兼容方式实现，逐测试绿。

## B3 体验细节批（小型）

1. **意图速度上 UI**：`battle_view._append_enemy_block` 意图行追加速度值（"掌势蓄而未发 · 速 1"），tooltip 同步。
2. **战斗日志可滚动**：日志区改 ScrollContainer 包裹或提高上限（不再截断）。
3. **结局统计三分**：`run_controller._record_run_end` 由 `won/dead` 二分改为 `won|risky|dead`（risky_success 单列）。
4. **敌人映射数据化**：`nodes.json` 全部可战节点加 `enemy_kind` 字段；`run_controller._start_battle` 改为读字段（缺省回退 `beast_swarm`），删除死代码分支（现 `greedy_wanderer` 分支被 `neutral_wanderer` 覆盖）。
5. **README 陈旧文案**：Godot 版本 4.6.2→4.7.2、GUT 版本、分支表表述。
6. **首战指引**：第一场战斗遭遇页加一行操作提示（"出手次数=魂魄；闪避需速度高于敌招"存在于 tooltip，另在首次进入战斗时 HUD 下方显示引导条）。

**验收**：每个小项一条结构化/行为断言 + 全量套件不回归。
