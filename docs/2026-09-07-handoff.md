## 3. 实测结论（拿来做设计决策的，别凭印象）

`tools/verify_pacing_density.gd` 三个种子实测：

| 种子 | 总节点 | 战斗 | 占比 |
|---|---|---|---|
| 101 | 162 | 114 | 70.4% |
| 4242 | 140 | 95 | 67.9% |
| 777 | 174 | 127 | 73.0% |

- **≈70% 战斗**（我曾报过 67% 和 72%，都不准——脚本原先把「非 shop/rest/refine/boss」一律算战斗，把 `yizang_ridge`（遗葬）和 `ascension_window`（无 `template_id`）都吞进去了。脚本已修并推送）。
- 每层 `unknown=1` **是预期的**：它就是 `ascension_window` 全局终点，本来就无 `template_id`。别再当数据洞查。
- **L5 最差（69–76%）且最长** —— 离 Boss 最近的那段最枯燥，正好命中玩家抱怨。
- 单局 140–174 节点，**低于 AGENTS 定的 200–300 目标**。
- 各层 shop=3 / refine=1 / rest=3–5 恒定；五层 pacing 结构完全相同，L5 占比高纯粹因为行数多。

**根因**：2026-09-06 收窄后生成图只剩 combat / rest / shop / boss 四类，锚点每行只占 1 槽，**非战斗节点无法随行数扩展** → 光调 pacing 数值降不动占比（再加商店也只是 3→4，72%→70%，治不了本）。
