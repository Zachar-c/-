# 《问真》变更控制协议 v1.0

## 一、目的

解决项目最大风险：

不断产生新想法，不断切换方向。

原则：

> 创意自由，执行受控。

------------------------------------------------------------------------

# 二、什么是变更

以下属于重大变更：

## 核心体验变化

例如：

从策略战斗改为自动战斗。

## 新增核心系统

例如：

新增：

-   魂魄体系；
-   境界体系；
-   仙窍经营。

## 阶段范围变化

例如：

MVP阶段突然制作完整世界。

## 技术路线变化

例如：

更换开发平台。

------------------------------------------------------------------------

# 三、变更等级

## IDEA

只是想法。

记录。

不开发。

------------------------------------------------------------------------

## RESEARCHING

研究阶段。

分析：

-   价值；
-   成本；
-   风险；
-   对当前目标影响。

------------------------------------------------------------------------

## APPROVED

L0批准。

进入路线图。

------------------------------------------------------------------------

## IMPLEMENTING

正在执行。

------------------------------------------------------------------------

## DONE

完成。

------------------------------------------------------------------------

# 四、新想法评估问题

任何新想法必须回答：

## 1

是否增强核心体验？

## 2

是否解决当前真实问题？

## 3

是否存在更简单方案？

## 4

是否应该现在做？

## 5

延期是否造成重大损失？

------------------------------------------------------------------------

# 五、开发保护规则

正在开发任务：

不能因为新想法直接停止。

正确流程：

    新想法出现

    ↓

    记录

    ↓

    继续当前任务

    ↓

    阶段结束评估

------------------------------------------------------------------------

# 六、优先级排序

任何冲突按照：

1.  核心体验验证
2.  产品问题修复
3.  玩家体验提升
4.  内容扩展
5.  技术优化
6.  装饰功能

------------------------------------------------------------------------

# 七、最终原则

《问真》不缺想法。

真正稀缺的是完成。

因此：

> 想法永远开放，执行永远受控。
