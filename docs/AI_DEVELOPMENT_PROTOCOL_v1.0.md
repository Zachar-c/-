# 《问真》AI开发总协议 v1.0

## 一、目的

建立多层AI协作体系。

解决问题：

AI能够执行任务，但不知道任务为什么存在。

------------------------------------------------------------------------

# 二、角色结构

    L0 产品决策者

    ↓

    L1 产品大脑

    ↓

    L2 Orchestrator

    ↓

    Worker 集群

------------------------------------------------------------------------

# 三、L0职责

L0负责：

-   产品方向；
-   核心体验；
-   优先级；
-   重大变更。

L0拥有最终裁决权。

L0不负责：

-   日常编码；
-   Worker管理。

------------------------------------------------------------------------

# 四、L1职责

L1是产品理解层。

对应：

ChatGPT。

负责：

## 产品理解

判断：

这个想法是否符合《问真》。

## 需求设计

输出：

-   PRD；
-   设计原则；
-   验收标准。

## Lore研究

负责：

-   原著蒸馏；
-   世界规则分析；
-   游戏化可能性。

## 审查

检查：

-   是否偏离目标；
-   是否过度设计；
-   是否提前建设。

------------------------------------------------------------------------

# 五、L2职责

L2是执行编排层。

对应：

Codex。

负责：

-   接收明确目标；
-   拆分任务；
-   调度Worker；
-   验收结果。

L2不是产品创造者。

禁止：

自行改变：

-   核心玩法；
-   产品方向；
-   阶段目标。

------------------------------------------------------------------------

# 六、Worker职责

Worker负责：

-   调研；
-   编码；
-   测试；
-   文档整理。

Worker不能：

-   扩大任务范围；
-   修改产品方向；
-   添加未经批准系统。

------------------------------------------------------------------------

# 七、任务流程

    需求
    ↓
    确认
    ↓
    拆解
    ↓
    执行
    ↓
    测试
    ↓
    审查
    ↓
    归档

禁止：

想法直接进入代码。

------------------------------------------------------------------------

# 八、文档优先级

1.  PRD
2.  AI开发协议
3.  阶段契约
4.  设计文档
5.  实施计划
6.  代码

低层不能推翻高层。

------------------------------------------------------------------------

# 九、任务模板

所有任务必须说明：

-   当前角色；
-   目标；
-   所属阶段；
-   允许修改；
-   禁止修改；
-   验收标准。

------------------------------------------------------------------------

# 十、核心原则

AI不是为了增加项目规模。

AI的目标：

> 让《问真》越来越接近正确产品。
