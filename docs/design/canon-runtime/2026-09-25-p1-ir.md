# P1：最小 Canon IR 设计（v0.1）

> 日期：2026-09-25。定位：`lore/wiki`（Source of Truth）与游戏（Game Projection）之间的**编译边界中间表示**。
> 原则：不过度设计。第一版只有 Entity / Rule / Relation / Provenance 四类对象；State / Event 结构化推迟到垂直切片验证后再扩。
> 禁入字段（Game Projection 专属）：damage、cooldown、drop_rate、success_rate、balance_value、任何游戏数值。

## 1. 目录与生成物

```text
lore/runtime/            ← 全部为生成物，不人工维护（原则：Wiki = Source of Truth）
├── manifest.json        编译元数据：source 身份（sha256/行数）、范围、计数、覆盖率声明
├── entities.json        Entity[]
├── rules.json           Rule[]
├── relations.json       Relation[]
└── packs/*.json         P4 Context Pack（按场景选装的最小子集）
```

编译器：`lore/wiki/tools/compile_runtime.py`（stdlib-only Python 3，与 lore/wiki/tools 既有工具同风格）。重跑即完全重建；不满足校验时**报错退出，不输出**。

## 2. 对象定义

### Entity

```json
{
  "id": "moonlight_gu",
  "type": "gu",
  "name": "月光蛊",
  "aliases": ["月光刃"],
  "description": "古月一族秘法培育的一转镇族蛊虫，发射月刃的基础战斗蛊",
  "properties": {
    "rank": 1,
    "rank_status": "verified"
  },
  "evidence": ["E:V1-001492"],
  "provenance": {
    "wiki_pages": ["lore/wiki/gu/moonlight-gu.md", "lore/wiki/gu/roster-3.md"],
    "canon_refs": ["CAN-SMALL-LIGHT-001"]
  }
}
```

- `id`：ASCII slug。gu 实体**直接取 roster-3.md 表的 id 列**（与 `game/data/gu.json` 同键空间），不另造第二套 id。
- `type`：v0.1 只出 `gu`；词表预留 `character | region | beast | concept`。
- `properties`：只放有 Canon 支持的结构化属性。v0.1 只承载 `rank`（转数）与 `rank_status`（`verified`＝roster-3 一致/裁定已改；`unverified`；`divergence`；`rank_cap`；`collision`；`name_reuse`；`timepoint`——沿 roster-3 状态图例）。**path/流派不入 v0.1**：wiki 尚无逐蛊结构化流派字段，等下一批次（避免把 game 的 school 字段倒灌 Canon）。
- `evidence`：身份/转数主张的 E-ID 集合（来自 roster-3 锚点列 + 实体页）。

### Rule

```json
{
  "id": "REF-004",
  "prefix": "REF",
  "domain": "refinement",
  "statement": "合炼：多只蛊合并炼成一只新蛊，通常二转及以上",
  "forbidden_misreading": "…（禁止误读列，可选）",
  "evidence": ["E:V1-012756"],
  "provenance": {
    "wiki_page": "lore/wiki/rules/refinement.md",
    "canon_ref": null,
    "generated_id": false
  }
}
```

- `id`：**优先沿用 wiki 原生 ID**（REF-*、KM-*、DM-*、PR-*、TRIB-*、VEN-*、DRM-*、CAN-*）。无 ID 规则表（如 `primeval-essence.md` 规则表）由编译器生成确定性 ID `{页slug缩写}-{NNN}`，`generated_id: true`，**不回写 wiki**。
- `domain`：`refinement | killer-move | true-qi | cultivation | aptitude | region | economy | gu-care | beast-tier | ascension | other`。
- `statement` 取表"内容/事实摘要"列原文；`forbidden_misreading` 取"禁止误读"列（无则省略）。

### Relation

```json
{
  "id": "REL-SMALLLIGHT-MOONLIGHT-SUPPORT",
  "relation": "supports",
  "from": "small_light_gu",
  "to": "moonlight_gu",
  "statement": "双蛊同催：月刃体积与攻击力各扩大一倍；一只即翻倍、两只不叠加",
  "evidence": ["E:V1-010926", "E:V1-017148"],
  "provenance": {
    "wiki_page": "lore/wiki/gu/small-light-gu.md",
    "state_ids": ["ST-SMALLLIGHT-03"],
    "canon_refs": ["CAN-SMALL-LIGHT-001"]
  }
}
```

```json
{
  "id": "REL-REFINE-MOONGLOW-FROM-MOONLIGHT-2SMALLLIGHT",
  "relation": "refinement",
  "inputs": ["moonlight_gu", "small_light_gu", "small_light_gu"],
  "output": "moon_glow_gu",
  "output_rank": 2,
  "statement": "月光蛊加两只小光蛊，可合炼成二转月芒蛊",
  "evidence": ["E:V1-015710"],
  "provenance": { "wiki_page": "lore/wiki/gu/small-light-gu.md", "state_ids": ["ST-SMALLLIGHT-04"], "canon_refs": ["CAN-SMALL-LIGHT-002"] }
}
```

- `relation` 受控词表 v0.1：`supports`（辅助/增幅，from→to）、`refinement`（合炼，inputs→output）。后续按需扩词表（每扩一词须在本文档登记）。
- `supports` 用 from/to；`refinement` 用 inputs/output（n-ary，允许同名蛊重复出现表达"两只"）。同一对象不同时用两套字段。

### Provenance（公共嵌入对象）

- 记录级：`wiki_pages`/`wiki_page`、`evidence`（E-ID 数组，放记录顶层）、`canon_refs`、`state_ids`。
- 全局级（manifest.json）：`source = {id, path, sha256, lines, recorded_at}`。**原文 hash 变化或文件缺失 → 编译失败**，不静默沿用旧 E-ID。这是对"E-ID 依赖 clean.txt 行号"的版本保护，不改 Wiki Schema。

## 3. 源页面（v0.1 编译范围）

| 源 | 产出 |
|---|---|
| `game/docs/lore/canon-index.md` 三个表段全部 CAN-* 行 | Rule[]（prefix=CAN，domain 按适用系统映射）＋ canon_refs 索引 |
| `lore/wiki/gu/roster-3.md` 转数表（六个分段） | Entity.rank / rank_status / evidence |
| `lore/wiki/gu/moonlight-gu.md`、`small-light-gu.md` | Entity 详情 + Relation（ST 行） |
| `lore/wiki/rules/refinement.md`（REF-001..022） | Rule[] |
| `lore/wiki/rules/killer-moves.md`（KM-001..018） | Rule[] |
| `lore/wiki/world/primeval-essence.md` 规则表（7 行，生成 ID PE-001..） | Rule[]（domain=true-qi） |

## 4. 校验（编译即验证）

1. manifest source hash 与本地原文一致（文件在主 checkout 根或工作树根均可，找不到则报错）。
2. 所有 E-ID 匹配 `E:V[1-6]-\d{5,6}` 且段号↔行号落在 section-index.md 段域内（check9 同款逻辑）。
3. Relation 引用的实体 id 必须存在于 entities.json（引用完整性）。
4. Rule id 无重复；canon_refs 引用的 CAN-* 必须在本次编译的 CAN 集合内。
5. 禁入字段黑名单扫描：输出 JSON 中不得出现 `damage|cooldown|drop_rate|success_rate|value|cost` 数值字段（文本 statement 内出现不算）。

## 5. 明确不做（v0.1）

- State/Event 独立对象类型（ST/EVT 行仅作为 Relation/Provenance 的锚点引用）。
- 认知标记（`[对话|已核]` 等）解析进 IR——statement 保真原文即可，标记解析等 Runtime Benchmark 暴露需求再做。
- 逐蛊 path/流派、全量 802 蛊、人物、事件编译。
- SQLite / FTS / embedding。

## 6. v0.1 → v0.2 增量登记（2026-09-25，P1 月光切片批）

- **Entity 增加可选 `states[]`**：来源＝实体页「状态时间线」表（ST-* 行），字段 `{id, stage, statement, evidence[], canon_refs[]}`；仅合并了实体页且页内存在 ST 表的实体携带该字段（当前＝moonlight_gu 7 条、small_light_gu 4 条），roster 骨架实体不携带。states 随实体流入 Context Pack。
- **触发依据**：runtime 基准一阶缺口题 G1/G2（月刃消耗、印记位置）显式登记"State 未进 IR 不可答"（benchmark-runtime-stage1.md、docs/debt.md「Canon IR v0.1 无 State/Event 对象」行）；L0 裁定 P1＝打通月光体系 Canon Runtime（RUL-2026-09-25-001 PRIO），垂直切片即 P1-IR §5 预留的 v0.2 触发条件。
- **不变项**：relation 受控词表仍为 `supports | refinement`；State/Event 独立对象类型（states.json / events.json）继续推迟；wiki Schema v2.1 冻结不受影响（states 只进 runtime 生成物）；E-ID 段域校验、BANNED_KEYS 扫描、原文 hash 锁均覆盖 states 证据。
- **机械校验**：check_runtime_benchmark.py 同步扩展——pack 实体 `states[].id` 计入可引用条目集。
