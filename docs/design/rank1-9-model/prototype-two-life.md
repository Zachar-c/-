## 已跑通的两世对照

固定种子 `20260927`。第一世走休整路线，在商队花 8 元石并占用该段抄月芒方；后来才买到第二只小光，已错过炼台。完成终验后只提交蛊方知识，未靠第一段直接升转。

刷新页面进入第二世后，一转、48 元石、初始四蛊重置，月芒方仍已知。先战胜拦路敌取得一次冲窍外援；在商队买第二只小光并补满元海，闭关十二次修到一转巅峰后冲二转。下一段用已知方合炼月芒；月光和双小光被投入，二转月芒进入编制并对敌造成可观察伤害。另测得：一转可持有炼成的二转白玉蛊，但不能编入战斗。

单独的机制回归还验证：没有外援或真元未满时按钮保持禁用；二转有效上限 440 而元海比例仍是 44%；白豕先耗元锻体，之后零元拳脚与合炼后的力量保留均生效；酒虫不作为战斗卡、不回元，也不能在一转巅峰跨转提纯。这里的“440”是青铜当量口径，不宣称空窍从 44% 变成 440%。

## 中断与续局边界

未结束本世时刷新，会按版本、种子和世次校验局内检查点，恢复当前路线、元石、蛊组、随机状态及战斗进度。本世抄得的方随同一世进度恢复，**直到结局才写入跨世记忆**；手动「重开本局」会丢弃未提交进度并恢复本世初始编制。结局清除旧检查点，刷新进入下一世。损坏或不匹配的检查点回退为当前世新局，不覆盖已提交的蛊方知识。页面内的「从零重测」经确认后只清除此原型的记忆与检查点，回到第一世；取消确认不会改动数据。若浏览器禁止本地存储，原型不会保住刷新前的局内进度；正式 Web 产品有独立存档实现，本实验不替代它。

`working/` 默认被 Git 忽略；本批已将四个浏览器测试文件显式列入待提交变更，供新 checkout 复核。当前测试由本地 Chromium 运行，尚未构成正式产品的 CI 门禁。

脚本只证明规则和流程确实运行，**还不能证明人会因为蛊方知识自发改变选择**。下一次产品判断应让不了解脚本的玩家连续玩两世，观察他们是否愿为巅峰冲窍投入修行、在战斗/购蛊/补元之间做取舍，以及炼成后打法是否真的改变。通过前，不把这份五段原型当作 PRD 所要求的完整长局，也不把 `working/` 本地代码直接并入 `game/wenzhen-web-lab/`。
