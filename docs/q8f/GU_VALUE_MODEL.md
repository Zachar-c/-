## 0. 核心命题：从"伤害价值"转向"构筑价值"

任务书 §五要求：蛊的价值必须表达为**构筑价值**（它在玩家手里能构成什么），
而不是**伤害价值**（它打多少点）。

**为什么必须这样 [INFERRED]**：`gu.json` 802 只蛊里只有 **57 只有显式 `v1_effect`**（7.1%），
其余 **745 只走 `combat` 字符串兜底**（129 个不同 `combat` 值，无统一数值语义）。
→ **用"伤害"给蛊定价在数据上根本不可行**，因为 92.9% 的蛊没有可读的伤害数值。

因此 F3 建立**多轴价值模型**，每轴给出可测代理（proxy），最后合成**构筑价值**。

## 1. 当前唯一生效的定价：`gu_value`

`[FACT]` `GuBalance.gu_value(def, instance_rank, cat)`（gu_balance.gd:20-24）：

```
value = max(定义字面 value, gu_value_by_rank[实例转数])
gu_value_by_rank = {1:3, 2:5, 3:8, 4:12, 5:20}
```

**这是卖蛊 / 商店回收的唯一入口**。它只有一个维度：**转数（rank）**。

### 1.1 与数据的吻合度 `[FACT]`

| rank | 蛊数 | 字面 value 分布 | 与表值关系 |
|---|---|---|---|
| 1 | 220 | 3,4,5,6,8,10 | 211 匹配 / **9 高于** |
| 2 | 157 | 5,9,10,30 | 154 匹配 / **3 高于** |
| 3 | 180 | 8,16 | 179 匹配 / **1 高于** |
| 4 | 97 | 12 | **97 全匹配** |
| 5 | 147 | 20 | **147 全匹配** |
| 10 | 1 | 0 | 测试蛊 `test_slay_gu`（`low_rank_exception`） |

> **关键事实**：**rank 4/5 的 244 只蛊价值完全由表决定**（字面 value 无区分度）；
> rank 1–3 有 13 只"手工蛊"高于表值，全部集中在 **light / force / earth / blood** 四流派。
> → **转数解释了价值，流派与稀有度不携带任何独立价值信息**（F1 §4 已推断，此处证实）。

### 1.2 `rarity` 是转数的影子 `[FACT]`

| rarity | rank 分布 |
|---|---|
| common | {1: 214, 2: 154} —— **只存在于低转** |
| rare | {1: 3, 2: 2, 3: 180} —— **基本=转 3** |
| epic | {1: 3, 2: 1, 4: 97, 5: 147, 10: 1} —— **基本=转 4/5** |

> `rarity` 与 `rank` 的相关性接近 1 → **它是转数的展示层别名，不是独立轴**。
> `gu_value` 只看 rank 是正确的（看 rarity 会重复计数）。

## 2. 多轴价值模型

对每只蛊，定义 11 条轴。每条给出：**数据来源** / **是否已被 `gu_value` 消费** / **可测性**。

| # | 轴 | 数据来源 | 当前被定价？ | 可测性 |
|---|---|---|---|---|
| A1 | **转数 rank** | `rank`（802/802） | ✅ 唯一被消费 | 强 |
| A2 | **稀有度 rarity** | `rarity`（802/802） | ❌（且=rank 影子） | 强 |
| A3 | **真元成本 essence_cost** | 16/802 有 | ❌ | 弱（覆盖率 2%） |
| A4 | **念头成本 thought_cost** | 3/802 有 | ❌ | 极弱 |
| A5 | **寿元成本 life_cost** | **1/802** 有 | ❌ | **近乎空** |
| A6 | **战斗效果 v1_effect** | 57/802 有 | ❌ | 中（7%） |
| A7 | **组合价值** | `synergy_hooks` 14/802 | ❌ | 弱 |
| A8 | **流派归属性** | `school` 802/802 | ❌ | 强 |
| A9 | **信息价值** | `field_actions` 12/802 | ❌ | 弱 |
| A10 | **稀缺性** | `source` 786/802 | ❌ | 中 |
| A11 | **可替代性** | 推导（同 school×role×rank 计数） | ❌ | 中 |

**结论 `[FACT]`**：11 条轴中，**只有 A1 被 `gu_value` 消费**。
其余 10 轴的数据**大部分存在（school/rarity/role 全覆盖）**，但**没有任何定价代码读取它们**。

## 3. 逐轴核查

### A1 转数 — 唯一生效轴

- `rank_step_ratio = 2.0` → `rank_multiplier(rank) = 2^(rank-1)`。
- `standard_gu_power(rank) = 100 × 0.2 × 2^rank` → 转 1 = 40，转 5 = 640（**16 倍**）。
- 而 `gu_value_by_rank` 只从 3 → 20（**6.7 倍**）。
- → **战力增长（16×）远快于价值增长（6.7×）** `[INFERRED]`：
  **高转蛊相对其战力被严重低估** → 这也是 F2 §3.2 所说"卖蛊不划算"的一环。

### A2 稀有度 — 影子轴，但有一个真实作用 `[FACT]`

- `gu_value` 不读稀有度。
- 但 **elite 战利品 `forced_rarity: epic`**（F1 §6.1）→ 稀有度**只影响掉落选择**，不影响价格。
- `[INFERRED]` 这导致：**打精英掉一只 epic 转 1 蛊，卖价与 common 转 1 蛊完全相同（3 石）**，
  而它的战斗期望可能是普通蛊的 3 倍 → **稀有度溢价被完全抹掉**。

### A3–A5 资源成本轴 — 覆盖率崩溃 `[FACT]`

| 轴 | 字段 | 覆盖 | 值域 |
|---|---|---|---|
| A3 | `essence_cost` | **16/802（2.0%）** | {0,1,2,3}，1 占 10 |
| A4 | `thought_cost` | **3/802（0.4%）** | 全部 = 2 |
| A5 | `life_cost` | **1/802（0.1%）** | 唯一一条 `blood_atk_5_02_gu` = 2 |

> **A5 是 F7 的核心问题**：`life_cost` 全场只有 1 只蛊设置（且是 rank5 血道），
> 其余 801 只**零寿元成本** → **寿元在蛊系统中完全不参与结算**。
> 而 A3/A4 的 16/3 条覆盖**全部集中在 16 只"手工蛊"**（与 A6 的 57 只部分重合）→
> **745 只批量蛊的资源成本轴是空的** `[GAP]`。
> 后果：`essence_cost` 缺失 → 所有批量蛊**驱动成本相同**（走 `standard_activation_cost = 0.1`）

### A6 战斗效果 — 唯一的"效果轴"，但只有 7% 覆盖 `[FACT]`

`v1_effect` 57 只，kind 分布：
```
strike 27 / heal 10 / shield 6 / shift 5 / sword_intent 5 / status 2 / heal_and_strike 1 / weaken_intent 1
```

按 rank 的 strike amount：
| rank | strike amount |
|---|---|
| 1 | 1, 2, 3, 4 |
| 2 | 3, 4 |
| 3 | 2 |
| 4 | 5 |
| 5 | 6, 8 |
| 10 | 999（测试蛊） |

> **观察** `[FACT]`：strike amount 随 rank 上升（1→8），但**rank 1 内部差异巨大（1 到 4，4 倍）**，
> 且 **rank 3 的显式 strike（2）低于 rank 2（4）** → **显式效果轴内部不自洽**。
> `[INFERRED]` 因为显式效果是**逐只手工填的**（57/802），没有统一公式 → 不适合作为定价轴。

### A7 组合价值 — 14/802（1.7%）`[GAP]`

- `synergy_hooks` 覆盖 14 只，`field_actions` 覆盖 12 只，`replace_value` 覆盖 16 只
  —— **三个字段覆盖的是同一批"手工蛊"**。
- 这是**唯一能表达"构筑价值"的数据**，但覆盖率 1.7% → **构筑价值在数据上几乎不存在**。

### A8 流派 — 全覆盖，结构高度均齐 `[FACT]`

- 20 个流派（19 个 ×40 + human 42）。
- **每流派 rank 分布几乎相同**（详见 school×rank 交叉表：每流派 r1≈10-13 / r2≈3-10 / r3≈7-13 / r4≈2-11 / r5≈4-13）。
- → **流派之间数量对等，但内部 role 构成不同**：
  - `force`：**0 recon / 0 logistics**，attack 33（全场最高）——**纯战斗流派**
  - `light`：recon 9（最高）+ logistics 4 ——**侦察流派**
  - `refine`：logistics 10（最高）——**后勤流派**
  - `wind`：movement 11（最高）——**机动流派**
  - `human`：attack 35（最高）、healing 1（最低）——**纯攻流派**

> **`[INFERRED]` 流派的价值差异在于 role 构成，而不在 rank**。
> 一个"构筑价值"定价必须能表达：**force 的转 1 攻击蛊 ≠ light 的转 1 侦察蛊**（当前两者同价 3 石）。

### A9 信息价值 — 12/802，且是 `light` 专属 `[FACT]`

- `field_actions` 12 只，`recon` role 在 light 有 9 只。
- `[INFERRED]` **信息能力几乎被 light 垄断** → 若给信息轴定价，会**单方面抬高 light 流派价值**。
  需要 F5 结合"侦察在节点上的实际收益"验证是否配得上。

### A10/A11 稀缺性 / 可替代性

- `source`：`novel` 261 / `school_derived` 525 / 缺失 16。
- `[INFERRED]` `novel`（原著）应稀缺高价，`school_derived`（派生批量）应廉价 ——
  **当前两者同价**（`gu_value` 只看 rank）→ **稀缺性溢价不存在**。
- 可替代性代理：同 school×role×rank 的蛊数。`sword` 转 1 攻击蛊有 15 只 →
  **单只可替代性极高**；`light` 转 1 侦察蛊只有 9 只 → 较低。

## 4. 候选公式（**提案，不落地**）

> 任务书 §五允许输出候选公式。以下为**提案**，等 F8 汇总 + 外部架构审阅者裁定。

### 4.1 构筑价值（Build Value）三因子提案

```
build_value(gu) = rank_value × school_factor × role_factor × scarcity_factor
```

| 因子 | 依据 | 建议取值（示意） |
|---|---|---|
| `rank_value` | 现 `gu_value_by_rank` | 3 / 5 / 8 / 12 / 20 |
| `school_factor` | 流派 role 稀缺度（A8） | 1.0 基线；`force`(纯攻) 0.9；`light`(侦察独有) 1.2 |
| `role_factor` | 角色在构筑中的不可替代性（A7/A9） | attack 1.0 / defense 1.05 / healing 1.05 / movement 1.0 / recon 1.15 / logistics 1.10 |
| `scarcity_factor` | `source==novel` 或有 `synergy_hooks` | 1.0 基线；novel 1.3；有 synergy 1.2 |

> **⚠ 提案的作者自评**：`school_factor` / `role_factor` 的取值**目前没有任何实证依据**，
> 属于"为了给流派差异定价而拍的数字"。**在没有 F8 模拟数据前，不应采用。**

### 4.2 替代方案：只补"手工蛊溢价"

若不想引入拍脑袋因子，最小可行提案是**只承认已有的三处显式溢价**：

```
value = max(
  literal_value,              # 手工蛊已手工调高的值（13 只）
  gu_value_by_rank[rank],     # 批量蛊基线
  has_v1_effect ? base × 1.5 : base   # 显式效果蛊（57 只）加 50%
)
```

> 这条**只用了数据里已存在的手工排序**（`literal_value` 已经高于表值 13 次），
> 不引入新因子 → **风险最低，但也不能解决"批量蛊 745 只全部同价"的问题**。

## 5. 结构诊断（F3 核心结论）

| # | 事实 | 后果 |
|---|---|---|
| 1 | `gu_value` **只看 rank** | 802 只蛊压缩成 **5 个价格档**（3/5/8/12/20） |
| 2 | rank 4/5 的 244 只**字面值全等于表值** | 高转区间**零区分度** |
| 3 | 11 条价值轴中 **10 条未被消费** | 流派 / 稀有度 / 成本 / 组合 / 信息**全部不计价** |
| 4 | `life_cost` 覆盖 **1/802** | 寿元在蛊系统**零参与**（→ F7） |
| 5 | `essence_cost` 覆盖 2%、`thought_cost` 0.4% | 资源成本对 745 只批量蛊**不存在** |
| 6 | 战力增长 16× vs 价值增长 6.7× | **高转蛊被系统性低估** |
| 7 | `rarity=epic` 的转 1 蛊与 common 同价 | 精英战利品的**稀有度溢价被抹掉** |
| 8 | `synergy_hooks` 仅 14 只 | **构筑价值在数据层几乎不存在** |

> **F3 结论**：蛊的"价值模型"在代码里**只有转数一条腿**。
> 因此"玩家为何要留/卖某只蛊"的答案**与它是什么蛊无关**，只与它几转有关 →
> **蛊作为"构筑素材"的差异性在交易层面被完全抹平**，只剩"转数批发价"。
