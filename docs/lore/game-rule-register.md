# 已确认游戏规则

本表记录制作人已确认的游戏规则。它不宣称每一项都是原著直接事实；涉及原著依据的内容必须同时引用 `canon-index.md` 与 `adaptation-register.md`。

| ID | 规则 | 设计后果 | 状态 |
| --- | --- | --- | --- |
| GAME-GU-LOADOUT-001 | 蛊师没有按数量计算的持蛊上限。玩家不会因系统蛊槽上限而被禁止拥有、携带或尝试使用某只蛊虫。 | 不采用“4 槽”“5 槽”或由修为直接扩格的硬容量设计。背包、常用、战斗显示等仅是界面组织，不是世界观限制。 | confirmed |
| GAME-GU-COMBAT-001 | 在遭遇中，玩家可催发自己所有已养、已炼化且当前满足规则条件的蛊虫。不存在战前选定一组“本场可用蛊”的规则，也不存在因界面限制而无法催发的已养蛊虫。 | 真元、伤势、冷却、封禁、蛊虫自身条件与遭遇状态可限制某次催发；任何限制必须来自可见的领域规则，不能来自隐藏的战斗栏位上限。 | confirmed |
| GAME-GU-COMBAT-002 | 蛊虫与杀招的组合是核心玩法。杀招不是系统预设、等待玩家触发的独立技能；它是玩家将多只已养蛊虫按自己选择的顺序、条件、目标和时机配合后，形成的有效战术方案。 | 每只蛊虫只提供自身可见、可测试的效果与条件；它们在同一局势中的叠加、增幅、移动、召回、控制和资源取舍由领域规则自然结算。不得维护“正确杀招组合”清单，也不得用弹窗宣布玩家发现预设杀招。 | confirmed |
| GAME-GU-COMBAT-003 | 玩家可以将一套自己认可的多蛊使用方案命名为杀招，并保存为个人的杀招方案。名称、参与蛊虫、建议顺序与使用备注由玩家决定；同一套蛊虫可被不同玩家用于不同杀招。 | 杀招方案是玩家的可编辑构筑记录和快捷操作，不是额外技能、固定配方或强制连招。它只能调用当前已养蛊虫的合法催发，仍受真元、伤势、冷却、封禁、目标与局势限制。 | confirmed |
| GAME-GU-COMBAT-004 | 杀招可被视为残蛊方：玩家反复使用、观察并完善的多蛊方案，可能成为推演或炼制单蛊的灵感来源。 | 残蛊方不是系统宣告的唯一答案。传承、炼道情报或玩家的既有方案可提供炼制方向；并非每个玩家命名的杀招都必须有一只可固化的对应蛊虫。 | confirmed |
| GAME-GU-LEGACY-001 | 自由杀招与内置收获并存，但职责不同。自由杀招由玩家自行组合蛊虫与局势产生；消耗蛊、改造蛊和前辈传承提供有限、可审查的内置增益、身体变化或打法方向。 | 不把玩家自创打法伪装为系统唯一正确答案，也不因追求自由度而放弃肉鸽中获得关键收获的兴奋感。所有内置收获须声明来源、效果、持续时间、代价与可叠加边界。 | confirmed |
| GAME-GU-LEGACY-002 | 消耗类蛊虫可提供一次性或有限次数的长期增益，例如力量、真元、恢复或抗性变化；它们是构筑资源，不是永久局外成长。 | 增益只在当前跑局生效，并纳入事件日志、角色状态与升仙结算。具体蛊虫及原著依据在进入内容池前单独审查。 | confirmed |
| GAME-GU-LEGACY-003 | 改造类蛊虫可改变蛊师身体，从而改变受伤、流血、防御、行动或其他身体相关规则。 | 身体改造必须有明确可见的规则变化与代价、冲突或机会成本；不可退化为无来源的纯数值词条。冰击蛊、玉骨蛊仅作为待核验候选，尚未宣称为可用首发内容。 | confirmed |
| GAME-GU-LEGACY-004 | 前辈传承可记载已被验证的蛊虫协同方向，例如限定标签、类别或状态下的战术效果。 | 传承提供的是提示、局部规则或受限加成，不封死玩家自由组合。它可以鼓励“攻伐光类蛊 + 标记光类蛊”等方向，但仍由实际蛊虫效果、真元与局势决定成败。 | confirmed |
| GAME-GU-LOADOUT-002 | 真正限制来自资源：每只蛊虫需要喂养，蛊师资金有限；每次催发消耗真元，真元有限。 | 每阶段结束自动汇总全体已养蛊虫的养护需求，形成一笔元石总账；一局仅在第一、二阶段结束后结算两次。拥有过多蛊虫或高消耗蛊虫应产生真实经营压力。 | confirmed |
| GAME-GU-FEEDING-001 | 喂养使用“阶段总账”：不逐只弹窗、不要求玩家逐项寻找食料、不做日常操作。 | 常驻界面仅显示“下次养护：预计 X 元石”；获得、出售、炼制或换蛊后立即更新预估值。结算只显示总额与主要构成，不打断普通节点流程。 | confirmed |
| GAME-GU-FEEDING-002 | 资金不足以支付阶段总账时，才进入一次明确的经营抉择。 | 玩家须通过卖蛊、炼蛊、换蛊、势力援助、附带条件的交易或放弃部分蛊虫解决；不允许无代价拖欠。具体未支付后果在终局设计中确定。 | confirmed |
| GAME-GU-TRADE-001 | 局内必须持续提供买蛊、卖蛊、换蛊与炼蛊的机会，使养护总账成为可主动经营的构筑系统。 | 每阶段至少提供一个可预期的调整窗口；商队、寨市、势力关系、传承和特定事件可提供额外窗口。交易价格、可见货品与换蛊条件受势力关系、情报与局势影响。 | confirmed |
| GAME-GU-TRADE-002 | 商队或特定势力可以提供一换一、多换一的蛊虫交换；这是珍稀蛊的重要获取渠道之一。 | 交换可要求指定蛊虫、同类蛊虫、多个低转蛊虫，或额外附带元石、情报、人情与势力条件。低转蛊虫不因后期出现高转蛊而失去全部交易价值。 | confirmed |
| GAME-GU-TRADE-003 | 珍稀蛊的获取不应主要依赖普通货币直购。 | 高价值蛊虫优先通过限定交换、传承、势力回报、高风险遭遇或炼制获得；商队直售仅覆盖合理的小部分内容池。 | confirmed |
| GAME-GU-LOADOUT-003 | 蛊虫的用途不同，至少区分攻击、防御、辅助、移动、治疗等功能。 | 构筑价值来自功能互补、条件联动和应对不同局面，而非单纯叠加伤害。首发内容表必须为每只蛊虫声明主要用途与资源曲线。 | confirmed |
| GAME-GU-LOADOUT-004 | 蛊师通常只会长期养几只同阶蛊虫，是经济与真元约束的自然结果，不是规则强加的数量上限。 | 修为、元石、真元恢复、维护需求和蛊虫用途共同决定实际可持续的养蛊规模；不将“同阶”简化成免费的自动扩容。 | confirmed |
| GAME-GU-DATA-001 | 每只蛊虫至少具有转数、催发能量消耗、喂养需求与效果四类核心规则属性。 | 数据与规则必须能分别表达一至九转、真元或仙元消耗、固定时间的材料喂养需求，以及可测试的实际效果。 | confirmed |
| GAME-GU-DATA-002 | 名称、简介、故事背景、合炼蛊方、晋升蛊方、购买价格区间与价值均是蛊虫内容数据的一部分。 | 内容生产应保持数据驱动；规则效果、原著来源与玩家可见文案不得混在不可审查的脚本中。 | confirmed |
| GAME-GU-DATA-003 | 本作首发是凡人阶段：可实际获得和使用的蛊虫以一至三转为范围；六至九转作为世界观阶位存在，不提前制作成可用内容。 | 数据模型支持一至九转，首发内容池和数值测试只覆盖一至三转。 | confirmed |
| GAME-GU-REFINEMENT-001 | 蛊师对蛊虫的主要关系是用、炼、养；炼蛊不是附属文案，而是构筑成长的正式路径。 | 路线、商队、传承与事件必须能提供炼蛊机会、材料、信息或风险；炼蛊结果需要进入不可变事件日志。 | confirmed |
| GAME-GU-REFINEMENT-002 | 炼制方法至少区分合炼、升炼、平炼与逆炼。合炼为多只蛊虫共同炼制；升炼使低转蛊虫升级为高转蛊虫；平炼前后转数不变；逆炼将高转蛊虫还原为低转蛊虫。 | 配方数据必须记录炼制类型、输入蛊虫、输出蛊虫、材料、转数变化、条件与风险；四种炼制不可混成一个没有差异的“升级”按钮。 | confirmed |
| GAME-GU-REFINEMENT-003 | 游戏要同时支持多只蛊虫配合形成杀招，以及多只蛊虫经炼制转化为更高转蛊虫。 | 杀招是遭遇内的协同使用规则；合炼或升炼是遭遇外、永久改变本局构筑的内容转换。两者分别数据化，允许共享前置蛊虫但不可互相替代。 | confirmed |
| GAME-GU-REFINEMENT-004 | 炼蛊失败可能直接毁掉输入蛊虫。 | 每张首发炼制配方都必须声明失败结果；高收益炼制应有真实的核心构筑损失风险，不能只扣除可忽略材料。 | confirmed |
| GAME-GU-REFINEMENT-005 | 多蛊杀招经探索与炼制可被固化为一只蛊虫；该蛊虫以单蛊形式承担原组合近似的作用。 | 这类蛊方可从玩家实战方案、传承或炼道情报得到方向，可能是合炼、升炼或平炼。单蛊可降低多蛊协同的操作与条件负担，但仍受转数、真元、喂养、获得难度和炼制失败风险制约。 | confirmed |

| GAME-CULTIVATOR-002 | 角色在界面上保留按转数区分的颜色识别：一转青铜、二转赤铁、三转白银、四转黄金、五转紫晶。原著证据直接对应的是各转真元品阶；“空窍颜色”作为视觉化表达，不冒充原著术语。 | 使用可审查的 `aperture_state` 与 `essence_tier` 两个字段；`essence_tier` 采用原著品阶，`aperture_state` 记录空窍窍壁状态。首发实现一至三转。 | confirmed |
| GAME-CULTIVATOR-003 | 资质表示空窍元海的可容纳比例：无资质为零，丁等二三成、丙等四五成、乙等六七成、甲等八九成，十绝体圆满十成。 | 资质影响真元容量与基础恢复，不直接代替修为、蛊虫效果、财富或战斗胜负。十绝体不作为首发玩家的普通选择。 | confirmed |
| GAME-PLAYER-001 | 固定开局的无名南疆散修为丙等资质，元海容量为四成四。 | 开局真元最大值、自然恢复与前期催蛊节奏以 `0.44` 的资质容量为基线；不把资质随机化或做成局外成长。 | confirmed |

## 待后续设计明确的实现边界

- 全量已养蛊虫和杀招在抽象状态对局中的分组、检索、快捷操作与可读性方案；其只能改变展示，不能限制催发资格。
- 真元上限、恢复、催发成本与修为的关系，以及不同用途蛊虫的最小首发配比。
- 四种炼制在首发中的具体机会频率、成功风险、失败后果与材料来源。
- 玩家自定义杀招方案的保存、命名、编辑与快捷调用方式，以及其如何提供炼制灵感而不被错误地做成预设配方。
- 消耗蛊、改造蛊与传承在首发内容池中的数量、获得频率、叠加边界和原文来源审查。
- 一转至二转、二转至三转各自所需的修行节点、资源、伤势与风险条件，以及三转最低资质阈值。
- 商队和各类势力交换池的配比、刷新规则与反复刷取限制。
