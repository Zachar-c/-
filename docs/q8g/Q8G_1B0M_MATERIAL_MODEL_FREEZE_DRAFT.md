## 0. 材料世界模型总纲（v2：五类属性）

```text
材料 = 物质形态（载体标签）
     × 道痕（可多重；用途与适配性的核心属性）
     × 来源（source_class——类型标签，非单轴层级）
     × 价值信息（簇：品质 / 稀缺 / 需求）
     × acquisition_mode（玩家取得材料的方式）
```

> ⚠️ 概念计数澄清：形态/道痕/来源/品质/稀缺/需求/获取方式是 **7 个概念、5 类属性**——
> 品质、稀缺、需求合为**价值信息簇**（三者共同决定价值，见 M-5），不是三个独立维度，也不是一个属性。

| 类 | 内容 | 依据（事实库） | 建模状态 |
|---|---|---|---|
| **物质形态** | 骨/血/皮/翅/泥/草/石/酒…它是**什么东西** | E4 载体证据群 + 【推导 D3】正交 | 设计维度：**载体标签**，不承担用途分类 |
| **道痕** | 材料承载的道属性，**可多重**；决定适配哪道 | E4×4（170534/170552/398318/142182）+【推导 D3】 | 设计维度：**核心用途属性** |
| **来源** | `source_class`：凡兽/荒兽/兽王/蛊仙/异人/蛊师本体——**类型**标签 | E4（野猪王/兽王部件）+【推导 D2】血源层级 | 语义维度；🔴 **不数值化**、不做单轴 tier（另行论证） |
| **价值信息** | 簇 = 品质（quality_band）/ 稀缺 / 需求面 | 【推导 D2】+ E4（腐泥/偏门材） | 经济**输入约束**（Batch 2 数值化）；品质带档位未冻结（M-8） |
| **获取方式** | `acquisition_mode` = **玩家取得材料的方式** | 【推导 D2】已冻结 | 正式设计维度；与"来源"分属两维（M-6） |

## 1. M-1~M-11 逐项裁定提案

### M-1 形态 × 道痕可分离 —— 提案：✅ 采纳

- 依据：【推导 D3】（事实库 §2.2/§4），D3 结构 = 4 条独立 E4 + 3 条边界/反例，已过审阅收紧。
- 冻结条文：**同一材料形态可承载不同道痕；道痕决定材料的适配方向；形态不决定道痕。**
- 禁止推论：任意形态承载任意道（原文未证）；形态即道（骨≠骨道）。

### M-2 物质形态的角色 —— 提案：✅ 采纳为"载体标签"

- 依据：同 M-1 + 【推导 D3】"形态不是用途分类的充分条件"。
- 冻结条文：物质形态保留为材料的**标签维度**（配方语义、UI 文案可引用，如"剑吃铁""血滴子食精血"），**不作为用途/适配的分类维度**。
- 附带澄清：道标签词表（blood/qi/force/moon/poison/human…）与流派词表（schools.json 20 派）**是两个词表**；材料道痕用的是前者，不得混同。

### M-3 道痕可多重 —— 提案：✅ 采纳（补设计抽象标注）

- 依据：【原文事实 E4】腐泥 毒+土（398318）；schema 现状 `beast_blood: ['blood','qi']`。
- 冻结条文：材料实例允许多道痕；区分**主道痕**（主要适配方向）与**副道痕**（次要/条件适配）。
- 🏷️ **【设计抽象】主道痕 / 副道痕是《問眞》的数据建模抽象，不声称为原文术语。**
- 边界（E4，170552）：道痕决定适配**强弱**，不决定可用与否（见 M-10）。

### M-4 来源 —— 提案：✅ 采纳；字段定名 `source_class`

- 依据：【推导 D2】血源层级 + E4（野猪王/兽王部件/仙僵）；审阅警告已载明。
- 🏷️ 字段名裁定：~~`source_tier`~~ → **`source_class`**——荒兽/兽王/蛊仙/异人描述的是**不同来源类型**，
  不能排成 `凡兽 < 荒兽 < 兽王 < 蛊仙 < 异人` 一条线；叫 tier 会诱导 Agent 未来做成 `1=凡兽 2=荒兽` 数值轴。
- 冻结条文：`source_class` 作为材料的**类型标签**入模；
  **本轮不数值化、不做单轴 tier、不映射 rarity**——若未来需要数值化，单独立项论证。

### M-5 价值信息簇 —— 提案：✅ 采纳为经济输入约束

- 依据：【推导 D2】（腐泥/偏门材/泪冰/仙材，含反直觉边界）。
- 冻结条文：`reference_value` 的输入 = **f(道痕品质, 稀缺, 需求面)**；"用途数量"单独不是价值因子；
  `reference_value` 理解为**经济模型的参考输入**，不是"原文给出的材料价格"；
  数值化归 Batch 2（先修 `gu_value`），1-B1 只需保证新实例带上三因子的**定性档位**。

### M-6 获取方式 —— 提案：✅ 采纳（补定义）

- 依据：【推导 D2】已获审阅"可冻结"结论。
- 🏷️ **定义：`acquisition_mode` = 玩家取得材料的方式。**它回答"玩家怎么拿到"，
  与"材料从哪来"（`source_class`）**分属两维**——例如 `source_class = 荒兽` 的材料，
  玩家可通过 `击杀` 或 `交易` 取得，两者不冲突。
- 冻结条文：枚举（前 6 项原文实证，后 2 项标 [设计]）：
  `击杀获取 / 采集 / 交易 / 豢养收取 / 环境·事件生成 / 炼制副产` + `[设计] 夺取 / [设计] 继承`。
- 影响：1-C/1-D 设计按"该材料的事实获取方式"选通道，不得默认全员掉落。

### M-7 七物质族处置 —— 提案：🔄 退役为"形态标签常用集合"

- 依据：【推导 D3】修正 + §8 对照（泪冰等异人来源无法归族）。
- 冻结条文：**"族"不再是一级维度**；既有 7 种材料的族名（兽材/植物材…）降级为形态标签的**常用集合**，保留在文档与 UI 文案中，不做数据迁移。

### M-8 品质维度 —— 提案：✅ 修改后采纳（解除 P1–P4 过早冻结）

- 依据：原文 E4 证明**材料存在品质差异**（道痕数量/品质，"准九转仙材""取一角可炼六转"）；
  但"必须分四档"是**离散化的游戏设计**，原文未支持，不得进入冻结条文。
- 冻结条文（本轮只冻这两句）：
  1. **材料具有 `quality_band` 属性；品质可以参与晋升材料匹配。**
  2. **`quality_band` 的具体档位数、名称、与 promotion rank 的映射，不在 1-B0-M 冻结，交由 1-B1 / Batch 2 根据实际材料实例与经济模型确定。**
- 🔴 已删除 v1 的 P1–P4 × 品质带映射表——那是设计草稿，不是世界模型；防止 Agent 把四档当世界真理。
- 工作单 §2.1 的 P1–P4 成本模板同步降级为"**未决设计草稿**"（待 1-B1/Batch 2 重建），不再是冻结内容。

### M-9 假设层两项 —— 提案：分流

- `venom_sac`：原型未定位 → **保持【假设】**；1-B1 允许继续使用该实例，标 `[设计] 游戏扩展`。
- `moon_dew`：月光系实证形态 = **花瓣喂养口粮**（E3：1 元石/10 片、日耗 4 片）→ 提案将其**改义为游戏设计候选**：
  "月光系材料的游戏抽象（原型：花瓣口粮）"，**不声称原文存在月华露**；是否改实例名/合并到花瓣体系，留 1-B1 决定。

### M-10 道痕排他性 —— 提案：✅ 不引入"专属"机制

- 依据：反证检索无果（弱命题，R17）+ E4 反例"金道蜂翅对星念蛊没有多少帮助"（是**弱适配**，不是不可用）。
- 冻结条文：道痕适配用**强弱**表达（主道痕高适配、副道痕低适配、无道痕不适配），**不做硬排他**；
  "某材料专属某道"若未来需要，属纯设计决策，须另过 R14–R18 流程。

### M-11 谱系表材料关系回填 —— 🔴 按裁定重写（禁止自动规则）

> 🔴 v2 裁定：v1 的"每派 promotion 主材的主道痕 = 流派之道"**被否决**——
> 即便标注 `[设计] 默认`，它也容易把 `school = dao → 主道痕 = school` 硬编码成世界规律，
> 而"材料形态 ≠ 道属性""来源 ≠ 道属性"刚刚确立——不能再造一个未被证明的全局规则。
> 未来完全可能出现"某流派的关键材料不是该道材料，而是由生态、来源、炼制机制、稀缺性或特定蛊的需求决定"。

- 冻结条文：
  1. **每派 promotion 主材必须具备与该流派核心炼制目标存在语义关联的道痕适配依据。**
  2. **"主道痕 = 流派之道"只能作为设计默认候选，不能作为自动规则。**
  3. **若使用其他道痕，必须提供三件套：① 原文事实；② D 层推导或明确 `[设计]`；③ 世界模型理由。**
- 审阅方式：1-B1 每批谱系回填时，逐派列出"主材道痕 ↔ 流派"的关联依据（默认候选也需过目），随批验收。
- 这样才真正贯彻：**先挖世界规律，再做设计；而不是为了让系统方便，把世界规律倒推出来。**

## 2. 冻结条文（v2，按 2026-09-13 审阅裁定修订）

```text
【材料世界模型 v2】
1. 材料五类属性：物质形态（标签）× 道痕（多重，主/副【设计抽象】）× 来源（source_class 类型标签）
   × 价值信息簇（品质 quality_band / 稀缺 / 需求面）× acquisition_mode（玩家取得材料的方式）。
2. 道痕是用途与适配的核心属性；形态不决定道痕与用途；适配分强弱，不硬排他（主道痕高适配、
   副道痕低适配、无相关道痕不适配/弱适配）。
3. source_class 只做类型标签；本轮不数值化、不做单轴 tier、不映射 rarity；数值化需单独立项。
4. 价值输入 = f(道痕品质, 稀缺, 需求面)；"用途数量"单独不是价值因子；reference_value 是经济模型
   的参考输入，不是"原文价格"；数值归 Batch 2。
5. acquisition_mode 为一级设计维度，定义 = 玩家取得材料的方式，与 source_class 分属两维；
   掉落只是获取方式之一。
6. 材料具有 quality_band 属性，品质可参与晋升材料匹配；档位数、名称、与 promotion rank 的映射
   不在本轮冻结，交 1-B1 / Batch 2 确定。
7. v2 七物质族退役为形态标签常用集合；"N 转材"术语退役。
8. 每派 promotion 主材必须具备与该流派核心炼制目标存在语义关联的道痕适配依据；
   "主道痕 = 流派之道"只是设计默认候选，不是自动规则；偏离候选须提供
   ①原文事实 ②D 层推导或明确 [设计] ③世界模型理由。
9. 所有新增材料实例必须携带：形态、主/副道痕、source_class、acquisition_mode、quality_band
   （loot_tables.materials 扩展）。
10. 任何新维度、新排他机制、来源数值化，须重新走 R14–R18 考据流程 + 世界模型裁定。
```
