## 3. 关键机制事实（接手必读）

- **craft_cap**：`SoulCapacity.craft_cap_for_soul`——soul 1–2 → 2 件，soul 3 → 3，soul 5 → 4。promotion 现为 1 蛊 + 1 材料 = 2 件，soul 1 可炼。**任何"加材料份数"的提案都会重新撞死这个门。**
- **`append_event` 语义**：返回新 RunState 并**自动应用 `event.after`**——绝不许在 append 后再手动赋值状态字段（曾产生产石翻倍 bug）。
- **被拒不落事件**：`Resolver._rejected` 只返回 `{ok:false, reason}`，不进事件日志——promotion 尝试统计只能在驱动器侧做。
- **拓扑**：`pacing.json` 每层已锚定 1 个可见 `refinement_hollow`（row=mid）+ rest 池随机补充 → route 恒 5 个 refinement 节点。边结构：每节点连下行 1–2 节点、下行每节点 ≥1 入边 → **bench 只对部分路径可达**（单向 DAG，错过 mid 行该层即无 bench）。单路径探访上限 5（seed 55 打满）。
- **掉落池**（`loot_tables.json`）：common 1 roll/60 权重（crude 为主，f1 唯一来源，共振后 ≈21%/场）；elite 1/75（f2/f3 主渠道）；boss 2/94（f4 唯一来源）。~~material_pity 目标是旧四材~~ **P2-a 已派系化（2026-09-13）**：`target_bands_by_tier`（common→crude、elite→plain/refined、boss→prized）× 本派 promotion 配方材料 ∩ 池成员（`loot_resolver._material_pity_targets`）；已知残留：f1 空档会因共享计数器被 elite f2/f3 掉落重置而持续（提案 §7.4）。
- **共振**：材料池 roll 时主道痕==玩家流派的条目权重 ×5（`loot_resolver._roll_materials`，`content_catalog` 有校验）。
- **76 条 promotion 配方全部 `default_unlocked`**——链路门禁只剩"持有指定输入蛊（starter 已含 f1 段）+ 材料 + 元石"。
- **R15 纪律**：任何新证据/新规则必须分层标注；材料不得由 Agent 设计（只考据原文）；反证搜索留痕。

### 5.2 附加硬约束（裁定补充，实施时必须满足）

1. **Pity state determinism（新 Gate）**：pity 引入历史状态依赖后，pity 状态必须进入不可变事件日志 / run snapshot——保存→读取→重放不得出现 pity 触发分歧。现状：`state.material_pity` 已随 `loot_materials_gained` 事件落 before/after（`loot_resolver._apply_loot`）；**存档序列化是否含 material_pity 尚未核验**，P2-a 施工时须确认，缺则补。
2. **Opportunity → Conversion 出口指标（新）**：R-3 最终不只看 promotion 次数，须分解因果链 `拥有足够材料 → 遇到 refinement → 成功执行 promotion`，分别统计 `material_ready / refinement_available / promotion_attempted / promotion_success`，区分"没材料 / 有材没台 / 有台没去 / 去了失败"。
3. **实验纪律**：一次只改一个变量，每阶段后用同一种子集复测归因。
