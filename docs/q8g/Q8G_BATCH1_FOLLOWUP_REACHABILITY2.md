## 0. 问题定义

R-3 的 O→C 漏斗在 3 局观测到"材料就绪 + 探访达成 → promotion 尝试 0"（如 force 20260927：探访 4、材料就绪 3、尝试 0）。原因不是炼蛊失败（拒因恒空），而是**未持有 promotion 指定输入蛊**——漏斗在"材料"与"尝试"之间还有一段：

```text
① gu_ready？        ← 本轮第一优先级
② material_ready？
③ refine_available？
④ promotion_attempt？
⑤ success？
```

## 1. 调查问题（本轮要回答的）

1. **Q1**：`material_ready` 但尝试 0 的探访中，缺的输入蛊是哪只？是 starter 缺失、链中间蛊被消耗，还是 rank 不满足？
2. **Q2**：输入蛊缺口是**普遍性**（所有 run/派都缺）还是**时序性**（前期缺、后期补上但探访已过）？
3. **Q3**：若为普遍性缺口，缺口源头在哪一段——基础蛊掉率（1-D common 6%）、派系池过滤、starter 配置、商店货架，还是 promotion 消耗了链上唯一实例？
4. **Q4**：输入蛊问题修复后，f1 带段是否仍频繁断档（决定第二优先级"f1 分计数器"是否立项）？

### 调查结论（Q1–Q4）

1. **Q1 否定——输入蛊不缺**：8 局全部 gu_ready == 探访；`gu_missing` 直方图 8 局全空。starter 与链上当前环的输入蛊始终在手。
2. **真正的断点是顺序链传导**：3 个"0 尝试"局（force 20260927、sword 11/33）全部是 f1 整局 ×0 的局——f1 缺 → 环 1 永不可执行 → 环 2+ 的输入蛊（= 上一环产出）**无法被获得** → 后段材料全部积压。`mat_ready 3 但 full_ready 0`（force 20260927）正是"材料就绪在环 2+、蛊就绪在环 1"的跨环错位。
3. **Q2**：缺口是**普遍性**（f1 整局 ×0），不是时序性；源头即 R-3 §7.4 已定位的 common 池 f1 掉落 × 共享保底计数器被 elite f2/f3 掉落重置。
4. **Q4 成立**：输入蛊侧**没有独立修复对象**，f1 带段连续性是直接约束——"f1/f2-f3/f4 分计数器"由第二候选升级为**第一候选**，待用户裁定后另立实施批。
