# 《蛊真人》完本精编纲目校准体系设计

## 1. 文档目的

本设计用于指导已经完本的《蛊真人》授权文本精编工作。

项目不以压缩原文为目标，也不以重新策划剧情、续写或补写为目标。核心任务是：依据完整原文、全书最终设定、人物弧线和伏笔回收情况，对正文进行出版级的清理、润色、校正和必要的结构整理，同时最大限度保留原作的剧情信息、心理描写、场景现场感、铺垫、伏笔和冷峻诡谲的叙事气质。

纲目体系是编辑内部的校准层，不是面向读者的剧情大纲。它用于提前发现跨章节、跨篇章和跨全书的问题，减少只看局部正文造成的误改与返工。

## 2. 背景与问题

《蛊真人》原文篇幅约 1457 万字，人物、势力、蛊虫、传承、资源、时间线和伏笔数量庞大。仅凭当前批次及相邻章节进行精编，会产生以下风险：

- 把后文已经解释的前文悬念误判为逻辑漏洞；
- 把原文有意保留的暧昧提前解释，破坏信息释放顺序；
- 只看到单节的重复，误删高潮前的必要铺垫；
- 为修复局部数字或时间而制造新的全书矛盾；
- 将人物心理压缩成剧情结论，削弱人物弧线；
- 忽略高潮后的长期后果，使篇章之间失去因果承接；
- 把精编稿逐渐改造成剧情摘要，而非更成熟的完整小说文本。

因此，正文精编前需要建立一套以完本原文为事实基础、能够逐级定位和回溯的总纲、分纲、细纲及校准台账。

## 3. 目标

### 3.1 主要目标

1. 建立覆盖全书的结构地图，掌握六部、主要篇章和高潮之间的因果关系。
2. 建立篇章级目标、阻力、选择、代价和结果模型。
3. 建立节次级正文校准依据，明确哪些内容必须保留、可以压缩或不得提前揭示。
4. 让每一处高风险正文修改都能回溯到原文证据、后文回收或明确的编辑决议。
5. 通过人物、伏笔、资源、时间和事实争议台账，支持跨批次的一致性核验。
6. 保留原作完整叙事体量和信息密度，避免精编过程演变成大纲化删减。

### 3.2 非目标

- 不把六部总纲直接当作精编正文。
- 不以固定字数比例压缩原文。
- 不新增原文没有的剧情、人物动机、力量体系或世界真相。
- 不为了追求局部整齐而擅自消除原作的悬念、歧义和叙事留白。
- 不在尚未完成全书核验时强行统一存在底本证据冲突的数字。
- 不覆盖、替换或提交完整原始文本。

## 4. 核心原则

### 4.1 完整原文是事实基线

完整原文是所有判断的首要来源。总纲、分纲、细纲和台账都是对原文的索引、归纳和编辑决议，不得反过来替原文创造未经证实的事实。

### 4.2 后文回收可以校准前文，但不能提前泄底

编辑可以利用完本信息判断前文的伏笔、人物真实动机和最终因果，但正文必须遵守原书的信息释放顺序。纲目可以记录答案，精编正文不能在原书尚未揭示的位置提前说出答案。

### 4.3 大纲的首要作用是确认保留边界

大纲不主要用于决定删多少，而用于判断哪些内容不能删。尤其是高潮前的资源积累、心理积累、关系转折、信息误导和环境铺垫，不得因为当节看似重复而删除。

### 4.4 关键场面保留力度

绝境、杀机、反噬、决裂、身份揭示和高潮决断等场面，应保留原作的确定性、心理压迫、动作现场感和句末力度。语言精炼不得把有气势的判断改成平直的剧情说明。

### 4.5 事实与推测分层

所有纲目和台账记录应区分明确事实、后文回收、多处印证、人物推测、有意悬念、底本矛盾和无法确定事项，避免把编辑推断伪装成作者设定。

## 5. 三层纲目架构

### 5.1 全书总纲

总纲按六部及其主要阶段组织，回答“全书为什么这样发展”。每部至少记录：

- 本部核心命题；
- 方源进入本部时的处境、能力、资源和限制；
- 方源的阶段性目标及其变化；
- 主要势力和关键人物的状态；
- 本部主线冲突；
- 重要高潮及其在全书因果链中的位置；
- 方源获得、损失和转换的关键资源；
- 人物弧线和主题线的长期推进；
- 本部结束时产生的不可逆变化；
- 对下一部的推动作用；
- 仍需保留为悬念或存在争议的内容。

总纲不逐节复述剧情，也不替正文解释每个细节。它用于防止在局部精编中误判方源的长期目标、人物关系和全书升级方向。

### 5.2 篇章分纲

分纲以主要篇章、战役、秘境、传承争夺或重要过渡段为单位。篇章边界不机械服从原书卷名或章节编号，而依据核心目标、冲突对象、资源闭环、关系转折、叙事空间变化和高潮后果判断。

每个分纲至少包含：

- 篇章范围；
- 所属部和总纲目标；
- 开端状态；
- 核心矛盾；
- 方源的明面目标；
- 方源的真实或长期目标；
- 主要对手与其他势力的目标；
- 关键资源、能力和限制；
- 冲突升级阶梯；
- 中段转折；
- 高潮及关键决断；
- 方源付出的代价与损失；
- 结果与不可逆后果；
- 伏笔的埋设、强化、转化和回收；
- 人物关系与心理弧线变化；
- 高潮前必须保留的铺垫；
- 不宜提前解释的信息；
- 连接下一篇章的状态变化。

每个分纲应能形成如下因果链：

```text
初始处境
→ 目标形成
→ 阻力出现
→ 方源做出选择
→ 对手反应
→ 局势升级
→ 方源付出代价
→ 高潮决断
→ 新状态建立
```

如果分纲只能写成“发生若干事件，最后方源获胜”，说明其中的目标、阻力、代价或后果仍未被拆清。

### 5.3 节次细纲

细纲以原书节次或连续场景为单位，直接服务正文精编。每节至少记录：

- 节次、标题和所属部；
- 所属篇章分纲及其节点；
- 本节叙事功能；
- 场景地点和时间；
- 进入本节前的人物与局势状态；
- 本节主要事件；
- 方源当下目标；
- 主要阻力；
- 方源的选择；
- 选择造成的结果；
- 本节结束时的状态；
- 关键人物的心理变化；
- 读者知道的信息；
- 相关人物知道的信息；
- 本节刻意隐藏的信息；
- 伏笔当前状态；
- 必须保留的原文内容；
- 可以压缩或合并的重复内容；
- 只能润色、不可削弱的段落；
- 不得提前揭示的后文信息；
- 需要核验的逻辑、时间、资源、称谓和设定问题；
- 对应精编正文文件和定位信息。

细纲必须关注“本节结束后发生了什么变化”。变化可以是人物状态、资源数量、关系方向、信息差、危险等级、目标优先级或主题意象的变化。没有变化的段落也可以保留，但必须说明其承担的是气氛、铺垫、节奏或人物塑造功能。

## 6. 纲目与正文的权威关系

发生冲突时，按以下顺序判断：

1. 完整原文中可以直接确认的事实；
2. 后文对前文的明确回收；
3. 多处情节相互印证的设定；
4. 总纲、分纲和细纲中的编辑归纳；
5. 单一段落中的人物推测或旁白推断。

底本存在数字、时间或设定冲突时，不得仅凭局部上下文强行制造唯一答案。应在事实争议台账中记录证据、冲突范围、暂定策略和后续决议。正文优先采用不扩大矛盾、且不破坏叙事功能的表达。

## 7. 证据等级与状态分类

纲目和台账中的结论统一使用以下分类：

| 分类 | 含义 | 正文处理原则 |
| --- | --- | --- |
| 已确认 | 原文明确陈述，或后文明确回收 | 可以作为事实校正依据 |
| 多处印证 | 多个事件或人物叙述相互支持 | 可以谨慎统一，但保留证据位置 |
| 人物推测 | 某人物基于当时信息做出的判断 | 保留为人物认知，不改写成全知结论 |
| 有意悬念 | 原作刻意延迟揭示的信息 | 正文不得提前解释 |
| 底本矛盾 | 不同位置无法同时成立 | 先记录，避免擅自选定 |
| 待核验 | 现有检索不足，尚不能判断 | 不作确定性修订 |
| 编辑决议 | 完成证据核对后形成的正文处理方案 | 记录理由和适用范围 |

## 8. 配套台账

现有台账继续保留，并按以下职责使用：

- `character-ledger.csv`：人物身份、关系、当前状态、动机和长期弧线；
- `foreshadowing-ledger.csv`：伏笔首次出现、强化、转化、回收和最终意义；
- `resource-ledger.csv`：元石、蛊虫、传承、修为、伤势、身份和其他关键资源的变化；
- `timeline-ledger.csv`：事件先后、持续时间、日期、相对顺序和时间冲突；
- `logic-issues.md`：逻辑、设定、称谓、数量和因果问题的分析记录；
- `editorial-notes.md`：每轮正文处理、取舍和高风险修改说明；
- `fact-disputes.csv`：事实争议、证据等级、冲突范围、暂定处理和最终决议。

每条高风险正文改动至少关联一种证据：原文定位、后文回收、台账条目或编辑决议。台账保存摘要和定位，不复制大段原文。

## 9. 从完整原文到正文的工作流程

### 阶段一：建立全书基线

只读取和索引完整原文，不修改正文：

1. 识别部、卷、节和章节标题；
2. 统计每节起止位置、字数和编码信息；
3. 建立人物、势力、传承、秘境、战役和关键资源的出现索引；
4. 标记作者按语、站点推广、连载通知、重复标题和转码残留；
5. 记录索引版本、源文件信息和扫描时间。

### 阶段二：形成全书总纲

依据完整原文和最终回收情况，按六部及主要阶段整理长期目标、冲突、人物弧线、主题线和高潮后果。总纲初稿可以由索引辅助生成，但必须回看正文，避免只依据章节标题概括剧情。

### 阶段三：形成篇章分纲

依据核心目标、阻力、资源闭环、关系转折、空间变化和不可逆后果划分篇章。为每个篇章建立目标—阻力—选择—代价—结果链，并标出高潮前的不可删除铺垫。

### 阶段四：制作节次细纲

按正文批次制作细纲，记录本节叙事功能、信息差、心理变化、伏笔状态、保留边界和可压缩内容。前二十节作为第一轮细纲试点，用于校验字段是否足够。

### 阶段五：正文精编与校准

每批正文按以下顺序处理：

1. 读取对应原文底稿；
2. 读取所属总纲、分纲、细纲和相关台账；
3. 保留完整事件、心理、铺垫和伏笔；
4. 删除连载噪声和无叙事价值的重复；
5. 修复有充分证据支持的语言、转码、时间、数字、称谓和因果问题；
6. 逐条检查细纲中的必须保留项和不得提前揭示项；
7. 更新人物、伏笔、资源、时间和事实争议台账；
8. 运行正文结构、编码、标题、噪声和空白校验；
9. 在编辑记录中说明高风险改动；
10. 提交并推送，保留可回退版本。

## 10. 正文修改尺度

### 一级：清理

删除站点推广、作者按语、打赏、推荐票、更新通知、重复标题和明显转码噪声。

### 二级：润色

调整语序、节奏、指代、段落衔接和同义重复，不改变信息量、事件顺序和情绪方向。

### 三级：校正

修复有充分证据支持的时间、数字、称谓、因果和设定错误。无法确认的冲突进入台账，不擅自改成确定事实。

### 四级：结构重构

重新安排段落、节次边界或叙事顺序。仅在原文存在明确结构问题，且总纲、分纲和细纲共同证明必要时使用。前二十节原则上以一级至三级为主，不主动进行大幅重构。

## 11. 信息释放规则

编辑内部大纲可以记录全书剧透，但正文必须保持原书的认知顺序：

- 方源当时不知道的真相，不以全知口吻提前写出；
- 后文才确认的因果，不在前文改成确定答案；
- 人物错误判断应保留其认知位置，必要时用叙事语气区分事实和推测；
- 伏笔可以通过动作、意象和异常细节强化，但不能直接标注其未来意义；
- 高潮前的铺垫不得因后文已知而被压缩为一句预告。

## 12. 验收标准

每批精编稿完成前，至少检查：

- 事件顺序与原文一致，除非有明确结构性错误；
- 主要心理转折没有被压缩为一句剧情结论；
- 伏笔没有被提前解释或无故删除；
- 关键行动能在细纲中找到前置状态和动机；
- 重要资源变化可以在资源台账中追踪；
- 重要时间关系可以闭合，无法闭合之处已有记录；
- 人物称谓和关系与人物台账一致；
- 高潮前铺垫和高潮后果没有被删除；
- 正文没有站点噪声、转码残留和明显重复；
- 高风险修改都有证据或编辑决议；
- 完整原始文本没有进入 Git；
- `git diff --check`、编码检查和结构校验通过。

## 13. 试运行与后续扩展

第一部《魔性不改》前二十节作为细纲试运行范围。试运行重点不是追求一次完成，而是验证：

- 细纲字段是否能覆盖心理、伏笔、资源和信息差；
- 总纲与分纲是否能解释前二十节的铺垫和转折；
- 事实争议台账是否能容纳花酒行者死因、元石流水等跨后文问题；
- 正文批次是否可以根据纲目直接执行，而不重复扫描全书；
- 校验命令是否能及时发现章节、编码、噪声和版本问题。

试运行通过后，按“总纲已建立的部或篇章 → 分纲已建立的篇章 → 细纲与正文批次”的顺序扩展。跨批次问题统一回写台账，不在正文中孤立修补。

## 14. 风险与应对

### 风险一：纲目变成大纲化删减工具

应对：细纲必须记录“必须保留”“只能润色”和“不得提前揭示”三类边界；验收时检查心理、铺垫和现场感，而不只检查事件是否齐全。

### 风险二：编辑过度依赖后文答案

应对：所有正文修改区分编辑已知信息和当时人物/读者信息，严格遵守原书信息释放顺序。

### 风险三：为了修复局部矛盾而制造全书矛盾

应对：数字、时间和力量体系问题先进入事实争议台账，完成全书证据核对后再形成编辑决议。

### 风险四：前期纲目制作过重，拖慢正文推进

应对：总纲和主要篇章分纲优先，细纲按正文批次滚动制作；台账只保存摘要和定位，不复制完整原文。

### 风险五：索引和台账失去同步

应对：每批正文提交前同步更新相关台账，并进行标题、文件、定位和状态字段检查。

## 15. 完成定义

纲目校准体系在以下条件满足时视为建立完成：

1. 六部总纲已覆盖全书主要结构和长期变化；
2. 主要篇章和高潮具有可追踪的分纲因果链；
3. 正文批次具有关联的节次细纲；
4. 事实、人物、伏笔、资源和时间问题可回溯到证据或决议；
5. 正文修改不会因局部精炼而破坏全书伏笔、人物弧线和信息释放；
6. 每批正文可以通过统一校验、提交和回退流程保存。

## 16. 下一阶段

本设计批准后，下一阶段制定具体实施计划，优先完成：

1. 六部总纲的文档结构和首版内容；
2. 主要篇章分纲的命名、范围和模板；
3. 第一部前二十节细纲；
4. `fact-disputes.csv` 的字段和初始问题迁移；
5. 依据细纲重新审查前二十节精编稿。
