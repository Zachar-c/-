## 0. 首要结论：晋升链只有两跳，且~~"377 条 advance 不升转"~~（⚠️ 后者已推翻，见头部横幅）

任务书假设的链条是 `低转蛊 → 晋升材料 → 元石 → 高转蛊`。实测**链条在第二跳断裂**。

### 0.1 三条颠覆性事实 `[FACT]`

| # | 事实 | 证据 |
|---|---|---|
| **A** | **377 条 `advance` 配方的输入与输出转数完全相同**（220 条 1→1、157 条 2→2），且 `output_gu_id == input_gu_ids[0]`（**377/377 同名**） | §1 |
| **B** | **只有 13 条 `fixed` 配方能提升转数**，且全部是手工蛊（light/earth/blood/sword 四流派） | §2 |
| **C** | **转 3/4/5 的蛊零晋升配方**（转 3 有 180 只、转 4 有 97 只、转 5 有 147 只，**全部无 advance**） | §1.2 |

> **含义 `[INFERRED]`**：`advance` 的真实语义**不是"升转"**，而是
> **"同名蛊 + 材料 + 元石 → 同名蛊"**（本体不变，只改实例转数）。
> 结合 `_apply_fixed_recipe` 第 232 行 `output_instance["rank"] = min(rank+1, 5)`，
> advance **确实会把实例转数 +1** —— ~~但**只在玩家持有高于定义转数的实例时才生效**，
> 而常规途径拿到的新实例 `rank = 定义 rank` → **advance 在普通情况下不升转**。~~
>
> ## ⚠️ **上述"只在持有高转实例时才生效"是错误推断（2026-09-12 实测推翻）**
>
> 实测（真实 `Resolver` 调用）表明：**普通 rank-1 实例经 advance 后变为 rank 2**。
> 原推断的漏洞在于：把 `mini(rank+1, 5) <= rank` 的**封顶判定**（第 211 行，仅在 rank=5 时成立）
> **误当成普遍条件**。正确读法是 **`rank+1` 就是常态结果，封顶只在 5→5 时拦截**。
> 详见 `Q8G_BATCH0_RULING.md` §13.1 —— **377 条 advance 是健康、有效的培炼路径**。

## 1. `advance` 配方解剖

### 1.1 形式结构 `[FACT]`

| 属性 | 值 |
|---|---|
| 数量 | 377（占配方 96.2%） |
| 输入 | **恒定 1 只蛊**（`inputs.size()` 必须 = 1，否则 `invalid_advance_recipe`） |
| 输出 | **与输入同名**（377/377） |
| 材料 | **恒定只见 `beast_bone`**（217+1+157 条），另 3 条例外用 `beast_blood`/`moon_dew` |
| 元石 | **按输出蛊的转数分档**：rank 1 → 6 石；rank 2 → 10 石 |
| 门禁 | `advance` **豁免蛊方图鉴**（`recipe_unlocked` 第 174 行直接 `return true`） |

### 1.2 转数分布 `[FACT]` — 链在这里断

| 定义转数 | 该类蛊总数 | 有 advance 配方 |
|---|---|---|
| 1 | 220 | **220（全覆盖）** |
| 2 | 157 | **157（全覆盖）** |
| 3 | 180 | **0** ⚠ |
| 4 | 97 | **0** ⚠ |
| 5 | 147 | **0** ⚠ |

**advance 素材消耗 `[FACT]`**：
- 转 1 蛊：219 份兽骨 + 1 份兽血 + 1 份月华露
- 转 2 蛊：314 份兽骨（**每条固定 2 份**）
- **合计 537 份兽骨**（= F1 §3.2 的"兽骨总消耗 537"，**全部来自 advance**）

> **关键 `[FACT]`**：F1 发现"兽骨垄断 378 条配方"，此处定位到根源 ——
> **垄断全部来自 advance**。兽骨是**"给低转蛊开一阶"的通用门票**。

### 1.3 成本分析 `[FACT]`

| 项目 | 转 1 蛊 | 转 2 蛊 |
|---|---|---|
| 元石 | 6 | 10 |
| 兽骨 | 1 | 2 |
| 进入下一转所需 | — | — |
| **卖价（`gu_value`）** | 3 | 5 |

> **净亏 `[FACT]`**：花 6 石 + 1 兽骨去 advance 一只转 1 蛊，
> 若结果仍是转 1（常规情况），**卖出只回 3 石** → **净亏 3 石 + 1 兽骨**。
> 只有在"实例转数已被抬高"时 advance 才有收益，而**抬高渠道只有 13 条 fixed**。

### 2.1 结构观察 `[FACT]`

1. **13 条全部集中在 4 个流派**（light 3 / earth 2 / blood 1 / **sword 6**）。
   其余 **16 个流派零升转通道**。
2. **sword 独占 6 条**，且是**唯一能从转 1 直达转 5 的流派**
   （`ascend_sword_rec` 一步 1→5）→ 与 MEMORY 记录的"剑道落地计划 T1–T14"一致，
   这批是**剑道专属设计的产物**。
3. **升转是"换名"而非"同名+1"**：`sword_atk_1_05_gu → sword_atk_2_12_gu`
   （名字里的转数标记变了）→ 这是**定向合炼（`output_rank` 路径）**，不是 advance。
4. **`stone_cost` 字段缺失** → 13 条全部**不花元石**（只有材料/蛊输入）。
5. **`default_unlocked` 8 条为 true** → 一半升转配方**开局即有**。

### 2.2 一句话成本效率 `[FACT]`

| 路径 | 成本 | 产出 |
|---|---|---|
| `ascend_sword_rec` | 1 只 sword_rec_1_10_gu（转 1） | sword_rec_5_17_gu（**转 5**） |
| 卖价对比 | 3 石 | **20 石** |

> ⚠️ ~~**零元石、零材料、一蛊直达五转** → **这是全游戏唯一"纯白嫖升转"通道**~~
>
> **2026-09-12 更正**：该配方实测为 **60 石 + 1 `boar_king_tusk`**（`stone_cost` 字段曾漏读）。
> **sword 并无"纯白嫖"通道**；0 成本通道实际存在于 **5 条 light 系配方**。
> 本节的"极端不对称"观察**方向需改写**：不对称不在成本，而在**覆盖流派数（4/20）**。
> 详见 `Q8G_BATCH0_RULING.md` §13.2 / §13.3。

## 3. `free_pair`（自由配蛊）与 `cultivate`（修二转）

### 3.1 `free_pair` `[FACT]` — 数据在，但无消费点

`balance.free_pair`：
```
success_pct: {2: 90, 3: 70, 4: 50, 5: 35}
stone_cost:  {2: 20, 3: 60, 4: 150, 5: 300}
```
- `[GAP]` **全仓无代码读取 `free_pair`**（`content_catalog.gd` 只校验键存在）。
- 但 `free_pair` **正是任务书描述的"元石 → 高转蛊"通道**：
  花 20/60/150/300 石把蛊推到 2/3/4/5 转，成功率递减。
- **该通道未接线** → 高转蛊**无法用元石获得**。

### 3.2 `cultivate_rank_two` `[FACT]` — 唯一接线的"用元石变强"

- 成本：`cultivate_rank_two_stone_cost = 5`（refine_command_rules.gd:371）。
- 效果：`cultivation = 2`（**人物修二转**，非蛊升转）。
- `[INFERRED]` 这是**提升"驱动低转蛊"的效率**（配合 `actual_cost_percent` 折扣），
  不是升蛊转数。**5 石是全场最便宜的成长**，且一次性。
- `[GAP]` **无 `cultivate_rank_three/four/five`** → 修三转以上**不存在**。

### 3.3 `advance_bonus_by_rank` `[FACT]` — 又一个孤儿

```
advance_bonus_by_rank = {1: 0, 2: 1, 3: 3, 4: 6, 5: 10}
```
- `[GAP]` **全仓无调用者**（`content_catalog.gd` 仅校验）。
- 这个表**正是最接近"升转奖励曲线"的定义**（0/1/3/6/10），却**未接线**。

## 4. 晋升经济全景（实测）

```
                    ┌──────────────────────────────┐
   低转蛊（转 1/2）  │  377 条 advance（同名，+1 实例转数）│
   220 + 157 只      │  成本：6/10 石 + 1~2 兽骨        │
                    │  ⚠ 常规下转数不变（定义=实例）    │
                    └──────────────────────────────┘
                                  │
                    ┌──────────────────────────────┐
                    │  13 条 fixed（换名，定向升转）   │
                    │  零元石，纯蛊/材料输入           │
                    │  8 条开局解锁                   │
                    │  ⚠ 仅 4 流派（sword 独占 6）     │
                    └──────────────────────────────┘
                                  │
                    ┌──────────────────────────────┐
                    │  free_pair（20/60/150/300 石）  │
                    │  [GAP] 未接线                   │
                    └──────────────────────────────┘
                                  │
                    ┌──────────────────────────────┐
   高转蛊（转 3/4/5）│  180 + 97 + 147 = 424 只       │
                    │  零晋升配方 / 零 free_pair      │
                    │  获取：商店买（≤80 石）/ Boss 0% │
                    └──────────────────────────────┘
```

**结论 `[FACT]`**：`低转蛊 → 晋升材料 → 元石 → 高转蛊` 这条**完整链条不存在**。
真实存在的是**两条互不相交的短链**：

| 链 | 形式 | 覆盖 |
|---|---|---|
| **链 A（advance）** | 同名蛊 + 兽骨 + 元石 → 同名蛊 | 转 1/2 全覆盖，**不改转数** |
| **链 B（fixed）** | 异名蛊 + 材料 → 高转异名蛊 | 13 条，**4 流派** |

## 5. 对红线（任务书 §六）的核查

> 红线："**不得破坏'低转蛊通过成本效率进入高转构筑'"**

| 检查项 | 结果 | 判定 |
|---|---|---|
| 低转蛊能否进入高转构筑？ | 能，但**仅 4 流派**（13 条 fixed） | ⚠️ 部分成立 |
| 成本效率是否优于直接购买？ | sword 链：**1 转 1 蛊 → 转 5 蛊，零元石** vs 商店买转 5 = 70 石 | ✅ 成立（但仅 sword） |
| 是否存在"低转蛊唯一出口是卖钱"？ | **16 流派是**（转 1/2 蛊只有 advance 同名升级 + 卖出） | ❌ 红线受损 |
| 高转蛊是否有获取通道？ | 商店买（6–80 石）/ Boss 掉落 **0%** / 无配方 | ⚠️ 单一 |

> **F4 判定**：红线**在 sword 流派成立，在其余 16 流派失效**。
> 原因不是定价，而是**"能升转的配方只做了 13 条"** —— 这是内容覆盖问题，
> 不是数值问题。**F4 不提出修改**，只记录该结构性缺口。
