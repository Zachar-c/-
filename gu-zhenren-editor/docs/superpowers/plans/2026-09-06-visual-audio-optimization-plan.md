## 五、前后端协作规范

### 5.1 数据流向

```
领域层（后端）                    表现层（前端）
┌─────────────────┐              ┌─────────────────┐
│  RunData 状态    │ ──快照──→   │  ScreenView 渲染  │
│  事件日志        │              │  动效/音效触发    │
│  配置表(JSON)    │ ←──读取──   │  视觉/音效配置    │
└─────────────────┘              └─────────────────┘
```

### 5.2 前端不得做的事

- ❌ 不得直接修改领域状态
- ❌ 不得硬编码视觉参数（应从配置表读取）
- ❌ 不得在UI层实现游戏规则
- ❌ 不得绕过统一命令入口

### 5.3 后端必须提供的事

- ✅ 所有视觉相关的元数据（流派、类型、品质、状态）
- ✅ 所有音效触发的事件数据（受击、死亡、状态变化）
- ✅ 屏幕切换事件（源/目标/原因）
- ✅ 统一的配置表接口（视觉配置、音效触发器）

## 七、风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 开源音效许可证不兼容 | 法律风险 | 优先使用CC0/CC BY音效，避免CC BY-NC；引入前确认许可证 |
| 美术资产风格不统一 | 视觉品质下降 | 制定美术风格规范（异常自然志图鉴），所有资产按规范生成/筛选 |
| 动效性能问题 | 游戏卡顿 | 限制同时播放的动效数量；使用对象池复用；低端设备降级 |
| 前后端接口漂移 | 联调失败 | 所有接口变更同步更新契约文档（docs/contracts/）；UI守卫测试覆盖 |
| 音效文件体积过大 | 包体膨胀 | 使用OGG格式压缩；单音效控制在500KB以内；环境音乐使用循环片段 |
