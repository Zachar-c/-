# 《问真》Web 线 · 交接（2026-09-18）

> 本目录是**独立于 Godot 项目**的平行技术实验。目的不是复刻 Godot 线，也不是做标准 Roguelike，
> 而是验证一件事：**对「个人导演 + AI 实现」这种生产模式，Web 是不是比 Godot 更短的那条路。**
>
> 评价标准不是「谁更专业 / 功能更多」，而是：从一句创作需求到可见结果要多久、AI 改一次视觉要几轮、
> 一个人做 100 个场景时更愿意走哪条。

## 三、技术选择

### 用了什么，为什么必要

| 技术 | 为什么 |
|---|---|
| 原生 HTML + CSS + JS (ES Modules) | **无构建步骤**。改一行文案 → 刷新 → 看到结果。整条实验线要测的就是这个循环 |
| CSS 分层 + `transform` 视差 | Cinematic 2D 的景深/视差不需要 GPU 代码，DOM 足够 |
| WebAudio 程序合成（雨、心跳、吞咽、颤音） | 零音频资产起步，先验证「声音和画面共同叙事」的成本 |
| Pointer Events | 拖拽喂食、悬停注视 |
| 一个普通 JS 对象 + `URLSearchParams` | 全部状态。够用 |
| `python -m http.server` | 只为 ES modules 的 CORS |

### 明确**不用**什么，以及为什么

- **TypeScript** — 引入编译等待，改文案的循环变慢；原型期类型收益为零。
- **React / Vue** — 本项目核心是「时序 + 排版 + 精确视觉」，框架的响应式解决的不是这些问题，只增加一层抽象。
- **PixiJS / Phaser** — 强项是 sprite 循环、物理、图集，一个都不需要；而且会把 UI 逼回 canvas，丢掉 DOM 免费的文字排版。
- **Three.js / WebGL** — 前三幕用不到。真要做体积光时**局部**加一层 shader，不是全局换引擎。
- **Vite / 打包器 / Tailwind / 状态管理 / ECS** — 全是「以后可能需要」的抽象。等真实需求出现。

## 四、10 分钟体验的设计（先写「玩家经历什么」）

**核心叙事原则：不替玩家总结答案，只创造足够真实的经历，让玩家自己问。**

| # | 时刻 | 玩家经历什么 | 承担什么 | 状态 |
|---|---|---|---|---|
| 1 | 0:00–1:20 | **空窍内部**。全黑，只有听不见的呼吸和一次心跳。微光扩成光膜球体，里面一片很浅的静止光海（丙等资质，只铺球体下半部），中央一只蝉在睡。**不给一个字。** 动鼠标，视线随之位移；悬停蝉上，蝉翅轻颤一下回应 | 无 | ✅ 已实现 |
| 2 | 1:20–3:00 | 心跳加重，空窍收缩成一点白光 → **白场曝光** → 屋梁、潮木、屋檐滴水、青山雨雾。玩家仍只能「看」。一行字比雨声还轻：`青茅山。落雨。` | 无 | ✅ 已实现 |
| 3 | 3:00–5:00 | 回到屋里。桌上摆着三颗元石——他全部的家当。把石头**拖进空窍**，蝉吞下，明灭强一点。剩下的肉眼可数，**没有数字 UI** | 机会成本的种子：三颗，喂一颗少一颗 | ✅ 已实现 |
| 4 | 5:00–6:30 | 一个同族少年主动示好，送一颗元石，理由是「你昨天帮过我」。但玩家在前两幕**自己观察到**这人曾在窗外和另一个人低语。三选：接受 / 反问为什么 / 拒绝。**没有任何旁白暗示这是不是陷阱** | 信息判断 | ⬜ 未写 |
| 5 | 6:30–8:00 | 接受 → 元石有问题，喂给蝉后元海浑浊，且少年隔天「借走」另一样东西；拒绝 → 情报流失，后山药圃那条路永远不再出现。两条路都具体、可见、不可回退 | 真实且不可回退的代价 | ⬜ 未写 |
| 6 | 8:00–9:30 | 机位回到那一滴屋檐水，但这条路上再没人经过。他只剩一个动作：向前走。**没有台词解释** | — | ⬜ 未写 |
| 7 | 9:30–10:00 | 标题《问真》，弦乐与人声气音 | — | ⬜ 未写 |

**美术方向**：Cinematic 2D —— 二维呈现，三维空间与光照逻辑。真实材质、体积光、空气透视、逆光、雾、景深。
**不画的**：宣纸滤镜、水墨滤镜、朱砂红、祥云、卷轴、印章、木框、满屏书法。东方来自世界怎么运转，不来自装饰。
**色彩纪律**：控颜色**数量**，不是机械降饱和。允许大面积安静色 + 少量极强情绪色。危险靠日常建立意义——不能让一局过半时间都在危险视觉状态。
**UI 纪律**：内容 > UI，层级 > 装饰，排版 > 边框，状态变化 > 永久 HUD。能靠状态变化说的，不做永久面板。

## 九、踩过的坑（下次别再踩）

1. **`--virtual-time-budget` 会骗你。这是最大的一个。**
   虚拟时间下 CSS 过渡**只有在别的操作触发样式重算时才推进**，所以截到的中间态是假的，
   严重时整页纯黑——而 DOM dump 显示一切正常、opacity 都是 1。
   我为它白查了很久（试过静态探针、三种淡入方式对照、强制重算、真实时间对照）。
   **结论：一律用 `tools/drive.mjs` 的真实时间。虚拟时间截图这个手段在本项目里作废。**
2. **`requestAnimationFrame` 在无头一次性渲染里不保证触发。**
   `stage.fade()` 因此不依赖 rAF，改用 `void node.offsetWidth` 强制一次回流把当前值坐实。
3. **`fadeOutAll()` 会同步抓取当前所有层。**
   必须在**建本场新层之前**调用。放在后面会把这一场自己的层也一起淡掉删掉，画面只剩黑底。踩过两次。
4. **黑屏时不要猜。** 加 `?probe=1` 把各层**实测** opacity 打到屏幕上，再 dump DOM。
   「没渲染」和「渲染了但看不见」是两类完全不同的 bug，混在一起查会浪费大量时间。
5. **无头浏览器里 WebAudio 会干扰渲染测试**，用 `?silent=1` 关掉再截。
   （反过来，音频本身在无头下**没有被验证过**，见第十节。）
6. **生图模型会在右下角打水印**，统一裁掉，别一张张手处理。
7. **本机环境怪癖**（与本项目无关，但会卡住你）：
   - bash 缺 coreutils，`ls`/`head`/`wc` 都不可用 → **用 PowerShell**。
   - PowerShell **不回显 stdout** → 输出重定向到文件再 Read。
   - `Remove-Item` 走「安全删除到回收站」包装，回收站 API 在本机会失败 →
     删文件用 `[System.IO.File]::Delete($path)`。

- 真机（非无头）上的性能与字体渲染差异。
- 第四幕起的任何东西。

## 十二、移交纪律

- **不碰父仓库的 Godot 线**。本目录与 `AGENTS.md` 的 Godot 约束体系正交，两者互不影响。
- **不做预抽象**。不因为「以后可能需要」创建 Manager / Service / EventBus / 自制引擎。
  方案优先级：**可完成 > 可维护 > 清晰 > 稳定 > 可扩展 > 理论优雅**。
- **不做持续昂贵的东西，只做瞬间昂贵的东西**：高质量静态资产 + 分层 + 轻微视差 + 局部动画 + 雾 + 光 + 声音，
  用低制作成本换高感知价值。不真的生产一个昂贵世界，生产一个**让玩家感觉昂贵**的世界。
- 每推进一幕就重跑第九节的验证循环，别攒着。
